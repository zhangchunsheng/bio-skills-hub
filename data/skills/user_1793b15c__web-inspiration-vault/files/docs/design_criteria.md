# 设计判据库（可计算版）

> 这份文档是「网页灵感风格模板库」的**审美判据层**。
> 《Refactoring UI》与 Bringhurst《The Elements of Typographic Style》提供判据，
> 本技能把它们转成可执行规则，落在 `scripts/extract_dna.py` 的 `audit_design()` 里，
> 每张灵感卡都会带一份体检结果。

## 为什么需要这一层

第一版只有"统计"（众数间距、最高频色），没有"判据"。统计能告诉你
*页面用了什么*，判据才能告诉你 *这样用对不对*。比如"平均间距 18.7px"是统计，
"相邻间距差小于 25% 就失去了系统的意义"才是判据。

## 判据清单

### 排版 · Typography

| 判据 | 规则 | 出处 | 系统内检查 |
|---|---|---|---|
| 行宽 measure | 45–75 字符可接受，**66 字符为理想** | Bringhurst 2.1.2 | 有正文栏宽约束时判定；否则标"无法静态确定" |
| 中文行宽 | 西文规则不适用；中文舒适区约 25–40 字/行 | Bringhurst 的适用边界 | 按 `cjk_ratio >= 0.3` 自动切换 |
| 行高 leading | 正文 1.4–1.9；**无衬线字体比衬线字体需要更大行距** | Refactoring UI / Bringhurst | 按 `html/body` 声明取值，不取全站最大值 |
| 行高与字号反比 | 小字要更大行距，大标题行高可低至 1 | Refactoring UI | 正文与标题行高分角色记录 |
| 字号阶梯 | 相邻值差距不小于约 **25%**，否则"阶梯"失去意义 | Refactoring UI · Establish a type scale | 对声明阶梯算相邻比值 |
| 字重档位 | 界面 2 档足够（400/500 + 600/700）；**不用低于 400** | Refactoring UI · Size isn't everything | 统计档位与过轻字重 |
| 数字对齐 | 表格数字右对齐（小数点对齐才好比较） | Refactoring UI | 需渲染，暂不检查 |
| 居中 | 长文（>2–3 行）一律左对齐 | Refactoring UI | 需渲染，暂不检查 |
| 字距 | 标题收紧；全大写加宽 | Refactoring UI | 记录 `letter_spacing` |

### 间距与布局 · Layout & Spacing

| 判据 | 规则 | 出处 | 系统内检查 |
|---|---|---|---|
| 间距阶梯 | 相邻值差距不小于约 25%；小端密集、大端拉开 | Refactoring UI | 对高频间距值算相邻比值 |
| 歧义间距 | **组外间距 > 组内间距**，否则元素归属不清 | Refactoring UI | 需渲染，暂不检查 |
| 分区标题 | 上方间距约为下方的 **2 倍** | Bringhurst（子标题 26pt above / 13pt below） | 建模板时手工遵守 |
| 留白起点 | 先从"太多"开始，再往回收 | Refactoring UI | — |
| 不填满屏幕 | 用 `max-width` 约束，别为对齐而拉伸 | Refactoring UI | 记录容器宽 |
| 段落宽度 | **段落宽度 ≠ 内容区宽度**；两者应分别约束 | Refactoring UI · Dealing with wider content | `prose_width` 与 `container_width` 分开统计 |

### 配色 · Color

| 判据 | 规则 | 出处 | 系统内检查 |
|---|---|---|---|
| 对比度 | 正文（<18px）≥ 4.5:1；大字号 ≥ 3:1 | WCAG | `contrast_text_bg` |
| 灰阶要有色温 | 纯灰（饱和度 0）显生硬；加 2–5% 同色相饱和度 | Refactoring UI · Greys don't have to be grey | 检查中性色饱和度 |
| 品牌色不得是近黑/近白 | 明度须在 0.18–0.85、饱和度 ≥ 0.28 | Refactoring UI · Don't let lightness kill your saturation | 已内建为品牌色选取硬约束 |
| 明度远离 50% 时要补饱和 | 否则浅色/深色档会显灰白 | Refactoring UI | 建模板时手工遵守 |
| 别靠颜色单独传达信息 | 色盲用户会读不到 | Refactoring UI | 建模板时手工遵守（加图标/文字） |
| 色彩数量 | 彩色过多会稀释层级 | Refactoring UI · 层级优先 | 统计高饱和色数量 |
| 标签要弱化 | 标签是辅助信息：更小、更浅、更轻；数据才是主角 | Refactoring UI · Labels are a last resort | 建模板时手工遵守 |

### 深度与分隔 · Depth

| 判据 | 规则 | 出处 | 系统内检查 |
|---|---|---|---|
| 光来自上方 | 凸起=上缘更亮+下方阴影；凹陷=上缘更暗 | Refactoring UI · Emulate a light source | 统计阴影 y 偏移方向 |
| 阴影分两层 | 大而柔（直接光）+ 紧而深（环境遮蔽）；后者随高度升高而变淡 | Refactoring UI | 建模板时手工遵守 |
| 少用边框 | 优先用阴影 / 两层底色 / 加大间距来分隔 | Refactoring UI · Use fewer borders | 比较边框与阴影数量 |
| 强调色点缀 | 用 accent border 加彩，而非大面积色块 | Refactoring UI | — |
| 图片防渗色 | 图片底色接近页面底色时，用内阴影而非边框 | Refactoring UI | — |

## 诚实边界（很重要）

1. **这是结构体检，不是审美终审。** 光学对齐、基线对齐、留白心理感受、
   层级是否"好看"——都需要真实渲染才能判断，静态解析做不到。
2. **判据读的是"声明"，不是"使用"。** 设计系统完备的站点（典型如 RAND）
   会在 CSS 里声明完整的字号阶梯、8 档字重、整套色板，但页面只用到其中一部分。
   所以"字号阶梯 13 处相邻差 <25%"这类告警，应理解为
   **"站点的可选范围偏宽"**，而不是"页面用得很乱"。
3. **宁可说不知道，也不给假数字。** 拿不到正文栏宽时，体检报告显示
   "行宽无法静态确定"并说明按容器估算是多少、为什么不予采信 ——
   而不是给一个看起来专业的错误结论。（RAND 第一次跑就吐出了"行宽 180 字符"，
   那是拿页面容器 1440px 算的，属于典型假警报。）
4. **异常值要先查来源再改判据。** RAND 报"正文行高 1.0"时，第一反应不该是
   "RAND 排得不好"，而该去查这个 1.0 从哪来 —— 结果发现是
   `:where(ul>li)::marker{line-height:1}`，伪元素样式，与正文无关。

## 量行宽时最容易错的三个地方（RAND 连错两轮）

1. **不要拿页面容器宽当行宽。** `container_width` 是版心，`prose_width` 才是段落。
   RAND 容器 1440px -> 按它算得 180 字符，纯属虚构。
2. **不要拿列表项/卡片/图片的宽度当行宽。** RAND 的 `&>li{width:55.5rem}`=888px 被误收，
   得出 111 字符。**排除 `li/ul/card/thumb/img/nav` 类选择器**；反过来，
   类名明示的 `.constrain-width` / `.prose` / `.measure` 即使标签角色不符也应采信 ——
   关键词比标签更有信息量。（RAND 真值：`.constrain-width{width:41rem}`=656px）
3. **不要用单点平均字宽估字符数。** 西文 0.45–0.6em 差异很大，单点 0.5em 会在临界值上假报警。
   用区间判断，并对边界情况如实标注"上限略高，取决于字体实际字宽"。

## 已固化为断言（`tests/test_extract_dna.py`）

- `sans-serif` 含子串 `serif` -> 族系判定顺序必须 mono -> sans -> serif
- `var(--color-pink-500)` 里的 "pink" 不是颜色
- 品牌自定义字体的**回退链不代表设计意图**（同一坑出现三次，已根治为
  `trusted_char()`：第一族不认识 -> 老实说"族系未知"）
- 近黑/近白永远不是品牌色
- 伪元素与嵌套 CSS 残片不得参与正文判据
- 图片多 ≠ 杂志风；**必须绑定页面类型**（内容枢纽页 vs 长文页）
