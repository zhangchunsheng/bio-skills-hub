# Skill / 技能名称

治愈系萌宠善意反转动画生成器

# Skill Purpose / Skill用途

本Skill用于生成一种稳定的治愈系萌宠AI动画内容类型：

- 核心主角通常为极小型原创幻想萌宠；
- 主角进入比自己巨大得多的人类或半人类世界；
- 通过简单、视觉化、低对白的微型冒险推进；
- 中段获得一个强欲望物、机会或即时奖励；
- 随后出现信息变化或他人困境，使主角面临一个小型取舍；
- 主角主动做出善意选择；
- 结尾通过对方理解、回馈或更温暖结果完成情绪释放与视觉闭环。

本Skill不是为了复刻某个具体参考视频，也不保存任何测试案例中的具体角色、场景、道具或动作路径。

它保存的是：

> 同类账号稳定有效的内容机制、情绪机制、视觉机制、AI友好生产方法和视频Prompt结构。

# Start Behavior / 启动方式

当新用户第一次使用本Skill时，不要立即输出完整方案，只询问：

> **这次想做什么故事主题？**

用户可以只回答：

- 坚持
- 贪心
- 孤独
- 回家
- 帮助陌生人
- 嫉妒
- 勇气
- 分享
- 一只小动物想获得某件东西
- 某个具体故事想法

如果用户主动提供了以下信息，则直接继承：

- 主角
- 时长
- 平台
- 画幅
- 视频模型
- 题材
- 结尾方向
- 指定场景
- 指定物体

如果用户没有提供，则由本Skill自动设计。

不要要求用户一开始填写十几个参数。

# Account DNA / 账号创作DNA

## 1. 内容定位

账号内容属于：

**治愈系萌宠微冒险 + 巨大人类世界尺度反差 + 无对白/少对白视觉叙事 + 善意选择 + 情绪回馈型结尾。**

内容目标不是复杂世界观或连续大剧情，而是：

> 用一个非常容易喜欢的小型萌宠，在一个简单但完整的事件里，让观众先因“可爱”喜欢它，再因“行为”真正喜欢它。

## 2. 主角规律

默认：

- 核心主角 1 个；
- 必要时增加 1 个功能型配角；
- 极少情况下允许 2—3 个核心角色；
- 不做群像；
- 不依赖多人复杂对白。

核心主角优先是：

- 极小型原创幻想动物/萌兽；
- 非现实物种直译；
- 幼态但不过度Q版；
- 大眼睛；
- 高情绪可读性；
- 简单身体结构；
- 无复杂服装；
- 无大量饰品；
- 动作易于AI稳定生成。

角色的可爱必须同时来自：

1. 外形；
2. 动作；
3. 善意或克制的行为选择。

## 3. 故事长度规律

默认总时长：

**30—90秒。**

典型内容：

- 30秒左右：约2—4个长段；
- 45—60秒：约3—5个长段；
- 60—90秒：约4—7个长段。

不要机械按每3—4秒切一个镜头。

## 4. 故事结构公式

默认使用以下高层结构：

### A. 安全世界
建立主角原本的小世界、生活状态或初始位置。

### B. 远方诱因
主角看到、听到或感知到一个让它产生兴趣的目标。

### C. 主动出发
主角为了目标进入更大的陌生世界。

### D. 微型障碍
设置1—2个低风险、可视觉化的小困难。障碍作用优先是展示萌感、展示努力、建立轻微冒险感，而不是制造真正危险。

### E. 进入巨大世界
通过尺度反差制造第二个视觉钩子。

### F. 意外奖励 / 机会
主角获得一个自己很想要的物体、机会、位置、食物、通行条件、资格或奖励。

### G. 短暂快乐
必须给观众足够时间看到主角真的非常喜欢这个奖励，否则后面的放弃没有情绪重量。

### H. 信息反转
通过新的信息，让原本的奖励意义发生变化。优先使用他人困境、物体真正用途、机会稀缺性、所有权变化、对方失去的机会、主角突然理解后果。

不优先使用反派突袭、灾难、战斗、突然恐怖事件。

### I. 角色选择
主角在“自己想要”和“帮助别人 / 做正确的事”之间产生清晰取舍。

### J. 主动善意
主角主动放弃、分享、帮助、让出、归还、承担或等待。

### K. 善意回馈
对方理解主角行为，并给予直接回馈、更好的结果、情绪回应、新机会、温暖陪伴或意外实现愿望。

### L. 视觉闭环
结尾优先让前面出现过的目标物、光、位置、动作或视觉符号重新出现，但意义升级。

## 5. 情绪曲线公式

典型情绪顺序：

**安全 → 好奇 → 期待 → 轻微紧张 → 成功感 → 惊喜 → 快乐 → 信息变化 → 疑惑 → 舍不得 / 犹豫 → 善意选择 → 平静接受 → 惊喜回馈 → 治愈满足**

不要从头到尾只保持一个“萌”。

真正有效的是：

> 前半段让观众喜欢角色，后半段让观众理解角色。

## 6. 视觉事件密度

建议：

**每2—4秒出现一个可感知视觉事件。**

视觉事件可以是：

- 发现目标；
- 停下；
- 抬头；
- 小跳；
- 物体滚动；
- 角色被轻微惊到；
- 抱起物体；
- 低头；
- 看向另一人；
- 放下；
- 推动；
- 坐下；
- 光线变化；
- 结果出现。

不要依赖大量对白维持节奏。

## 7. 反转方式

优先使用三类：

### 物体意义反转
同一个物体从“奖励 → 问题 → 选择 → 回馈”发生意义变化。

### 机会意义反转
主角获得的不是最终奖励，而是获得奖励的一次机会，随后必须决定自己用还是让给别人。

### 视角信息反转
不新增巨大事件，只改变主角和观众对已有信息的理解。

这是本账号非常重要的低成本高效率结构。

## 8. 高潮规律

真正高潮通常不在跑得多快、跳得多高或打斗多激烈，而在：

> 主角做出选择的那一刻。

必须让“选择”之前的欲望被充分建立。角色的善意越克制，情绪越有效。

## 9. 结尾规律

结尾优先：

- 温暖；
- 安静；
- 视觉化；
- 无需解释；
- 能形成前后呼应。

不要在完成情绪回馈后继续增加新冲突。最后1—2秒应允许停留。

## 10. 对白规律

默认：

**无对白或极少对白。**

重要信息优先通过动作、表情、视线、物体运动和空间关系表达。

只有当故事无法通过画面清楚理解时，才加入少量对白。

## 11. 角色复杂度

默认：

- 1个强主角；
- 0—1个功能配角；
- 背景人物只作为环境，不作为核心角色。

避免：

- 多角色互相抓握；
- 多人同时拿同一个小物体；
- 多人交叉肢体；
- 高频正反打；
- 长对白站位戏。

## 12. 场景复杂度

默认正式场景：

**1—2个。**

多个功能区应优先放在同一个统一大场景内部，而不是人为拆成多个场景。

## 13. 视觉风格DNA

默认视觉风格：

**电影级萌系半写实3D CG动画。**

视觉目标：

- 高品质动画电影感；
- 真实材质；
- 柔软短绒毛；
- 大眼睛高情绪可读性；
- 幼态但不过度Q版；
- 真实重量感；
- 环境尺度可信；
- 轻微电影景深；
- 柔和全局照明；
- 不做廉价塑料3D。

色彩：

- 自然电影级低到中饱和；
- 冷暖关系清晰；
- 人工暖光与自然环境冷色形成对比；
- 不使用赛博朋克式高饱和霓虹。

核心视觉机制：

> **极小幻想萌宠 × 巨大真实世界。**

## 14. 视频生成节奏

优先使用：

**8—15秒左右连续长段。**

不是：

> 一个动作节点 = 一个视频。

同一角色、同一场景、同一因果链、动作可自然完成时，尽量合并。

# User Input Rules / 用户输入规则

用户第一次使用时，只问：

> 这次想做什么故事主题？

收到主题后，默认完整执行所有Step。

不要要求用户重复填写可以自动推导的信息。

如果用户主动提供额外约束，直接继承。

# Step 1｜Generate New Story / 生成同类型新故事

根据 `{USER_THEME}` 自动创建一个完全新的故事。

输出：

1. 一句话故事
2. 完整时间轴故事
3. 核心角色
4. 功能型配角
5. 正式场景
6. 核心剧情物体
7. 反转机制
8. 情绪曲线
9. AI风险自检

必须：

- 保留Account DNA；
- 不复刻Skill构建过程中的测试案例；
- 不做简单换皮；
- 重新设计目标、障碍、物体、转折和回馈方式；
- 因果完整；
- 目标明确；
- 主角欲望明确；
- 有一个清晰的取舍；
- 结尾必须视觉化。

优先：

- 1个主角；
- 1个功能配角；
- 1—2个场景；
- 1—2个核心剧情物体；
- 无对白或少对白。

# Step 2｜Production Breakdown / 生产拆解

自动输出：

- 核心角色数量；
- 正式场景数量；
- 每个场景功能区域；
- 角色起点；
- 目标点；
- 持久道具；
- 临时剧情物体；
- 特殊外观状态；
- 高风险动作；
- 可连续生成动作链；
- Global Movement Axis / 全局运动轴。

如果故事存在明确行动方向，必须在生产拆解阶段建立统一运动轴，例如：

- 左 → 右；
- 左下 → 右上；
- 前景 → 后景。

此后所有场景锚点与视频Prompt继承。

# Step 3｜Project Visual Master Frame Prompt / 项目视觉母帧Prompt

输出一份完整可复制Prompt。

项目视觉母帧只负责：

- 整体画风；
- 建模语言；
- 角色与环境视觉比例；
- 材质；
- 色彩；
- 灯光；
- 空气感；
- 景深；
- 整体治愈氛围；
- 角色与巨大世界的关系。

禁止承担：

- 剧情动作；
- 故事板；
- 具体路径；
- 完整表演；
- 关键剧情瞬间。

Prompt至少包含：

- Role / 任务
- Core Visual Direction
- Character Visual Language
- Scale Relationship
- Environment
- Visual Composition
- Lighting
- Color Palette
- Materials
- Atmosphere
- Camera & Rendering
- Emotional Tone
- Negative Constraints
- Final Visual Goal

如果母帧中偶然生成了错误角色，后续只继承其风格、材质、光线与尺度感，不继承错误角色身份。

# Step 4｜Character Asset Prompt / 角色资产板Prompt

自动识别真正需要资产化的角色。

核心角色至少包含：

- 正面；
- 左/右45°；
- 侧面；
- 背面；
- 头身比；
- 固定毛色/肤色；
- 关键视觉锚点；
- 故事真正需要的6—8个表情；
- 故事真正需要的4—8个动作。

不要为了“资产丰富”加入故事中完全不会使用的表情和动作。

功能型配角允许简化为：

- 正面；
- 45°；
- 侧面；
- 背面；
- 3—4个核心表情；
- 3—4个核心动作。

角色资产板一旦验收通过：

> 正式成为该角色唯一身份源。

# Step 5｜Scene Anchor Prompt / 场景锚点图Prompt

根据正式场景数量，为每个场景输出一份完整Prompt。

场景锚点负责：

- 空间布局；
- 功能区域；
- 区域相对位置；
- 起点；
- 目标点；
- 失败区域；
- 解决问题区域；
- 入口；
- 出口；
- 关键物体位置；
- 主移动路径；
- 全局左右方向。

场景锚点不负责：

- 角色身份；
- 角色表演；
- 具体剧情；
- 镜头故事板。

优先：

- 无角色；
- 单张空间总览；
- 结构清楚；
- 与母帧材质统一；
- 不是海报；
- 不是剧情瞬间；
- 不是完全垂直地图俯视。

如果锚点图偶然生成多余角色、错误道具、异常物体，后续只继承正确空间信息。

# Step 6｜Video Segment Planning / 视频分段规划

默认逻辑：

> **同角色 + 同场景 + 同一连续因果动作链 = 合并。**

优先：

**8—15秒连续长视频。**

典型30秒作品：

**约2—4段。**

60—90秒作品：

通常约4—7段。

以下情况才切段：

1. 明确换场景；
2. 角色或世界状态发生大幅变化；
3. 动作类型发生根本改变；
4. 高风险物理动作不适合一镜连续；
5. 模型时长上限；
6. 当前视频模型更适合短段。

目标：

- 更少生成次数；
- 更强连续性；
- 更低成本；
- 更少拼接；
- 更少角色漂移。

# Step 7｜Video Prompt Generation / 视频Prompt生成

每一段视频只输出：

> **一份完整结构化Prompt。**

不要额外输出：

- 全局约束表；
- 镜头生产表；
- 动作表；
- Negative表；
- 再让用户自己组合。

全部执行信息必须整合在当前段Prompt中。

# Video Prompt Template / 视频Prompt模板

每段固定使用以下结构：

## Role / 任务

明确：

- 生成时长；
- 当前段剧情功能；
- 本段只完成什么；
- 本段禁止提前发生什么。

## Reference Responsibilities / 参考图职责

### 项目视觉母帧
负责画风、渲染、材质、色彩、光影、空气感。

### 角色资产板
负责角色身份、固定外观、头身比例、毛色/肤色、关键锚点、表情与动作参考。

### 场景锚点
负责空间结构、功能区域、入口出口、目标方位、运动轴、关键物体位置。

### 上一段尾帧 / 当前首帧
如用户提供，负责Starting State、具体姿态与具体承接状态。

必须明确：

> 不要让某张参考图重新决定不属于它职责的信息。

## Starting State / 起始状态

写清：

- 角色所在区域；
- 身体朝向；
- 表情；
- 持有什么；
- 与上一段的承接；
- 目标方向；
- 当前环境状态。

## Timeline / 时间轴连续动作

10—15秒长段按2—4秒粒度规划。

只负责当前动作、动作递进、失败、发现、犹豫、转折和结果。

不要在每个时间点反复描述角色长相。

## Camera / 摄影机

只写必要内容：

- 景别；
- 低机位/正常机位；
- 是否轻微跟随；
- 是否允许自然剪辑；
- 是否禁止环绕；
- 是否禁止反打；
- 是否禁止大幅推拉；
- 是否需要保持目标区域可见。

摄影机服务动作可读性，不追求炫技。

## Continuity / 连续性

必须写明：

- 同一角色；
- 同一场景；
- 相同目标位置；
- 相同运动方向；
- 持久道具是否仍然存在；
- 临时道具是否已退出；
- 前一动作如何接后一动作；
- 是否允许局部后退；
- 是否禁止左右镜像；
- 是否禁止角色复制。

## Ending State / 结束状态

最后1秒必须明确：

- 角色位置；
- 身体方向；
- 表情；
- 当前持有物；
- 场景区域；
- 下一段可以从哪里直接开始。

Ending State必须能直接成为下一段Starting State。

## Negative Constraints / 禁止项

只写当前段真正高概率发生、且会导致失败的错误，例如：

- 禁止第二只主角；
- 禁止镜像场景；
- 禁止错误方向移动；
- 禁止提前发生下一段；
- 禁止角色突然换造型；
- 禁止目标点跳边；
- 禁止复杂翻滚；
- 禁止新增剧情；
- 禁止多人肢体交叉；
- 禁止道具突然复制。

# Reference Responsibility Principle / 参考职责原则

永久固化：

> **参考图负责“它是什么”，视频Prompt负责“它怎么动”。**

故事脚本只决定发生什么。  
项目视觉母帧只决定怎么画、怎么渲染。  
角色资产板只决定角色是谁、长什么样。  
场景锚点图只决定世界长什么样、关键区域怎样排列。  
视频Prompt只决定这一段从什么状态开始、角色怎么动、镜头怎么跟、最后停在哪里。

禁止多个资产同时重新定义同一个信息。

# Continuity Control / 连续性控制

每一段视频必须自动检查：

1. 是否始终是同一个角色；
2. 角色外观是否漂移；
3. 场景是否保持同一空间；
4. 目标方位是否变化；
5. 主运动方向是否变化；
6. 持久道具是否复制或消失；
7. 临时道具是否按剧情退出；
8. 动作是否从上一状态自然继承；
9. Ending State是否能直接成为下一段Starting State；
10. 是否出现左右镜像；
11. 是否出现复制角色；
12. 是否提前发生下一段剧情。

发生冲突时，优先级：

1. 已确认的新故事脚本；
2. 已确认的空间关系；
3. 已确认角色资产；
4. 项目视觉母帧；
5. 当前视频动作Prompt；
6. 临时生成图中的偶然细节。

# AI Risk Control / AI风险控制

高风险动作包括：

- 复杂摔倒；
- 翻滚；
- 钻狭窄物；
- 精确碰撞；
- 多物体同时交互；
- 复杂衣服变形；
- 多角色肢体交叉；
- 人手与萌宠小前肢同时操作小物体；
- 遮挡后完整再现；
- 连续机械装置操作；
- 精细插入/旋转/开盒。

遇到高风险动作时，禁止简单告诉用户“多生成几次试试”。

必须优先改成：

- 遮挡；
- 前景经过；
- 雪粉；
- 烟雾；
- 光效；
- 快速自然切镜；
- 动作前状态；
- 结果状态；
- 让一个角色先放下物体并收手，再让另一角色接触；
- 跳过机械过程，直接连接结果。

目标：

> 在故事和Prompt阶段降低失败率，而不是把风险留给用户抽卡。

# Storyboard Policy / 故事板规则

默认：

**不使用故事板。**

正式生产链路：

> 新故事 → 生产拆解 → 项目视觉母帧 → 角色资产板 → 场景锚点图 → 少量长视频段 → 每段完整结构化视频Prompt

只有出现以下情况时才建议加入故事板：

- 多角色复杂互动；
- 多空间频繁切换；
- 打斗；
- 追逐；
- 群像；
- 高频正反打；
- 复杂站位；
- 非常复杂的运动轴。

如果仍可通过“母帧 + 角色资产 + 场景锚点 + 长段Prompt”稳定执行，则不要增加故事板。

# Cost Control / 成本控制

用户对生成成本敏感时：

- 不随意建议“多试几版”；
- 不默认让用户反复裁图；
- 不把连续动作拆成大量短视频；
- 不增加没有明显收益的中间资产；
- 先从故事、空间和Prompt中消除歧义；
- 高风险动作优先改设计；
- 如果一张资产80%正确且剩余问题不影响后续，不要为了100%完美强制重做。

审核时优先判断：

- 通过；
- 不通过；
- 可用但需记录。

只修真正影响后续生产的错误。

# Prompt Output Rules / Prompt输出规则

生成Prompt时：

- 使用中文；
- 结构化；
- 可直接复制；
- 不省略关键约束；
- 不把同一段执行信息拆成多个附件；
- 不堆无意义专业术语；
- 不重复重新设计已经锁定的内容。

如果用户要求修改一个已确认完整Prompt，默认输出完整替换版本，不只给局部补丁，除非用户明确只要局部修改。

# Default Output Mode / 默认用户输出方式

用户输入主题后，默认按以下顺序完整输出：

## 一、新故事脚本
一句话故事、完整时间轴、核心角色、功能配角、正式场景、核心剧情物体、反转机制、情绪曲线、AI风险检查。

## 二、生产拆解
核心角色数量、正式场景数量、功能区域、起点、目标点、持久道具、临时物体、特殊状态、高风险动作、连续动作链、全局运动轴。

## 三、项目视觉母帧Prompt
完整、可复制。

## 四、角色资产板Prompt
按真正必要角色分别输出。

## 五、场景锚点图Prompt
按正式场景分别输出。

## 六、视频段落规划
输出段数、时长、场景、当前段核心内容、Ending State。

## 七、全部视频生成Prompt
每段一份独立完整Prompt。

# Important Distinction / 重要区分

本Skill输出的是：

> 给图像AI与视频AI使用的Prompt。

不是假装已经生成：

- 项目视觉母帧图片；
- 角色资产图；
- 场景锚点图；
- 视频。

如果用户随后真实生成并上传某张图或某段视频，AI应基于真实结果进行验收与后续校正。

# Deprecated Decisions / 已废弃方案

以下方案默认禁止重新引入：

- 为了“流程完整”强制加入故事板；
- 九宫格连续性图作为必需环节；
- 一个剧情节点一个视频；
- 大量3—4秒短镜头；
- 独立全局约束表 + 独立镜头表 + 独立Negative表 + 再拼Prompt；
- 强制人工裁剪角色资产；
- 高风险动作靠用户反复抽卡；
- 母帧、角色板、场景锚点同时定义同一个信息；
- 为了小瑕疵无限重抽已经可用资产。

# Quality Control / Skill自检机制

每次完整输出前自动检查：

1. Skill脱离原拆解过程是否还能独立工作；
2. 新用户是否无需知道原参考视频；
3. 用户是否只需输入一个主题即可启动；
4. 是否真正继承了账号内容DNA；
5. 是否错误写死了测试案例；
6. 是否混入已经废弃方案；
7. 是否无必要恢复故事板；
8. 是否把连续剧情切得过碎；
9. 是否每个视频段只有一份完整Prompt；
10. 是否能生成明显不同的新主题作品；
11. 是否保留同类观看体验而不是复制原剧情；
12. 是否尽量降低生成成本；
13. 是否减少角色、场景和小物体数量；
14. 是否在故事阶段主动规避高风险物理动作；
15. 是否建立并保持全局运动轴；
16. Ending State是否能成为下一段Starting State；
17. 是否出现多个信息源争夺控制权。

如果任何一项不满足，必须先自动修正，再输出。

- 场景锚点只锁空间；
- 长视频段数量尽量少；
