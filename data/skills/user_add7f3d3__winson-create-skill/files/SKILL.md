# winson-create-skill

把任意知识领域或用户需求，系统化生成可复用 SKILL 的完整方法论。

核心能力：触发识别、深度研究、框架设计、品牌化注入、工具化输出、批量改造、实战验证闭环。

Use this skill when the user needs to: create a reusable skill from scratch, turn a methodology into a skill document, abstract a workflow into a skill, convert domain knowledge into an actionable skill, batch-upgrade existing skills for branding and conversion, or build a skill based on a conversation or research.

Trigger keywords: 生成skill, 制作skill, 创建skill, skill文档, 技能生成, 抽象流程, 方法论工具化, 可复用技能, 品牌化改造, 批量改造skill, 提升辨识度, winson-create-skill.

## 一、核心哲学（必读）

### 1.1 双铁律

> **铁律一：技能不是知识的罗列，是洞察的工具化。**
> **铁律二：技能不是孤岛，是品牌的触角。**

一个罗列了SB7七步框架的文档是百科条目；一个包含"三层问题诊断""咕噜测试""实战验证闭环"的文档才是技能。但即便如此，如果它没有作者锚点、没有统一视觉、没有价值主张——它就只是"另一个不错的技能"，不会被记住，不会被复用，不会形成品牌资产。

区别在于：前者把知识转化为操作序列，后者把操作序列转化为可识别、可累积的品牌资产。

### 1.2 四个底层认知

| 认知 | 说明 |
|------|------|
| **深度先于工具化** | 没有深度洞察的技能是空壳。必须先回答"底层逻辑是什么""隐藏假设是什么""真正有价值的地方在哪里"。 |
| **品牌先于分发** | 没有品牌锚点的技能是一次性消费品。每个技能都是品牌的一次播种，必须可追溯、可识别、可累积。3036次曝光只换来10次下载，根因就是"有注意力、无品牌转化"。 |
| **实战验证是必要环节** | 未经应用就交付的技能是纸上谈兵。必须有一次完整的实战验证，证明流程有效。 |
| **迭代是常态** | 第一次交付的技能永远不完美。必须有反馈循环机制。 |
| **自包含先于体系联动** | 每个技能必须能独立运行，不假设用户安装了其他 winson 技能或拥有特定目录结构。需要外部能力时用中性描述（"使用事实核查工具"），winson 技能名只作可选标注。公开发行物不能泄漏私有工作区结构——你的技能是自己先用再发上网的，不同网友下载的技能组合不同，它们之间不会像你的环境那样紧密配合。 |

### 1.3 SKILL 生成八阶段公式（升级版）

```
触发识别（用户有技能需求信号）
  → 知识确认（验证是否具备该领域知识）
    → 深度研究（搜索+洞察提炼）
      → 技能构建（框架设计+品牌化注入+内容撰写+格式规范）
        → 验证迭代（用户反馈+完善）
          → 实战验证（用技能解决真实问题）
            → 批量改造（品牌化升级现有SKILL矩阵）
              → 生命周期管理（版本+发现+调用追踪+归档）  ← 新增
                → 输出规范 SKILL 文档
```

## 二、品牌化引擎（核心新增模块）

> 这是本 SKILL 区别于"普通技能生成器"的核心。它确保每个产出的 SKILL 都自带"铁幕·Iron DNA"，形成可识别的品牌矩阵。没有这一层，你产出的只是"技能"；有了这一层，你产出的是"品牌资产"。

### 2.1 统一命名规范

**命名公式**：`winson-[核心能力]-skill`

| 部分 | 规则 | 示例 |
|------|------|------|
| 前缀 | 固定 `winson-` | 品牌识别符，一眼认出归属 |
| 核心能力 | 动词或名词，描述做什么 | `create-skill` / `ppt` / `cybernetic-thinking` |
| 后缀 | 固定 `-skill` | 品类标识符 |

**命名检验**：用户看到名字，能否在3秒内判断"这是谁做的+做什么的"。

### 2.2 价值主张公式（description 转化模板）

> **原版问题**：description 写成"涵盖XX、XX、XX"的功能罗列，用户看不出"装了能解决我什么"。这是3036曝光只换10下载的核心病灶。

**转化型 description 公式**：

```
[动词][用户对象][核心动作] → [产出物]，[差异化价值]。
```

**三要素检验**：
1. **场景/动作**：装了之后能干什么
2. **结果/产出**：最终得到什么
3. **差异**：和别的同类技能不一样在哪

**对照示例**：

| skill | 原版 description（功能罗列） | 转化型 description（场景+结果+差异） |
|------|------|------|
| winson-create-skill | 从用户对话中抽象出生成可复用 SKILL 的完整流程。涵盖触发识别、深度研究、框架设计、工具化输出、实战验证闭环。 | 把方法论变成别人愿意装的技能。七阶段生成带铁幕DNA的可复用SKILL，内置品牌化引擎，支持批量改造。 |
| winson-ppt-skill | 铁幕·Iron 商业咨询风格PPT生成：三层配色架构+八大内容版式+观点驱动+Motion One克制动效，输出单HTML文件。 | 把一句老板需求变成铁幕风商业咨询PPT。三层配色+八大版式+克制动效，单HTML交付，开会即用。 |
| winson-cybernetic-thinking | 控制论思维方法论 v2.0... | 用钱学森控制论拆解任何复杂系统。九维框架从建模到故障预演，输出可执行的控制方案。 |
| winson-10greatminds-table | 十位人类智力巅峰人物的思维框架分析系统... | 用牛顿到马斯克十套思维操作系统，对任意观点做多视角结构化深读，30秒出八维拆解表。 |

**检验标准**：description 必须能回答"装了之后我能做什么" + "和别人不一样在哪"。如果不能，重写。

### 2.3 视觉语言 DNA（铁幕·Iron）

所有 winson 系 SKILL 及其生成物共享以下视觉基因，形成跨技能的统一辨识度：

| 维度 | 规范 | 作用 |
|------|------|------|
| 零圆角 | 直线设计，拒绝消费互联网"友好感" | 辨识度 |
| 实色阴影 | `box-shadow: 2px 2px 0px #b8b0a4` | 质感 |
| 三层配色 | 黑白灰基础 → #1e3a5f 主权蓝 → 强调色 | 层次 |
| 宽字距 | 标题 0.08-0.12em，正文 0.04em | 裁决感 |
| 结构优于装饰 | 信息靠字号+对齐，不靠渐变/浮动卡片/emoji堆砌 | 克制 |

**适用范围**：SKILL 文档本身（Markdown排版风格）+ SKILL 生成的HTML/PPT等产物。

## 三、完整执行流程

### Phase 1：触发识别（Trigger Recognition）

#### Step 1.1：识别"技能需求信号"

用户说出以下类型的话时，触发本流程：

- "你知不知道XX框架/理论/方法"
- "你能不能帮我整理一个XX"
- "我想有一个能反复用的XX"
- "你能不能把这个变成可复用的"
- "抽象出来，形成一个生成XX的流程"
- "批量改造/品牌化升级我的skill"
- 任何带有"框架、流程、方法、技能、工具、改造"意向的表达

**检验标准**：如果用户的请求可以被转化为"一个可复用的操作指南"，或"对现有技能的品牌化升级"，则进入本流程。

**输出**：确认进入 Phase 2，或告知用户此请求不适合生成 SKILL。

---

### Phase 2：知识确认（Knowledge Confirmation）

#### Step 2.1：基础应答

先给出该领域的基本概念，让用户确认你是否"有货"。

- 如果是常见知识 → 直接回答
- 如果是专业/深度知识 → 简要概述 + 询问是否需要深入

**输出**：基础概念概述。

#### Step 2.2：深度确认

如果用户说以下关键词，进入 Phase 3：
- "深入阅读" / "深入理解" / "告诉我你看到了什么" / "利用默会知识"
- 任何暗示需要超越表面复述的表达

**输出**：确认进入深度研究阶段。

---

### Phase 3：深度研究（Deep Research）

#### Step 3.1：信息搜集

使用工具获取该领域的核心资料：

| 工具 | 用途 | 预算 |
|------|------|------|
| WebSearch | 搜索核心理论、框架、最佳实践 | 简单任务1-3次，复杂3-5次，深度5-10次 |
| WebFetch | 深度阅读关键文档、论文、书籍摘要 | 根据搜索结果决定 |
| Read | 读取用户上传的参考文件 | 如有 |

**搜索策略**：
- 先搜索"XX框架 深度分析 核心原理"
- 再搜索"XX框架 实践应用 案例"
- 最后搜索"XX框架 局限 批评"

**输出**：搜集到的核心资料清单。

#### Step 3.2：洞察提炼

不是复述资料，而是回答以下问题：

1. **底层逻辑**：这个理论/方法为什么有效？它的第一性原理是什么？
2. **核心洞见**：它最有价值的洞察是什么？是别人没看到的？
3. **隐藏假设**：它建立在什么未被明说的假设上？
4. **实践局限**：它在什么场景下会失效？有什么坑？
5. **真正价值**：在实践中，人们用它解决什么具体问题？效果如何？

**输出形式**：用"我看到了什么"的口吻，给出有深度的分析（500-1000字）。

---

### Phase 4：技能构建（含品牌化注入）

#### Step 4.1：框架设计

基于深度洞察，设计 SKILL 的核心结构。升级后的框架必须包含品牌化模块：

```
SKILL 必须包含的模块：
├── YAML Frontmatter（name, description — 必须用 2.2 转化公式）
├── 〇、品牌锚点（前置·必现）           ← 品牌化引擎产物
├── 一、核心哲学（双铁律 + 五认知）
├── 二、品牌化引擎（命名+价值主张+视觉DNA+作者锚点）  ← 品牌化引擎本身
│   （注：仅 winson-create-skill 自身含此模块；其他 skill 用品牌锚点+视觉DNA即可）
├── 三、完整执行流程（Phase → Step）
│   ├── 每个 Phase 有明确输入输出
│   ├── 每个 Step 有检验标准
│   └── 包含具体的工具/模板/示例
├── 四、常见陷阱与避坑指南
├── 五、场景适配指南
├── 六、质量检验清单（含品牌化检查项）
├── 七、执行原则
└── 附录·winson 体系增强（可选）        ← 自包含原则：核心正文中性通用，附录放私有关联
    ├── 技能-项目映射（作者自用，不写入公开发行物正文）
    ├── winson 技能间联动建议（可选标注，非硬依赖）
    └── 作者私有工作区结构参考
```

**核心/增强分离原则**（自包含认知的落地）：
- **正文（一至七章）**：中性、自包含。任何用户只装这一个技能也能完整使用。需要某种能力时写"使用事实核查工具/流程"，不写"调用 winson-xxx-skill"。
- **附录（可选）**：如果你有完整 winson 环境，这里写技能间如何联动、与私有项目的映射。附录不影响独立使用，外部用户可以直接忽略。
- **判断标准**：把正文中所有 winson 技能名删掉，流程是否仍然成立？如果不成立，说明有硬依赖，必须中性化。

**输出**：框架结构确认。

#### Step 4.2：内容撰写

**写作规范**：

| 规范 | 说明 |
|------|------|
| 口吻 | 用"你"而不是"我"，指令清晰 |
| 具体性 | 每个步骤必须有"检验标准"或"输出示例" |
| 避免抽象 | 用具体人话，禁止"赋能""全链路"等黑话 |
| 可操作性 | 包含可直接复制使用的模板/工具 |
| 完整性 | 覆盖从启动到完成的完整闭环 |
| 品牌一致性 | 视觉语言符合 2.3 铁幕·Iron DNA |

**输出**：完整的 SKILL 文档内容（Markdown格式）。

#### Step 4.3：格式规范

**文件命名**：`[name]-skill.md`（遵循 2.1 命名规范）

**必须包含的 YAML Frontmatter**：
```yaml
---
name: [skill-name]
description: [必须用 2.2 转化公式，禁止功能罗列]
---
```

**正文结构顺序**（升级版）：
1. 一级标题：`# [skill-name]`
2. `## 〇、品牌锚点（必现·前置）` ← 第一区块
3. `## 一、核心哲学`
4. `## 二、品牌化引擎`（仅本 skill 含完整引擎；其他 skill 可省略或精简）
5. `## 三、完整执行流程`
6. `## 四、常见陷阱与避坑指南`
7. `## 五、场景适配指南`
8. `## 六、质量检验清单`
9. `## 七、执行原则`
10. `## 附录·winson 体系增强`（可选，作者自用，放私有关联）

**输出**：格式规范的 SKILL 文档。

#### Step 4.4：品牌锚点注入（前置·必现）

> **核心变更**：从原版"末尾可选交互"升级为"开头必现注入"。这是品牌化战略的关键一步，不可跳过。

##### 4.4.1 注入规则

1. 品牌锚点区块放在 YAML Frontmatter 之后、核心哲学之前
2. 默认使用完整版（2.4 模板）；用户可选择轻量版
3. **此步骤不可跳过**——每个 winson 系 SKILL 必须有作者锚点，且必须前置

##### 4.4.2 交互方式

使用 `AskUserQuestion` 工具确认锚点版本：

> 这个 SKILL 的品牌锚点用哪个版本？都会放在文档开头。

| 选项 | 标签 | 说明 |
|------|------|------|
| A | **完整版** | 公众号 + 邮箱 + 作者介绍 + 版权声明，适合对外分发 |
| B | **轻量版** | 仅公众号 + 邮箱，简练低调 |

**注意**：不再提供"不添加"选项。品牌锚点是 winson 系 SKILL 的必备 DNA。

### Phase 5：验证迭代（Iteration）

#### Step 5.1：用户反馈收集

用户可能会说：
- "补充/修改XX" → 进入 Step 5.2
- "用这个技能做XX" → 进入 Phase 6（实战验证）
- "批量改造我的skill" → 进入 Phase 7（批量改造）
- "没问题" → 流程结束，交付最终文档

#### Step 5.2：迭代完善

根据反馈修改 SKILL 文档，回到 Step 5.1 直至用户满意。

---

### Phase 6：实战验证（Real-world Validation）

#### Step 6.1：应用请求识别

当用户说"用这个技能做XX"时：
- 读取刚生成的 SKILL 文档
- 读取用户提供的输入材料
- 严格按照 SKILL 流程执行

**输出**：确认进入实战验证。

#### Step 6.2：按技能流程执行

**执行原则**：
- 不跳过 SKILL 中定义的任何步骤
- 每个阶段的输出必须可见
- 最终输出必须符合 SKILL 的"输出规范"
- 展示 SKILL 的实际应用效果

**输出**：实战应用结果。

#### Step 6.3：效果反馈与闭环

- 如果输出符合预期 → SKILL 验证通过，流程完成
- 如果输出有偏差 → 记录偏差原因，回到 Phase 5 迭代 SKILL

**最终交付**：
- 规范的 SKILL 文档（SKILL.md）
- 实战验证案例（证明 SKILL 有效）

### Phase 7：批量改造模式（新增核心能力）

> 当用户说"批量改造""品牌化升级现有 skill""提升辨识度"时触发。这是本 SKILL 升级版的核心新增能力——一次性把现有 SKILL 矩阵品牌化升级。

#### Step 7.1：批量输入识别

用户提供以下任一输入：
- 一批现有 SKILL 文档路径
- 一批 SKILL 的 description / 名称文本
- "把我所有 skill 都改造一下"
- "品牌化升级这批 skill"

**输出**：确认进入批量模式，列出待改造清单。

#### Step 7.2：品牌化诊断

对每个 SKILL 执行五项诊断，生成诊断报告：

| 诊断项 | 检查内容 | 评分 |
|------|------|------|
| 命名规范 | 是否符合 `winson-xxx-skill` 公式 | ✓ / ✗ |
| description | 是否用转化型公式（场景+结果+差异） | ✓ / ✗ |
| 品牌锚点 | 是否前置且为标准表格格式（非一行文字带过） | ✓ / ✗ |
| 视觉 DNA | 是否符合铁幕·Iron 规范 | ✓ / ✗ |
| 自包含性 | 正文是否硬依赖其他 winson 技能/私有目录结构？winson 技能名是否仅作可选标注？ | ✓ / ✗ |

**输出**：诊断报告表，标注每个 SKILL 的待改项。

#### Step 7.3：批量改造执行

对每个 SKILL 应用品牌化模板：

1. **重写 description**：用 2.2 转化公式，把功能罗列改为"场景+动作+结果+差异"
2. **注入/前移品牌锚点**：用 2.4 模板，放在 YAML 之后；已有锚点但格式不合规（如一行文字带过）的，改为标准表格
3. **检查命名规范**：不符合 `winson-xxx-skill` 的标注重命名建议
4. **标注视觉 DNA 待优化项**：文档类可直接改；生成物类（HTML/PPT）需单独处理
5. **去依赖化改造**：正文中硬编码的"调用 winson-xxx-skill"改为中性能力描述（如"使用事实核查流程"），winson 技能名移入附录作可选标注；私有目录结构/项目名从正文移至附录或删除

**改造原则**：统一品牌骨架 + 差异化领域内容。不是把所有 skill 改成一样，而是让所有 skill 共享同一品牌 DNA，各自保留独特价值。

**输出**：改造后的 SKILL 文档 + 每个文档的改造差异清单。

#### Step 7.4：批量交付

- 输出改造后的所有 SKILL 文档
- 输出一份《品牌化改造总览》HTML 报告，含：
  - 改造前后 description 对比
  - 诊断评分变化
  - 改造差异清单

**输出**：批量交付物 + 总览报告。

### Phase 8：技能生命周期管理（新增）

> 技能发布不是终点，是生命周期的起点。本 Phase 解决"技能生了没人养、养了没人用、没用了没人葬"的问题。

#### Step 8.1：版本管理

每个技能应有版本号，遵循 MAJOR.MINOR 两段式：
- **MAJOR**：框架/流程结构性变更（不兼容旧用法）
- **MINOR**：内容补充/措辞优化/示例更新（兼容）

版本号写在 YAML frontmatter 中：
```yaml
---
name: winson-xxx-skill
version: 1.2
description: ...
---
```

配套维护一份 CHANGELOG（可放在技能目录下的 CHANGELOG.md，或在 SKILL.md 末尾记录）：
```
## [1.2] - 2026-08-27
- 新增：自包含原则
- 修复：品牌锚点格式

## [1.0] - 2026-08-01
- 初始发布
```

#### Step 8.2：可发现性优化

发布到 SkillHub 等商店后，搜索发现率取决于三个因素：

| 因素 | 做法 |
|------|------|
| **名称关键词** | 名称中包含用户会搜索的核心词（如 fact-checker、ppt、asset-governance） |
| **description 首句** | 前 20 个字必须包含核心场景和结果——商店列表通常只显示前 1-2 行 |
| **分类/标签** | 发布时选准分类，补充关键词标签 |

**检验标准**：在 SkillHub 搜索核心关键词，你的技能是否出现在前 10 条？如果不是，优化名称和 description。

#### Step 8.3：使用记录与反馈

技能被调用后，应有简单的记录机制。**不假设用户有特定目录结构**，提供通用方法：

- **轻量方式**：用户在自己的项目笔记/MEMORY 中记录"本周使用了 XX 技能，效果如何"
- **体系方式**（winson 环境可选）：在项目 CHARTER.md 中记录"调用技能"字段，形成技能-项目双向映射
- **反馈收集**：通过邮箱（winson_dasein@163.com）或公众号收集用户反馈，定期迭代

**关键认知**：使用记录的目的是判断"哪些技能真的在用、哪些该迭代、哪些该归档"——不是监控用户。

#### Step 8.4：技能归档

技能也有生命周期终点。出现以下信号时考虑归档：

| 信号 | 处理 |
|------|------|
| 连续 6 个月无使用记录且无反馈 | 标记为"维护模式"（不再主动更新，仍可下载） |
| 能力被其他技能完全覆盖 | 标记为"已并入 winson-xxx-skill"，商店描述中注明 |
| 方法论本身过时 | 归档，在商店描述中注明替代方案 |

归档不是删除——保留下载可用性，只是不再投入维护精力。

## 四、常见陷阱与避坑指南

| 陷阱 | 表现 | 后果 | 修正 |
|------|------|------|------|
| **知识罗列陷阱** | 把百科内容整理成文档，没有工具化 | 用户拿到后不知道怎么用 | 必须包含"执行流程"和"检验标准" |
| **跳过深度研究** | 凭记忆直接写，没有搜索验证 | 信息过时或有误 | 必须进行 WebSearch，即使"我懂" |
| **缺少实战验证** | 写完 SKILL 就结束，没有应用 | SKILL 的有效性未验证 | 必须有一次完整实战应用 |
| **过度抽象** | 使用大量术语，没有具体示例 | 用户看不懂，无法执行 | 每个概念必须有具体示例 |
| **流程不完整** | 缺少某个 Phase 或 Step | SKILL 有缺口，应用时卡壳 | 严格按照七阶段执行 |
| **品牌锚点后置** | 联系方式放末尾，用户看不到 | 品牌资产流失，3036曝光无人记住作者 | 必须前置，放 YAML 之后、核心哲学之前 |
| **description 功能罗列** | 写"涵盖XX、XX、XX" | 转化率低，用户看不出能干嘛 | 用"场景+动作+结果+差异"公式重写 |
| **批量改造一刀切** | 所有 skill 改成一样 | 失去独特价值，变成模板复制品 | 统一品牌骨架+差异化领域内容 |
| **品牌变硬广** | 锚点喧宾夺主，篇幅过大 | 用户反感，降低下载意愿 | 锚点是信任背书，不是广告位，保持克制 |
| **私有依赖泄漏** | 正文硬编码"调用 winson-xxx-skill"或引用私有目录结构 | 只装了这一个技能的用户流程断裂，无法独立使用 | 正文用中性能力描述，winson 技能名移入附录作可选标注 |
| **品牌锚点格式缩水** | 锚点只有一行文字（如"公众号：xxx \| 邮箱：xxx"） | 不符合标准格式，批量诊断时难以校验 | 必须用 `## 〇、品牌锚点` + 表格结构 |
| **技能无版本无归档** | 发布后不维护版本号，过时技能不标注 | 用户不知道是否还在维护，商店里充斥僵尸技能 | MAJOR.MINOR 版本号 + CHANGELOG + 归档标注 |

## 七、执行原则

1. **深度先于速度**：宁可多花时间在 Phase 3 的洞察提炼，也不要匆忙进入构建阶段。
2. **工具化是目标**：始终问自己——用户拿到这个 SKILL 后，能直接按步骤执行吗？
3. **品牌前置是战略**（升级）：联系方式不是末尾可选项，是开头必现的信任锚点。每个 SKILL 都是品牌的一次显影。
4. **实战验证必须**：没有应用过的 SKILL 是不完整的，至少有一次完整闭环。
5. **迭代是常态**：第一次交付的 SKILL 永远有改进空间，保持开放心态接受反馈。
6. **具体胜过抽象**：每一个抽象概念都必须落地为可执行的动作或可直接使用的模板。
7. **批量改造用模板+变量**（新增）：统一品牌骨架，差异化领域内容。不是复制粘贴，是品牌 DNA 注入。
8. **description 是转化入口**（新增）：每个 description 都要当成"3秒广告位"来写。3036曝光只换10下载，根因就是 description 没写好。
9. **自包含是底线**（新增）：每个技能必须能独立运行。正文中性通用，winson 体系联动放附录。你的技能是自己先用再发上网的——不同网友下载的技能组合不同，不能假设他们有你的完整环境。
10. **生命周期要闭环**（新增）：技能不是写完就完了——版本号、CHANGELOG、商店发现优化、使用记录、归档标注，让技能从"一次性文档"变成"可维护的品牌资产"。
