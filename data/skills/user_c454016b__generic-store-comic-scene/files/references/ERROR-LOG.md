# 门店漫画场景生成 · 错误记录与防错手册（通用版）

> 适用：线下零售门店「员工 + 顾客」同框漫画场景（ImageGen 生成，16:9 或 9:16），不限品牌、不限零售品类。
> 目的：把实战中反复出现的失败模式**抽象归档**，后续生成前逐条对照，避免重蹈。
> 范围：本手册只记录**与品牌无关的通用失败模式**。品牌专属资产（角色参考图、锁定背景、材质规则）见 `profiles/<brand>.md`。

---

## 〇、一句话核心结论

**非对称特征是最容易翻车的点。** 模型对「仅单侧」的理解极不稳定，会对称地给两侧都加上；但只要在 prompt 里同时做到「**EXACTLY ONE 计数词 + 视角侧位置描述 + 三重负面约束 + image1 锁定该角色参考图**」，就能稳定通过。

其余问题（背景漂移、角色头部漂移、材质混入）都是「**约束写不够明确**」所致——把锁定图强制复用、把材质写死，即可解决。

**这条规律跨品牌、跨品类成立**：只要涉及单侧特征，无论什么行业、什么品牌，处理方式完全一致。

---

## 一、错误类型（按发生频率排序）

### ❌ 错误 1：非对称特征被对称化 —— 最高频

**典型表现**：同一角色的双手（或双侧）都出现了该单侧特征，而要求是仅一侧；或单侧特征被补成对称。

- **发生频次**：最高。多轮迭代中反复出现，**仅靠一句"只有某一侧"从未成功过**。
- **根因**：
  1. 模型对「单侧」理解不稳定，会对称性地给两侧都加；
  2. 当把**对手方角色参考图**作为 **image1** 时，主角色形象失去锚定，漂移更严重。
- **失败尝试**：仅写 `ONLY her LEFT hand wears the item` —— **不够**，实测仍生成双侧同类特征。
- **有效修复（四要素，缺一失效）**：
  1. **EXACTLY ONE 计数词** —— 明确"恰好一个"；
  2. **视角侧位置描述** —— `her LEFT hand (on the viewer's RIGHT side of her body) is the hand extended…; her RIGHT hand (on the viewer's LEFT side of her body) is completely BARE`；
  3. **三重负面约束** —— `NO X on the other hand, NO X on both sides, NO second X anywhere`；
  4. **image1 必须 = 有非对称特征的角色参考图**，绝不用对手方参考图作 image1。
- **防错规则（每次 prompt 必写）**：
  ```
  CRITICAL ASYMMETRY RULE: {{角色}} wears EXACTLY ONE {{feature}} on the hand on
  the viewer's {{LEFT|RIGHT}} side of the body only; the other hand is completely
  BARE with visible skin. NO {{feature}} on the other hand, NO {{feature}} on both
  sides, NO second {{feature}} anywhere.
  ```

> **为什么必须写 viewer's side**：只写 left/right 时，模型可能以「画面中的左右」理解，也可能以「人物自身的左右」理解，两种理解在镜像时冲突，导致约束失效。显式写出 `her LEFT hand (on the viewer's RIGHT side)` 就把参照系钉死了。

### ❌ 错误 2：背景与锁定场景不符

**典型表现**：生成的门店是另一家店——布局、家具、配色全不对。

- **根因**：仅写文字描述 `store environment`，未强制复用锁定图。
- **有效修复**：把锁定背景图放入背景槽位，并在 prompt 写明：
  ```
  BACKGROUND MUST BE EXACTLY the store environment in image{{N}}, used as the literal
  background plate... Reproduce image{{N}}'s exact layout, furniture placement, and
  color palette — do NOT invent a different store.
  ```
- **防错规则**：每个场景固定映射一张锁定背景图，并在 prompt 强制复用。**映射表写在品牌档案里，不要每次临时找。**

---

### ❌ 错误 3：对手方角色头部 / 发型漂移

**典型表现**：同框的对手方角色每次生成长得不一样，发型、脸型对不上。

- **根因**：对手方角色缺乏稳定锚定；若用它的参考图占 image1，又会牺牲主角色的锚定。
- **有效修复**：
  - 有参考图 → 放入 image2/image3，并声明 `EXACTLY as in image{{N}}`；
  - 无参考图 → 用**强文字约束**，且描述要写到"只靠文字也能还原"：
    ```
    {{发型 — 长度/卷直/颜色}} with NO bangs, NO ponytail, NO bun, NO hairclip;
    {{配饰，注明在哪一侧}}; {{上装规格}}.
    ```
- **防错规则**：同框时 **image1 永远留给有非对称特征的角色**；对手方角色用参考图 + 文字双重约束，**并附「禁止发型变化」负面项**。

> **权衡记录**：图槽位有限时，把 image1 让给对手方角色，就等于牺牲主角色的锚定。实测结论是**有非对称特征的一方优先**——它最难约束。

---

### ❌ 错误 4：展示商品混入非目标材质 / 品类

**典型表现**：要求展示单一材质或单一品类，画面里却出现其他材质、其他品类。

- **根因**：模型默认会画混合品类 / 混合商品，不主动限定材质。
- **防错规则（每次 prompt 必写）**：
  ```
  ALL products displayed are {{允许品类}} ONLY — {{具体列举}}; plus {{辅助道具}}.
  NO {{禁止材质1}}, NO {{禁止材质2}}, NO {{禁止材质3}}.
  ```
- **通用化提示**：换成任意零售品类同理——服装店要锁「无其他品牌 Logo」，食品店要锁「无禁忌食材」，均需显式列举**允许项 + 禁止项**，只写允许项不够。

---

### ❌ 错误 5：水印未清除（右下角「AI生成」角标）

- **发生**：每轮 ImageGen 默认带右下角水印。
- **修复（PIL）**：取水印上方同色调区块粘贴覆盖（区域约 220x70，y 偏移 -80）。
  ```python
  from PIL import Image
  im = Image.open(src).convert('RGB'); w, h = im.size
  rw, rh = 220, 70
  patch = im.crop((w - rw, h - rh - 80, w, h - 80))
  im.paste(patch, (w - rw, h - rh)); im.save(dst)
  ```
- **注意**：实测 16:9 输出实际尺寸为 **1920x1072**（非 1080），裁剪坐标按实际尺寸算。
- **已脚本化（v2）**：`python scripts/watermark.py <file.png>`（原地修改）或指定输出路径。
  - v2 新增边缘羽化与可调参数：`--rw / --rh / --offset / --feather`
- **⚠️ 局限（实测）**：水印落在**复杂图案区**（如花纹台面、纹理墙纸、密集商品陈列区）时会留下**可见的纹理接缝**——羽化只能减轻、无法消除。缓解顺序：
  1. 调大 `--offset`（如 90~120），让采样块取自更同质的区域；
  2. 调大 `--feather`（6~12），使过渡更柔和；
  3. 仍留痕时，改用 ImageGen 对水印区局部重绘，或直接裁掉底部若干像素。
  水印落在纯色 / 渐变 / 低频背景时，本脚本效果良好。

### ❌ 错误 6：HTML 编辑引入多余 `</div>`

- **发生**：加警示样式时，多次在 edit 中多写一个 `</div>`，导致页面结构错位（嵌套层级未对齐）。
- **修复**：用脚本统计 `<div>` vs `</div>` 是否平衡。
- **已脚本化**：`python scripts/check_html_divs.py <file.html>`，退出码 0=平衡、1=不平衡。
- **防错规则**：批量改 HTML 后，跑 div 平衡校验再 present。

---

### ❌ 错误 7：「其他不变」式最小修改，重生成却改了别处

- **发生**：用户说「只改 X，其他不变」，重生成时人物左右位置变了。
- **根因**：未固定构图，模型自由布局。
- **防错规则**：
  - 收到「其他不变」时，复用上一版**完全相同**的 prompt，**仅改目标项**；
  - 若需严格保构图，可把上一版成品作为 image1 传入以保一致性（但需评估与角色锁定的冲突——**优先保非对称特征锁定**）；
  - 若用户对构图有硬要求，建议改用**局部修补**（PIL 改色 / 改配饰）而非重新生成。

---

### ❌ 错误 8：用「与参考图同一只手」抽象表述替代方位描述

**典型表现**：为规避"左右写反"的风险，把单侧约束改写成 `the SAME single hand as in the reference image` 这类**抽象指代**，结果**双侧都变成了该特征**。

- **实验设计**：同场景、同输入图，**仅替换该约束段**（方案 A / 方案 B），其余 prompt 逐字相同。
- **根因**：抽象指代无法给模型提供**可定位的空间锚点**。模型无法据此确定"哪一侧"，默认对称化补全 → 双侧。
- **失败尝试**：外部人物规格文档曾建议"不硬编码左右，统一写与参考图同一只手"——本实验证明该方案不可用。
- **有效修复（方案 A 通过）**：保留「EXACTLY ONE 计数词 + 视角侧位置描述 + 三重负面约束」。
  - 对照结果：方案 A 单侧正确 ✅ / 方案 B 双侧漂移 ❌。
- **附带发现（重要）**：
  - **有 image1 锚定时，文字方位被参考图覆盖**——方案 A 文字写「观众右侧」，实际生成「观众左侧」，与基准图一致；
  - **无图锚定的角色文字方位会生效**，按「角色自身」理解。
  - 因此：方位正确性由参考图保证，文字方位仍应当**与基准图实际对齐**以消除文字-图形冲突。
- **防错规则**：
  1. **禁止**用「同一只手 / the same hand as in the reference image」类抽象表述替代方位描述；
  2. 填方位前**放大基准图目视确认**是哪一侧——纯像素统计会被深色衣物、发色干扰，**必须目视复核**；
  3. 有图锚定与无图锚定的角色，方位写法规则不同，勿混用。

---

### ❌ 错误 9：并行生成撞同一时间戳文件名，互相覆盖

**典型表现**：同时发起多个 ImageGen 调用，产物落在**同一时间戳文件名**上，后完成的写覆盖先完成的，最终只剩一张或产物错乱。

- **根因**：默认输出文件名由时间戳生成；并行调用在同一秒内可能撞名。
- **防错规则**：
  1. **必须串行生成**——一次调用完成后再发下一次；
  2. 需要并行时，**每路指定不同的 `output_dir`** 做隔离；
  3. 生成后核验产物**数量与文件名**是否符合预期（数量对不上即为覆盖征兆）。

---

### ❌ 错误 10：双角色同框，两角色约束方向相反时互相污染

**典型表现**：同框场景中两个角色的外观约束**方向相反**时，模型会把 A 的规则套到 B 身上。典型组合：一方「仅单侧佩戴某配饰」、另一方「完全禁戴任何配饰」——若不做防污染处理，禁戴方会被加上该配饰，或单侧方被补上第二只。

- **发生条件**：同框 + 两角色约束方向相反（一方「仅一侧」、另一方「完全没有」）。服装相同但配饰规则相反的组合风险最高。
- **实测结果**：**加入防污染声明后通过**——单侧方仅一侧佩戴正确、禁戴方完全无配饰正确，未互相污染。
- **有效修复（四项缺一不可）**：
  1. **每段约束显式限定对象**，写在段首：
     ```
     CRITICAL ASYMMETRY RULE (applies to {{角色 A}} ONLY): ...
     {{某约束}} RULE (applies to {{角色 B}} ONLY): ...
     ```
  2. **双向防污染声明**，两句都要写，缺一句仍可能反向污染：
     ```
     Do NOT apply {{角色 A}}'s one-sided rule to {{角色 B}}.
     Do NOT give {{角色 A}} a second one.
     ```
  3. **两角色共有的负面项合并写**，避免重复与遗漏：
     ```
     NO {{共同禁忌项}} ... on EITHER character.
     ```
  4. **槽位分配**：image1 = 有非对称特征者（优先锚定），image2 = 第二角色，image3 = 锁定背景。
- **防错规则**：凡「一方单侧、一方全无」的角色组合，上述四项缺一不可。

## 二、生成前防错清单（每次调用 ImageGen 前逐项勾选）

- [ ] **image1 = 有非对称特征的角色参考图**（绝不用对手方参考图作 image1）
- [ ] 锁定背景已分配到**最后一个可用槽位**
- [ ] prompt 含 **ASYMMETRY RULE**（EXACTLY ONE + 视角侧位置 + 三重负面约束，三要素都在）
- [ ] 该约束段**未使用**「与参考图同一只手」类抽象表述（错误 8，实测导致双侧漂移）
- [ ] 方位描述已**放大基准图目视确认**（勿只用像素统计，会被深色衣物干扰）
- [ ] prompt 含**对手方角色强文字约束** + 禁止发型变化（NO bangs/ponytail/bun）
- [ ] **双角色同框时**：各段约束已显式限定对象 + 双向防污染声明
- [ ] prompt 含 **品类/材质锁定** + 负面约束
- [ ] prompt 含 `NOT a photograph, NO photorealistic rendering, NO English text on signage, NO watermark, NO dark vignette`
- [ ] 已确认本次为**串行生成**（并行会撞时间戳文件名互相覆盖，见错误 9）
- [ ] 生成后：**读图核验非对称特征 → 清除水印（复杂图案区注意接缝）→ 重命名**
- [ ] 若改 HTML：**跑 div 平衡校验** 再 present
- [ ] 旧版按迭代归档，不删

## 三、单侧特征「铁律」模板（直接复制，替换 `{{feature}}` 与 `{{LEFT|RIGHT}}`）

> ⚠️ `{{LEFT|RIGHT}}` 必须按**基准图实际方位**填写，填前放大基准图目视确认。
> 🚫 **禁止**改写成「the same hand as in the reference image」类抽象表述（见错误 8，实测导致双侧漂移）。

```
CRITICAL ASYMMETRY RULE: {{角色}} wears EXACTLY ONE {{feature}}
on the hand on the viewer's {{LEFT|RIGHT}} side of the body only;
the other hand (on the viewer's {{RIGHT|LEFT}} side of the body) is completely
BARE with visible skin and is NOT holding anything.
NO {{feature}} on the other hand. NO {{feature}} on both sides.
NO second {{feature}} anywhere. NO praying-hands pose.
NO bare hand holding {{product}}.
```

**可替换场景**（同一模板通吃，只换 `{{feature}}`）：

| 单侧特征 | `{{feature}}` 填法 |
|----------|-------------------|
| 单只手套 | `glove` |
| 单侧长袖 | `long sleeve` |
| 单肩包 | `shoulder bag strap` |
| 单侧胸针 / 徽章 | `brooch` / `name badge` |
| 单侧发型（仅一侧垂发） | `side-swept lock of hair` |

> **注意**：特征若涉及"持物"，必须同时指定是哪一侧持物，并加 `NO praying-hands pose`——模型在没有明确指示时会自作主张让双手合拢持物。

## 五、迭代归档约定

每轮旧版入对应版本文件夹，便于回溯、不删。建议命名格式：

```
v<N>-raw/          原始生成
v<N>-backup/       修改前备份
v<N>-<问题标签>/    已知存在该问题的版本（如 v1-drift）
```

**命名建议**：版本名带上问题标签，回溯时能一眼看出该版为什么被淘汰。

## 六、把新失败沉淀为规则的方法（元方法）

规则库要能自己长大。遇到新失败点，按这 6 步做：

1. **定位现象** — 具体到什么位置错了（哪张图、哪个人物、哪个部位）。"效果不好"是无效记录。
2. **归因根因** — 区分「约束写得不够明确」（加约束可解）与「模型能力边界」（需换策略，如局部修补）。
3. **记录失败尝试** — 写清"试过 X 但没用"。**这是最有价值的一栏**，避免下次重复试错。
4. **给出有效修复** — 标注是在哪一轮对照中验证通过的，让规则可信。
5. **固化为可复制模板** — 写成 prompt 片段，不要只写"要写清楚左右"。
6. **进 checklist** — 只有进了生成前清单的规则才会被真正执行。

## 七、本手册的组织原则

- **只写通用模式**：不记录任何具体品牌、角色名、商品品类、门店场景。
- **案例抽象化**：具体案例保留"机制层"信息（什么触发了漂移、什么表述无效），去掉"项目层"细节（版本号、文件名、产物清单）。
- **品牌差异外置**：品牌专属的失败记录写在各自 `profiles/<brand>.md` 的「已知漂移记录」一节，不污染本手册。
