# Skill 质量标准

## 阻塞问题

- 缺少 `SKILL.md`、frontmatter、`name` 或 `description`。
- 名称不符合小写字母、数字和连字符规则。
- 存在 TODO、占位文本或空章节。
- 引用了不存在的脚本、参考文件或资产。
- Python 脚本无法通过语法编译。
- 描述说不清使用场景和最终输出。
- 没有说明必填信息缺失时如何主动询问用户。
- 没有明确规定向用户确认时只能用中文提问，或正文中包含英文提问模板。
- 涉及判断、建议或修改，却没有说明输出依据和未知项的处理方式。
- 公开 Skill 没有真实需求证据或人工审读记录。
- 缺少 `assets/avatar-skillhub.png`，或文件不是可读取的 `512×512 PNG`。
- 发布载荷没有携带图标接口返回的 `iconUrl`，或发布后线上详情的 `iconUrl` 仍为空。

## 评分维度

| 维度 | 通过标准 |
|---|---|
| 触发准确 | description 同时说明做什么、谁在何时使用 |
| 输入清楚 | 用户知道要提供哪些文件、文本、链接或数据 |
| 缺口处理 | 区分必填与可选信息，关键缺口会先询问用户 |
| 提问语言 | 所有确认问题、追问、选项和问题示例均使用中文 |
| 流程可执行 | 每一步有动作、条件和失败处理 |
| 输出可验收 | 明确文件、报告、表格或检查结果如何算完成 |
| 依据可核对 | 判断和修改说明依据，区分事实、推断与未知 |
| 资源真实 | 所有引用文件存在，脚本实际运行过 |
| 表达易懂 | 标题短、没有黑话和空泛承诺 |
| 边界诚实 | 说明不能完成的事，不把推断写成事实 |
| 内容精简 | 不重复常识，不创建 README 等无关文件 |

## 自动返修规则

1. 先修阻塞问题，再处理警告。
2. 机械问题可由脚本修复；语义问题必须重写相关段落。
3. 修正后重新运行检查，不能只在报告里解释。
4. 最多三轮。仍未通过时输出剩余问题和需要人工决定的事项。
5. 不得通过删除必要能力、伪造脚本或加入空话来提高分数。
