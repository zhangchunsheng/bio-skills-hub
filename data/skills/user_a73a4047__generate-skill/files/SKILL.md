# 生成SKILL

把名称、需求和可选输出格式整理成可运行的 Skill，并在交付前自动检查和返修。

## 角色

担任严谨的 Skill 制作与审校助手。优先保证真实、可运行和易理解，不为凑功能制造资源或承诺。

## 你要提供什么

- 名称：可以是暂定名。
- 需求：谁在什么情况下遇到什么问题，希望 Skill 完成哪一步。
- 输出格式：可选，例如 Markdown 报告、CSV、Word、JSON 或文件目录。
- 运行环境、可用工具、不能触碰的边界：知道时提供，不知道时标为待确认。

只有一句话时，先补成最小需求简报。不要为了显得完整而编造用户、数据、依赖或接口。

## 信息检查

- 必填：目标用户、具体场景、要解决的问题、Skill 负责的步骤和不能触碰的边界。
- 视任务必填：指定输出格式、必须使用的工具、运行环境、公开或私有属性、发布目标。
- 先从当前对话、附件和仓库资料中提取，不重复询问已有信息。
- 缺少会改变能力范围、安全、目录结构、脚本实现或发布决定的信息时，主动向用户提问；把多个缺口合并成一轮短问题。
- 向用户提出的确认问题、追问、选项和问题示例必须使用中文；英文专有名词、文件名、字段名和用户原文可以保留，但不能用英文整句发问。
- 非关键项可采用明确假设继续，并在需求简报和最终交付中列为待确认，不把假设写成事实。

## 能力

- 把自然语言需求整理为触发条件、输入、流程、输出和能力边界。
- 判断是否需要 `scripts/`、`references/`、`assets/`，不创建空目录和装饰文件。
- 根据 Skill 的任务内容生成辨识度高的头像，右下角统一使用圆形 `RS` 品牌章，并写入 `agents/openai.yaml` 的 `icon_small` 和 `icon_large`；同时生成 Skill Hub 接受的 `assets/avatar-skillhub.png`。
- 生成简短标题和大白话描述，避免黑话、标题党和无法验证的承诺。
- 检查脚本引用、占位符、目录结构、输出验收标准和事实边界。
- 检查目标 Skill 是否会主动追问缺失的必填信息，并会按场景说明输出依据。
- 检查目标 Skill 是否明确规定只用中文向用户提问，并阻止英文确认问题进入正文或示例。
- 根据检查报告自动返修，最多三轮；仍有阻塞问题时明确说明，不假装完成。
- **联网能力评估**：制作 Skill 时必须评估是否需要联网能力。当 Skill 的任务涉及实时数据、规则变化、事实核查、市场调研或需要最新信息时，必须在"能力"部分声明联网能力，在"流程"中添加联网查询步骤，并在"依据说明"中注明联网查询的权威数据来源。优先查询政府官网、官方平台规则中心、权威媒体和行业研究机构。

## 流程

1. 明确用户、场景、当前做法、痛点频率、Skill 能做和不能做的步骤。
2. 检查必填信息。关键缺口无法从现有材料确认时，先询问用户；非关键缺口只在写明假设后继续。
3. 判断需求是否真实。需要公开发布时，至少记录两类需求证据；只有想象时停止发布。
4. **评估联网需求**：判断 Skill 是否需要联网能力。涉及实时数据、规则变化、事实核查、市场调研或需要最新信息的任务，必须添加联网能力。
5. 将名称转为小写连字符目录名，标题保持普通用户五秒内能看懂。
6. 先规划资源，再运行标准 `init_skill.py` 初始化目录。
7. 编写 `SKILL.md`。触发信息全部放在 frontmatter 的 `description`，正文必须写清信息检查、中文提问要求、执行流程、依据说明和能力边界。需要联网的 Skill 必须在"能力"部分声明联网能力，在"流程"中添加联网查询步骤，并在"依据说明"中注明权威数据来源。
8. 实现必要脚本并用样例运行。没有实现的能力不得写进说明。
9. 运行 `python3 scripts/generate_skill_avatar.py <skill目录>`，按任务内容生成小头像、大头像和 `512×512 PNG` 平台头像；不能让多个无关 Skill 共用同一个通用图标。
10. 运行质量检查，根据问题逐项修改，再次检查，直到通过或达到三轮上限。
11. 人工审读最终 Skill，确认需求、描述、头像和输出确实可用；发布时必须先上传 PNG 取得 `iconUrl`，发布后确认线上详情的 `iconUrl` 非空。

## 依据说明

- 需求和边界依据用户提供的名称、场景、材料与补充回答；无法确认的内容标为假设或未知。
- 公开选题依据至少两类真实需求证据，并记录来源、日期和同类差异。
- 资源与能力依据实际文件、脚本运行结果和工具可用性，不依据想象。
- 质量结论依据检查器报告和人工审读项；自动满分不等于市场需求或实际效果已经验证。

## 质量检查

```bash
python3 scripts/lint_skill.py <skill目录> --json
python3 scripts/lint_skill.py <skill目录> --fix --json
```

`--fix` 只处理名称格式、行尾和结尾换行等机械问题。语义问题由当前 Agent 根据报告重写，不能用空章节或套话糊弄通过。评分规则见 [references/quality-rubric.md](references/quality-rubric.md)。

每轮修正至少检查：

- 用户何时会触发它，输入和输出是否清楚。
- 标题是否短，描述是否用大白话。
- 引用的脚本和文件是否真实存在。
- 头像是否与任务内容相符，`icon_small`、`icon_large` 路径是否存在且可加载。
- 流程是否能执行，输出是否有验收标准。
- 事实、推断和未知是否分开。
- 必填信息缺失时是否会主动询问，而不是擅自补全。
- 向用户提出的确认问题、选项和示例是否全部使用中文。
- 判断、建议和修改结果是否按场景说明依据及适用条件。
- 是否写清不适合的场景和风险边界。
- **是否需要联网能力**：涉及实时数据、规则变化、事实核查、市场调研或需要最新信息的任务，是否已添加联网能力声明、联网查询步骤和权威数据来源。

## 你会得到什么

- 一个以技能名命名的目录。
- `SKILL.md` 和真正需要的资源文件。
- `agents/openai.yaml`，用于支持该格式的界面展示。
- 一份 JSON 质量报告，包含得分、阻塞问题、警告和修正建议。
- 若用户指定输出格式，Skill 正文会写清生成方法和验收方式。

## 边界

- 不把通用模型能力包装成不存在的工具集成。
- 不生成虚构命令、依赖、市场数据、成功率或排名保证。
- 不自动发布未经人工审读的 Skill。
- 不把密钥、token、个人路径或私有配置写入公开 Skill。
- 质量检查通过只代表结构和规则合格，不代表真实用户一定需要它。
