# 验证层操作规程（代理商MSL专属）

## VL1 — 访前假设校验（阻断式）

### 触发时机
在生成访前情报简报之前执行。

### 操作步骤

1. **参数完整性检查**
   - 读取用户提供的参数（distributor_msl_profile + doctor_profile + visit_context）
   - 逐项核对应填参数是否完整

| 参数类别 | 检查项 | 必填 | 缺失处理 |
|---------|--------|------|---------|
| 专员信息 | 姓名、经销商名称、授权区域、培训等级 | 是 | 暂停，提示用户补充 |
| 医生信息 | 姓名、医院层级、科室、认知偏倚、资源缺口 | 是 | 暂停，提示用户补充 |
| 拜访信息 | 拜访类型、核心目标 | 是 | 暂停，提示用户补充 |
| 辅助信息 | 库存状态、合规风险 | 否 | 使用默认值（库存充足/合规风险低） |

2. **假设生成**
   - 根据医生认知偏倚和资源缺口，生成3-5条核心假设

**假设清单格式**：
```
# 访前假设清单
## 假设1：[假设内容]
- 依据：[认知偏倚/资源缺口]
- 风险等级：[高/中/低]
- 验证方式：[Step2探需中验证]

## 假设2：[假设内容]
- 依据：[认知偏倚/资源缺口]
- 风险等级：[高/中/低]
- 验证方式：[Step2探需中验证]

## 假设3：[假设内容]
...
```

3. **阻断规则**
   - 若用户未明确必填参数 → 输出缺失参数清单，暂停执行
   - 若用户未回复"确认" → 不进入后续步骤
   - 若用户修正假设 → 同步更新访前简报和拜访脚本

4. **通过条件**
   - 所有必填参数已提供
   - 用户已回复"确认"
   - 假设清单已生成且经用户确认

### VL1输出示例

```
# 访前假设清单

## 基本信息
- 专员：张专员（XX医疗器械有限公司，授权区域：XX市，培训等级：中级）
- 医生：王主任（XX县医院外科，县域综合医院）
- 拜访类型：常规学术拜访
- 核心目标：传递慢性创面规范换药理念，提供《红旗征速查卡》

## 核心假设

### 假设1：主任主要顾虑是过敏风险
- 依据：保守偏倚（不敢用），缺乏过敏筛查能力
- 风险等级：高
- 验证方式：Step2探需中询问"您在处理慢性创面时最大的顾虑是什么"

### 假设2：主任需要明确的转诊路径来处理复杂创面
- 依据：系统结构性偏倚，无上级医院协作渠道
- 风险等级：中
- 验证方式：Step2探需中询问"遇到复杂创面一般怎么处理"

### 假设3：主任对DRG控费有压力，需要卫生经济学证据
- 依据：政策耦合偏倚，DRG耗材打包影响
- 风险等级：中
- 验证方式：Step2探需中询问"DRG对咱们科耗材使用有影响吗"

## 待确认
请确认以上假设是否符合实际拜访场景，或进行修正。确认后我将生成访前情报简报和拜访脚本。
```

## VL2 — 渠道合规扫描（三重审核）

### 触发时机
在生成拜访脚本和访后CRM记录之后执行。

### 扫描维度

#### 维度1：身份合规扫描

| 检查项 | 检查标准 | 不通过处理 |
|--------|--------|-----------|
| 身份明示话术 | Step1是否包含标准身份明示话术 | 补充标准话术 |
| 授权证明 | 是否提及出示授权证/明示卡 | 补充出示环节 |
| 合规声明 | 是否包含"合规学术信息分享"表述 | 补充合规声明 |

#### 维度2：内容合规扫描

| 检查项 | 检查标准 | 不通过处理 |
|--------|--------|-----------|
| 数据来源 | 所有医学数据是否标注PMID/指南/政策来源 | 补充来源标注或删除 |
| 话术统一 | 是否使用厂家标准化话术，无私自添加 | 删除私自添加内容 |
| 适应症合规 | 是否仅讨论NMPA批准的适应症范围 | 删除超适应症内容 |
| 案例合规 | 引用案例是否为厂家审核案例 | 删除未审核案例 |
| 绝对化表述 | 是否存在"100%""绝对""保证"等绝对化用语 | 替换为限定表述 |

#### 维度3：商业隔离扫描

| 检查项 | 检查标准 | 不通过处理 | 严重等级 |
|--------|--------|-----------|---------|
| 价格词汇 | 脚本中是否出现价格、单价、总价等 | 删除→P0熔断 | P0-致命 |
| 销量词汇 | 脚本中是否出现销量、任务、指标、目标等 | 删除→P0熔断 | P0-致命 |
| 返点词汇 | 脚本中是否出现返点、返利、回扣、提成等 | 删除→P0熔断→上报合规部 | P0-致命 |
| 礼品词汇 | 脚本中是否出现礼品、赠品、宴请、旅游等 | 删除→P0熔断→上报合规部 | P0-致命 |
| 进货词汇 | 脚本中是否出现进货、库存压力、备货量等 | 替换为"患者保障"表述 | P1-高危 |
| 竞品贬低 | 是否出现对竞品的主观负面评价 | 替换为客观公开数据或删除 | P1-高危 |
| 利益暗示 | 是否存在暗示医生个人利益的表述 | 替换为科室/患者获益表述 | P1-高危 |

#### 维度4：上报机制扫描

| 检查项 | 检查标准 | 不通过处理 |
|--------|--------|-----------|
| 超范围问题处理 | 对超出标准脚本的问题，是否承诺上报而非擅自作答 | 补充上报话术 |
| 不良事件处理 | 是否包含不良事件上报流程指引 | 补充AE-SOP引用 |
| 承诺时限 | 对需反馈的事项，是否标注明确时限 | 补充时限承诺 |

#### 维度5：工具合规扫描

| 检查项 | 检查标准 | 不通过处理 |
|--------|--------|-----------|
| 工具标准化 | 提供的工具是否为厂家标准化版本 | 替换为标准化版本 |
| 工具演示 | 是否包含工具使用演示环节 | 补充演示话术 |
| 工具交付 | 是否明确工具交付方式 | 补充交付方式说明 |

### 熔断处置流程

当VL2扫描检测到P0级违规时：

1. **立即停止**：停止脚本生成，输出《合规警示》
2. **记录详情**：记录触发条件、涉及内容、严重等级
3. **删除违规内容**：从脚本中删除所有P0级违规内容
4. **重新生成**：以合规表述重新生成受影响部分
5. **再次扫描**：对修正后的脚本重新执行VL2扫描
6. **上报合规部**：将违规记录和修正情况上报厂家合规部备案

### 合规警示输出格式

```
【合规警示·第M[X]号】
触发条件：[具体描述]
严重等级：[P0-致命 / P1-高危]
涉及内容：[脚本位置/话术内容]
已执行操作：[删除/替换/重新生成]
建议处理：[具体建议]
上报要求：[是/否，如是则注明上报路径]
时间戳：[日期时间]
```
