# 剧荒推荐 Skill — 观影DNA分析框架

## 一、整体流程

```
用户输入（10部最爱 + 类型方向）
    → Step 2: 作品标签化（6维度 × N标签）
    → Step 3: DNA模式提取（高频/中频/缺失/组合）
    → Step 4: 观影人格建模（六维评分 + 人格命名）
    → Step 5: 推荐生成（70%相似 + 20%相邻 + 10%突破）
    → 输出：人格画像 + 推荐list（10-15部）
```

### 输入要求
- 用户先从 **电影 / 电视剧 / 动漫** 三个方向中选一个
- 在选定方向内提供 **约10部最喜欢的作品**（8-12部均可，低于8部信号不足，高于12部噪音过多）
- 可选附加信息：每部作品的一句话理由（提升标签精度，但不强制）

## 三、DNA模式提取

### 3.1 聚合规则

对10部作品的所有标签进行频次统计：

| 频次区间 | 含义 | 权重 | 用途 |
|---------|------|------|------|
| ≥7/10（高频） | 核心偏好 | 3x | 人格建模主输入，推荐匹配的主依据 |
| 4-6/10（中频） | 次要偏好 | 2x | 人格建模辅助输入，推荐的弹性区间 |
| 1-3/10（低频） | 偶然触碰 | 1x | 不纳入人格，但作为推荐diversity的参考 |
| 0/10（缺失） | 排斥区 | -2x | 推荐时主动避开 |

### 3.2 组合模式识别

单独的标签频次不够，还需要识别**标签之间的稳定共现模式**：

- **共现簇**：某些标签总是同时出现（如"暗黑+反英雄+非线性"），说明这是一种审美取向而非随机组合
- **互斥检测**：如果"治愈"和"暗黑"各出现5次但从不在同一部作品中出现，说明用户在两种模式间切换，而非混合偏好
- **签名提取**：高频共现簇的组合构成用户的"观影签名"，如"慢热+多线+留白+深度思辨"→ 迷宫型叙事爱好者

### 3.3 权重微调

并非所有维度权重相等。根据对观影体验的影响力：

- **主题维度** 和 **情感维度**：最高权重（决定"为什么看"）
- **叙事维度** 和 **角色维度**：高权重（决定"怎么看"）
- **美学维度**：中权重（重要但通常不构成核心驱动力）
- **题材主轴**（元维度下的子维度）：高权重——"运动/音乐/料理/棋道…"这类题材主轴是比泛类型更强的签名信号，应提升至与主题维度同级
- **元维度（类型/地域/年代/体量）**：低权重（类型偏好是结果而非原因，避免只按类型推荐）

## 四、观影人格建模：六维模型

### 4.1 六维定义

将DNA模式压缩为 **6 个 0-100 分**的维度。所有人格的触发指标都来自这同一组维度，保证判断逻辑一致：

| 维度 | 低分（0-30） | 高分（70-100） | 计算来源 |
|------|-------------|---------------|---------|
| 沉浸度 | 偏好现实叙事、短篇、单线 | 偏好世界观构建、长篇系列、多线 | 奇幻/科幻类型 + 多线/迷宫结构 + 长篇体量 + 世界观议题 |
| 情感度 | 理性观看、冷峻、旁观 | 情感共振、代入、爆发 | 情感强度(爆发) + 悲剧/治愈基调 + 代入共情 + 角色成长弧光 |
| 智识度 | 纯娱乐、线性、直给 | 深度思辨、非线性、留白 | 哲学深度(思辨) + 非线性/碎片结构 + 留白结局 + 存在主义议题 |
| 暗度 | 明亮、温暖、英雄 | 黑暗、压抑、反英雄 | 暗黑基调 + 反英雄主角 + 道德灰度 + 禁忌/争议议题 |
| 群像度 | 个人英雄、单一主角、关系简单 | 群像、普通人主角、关系驱动的成长 | 角色聚焦方式(群像/个人) + 主角类型(普通人/英雄) + 角色弧光(成长) + 关系驱动 |
| 冒险度 | 题材单一、经典叙事、传统美学 | 题材开放（跨类型广）+ 形式实验（先锋/争议） | 内部由「题材开放度×0.5 + 形式实验度×0.5」合成；前者看跨类型广度，后者看叙事/美学先锋性（详见4.1.1）|

### 4.1.1 冒险度的两个子维度

「冒险度」在实际建模中建议拆开评估，因为两者经常不一致（例如题材极广但形式保守的用户）：

- **题材开放度**：跨类型的广度。运动/音乐/料理/异界/战斗…覆盖越多越高。
- **形式实验度**：叙事与美学的先锋性。非线性结构、先锋视觉、争议议题、非常规视角越多越高。

六维雷达仍显示单一「冒险度」分数（两者均值），但在推荐与人格描述时分别引用两个子维度，避免误判。

### 4.2 人格类型库

每种人格都是六维空间里的一个「目标向量」。用户同样被映射为六维得分向量；通过统一打分，选择距离最近（得分最高）的人格作为唯一主人格。

| 人格名称 | 典型六维画像<br>（沉浸 / 情感 / 智识 / 暗度 / 群像 / 冒险） | 描述 |
|---------|--------------------------------------------------------|------|
| 暗夜造梦师 | 75 / 55 / 70 / 75 / 45 / 55 | 沉迷黑暗复杂的世界观构建，热爱在虚构宇宙中探索人性深渊 |
| 温暖治愈系 | 35 / 75 / 35 / 20 / 55 / 35 | 在明亮温暖的故事中寻找情感共鸣，偏爱日常与治愈 |
| 智性探索者 | 55 / 35 / 80 / 45 / 30 / 70 | 追求智力挑战与实验性叙事，享受烧脑的快感 |
| 情感深渊潜行者 | 50 / 75 / 40 / 75 / 45 / 35 | 在黑暗中寻求强烈的情感冲击，偏爱悲剧与挣扎 |
| 冒险浪漫派 | 55 / 70 / 50 / 30 / 55 / 75 | 热爱新鲜体验与浪漫情感的碰撞，不惧实验性 |
| 世界观建筑师 | 80 / 50 / 70 / 30 / 30 / 50 | 沉醉于精密构建的虚构宇宙，热爱设定与细节 |
| 纯粹感受者 | 35 / 75 / 25 / 25 / 55 / 35 | 不需过度思考，只需被故事的情感洪流裹挟 |
| 暗黑实验家 | 50 / 35 / 65 / 75 / 30 / 75 | 追求极端与前卫的视听体验，偏爱挑战与冒犯 |
| 现实凝视者 | 30 / 55 / 70 / 65 / 45 / 50 | 在现实主义的冷峻中思考人性，拒绝逃避 |
| 复杂共情者 | 55 / 65 / 65 / 60 / 45 / 50 | 在灰度叙事中寻找深层共鸣，爱复杂人性 |
| 热忱群像派 | 45 / 70 / 50 / 25 / 90 / 55 | 爱看普通人因热爱一门手艺/竞技而彼此羁绊、共同成长，热血与治愈并存 |
| 多元观影者 | 50 / 50 / 50 / 50 / 50 / 50 | 兜底人格；当用户的六维得分非常均衡、没有明显偏向时触发 |

> 注：上表数值是目标向量的示例锚点，实际实现时允许±5的模型微调空间。所有 12 种人格使用同一套六维指标触发。

### 4.3 人格命名规则

- 名称 = 2-5字意象词 + 角色后缀（师/者/派/系/家）
- 意象词来自最突出的1-2个维度（暗→暗夜，智→智性，浸→造梦，群→群像）
- 所有人格使用同一套六维指标触发，不再区分「五维型」和「签名型」

### 4.4 人格匹配规则：每人只触发一种人格（必读）

为回答三个关键问题，采用统一的匹配函数：

**1. 统一打分，而非二值阈值**

用户六维得分向量 `U = (u₁…u₆)`，每种人格 `p` 有目标向量 `T_p = (t₁…t₆)`。

```
Score_p = 100 - mean(|u_i - t_i|)    // 0–100，越高表示越匹配
```

**2. 保证每个用户都会且只会触发一个人格**

- **主人格 = argmax(Score_p)**，在所有 12 种人格中取匹配分最高的一个。
- 12 种目标向量彼此不同，argmax 在正常情况下天然唯一。
- 若因浮点计算出现同分，按预设的优先级 tie-break（越独特的类型优先级越高：热忱群像派 > 暗黑实验家 > 智性探索者 > 世界观建筑师 > 暗夜造梦师 > 冒险浪漫派 > 情感深渊潜行者 > 复杂共情者 > 现实凝视者 > 温暖治愈系 > 纯粹感受者 > 多元观影者）。
- 因此**不存在「无人格」或「同时触发多个人格」**的情况。

**3. 多元观影者的兜底机制**

- 多元观影者的目标向量是六维中心点 `[50,50,50,50,50,50]`。
- 它只在用户得分非常均衡、所有特征型人格匹配分都较低时才会胜出。
- 若主人格是多元观影者，输出中诚实说明「你的观影DNA较均衡/多元，未形成强特征」。
- 可以不定期报出「次级倾向」：主人格之外，匹配分 ≥ 主人格 90% 的类型可作为「你也有这面的倾向」补充，但**正式人格仍只有一个**。

## 五、推荐生成策略

### 5.1 候选库构建

推荐不是从固定数据库查询，而是基于LLM的影视知识库。对每个候选作品，LLM内部完成与Step 2相同的6维度标签化，然后计算DNA匹配度。

候选库范围：
- 排除用户已提供的10部作品
- 聚焦用户选定的方向（电影/电视剧/动漫），但允许跨方向少量推荐（最多1-2部）
- 覆盖主流 + 中等冷门 + 极冷门三个层次

### 5.2 DNA匹配算法

对每个候选作品计算与用户DNA的匹配分：

```
匹配分 = Σ(标签匹配权重 × 标签频次权重 × 维度权重)

- 标签匹配权重：候选作品有此标签 = 1.0，无 = 0
- 标签频次权重：高频标签 ×3，中频 ×2，低频 ×1，排斥区 ×(-2)
- 维度权重：主题/情感 ×1.5，叙事/角色 ×1.2，美学 ×1.0，元维度 ×0.8
```

### 5.3 混合排序策略

最终推荐list = 70%相似 + 20%相邻 + 10%突破

| 类别 | 占比 | 数量 | 选择逻辑 |
|------|------|------|---------|
| 相似推荐 | 70% | 7-10部 | 匹配分最高的作品，让用户感到"懂我" |
| 相邻推荐 | 20% | 2-3部 | 核心维度匹配但有一个维度偏移±20分，拓展舒适区边缘 |
| 突破推荐 | 10% | 1-2部 | 基于用户冒险度：高→推实验性冷门；低→推温和跨界作品 |

### 5.4 推荐list结构

每部推荐作品包含：
```
作品名（年份）
- 类型标签
- 匹配理由（1-2句，说明为什么推荐给这个人格）
- DNA匹配维度（列出最匹配的2-3个维度）
- 推荐类别：相似 / 相邻 / 突破
- 评分参考（豆瓣/IMDb，如有）
```

## 六、边界情况处理

### 6.1 品味过于多元
**表现**：10部作品分散在多个截然不同的类型/风格中，高频标签很少
**处理**：识别出2-3个"子人格"，分别推荐，在输出中说明"你的观影DNA有多个分支"

### 6.2 品味过于单一
**表现**：10部作品高度同质化（如同一系列、同一导演）
**处理**：正常提取DNA，但在推荐中提高"相邻推荐"和"突破推荐"的比例（调整为50%/30%/20%），避免推荐同系列作品

### 6.3 冷门作品处理
**表现**：用户提供的作品中LLM不认识或信息不足
**处理**：基于作品名和用户提供的一句话理由做最大努力标签化；如果完全无法识别，跳过该作品并提示用户补充信息，不强行编造标签

### 6.4 跨类型推荐
**表现**：用户选了"电影"方向，但DNA显示其偏好其实更适合某部电视剧
**处理**：默认遵守用户选择的方向，但在"突破推荐"中允许1部跨方向作品，并标注"虽然你选了电影，但这部电视剧/动漫与你的DNA高度匹配"

### 6.5 作品数量不足
**表现**：用户提供少于8部作品
**处理**：提示用户补充至8部以上；如果用户坚持，基于已有作品提取DNA但降低置信度，在输出中标注"基于N部作品分析，结果仅供参考"

## 八、Skill实现要点

### 8.1 核心Prompt结构

Skill的prompt应按pipeline的5步顺序引导LLM：

```
1. [标签化] 对用户提供的每部作品，从6个维度提取标签，输出为结构化JSON
2. [DNA提取] 跨作品聚合标签频次，识别高频/中频/缺失/组合模式
3. [人格建模] 将DNA模式映射到六维模型，计算分数并匹配人格类型
4. [推荐生成] 基于DNA匹配候选作品，按70/20/20混合策略排序
5. [格式化输出] 按规范格式输出人格画像 + 推荐list
```

### 8.2 关键约束
- 标签化必须基于作品的实际特征，不能泛化（如不能把所有科幻片都标为"非线性"）
- 推荐作品必须是真实存在的，不能编造
- 推荐list中必须包含匹配理由，不能只给名字
- 如果用户提供的作品跨了多个方向（如既有电影又有动漫），优先按用户选择的方向推荐

## 九、反馈循环：推荐后的二次分析

用户拿到首版报告（人格卡 + 推荐 list）后，会进入两类典型反馈。本章定义这两种反馈的**分析模型**与**新报告产出规范**，使 Skill 能在不重建人格的前提下，对推荐层进行"有记忆"的迭代。

### 9.1 反馈入口与总原则

| 反馈类型 | 用户原话示例 | 含义 | 默认处理策略 |
|---------|------------|------|------------|
| A. 不喜欢 | "推荐的作品我都不喜欢" / "这批不对味" | 推荐层与口味失配 | 保持人格，构建动态排斥区重推；连续 2 轮仍不满意再回溯人格 |
| B. 都看过了 | "符合我口味，但基本都看过了" | 人格正确，仅治"片荒" | 标记 seen、加入全局排除集，同人格冷门下钻 + 少量跨人格相邻补位 |

总原则：
1. **人格默认稳定**：首轮匹配到的人格默认不变；只有证据显示首轮 DNA 估计系统性偏差时才回溯（见 9.4）。
2. **推荐层有记忆**：用户每一轮的正负反馈都沉淀为结构化数据（排斥区、已看集、排除集），驱动下一轮重生成，而非重新跑全流程。
3. **每轮解释"为什么"**：新报告必须向用户说明"这轮为何这么推"，让反馈闭环可见、可信任。

### 9.2 场景 A：用户不喜欢推荐作品

#### 9.2.1 分析模型（三步归因）

**第一步——定位失配层级。**
- 否定集中在「最像你」层 → 首轮 DNA / 人格存在系统性偏差，进入 9.4 人格回溯评估。
- 否定集中在「扩一扩 / 试试水 / 冷门」等外圈层 → 仅边界探索失配，人格本身大概率正确，只收紧推荐边界，不动人格。
- 全盘否定（各层都点名）→ 优先怀疑人格，走 9.4 回溯。

**第二步——反查失败属性簇。**
- 把被点名"不喜欢"的作品拉出，反查它们在 6 维度上的标签分布，与用户 DNA 高频标签做差集，揪出"用户本以为喜欢、实际排斥"的隐性属性（例如：DNA 显示爱热血群像，但个别作品命中"运动题材 / 恋爱线"，而用户明确反感——这类排斥要靠反馈暴露）。
- 产出「排斥属性簇」清单，格式：`{维度: 标签, 权重: 强 / 中}`。

**第三步——写入动态排斥区。**
- 将「排斥属性簇」加入 `reject_zones`，重推时对这些标签做惩罚加权（强排斥 ×0.3，中排斥 ×0.6 匹配分；匹配分公式见 §5.2）。
- 被点名作品整体加入 `exclude_set`，杜绝复推。

#### 9.2.2 新报告产出

- **人格卡**：默认不变。仅当 9.4 触发回溯重推时才重新生成，并在卡片加注「已重新校准」印章与变化说明。
- **推荐 list（重生成）**：
  - 顶部新增状态条：「上一轮已剔除 N 部含 {排斥属性} 的作品，本轮已避开」。
  - 比例动态调整：相似层由 70% 降到 60%，相邻 25%，突破 15%（承认当前探索边界要收窄）。
  - 每部保留「匹配理由」，且必须显式说明"已规避你排斥的 {某属性}"。
  - 分层徽标保留（最像你 / 扩一扩 / 试试水 / 冷门），冷门层优先用"同 DNA、无排斥属性"的替补，而非单纯更偏。

### 9.3 场景 B：喜欢但基本都看过

#### 9.3.1 分析模型

**第一步——确认正面信号。**
- "都喜欢"是强信号：人格正确、DNA 可信。本轮不修正人格、不调整 DNA，只治理"片荒"。

**第二步——批量标记 seen。**
- 将用户点名"已看"的作品 + 本轮推荐全部标记 `seen`，一次性写入全局 `exclude_set`，确保后续任何轮次不复推。

**第三步——扩展路径（默认双路径）。**
- **主路径 · 同人格冷门下钻**：在本人格签名内沿 tier 向下钻（最像你 → 扩一扩 → 试试水 → 冷门）。若冷门层也已耗尽（用户是资深老观众），切换「题材主轴」——保持 6 维签名不变，用次级标签（题材 / 年代 / 国家）换一条主轴继续挖。
- **辅路径 · 跨人格相邻补位**：借相邻人格与当前人格的 6 维重叠区，补 ≤2 部"口味近但人格略偏"的作品，扩大片源又不偏离核心。相邻人格映射见 9.5。

#### 9.3.2 新报告产出

- **人格卡**：默认不变，但展示正面徽标「✓ 口味已验证」，强化信任。
- **推荐 list（重生成）**：
  - 顶部状态条：「已排除 N 部已看作品，以下为未看过的深度 / 相邻推荐」。
  - 分层改为：**冷门补完**（同人格更深）、**深度挖掘**（换题材主轴）、**相邻新发现**（跨人格 ≤2 部）。
  - 每部带「与已看作的区别点」说明，帮助用户快速判断"这跟我看过的有什么不同"。

### 9.4 反馈数据结构与人格回溯

首轮产出后，维护一份**会话级**状态对象（仅本轮会话内有效，不落盘）：

```
feedback_state = {
  "persona_locked": true,            # 人格是否已锁定（首轮默认锁定）
  "reject_zones": [                  # 动态排斥属性簇
    {"dim": "题材", "tag": "运动", "weight": "strong"}  # strong / mid
  ],
  "exclude_set": ["作品A", "作品B"],  # 已看 + 已否决，全局不复推
  "seen_set": ["作品B", "作品C"],     # 已看（场景 B）
  "round": 1,                        # 重推轮次
  "dislike_streak": 0                # 连续否决轮次，>=2 触发回溯
}
```

**人格回溯触发条件（9.4 核心规则）：**
- `dislike_streak >= 2` 且否定覆盖「最像你」层 → 解除 `persona_locked`，回到 §4.4 匹配逻辑，但**排除已识别的排斥属性簇**后重新推导 DNA，可能切换人格。
- 回溯后新人格首轮匹配良好 → 锁定新人格，报告标注「已重新校准」。

### 9.5 相邻人格映射（场景 B 辅路径用）

基于六维模型的距离，每个主流人格的相邻人格即与其六维向量余弦最近的 2–3 个。示例：

| 当前人格 | 相邻人格（推荐补位来源） |
|---------|----------------------|
| 热忱群像派 | 温暖治愈系、纯粹感受者 |
| 温暖治愈系 | 热忱群像派、纯粹感受者 |
| 智性探索者 | 世界观建筑师、现实凝视者 |
| 暗黑实验家 | 现实凝视者、情感深渊潜行者 |

> 实现时**不应硬编码整张表**，而应在运行时计算当前人格向量与 12 人格库的余弦距离，取 Top-3 作为相邻人格候选。

### 9.6 实现要点

- 反馈循环只重跑 pipeline 第 4 步（推荐生成）+ 第 5 步（格式化输出）；不重跑标签化 / DNA 提取 / 人格匹配（除非触发 9.4 回溯）。
- `feedback_state` 必须随每一轮报告一起回传用户侧，作为下一轮重推输入。
- 每一轮新报告保留"上轮发生了什么"的简短状态条，形成可追溯的对话式闭环。
