# 剧荒推荐 · 批量扩库提示词（文本优先 / 封面后置）

> 用途：让 LLM 一次性产出大批量作品条目，直接灌入 `works_pool.py` 的 `WORKS_POOL`，
> 从而把片单库从 106 部快速扩到几百 / 上千部。
> 核心原则：**封面不是入库门槛**——名字 / 标签 / 简介 / 推荐理由 四要素齐全即可入库，
> 封面由 `fetch_official_covers.py`（AniList 官方海报）或 `ensure_cover`（渐变兜底）后续按需补齐。

---

## 一、入库字段规范（四要素为必需，其余可选）

每部作品 = 一个 dict，字段如下：

| 字段 | 是否必需 | 说明 | 示例 |
|---|---|---|---|
| `name` | ✅ 必需 | 作品官方中文名（动漫用常用译名；电影/剧用通用译名） | `"葬送的芙莉莲"` |
| `cat` | ✅ 必需 | **标签**：类型·子类型，2~4 个汉字词组用 `·` 连接 | `"奇幻·治愈"` |
| `synopsis` | ✅ 必需 | **简介**：一句话剧情/看点，≤ 40 字，客观不剧透结局 | `"精灵法师在勇者死后踏上理解人性的漫长旅程。"` |
| `reason` | ✅ 必需 | **推荐理由**：为什么匹配该人格，≤ 30 字，带人格视角 | `"冒险后的治愈与告别"` |
| `year` | 可选 | 首播/上映年份 | `2023` |
| `direction` | 可选 | `动漫` / `电视剧` / `电影` | `"动漫"` |
| `region` | 可选 | `日本` / `中国` / `欧美` / `韩国` … | `"日本"` |
| `persona` | 可选 | 主匹配人格（12 选 1，见下） | `"热忱群像派"` |
| `tier` | 可选 | `like` / `expand` / `try` / `niche` | `"like"` |

> ⚠️ **不要为了凑数编简介/理由**：宁缺毋滥，未知的作品不写 `persona`/`tier`，
> 交给 `pool_query` 的相邻人格补位逻辑处理。

## 三、直接可用的提示词（复制给任意 LLM）

```
你是「剧荒推荐」的片单策展助手。请为下面的【人格 + 方向 + 区域】组合，
产出 N 部高质量作品条目，用于扩充推荐库。

【目标】
- 人格：<填入 1 个或多个人格，如 热忱群像派 / 温暖治愈系>
- 方向：<动漫 / 电视剧 / 电影，或"全部">
- 区域：<日本 / 中国 / 欧美 / 不限>
- 数量：<如 30>

【每条输出格式】（严格 Python dict，四要素必填）
dict(name="作品名", year=2020, direction="动漫", region="日本",
     cat="类型·子类型", persona="主匹配人格", tier="like",
     synopsis="一句话简介，≤40字，不剧透结局。",
     reason="为什么匹配该人格，≤30字。"),

【质量要求】
1. 名字用官方/通用中文译名；动漫优先常用译名。
2. 标签 cat 用「大类·小类」，如 运动·热血 / 悬疑·人性 / 治愈·日常。
3. 简介客观、有信息量；推荐理由必须带人格视角，不要写成通用好评。
4. 尽量覆盖不同 tier（like 最契合 / expand 稍拓展 / try 冒险 / niche 冷门）。
5. 不重复已存在作品；如不确定某作品是否匹配，宁可不填 persona/tier。
6. 不要编造不存在的作品；冷门但真实存在的作品优先于热门套路。

请直接输出可粘贴进 works_pool.py 的 dict 列表（无需解释）。
```

---

## 四、入库后的两步（封面后置，不阻塞）

1. 把 LLM 产出的 dict 列表粘贴进 `works_pool.py` 的 `WORKS_POOL`。
2. 跑 `python fetch_official_covers.py`：对库中所有作品尝试拉取 AniList 官方海报，
   写入 `assets/covers/by_name/<作品名>.jpg`；拉不到的，渲染时由 `ensure_cover`
   生成渐变占位，**不影响推荐与入库**。

---

## 五、为什么这样能快速扩库

| 维度 | 旧流程（带封面） | 新流程（文本优先） |
|---|---|---|
| 每部成本 | 文本标注 + 取图 + 命名 + 校验（封面最贵，ImageGen 还需 5~10 积分/张） | 纯文本四要素，LLM 单次批量产出 |
| 产出速度 | 封面是瓶颈（每部一次请求/生成 + 人工核对） | 即写即入库，零资源依赖 |
| 内容质量 | 精力分散到图 | 聚焦 标签/简介/理由，匹配更准 |
| 扩容上限 | 受美术资源约束 | 仅受文本策展 + 分层标注约束，可上千部 |
