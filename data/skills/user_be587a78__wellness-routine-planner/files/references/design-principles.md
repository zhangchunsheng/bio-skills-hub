# 设计原则：锚点制 + 双层提醒

本文件详述养生时间表的核心方法论，供 WorkBuddy 在执行时遵循。

## 1. 锚点制（不靠死钟数）
- **定义**：把所有想养成的习惯"挂"在用户本来就固定会做的动作（锚点）上。
- **常见锚点**：起身、刷牙、吃饭、洗面、冲凉、上床睡。
- **写法**：写"做完 A 就做 B"，而非"几点做 B"。例如「晨起链：起身 → 刷牙 → 温水一杯 → 洗面护肤 → 晨间运动 → 早课 → 开工」。
- **好处**：不依赖意志力盯钟，习惯随生活流走，容易坚持。
- **弹性处理**：忙日可减；某项做不到，用更轻的替代打底（如夜晚瑜伽做唔到就用温和运动打底），唔使硬补。

## 2. 双层提醒（防"一埋头就忘"）
- **第一层 · 定时自动化**：对"必须做、易忘"的项，用 `automation_update` 设近似钟点弹（如每日 11:15 食保健品、22:00 睡前链）。
- **第二层 · 主动口头提醒**：对"已内化但仍易漏"的项（如工作期间喝水/拉伸），**不设**定时弹，改为在对话中主动提——用户说"得闲"或工作一段后，主动讲一句「起身拉伸吓、去饮杯水」。
- **文档化**：时间表末尾列"自动提醒一览"，让用户一眼看清哪些靠系统弹、哪些靠口头提。

## 3. 温和原则
- 除非用户明确说明，默认温和方案（如甲亢忌剧烈出汗 → 选微汗即收的轻柔运动）。
- 有健康禁忌时，在文档注明「以专业意见为准」，不越界给医疗建议。

## 4. 清晰画面（降低执行门槛）
- 每个时段标注**总时长**（"做几多 + 用几多时间"），例如「晨起链整体约 1 个钟」。
- 区分**死守项**与**弹性项**：死守项（晨 startup、晚课）不可 skip；弹性项可减、可替。

## 5. 频率分类与提前提醒
- 频率分：每日 / 每周（指定星期几）/ 每月 / 每两月 / 每半年·每年。
- 复诊、剪发、洗牙、验眼等**预约类**：设"提前 2–3 周"提醒，避免错过窗口。
- 一次性预约：用 `scheduleType=once` + `scheduledAt`。

## 6. 手机优先交付
- 用户若早上不开电脑、靠手机看，优先把 HTML 部署到线上 URL。
- 本地文件经 edge sync 需 PC 开着 WorkBuddy 才能同步到手机，故治本是 deploy，不是等 sync。
