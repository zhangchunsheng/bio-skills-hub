# 07 网络安全体系与文档

> 用途：回答「ISO 81001-5-1 是什么？和 13485/62304/27001 什么关系？申报要准备哪些文档？」。
> 核对基准日：2026-08-27

## 1. 核心标准体系一览

| 标准 | 定位 | 与医械网络安全关系 |
|---|---|---|
| **ISO/IEC 81001-5-1:2021** | 健康软件与健康 IT 产品全生命周期网络安全 | 医械网络安全工程的**主干标准**（Security by Design 活动谱系） |
| **ISO 13485:2016** | 医疗器械质量管理体系 | QMSR 引用并入 → 网络安全活动必须落在 QMS 流程内（FDA 2026 核心立场） |
| **IEC 62304** | 医疗器械软件生命周期 | 软件生存周期过程，网络安全活动与其各阶段衔接 |
| **ISO 14971:2019** | 医疗器械风险管理 | 网络安全风险作为「可合理预见的风险」纳入风险管理 |
| **ISO/IEC 27001** | 组织信息安全管理 | 管组织层面信息安全，**不是**产品网络安全替代 |
| **IEC 62443** | 工业自动化与控制系统安全 | 医疗器械与工业网络交互时的参考 |
| **ISO/IEC 15408（CC）** | 通用评估准则（信息安全） | 深度安全评估可选参考 |

## 2. ISO/IEC 81001-5-1 在干什么

- 覆盖健康软件与健康 IT 系统的**全生命周期**安全活动（设计、开发、验证、部署、维护、退役）；
- 与 IEC 62304 的生命周期过程对齐，把「网络安全工程活动」映射进既有软件过程；
- 对 2026 FDA 指南：SPDF（Secure Product Development Framework）可视为 81001-5-1 式做法的体现——先做威胁建模，再做安全架构、安全测试、发布、上市后监控。

## 3. 网络安全文档包（上市前申报参考清单）

**FDA（cyber device 提交）**：
1. 网络安全管理计划
2. SPDF / 安全开发生命周期证据
3. 威胁建模分析（方法 + 结果 + 残余风险）
4. 安全架构视图（全局/多患者伤害/可更新可修补）
5. 安全风险评估（按可利用性）
6. SBOM（机器可读 + 漏洞分析）
7. 安全测试报告（渗透/模糊/静态/漏洞扫描，独立团队）
8. 更新能力验证（patchability）
9. 上市后监控计划 + CVD 流程
10. 网络安全标签
11. 风险-控制-测试可追溯矩阵

**NMPA（注册申报）**：
1. 网络安全描述文档（单独提交）
2. 产品技术要求中的数据接口/用户访问控制要求
3. 说明书网络安全内容
4. 网络安全更新研究报告（发生网络安全更新时）

**欧盟（MDR + CRA 准备）**：
1. Annex I 17.2 符合性论证（IT 安全措施 + 风险评估）
2. CRA 技术文档（非医械软件/组件适用时）
3. 符合性声明（DoC）+ CE 标志（适用时）

## 4. 体系联动示意（QMS 内嵌）

```
ISO 13485 QMS（设计控制/验证/CAPA）
   └─ 网络安全活动（ISO/IEC 81001-5-1）←→ IEC 62304 软件过程
         └─ 风险输入/输出 ←→ ISO 14971 风险管理
               └─ 漏洞处置/上市后 ←→ 上市后监督 + CVD
```

要点：网络安全不是一套「并行文档」，而是**贯穿 QMS 各过程的横切活动**——审评机构现在核验的是「这些活动是否从受控 QMS 流程产出」。
