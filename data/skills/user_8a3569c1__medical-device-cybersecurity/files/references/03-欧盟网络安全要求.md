# 03 欧盟网络安全要求

> 用途：回答「欧盟 MDR / NIS2 / CRA 对医械网络安全的要求」。
> 核对基准日：2026-08-27

## 1. 欧盟四层框架

| 层级 | 文件 | 状态 |
|---|---|---|
| 产品 | **MDR (EU) 2017/745 Annex I 第 17.2 条** | 现行强制 |
| 网络 | **NIS2 指令 (EU) 2022/2555** | 2022-12-27 生效，成员国 2024-10-17 前完成转化 |
| 横向产品法 | **CRA《网络弹性法案》(EU) 2024/2847** | 2024-12-10 生效，分阶段适用 |
| 无线 | **RED 2014/53/EU 第 3.3(d) 条** | 无线器械额外适用 |

## 2. MDR Annex I 第 17.2 条（医械网络安全基础要求）

- 采取与风险相称的 **IT 安全措施**（含安全认证），保护器械开发与运行免受未经授权的访问；
- 评估安全措施与风险的关系，涵盖：硬件/网络连接、可能的干扰源（电磁、静电）、操作系统、软件、患者数据保密与完整性；
- 实现方式通常借助：ISO/IEC 81001-5-1（产品网络安全工程）、IEC 62443 系列（工业控制）、ISO/IEC 27001（组织信息安全）支撑；
- MDR 本身不强制 SBOM/渗透测试，但审评实践中网络安全文档日益成为预期内容。

## 3. CRA 网络弹性法案——三个里程碑（必须记住）

| 日期 | 事件 |
|---|---|
| **2024-12-10** | 生效（公报 2024-11-20，条例编号 (EU) 2024/2847） |
| **2026-06-11** | 符合性评定机构（公告机构）指定规则适用 |
| **2026-09-11** | **报告义务生效**（Article 14）：主动被利用漏洞与严重安全事件 → ENISA 单一报告平台 + 国家 CSIRT |
| **2027-12-11** | **全面适用**：essential requirements、符合性评定、CE 标志、技术文档 |

**报告时限（2026-09-11 起，注意这是最早咬人的义务，且适用于已在市场产品）**：
- 预警：24 小时内
- 完整报告：72 小时内
- 最终报告：修复措施可用后 14 天内（严重事件可放宽至 1 个月）

**CRA 与医械的关系（关键澄清）**：
- MDR/IVDR 下医械产品**豁免 CRA**（避免双重监管，产品级豁免）；
- 但**供应链组件、非医械软件（患者门户/管理软件/配套 App）、远程数据处理基础设施**仍在 CRA 范围内——医械厂商对供应商要有 CRA 合规证据要求；
- 罚款：最高 **1500 万欧或全球营业额 2.5%**（取高）。

**CRA 产品分级与符合性路径**：

| 级别 | 范围示例 | 路径 |
|---|---|---|
| Default（一般） | 多数产品 | 自评 + 技术文档 + 符合性声明 |
| Important Class I | 身份管理、浏览器、VPN、密码管理器、网络管理、SIEM、非工业防火墙、路由器 | 用协调标准可自评 |
| Important Class II | 操作系统、虚拟化、容器运行时、PKI、带安全功能的 CPU、工业防火墙/IDS | 第三方公告机构 |
| Critical（Annex IV） | 最高风险产品 | 公告机构强制 |

## 4. NIS2（运营者层面）

- 医疗行业（医院、医疗器械制造商中属「重要实体」者）需落实网络与信息安全风险管理措施；
- 事件报告义务：重大事件向 CSIRT 报告；
- CRA 覆盖产品安全，NIS2 覆盖组织韧性，两者并行。

## 5. 时间线提醒（对医械厂商的实际影响）

- **2026-09-11 前**：建立漏洞检测与上报能力（对已上市产品同样适用，不能拖到 2027）；
- **2027-12-11 前**：医械本体（MDR 路径）补强网络安全文档；非医械软件/组件按 CRA 全面合规；
- **2027-12-11 之后**：无 CRA 合规证据的数字化产品（含组件）不得投放欧盟市场。
