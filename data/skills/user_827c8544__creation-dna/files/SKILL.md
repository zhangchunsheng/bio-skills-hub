# Creation DNA - 创作交付进化引擎

> 不是通用的错误日志本，而是专为 AI 内容创作场景设计的审美记忆与质量闭环系统。
> 每一次交付反馈都在塑造创作 DNA，让下一次产出更接近用户心中的标准答案。

## 适用定位

本技能服务于 AI 代理的内容创作交付环节，覆盖以下创作类型：

| 创作类型 | 典型交付物 |
|----------|-----------|
| 文案写作 | 公众号文章、小红书笔记、短视频脚本、口播稿、广告语 |
| 视觉设计 | 海报、封面、主视觉、电商详情页、Logo 方案 |
| 图像生成 | AI 绘画、人像修图、场景图、产品图 |
| 视频制作 | 短视频、宣传片、动画、数字人口播 |
| 结构化内容 | PPT、信息图、知识卡片、思维导图 |

核心价值：把"用户说了 N 次才改对"的隐性审美，转化为"下次自动做对"的显性参数。

各创作类型的详细质量维度矩阵，详见 `references/quality_dimensions.md`。

## 一、触发与禁用场景

### 触发场景（自动启动捕获）

满足以下任一条件即进入创作 DNA 捕获流程：

1. **交付后反馈**：用户对已交付的创作物提出修改意见（"颜色太艳了""标题不够抓眼""节奏太慢"）
2. **返工信号**：同一交付物被要求修改2次以上，或用户使用"还是不对""重来""不是这个感觉"等表达
3. **明确偏好声明**：用户说出"我喜欢...""以后都...""记住我要...""我的风格是..."
4. **正向确认**：用户明确表扬某个具体维度（"这个色调很好""开头这句不错""排版很舒服"），且该维度可复用
5. **风格锁定请求**：用户要求"保存这个风格""下次按这个来""套用上次的感觉"

### 禁用场景（不捕获、不写入）

以下情况不得触发本技能的写入操作：

1. **纯事实性纠错**：用户纠正日期、人名、数据、引用来源等事实错误，属于信息准确性问题，不属于审美/风格范畴
2. **一次性指令**："把这个字改成红色""这里加个逗号"等单次、无复用价值的微调
3. **假设性讨论**："如果是你会怎么做""有没有可能..."等未落地的探讨
4. **第三方偏好**："我客户喜欢...""我老板要..."等非终端用户本人的偏好，除非用户明确要求代为记录
5. **敏感内容**：涉及隐私、医疗、法律、金融建议的内容创作反馈，仅记录格式/结构层面的偏好，不记录具体敏感内容
6. **用户明确拒绝**：用户说"不用记""这次是特例""别保存"

### 静默行为（未触发时）

当以上触发条件均不满足时，本技能保持完全静默：
- 不产生任何输出或提示
- 不创建或修改任何文件
- 不影响正常的创作交付流程
- 不消耗额外上下文

## 二、核心概念

### 2.1 创作 DNA 双螺旋

本技能将创作偏好拆解为两条互补的螺旋：

| 螺旋 | 含义 | 示例 |
|------|------|------|
| A 链-审美参数 | 用户对感官维度的稳定偏好 | 色调偏冷、字体偏爱无衬线、文案调性偏犀利、视频节奏快切 |
| B 链-返工抗体 | 历史踩坑的免疫记录 | 标题避免疑问句、封面不用绿色、口播不超过3分钟、PPT不超过20页 |

A 链回答"用户喜欢什么"，B 链回答"用户讨厌什么"。两者共同构成完整的创作 DNA。

### 2.2 返工根因四象限

每次返工必须归入以下四个象限之一，用于定位问题本质：

```
              理解偏差
                 |
  需求侧 <------+------> 感知侧
  需求没听懂    |       审美不匹配
                |
  执行侧 <------+------> 环境侧
  技术没做到    |       需求已变更
                 |
              外部变更
```

| 象限 | 根因 | 典型表现 | DNA 写入位置 |
|------|------|---------|-------------|
| 需求侧 | 理解偏差 | 用户说"简约"，AI 做成了"简陋" | A 链-语义映射表 |
| 感知侧 | 审美不匹配 | 色调/构图/调性不符合用户预期 | A 链-审美参数 |
| 执行侧 | 技术缺陷 | 分辨率不够、字幕错位、导出失败 | B 链-技术抗体 |
| 环境侧 | 需求变更 | 平台规则变了、用途变了、受众变了 | 不写入（标注为环境变更） |

### 2.3 质量维度矩阵

不同创作类型有不同的质量评估维度，捕获反馈时必须标注对应维度。详细维度定义见 `references/quality_dimensions.md`。

## 三、工作流程

### 阶段 1：交付后捕获（Delivery Capture）

**时机**：AI 完成创作交付，且用户给出反馈之后。

**步骤**：

1. **识别反馈类型**
   - 正向反馈：提取 A 链审美参数
   - 负向反馈/修改要求：先归入返工四象限，再提取对应链
   - 中性追问：不捕获，等待明确结论

2. **结构化提取**

   将用户的自然语言反馈转化为结构化条目，遵循以下格式：

   ```json
   {
     "creationType": "writing|image|video|design|structured",
     "qualityDimension": "对应质量维度矩阵中的维度",
     "polarity": "positive|negative",
     "rootQuadrant": "requirement|perception|execution|environment",
     "rawExpression": "用户原话，不超过30字",
     "extractedParam": "可复用的具体参数",
     "confidence": "high|medium|low",
     "timestamp": "YYYY-MM-DD"
   }
   ```

3. **置信度判定规则**
   - 高：用户明确说"always/never/以后都"，或同一偏好出现3次以上
   - 中：用户单次明确表达偏好，但未强调永久性
   - 低：从单次修改中间接推断的偏好

### 阶段 2：DNA 比对与去重（Dedup）

**步骤**：

1. 在 `.creation-dna/` 对应创作类型文件中搜索相似参数
2. 若已存在相同/相似条目：
   - 正向一致：提升置信度，更新最后确认时间，将引用计数加1
   - 反向矛盾：进入冲突处理流程（见异常兜底 5.2）
   - 互补细化：合并为更精确的参数描述
3. 若不存在：标记为新条目，进入沉淀阶段

### 阶段 3：画像沉淀（Sedimentation）

**写入规则**：

- 置信度"高"：直接写入对应创作类型 `profile.md` 的"已确认偏好"区
- 置信度"中"：写入"待验证偏好"区，标注出现次数
- 置信度"低"：写入"观察候选"区，不主动使用，仅在用户主动询问时参考

**晋升机制**：

| 当前层级 | 晋升条件 | 目标层级 |
|----------|---------|---------|
| 观察候选 | 被用户再次提及 | 待验证偏好 |
| 待验证偏好 | 在交付中被成功使用2次以上且无负面反馈 | 已确认偏好 |
| 已确认偏好 | 被用户否定 | 已废弃偏好（保留历史） |

**使用计数跟踪**：每次交付前预检命中某条偏好并在交付中采用时，在该条目末尾追加使用标记 `[used: YYYY-MM-DD]`。连续2次使用且无负向反馈即满足晋升条件。

### 阶段 4：交付前预检（Pre-delivery Check）

**时机**：AI 即将交付新的创作物之前。

**步骤**：

1. 识别当前创作类型
2. 检查 `.creation-dna/` 目录是否存在：
   - 存在：加载对应类型的 `profile.md`
   - 不存在：跳过预检，正常交付（视为首次使用）
3. 检查对应类型的 `profile.md` 是否存在：
   - 存在且有效：逐项对照"已确认偏好"和"返工抗体"检查当前交付物
   - 存在但损坏：按异常兜底 5.6 处理
   - 不存在：跳过预检，正常交付
4. 若发现冲突：
   - 明显违反已确认偏好：主动修正后再交付
   - 不确定是否适用：在交付时附提醒："注意：您之前偏好 X，本次因 [原因] 采用了 Y，如需调整请告知"
5. 若预检命中并采纳了某条偏好：在条目末尾追加使用标记

**冲突优先级规则**（当多条偏好同时适用且矛盾时）：

1. 已确认偏好 > 待验证偏好 > 观察候选
2. B 链返工抗体（禁忌） > A 链审美参数（偏好），即"避免用户讨厌的"优先于"满足用户喜欢的"
3. 同级冲突时，取最近确认时间的条目（更新时间更近的优先）
4. 仍无法判定时：在交付时说明冲突并询问用户

### 阶段 5：周期维护（Maintenance）

**触发**：基于交付计数器，存储于 `.creation-dna/.delivery-counter`（内容为累积交付次数的整数）。每次交付完成后递增1，达到10时触发维护并归零。

也可由用户主动要求"整理创作 DNA"触发。

**操作**：

1. 读取各创作类型画像文件，统计条目数
2. 将超过90天未被引用的"已确认偏好"降级为"休眠偏好"
3. 清理"观察候选"区中超过30天未被再次提及的条目
4. 合并语义重复的条目
5. 生成简短的进化摘要供用户审阅
6. 重置交付计数器

存储结构、profile.md 内部格式、index.md 模板等详细规范，见 `references/storage_format.md`。模板文件见 `assets/profile_template.md` 和 `assets/index_template.md`。

## 四、存储结构（摘要）

所有数据存储在当前工作目录的 `.creation-dna/` 文件夹下：

```
.creation-dna/
+-- index.md                  # 画像索引
+-- global.md                 # 跨类型通用偏好
+-- .delivery-counter          # 交付计数器（纯整数）
+-- writing/
|   +-- profile.md            # 文案创作 DNA
+-- image/
|   +-- profile.md            # 图像创作 DNA
+-- video/
|   +-- profile.md            # 视频创作 DNA
+-- design/
|   +-- profile.md            # 设计创作 DNA
+-- structured/
|   +-- profile.md            # 结构化内容 DNA
+-- archive/
    +-- deprecated.md         # 已废弃偏好 + 模糊反馈记录
```

**跨项目隔离**：`.creation-dna/` 始终绑定当前工作目录。不同项目目录各自独立，偏好数据不跨目录共享、不自动同步。

**首次初始化**：当 `.creation-dna/` 不存在时，在首次捕获触发时自动创建目录结构和 `index.md`，初始化 `.delivery-counter` 为 `0`。不创建空的 profile.md（按需创建，避免空文件堆积）。

## 五、异常兜底

### 5.1 用户反馈模糊

**场景**：用户说"感觉不对""差点意思""再改改"，未指明具体维度。

**处理**：
1. 不强行提取参数，不写入 DNA
2. 主动追问1个具体维度："是色调/构图/文案调性/节奏哪个方面需要调整？"
3. 用户给出具体方向后再进入正常捕获流程
4. 若始终无法具体化：记录为"模糊反馈事件"到 `archive/deprecated.md` 的备注区，不进入正式画像

### 5.2 偏好冲突

**场景**：新反馈与已确认偏好矛盾。

**处理**：
1. 不立即覆盖旧偏好
2. 将新偏好写入"待验证偏好"区，标注"与已确认偏好 [X] 存在冲突"
3. 在下次交付时主动告知用户："注意到您这次的偏好与之前记录的 [X] 不同，是否需要更新？"
4. 用户确认更新：旧偏好移入"已废弃"，新偏好晋升为已确认
5. 用户表示"这次是特例"：新偏好移入"观察候选"并标注"一次性特例"

### 5.3 存储写入失败

**场景**：目录无写入权限、磁盘已满、文件被占用。

**处理**：
1. 不阻塞当前交付任务，正常完成创作
2. 将待写入的 DNA 条目暂存在当前对话上下文中（内存态）
3. 告知用户："创作 DNA 记录暂时无法写入文件，已在本次会话中保留。稍后可执行 `creation-dna flush` 手动落盘"
4. 下次工具调用成功时自动重试落盘
5. 若连续3次失败：停止重试，提示用户检查目录权限

**`creation-dna flush` 命令定义**：扫描当前对话上下文中暂存的待写入 DNA 条目，逐条写入对应的 profile.md 文件。执行后输出落盘结果摘要（成功 N 条、失败 M 条、跳过 K 条）。若上下文中无暂存条目则提示"无待落盘数据"。

### 5.4 创作类型无法判定

**场景**：交付物混合多种类型（如"图文并茂的公众号文章"）。

**处理**：
1. 按主要交付形态判定主类型
2. 若反馈涉及次要类型维度：同时写入主类型和次类型的 profile.md，各自标注对应维度
3. 若仍无法判定：写入 `global.md`，标注"未分类，待后续明确"

### 5.5 用户要求清空

**场景**：用户说"清空创作 DNA""重置风格记录"。

**处理**：
1. 不直接删除
2. 先将 `.creation-dna/` 整体复制到 `.creation-dna/backup-YYYYMMDD/`
3. 告知用户备份位置
4. 确认用户仍要清空：清空各 profile.md 内容（保留目录结构和 index.md）
5. 重置 `.delivery-counter` 为 `0`
6. `archive/deprecated.md` 中的历史记录保留，不随清空删除

### 5.6 文件损坏或格式异常

**场景**：profile.md 内容被手动篡改、格式损坏、编码异常。

**处理**：
1. 检测到格式异常时，不直接覆盖原文件
2. 将损坏文件备份为 `profile.md.corrupted-YYYYMMDD`
3. 从 `archive/deprecated.md` 或备份中尝试恢复有效条目
4. 若无法恢复：以空 profile.md 重新初始化，并告知用户"创作 DNA 画像文件损坏已重置，历史偏好无法恢复"
5. 记录损坏事件到 `archive/deprecated.md` 备注区

### 5.7 并发会话冲突

**场景**：多个会话同时向同一 profile.md 写入。

**处理**：
1. 写入前读取文件当前内容并记录读取时间戳
2. 写入时检查文件最后修改时间是否早于读取时间戳
3. 若文件已被修改：重新读取最新内容，将当前条目合并后写入（合并策略：以最新内容为基础，追加新条目到对应分区末尾）
4. 若合并失败（格式冲突）：将当前条目暂存在对话上下文，延迟到下次写入周期处理
5. 不使用文件锁（避免死锁和跨平台兼容问题），采用"读-检-写"乐观并发策略

### 5.8 目录缺失

**场景**：预检或捕获时发现 `.creation-dna/` 目录不存在。

**处理**：
1. 捕获阶段：执行首次初始化流程，创建目录结构后正常写入
2. 预检阶段：跳过预检，正常交付，视为首次使用
3. 若目录曾被删除且用户有备份：提示用户从备份恢复

## 六、数据验证与完整性

### 写入前验证规则

每条 DNA 条目写入前必须通过以下校验：

| 校验项 | 规则 | 失败处理 |
|--------|------|---------|
| creationType | 必须为 writing/image/video/design/structured 之一 | 拒绝写入 |
| qualityDimension | 必须非空且不超过50字 | 拒绝写入 |
| polarity | 必须为 positive 或 negative | 拒绝写入 |
| rootQuadrant | 必须为 requirement/perception/execution/environment 之一 | 拒绝写入 |
| rawExpression | 必须非空且不超过30字 | 截断后写入 |
| extractedParam | 必须非空且不超过200字 | 截断后写入 |
| confidence | 必须为 high/medium/low 之一 | 默认为 medium |
| timestamp | 必须为 YYYY-MM-DD 格式 | 使用当前日期替换 |

### profile.md 格式校验

- 每个分区标题必须严格匹配模板定义（见 `assets/profile_template.md`）
- 条目格式：`- [参数描述] -- [标注信息]`
- 同一参数不得在同一分区出现两次（去重由阶段2保证）

## 七、合规与免责（摘要）

### 学术诚信边界

本技能不得用于论文代写辅助、数据造假偏好记录、引用伪造、身份冒用。若检测到相关请求，拒绝记录并说明原因。详见 `references/compliance_rules.md`。

### 版权与原创边界

- 风格学习不等于内容复制：仅记录抽象审美参数，不存储受版权保护内容的全文或核心表达
- 参考图脱敏：仅记录从图中提取的风格参数关键词，不存储图片本身或 URL
- 他人作品参考：仅记录"用户喜欢该作品的 [抽象维度]"，不记录作品具体内容

### 隐私与数据权利

- 所有沉淀的创作 DNA 均为用户个人偏好的结构化存档
- 用户享有完全的知情权、修改权、删除权（遗忘权）
- 遗忘权执行：用户要求删除的偏好必须在1次工具调用内完成移除并确认
- 数据不离开本地文件系统，不上传、不外传、不用于训练
- 数据保留策略：休眠偏好保留90天后降级，观察候选30天未提及后清理

## 九、维护原则

1. **少即是多**：宁可少记，不可错记。低置信度条目永远不主动影响交付。
2. **用户主权**：所有偏好记录用户可随时查看、修改、删除。没有隐藏规则。
3. **可解释性**：每次因创作 DNA 主动调整交付物时，必须告知用户"因为您之前偏好 X，所以本次做了 Y 调整"。
4. **不跨场景污染**：文案创作的偏好不自动应用于图像创作，除非用户明确声明跨类型通用。
5. **遗忘权**：用户要求遗忘的偏好，必须在1次工具调用内完成移除并确认。
6. **静默优先**：不触发时完全静默，不影响正常工作流。
