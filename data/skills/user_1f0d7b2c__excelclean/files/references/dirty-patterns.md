# 中文脏数据模式手册

每种坑讲清四件事：**长什么样、为什么会有、不修会怎样、怎么修**。
脚本覆盖不到的边角情况，看完原理可以自己判断。

---

## 1. GBK / GB18030 编码乱码

**长什么样**：`\xb4\xf3\xc7\xf8` 或 `´óÇø` 或 `�` 黑菱形问号。

**为什么会有**：Windows 中文版 Excel 另存为 CSV 时默认用系统 ANSI 编码（GBK），
而 Python / pandas / 大多数工具默认按 UTF-8 读。两边对不上就乱码。
UTF-8 解码失败会直接抛 `UnicodeDecodeError`，连文件都打不开。

**注意**：不要一看解码失败就 `errors="ignore"` 或 `latin-1` 兜底。
那样不报错，但中文全变乱码，且**没有任何提示**——比报错更危险。

**怎么修**：
```python
# 正确顺序：BOM → UTF-8 → GB18030 → Big5
# gb18030 兼容 gbk 与 gb2312，所以只需试这一个
```
输出时写 `utf-8-sig`（带 BOM）。没有 BOM 的话，Excel 双击打开中文仍会乱码——
这是 Excel 的历史行为，怪不了用户。

## 2. 合并单元格表头

**长什么样**：
```
A1:C1  2026年第一季度销售报表     ← 大标题，合并
A2:A3  华东                        ← 纵向合并
```

**为什么会有**：中文报表讲究"好看"，合并单元格是标配。
但 xlsx 里**只有左上角单元格存了值**，其余格子是空的。

**不修会怎样**：pandas 读进来整列变成 `NaN`；
用 openpyxl 逐格读则大区列一片空白，按大区分组统计直接崩。

**怎么修**：把左上角的值铺满整个合并区域。
`sheet.merged_cells.ranges` 拿到所有区域，逐个填充。
表头区的合并要**向右**填，数据区的合并要**向下**填——本技能统一铺满整个区域，两种情况都覆盖。

---

## 3. 表头不在第一行

**长什么样**：第 1 行是大标题，第 2 行空，第 3 行才是列名。
有的还带"填报单位：""统计周期：""单位：万元"。

**为什么会有**：给人看的表和给机器读的表结构不同，中文报表习惯加表头装饰。

**不修会怎样**：`pd.read_excel()` 默认拿第 1 行当列名，
结果列名变成"2026年第一季度销售报表"，真正的列名在第 3 行被当成数据。

**怎么修**：打分判断——候选行应满足：
填充率高（不是大标题那种单格）、多为短文本（像列名）、
上一行像大标题、下一行出现数值/日期。
本技能 `detect_header_row()` 用这个逻辑，置信度低时会在报告里提示你用 `--header-row` 手动指定。

## 4. 中文数值单位（重灾区）

**长什么样**：`1.2万`、`1.5亿`、`8,500元`、`35%`、`3.5千`、`2百万`、`约200`、`1.2万元`

**为什么不修不行**：`1.2万` 是文本，`SUM` 直接跳过，排序时 `1.2万` 排在 `9,800元` 前面（字符串比较）。

**修的关键——精度**：
```python
>>> 5.06 * 10000
50599.99999999999        # 浮点误差，金额差一分钱都是事故
>>> Decimal("5.06") * Decimal("10000")
Decimal('50600.00')      # 正确
```
**凡是涉及万/亿换算，必须用 `Decimal`，不能用 float。**

**单位识别的坑**：`万象城`、`万豪酒店` 里的"万"不是单位。
所以正则必须要求**数字在前、单位紧跟数字**，不能全文搜索"万"字。

**边界处理**：
- 百分号：默认 `35%` → `35`（保留原数值），需要 `0.35` 时加 `--percent decimal`。
  不自动除 100，因为不同场景语义不同，改错了很隐蔽。
- 范围 `100-200`：**只取下限 100 并标记**，不猜中值 150——那是编数据。
- `(100)`：财务惯例表示负数 → `-100`。

## 5. 数字存成文本（左上角绿三角）

**长什么样**：单元格左上角有个绿色小三角，左对齐（数字默认右对齐）。

**为什么会有**：从系统导出、从网页复制、前面带了不可见空格、或者单元格被设成文本格式。

**不修会怎样**：`SUM` 得到 0，排序按字典序（`10` 排在 `9` 前面），透视表无法聚合。

**怎么修**：转成 `int` / `float`。注意保留整数形态——`100` 不要变成 `100.0`。

## 6. 中文日期

**长什么样**：
```
2026年3月5日    2026.3.5    2026/3/5    20260315
3月8日（无年份）  2026年3月    2026年Q1    一季度
```

**为什么不修不行**：这七种写法在同一列里，`sort_values()` 出来的顺序是错的，
时间序列重采样直接失败。

**关键边界**：
- **无年份的 `3月8日` 绝不自动补年份**。跨年数据补错了，一整年的趋势分析都是反的。
  本技能只在用户显式给 `--default-year` 时才补，否则原样保留并列入"待确认"。
- **`1/12` 有歧义**：1月12日 还是 12月1日？中欧美习惯不同，不猜。
- 非法日期（`2026年13月`）直接判为不匹配，不要抛异常中断整个文件。

## 7. 全角与不可见字符

**长什么样**：
- 全角：`（含退货）`、`１２３`、`，`
- 全角空格：`　`（U+3000）
- 不换行空格：`\xa0`（从网页复制带进来）
- 零宽字符：`\u200b\u200c\u200d\ufeff`

**不修会怎样**：最阴险的一类——**肉眼完全看不出来**，
但 `VLOOKUP` 匹配不上、分组统计把"张三"和"张三 "算成两个人、
去重后数量对不上。

**怎么修**：
```python
# FF01-FF5E 全角 -> 21-7E 半角，偏移 0xFEE0
# 零宽字符直接删，各类 Unicode 空格统一成普通空格
```
**注意**：顿号`、` 不要动。它在中文里是语义分隔符（"北京、上海"），
换成逗号会改变数据含义。

## 8. 合计 / 小计 / 备注行混在数据里

**长什么样**：数据区末尾或中间夹着 `合计`、`小计`、`总计`，
以及 `注：数据截至3月31日`、`制表人：小李`。

**不修会怎样**：`df.sum()` 把合计行也算进去，**结果翻倍**。
这是最常见的报表错误，而且错了还看不出来。

**怎么修**：按首列文本匹配 `^合计|总计|小计|total|sum$` 识别。
提供两种模式：
- `--drop-total` 直接剔除（要汇总时用）
- `--tag-total` 保留但打 `__合计行__` 标记（要核对原表时用）

备注行（首列以"注/备注/说明/制表/审核"开头）默认剔除。

---

## 9. 一个 sheet 里塞了多张表

**长什么样**：中间隔几个空行，上面一张表，下面换个表头又一张。

**为什么不修不行**：pandas 读进来是一张表，列名重复、数据错位。

**怎么修**：用"连续空行 + 空行后只有 1-2 格有内容（像小标题）"切成块。
`--split-blocks` 会报告每块的行号范围，需要拆成独立文件时对每块单独跑一次。

---

## 10. 占位符不是数据

**长什么样**：`--`、`/`、`NA`、`无`、`待定`、`暂无`、`未知`、`?`

**为什么不修会怎样**：它们看着像数据，实际表示"没有值"。
`count()` 会把它们算进去，均值分母就错了。

**怎么修**：**不自动删**。有些场景"无"是有语义的（"无违规记录"≠"未登记"）。
本技能只在报告里标记出来，由用户决定是置空还是保留。

---

## 11. 数字列里混进文本

**长什么样**：客户数列里出现 `(含退货)`、`待定`、`12（预估）`

**为什么不修会怎样**：`astype(float)` 直接抛异常，整个流程中断。

**怎么修**：清洗后做一遍扫描——某列 ≥50% 是数字却混了文本，就标记为可疑值，
连同行号列在报告里，**不猜、不改**。

---

## 12. 同一实体多种写法

**长什么样**：
```
北京分公司 / 北京分公司（总部） / 北京分公司(总部)
有限责任公司 / 有限公司
张三 / 张三 
```

**为什么不修会怎样**：分组统计把同一家公司拆成三行。

**怎么修**：
- 全角括号统一成半角（本技能已做）
- 首尾空格 trim（本技能已做）
- **公司名后缀归一化不建议自动做**——"北京分公司"和"北京分公司(总部)"
  在有些报表里确实是两个统计主体。列入待确认更稳妥。

## 13. 重复值：看着像重复，其实可能是合法明细

**长什么样**：两行内容几乎一样，或同一客户/同一单号出现多次。

**为什么会有**：多份表格合并、系统重复导出、人工重复录入。
但也要小心——**一张发票本来就可能有多行明细**，一张考勤表同一员工每天一行。

**不修会怎样**：不去重 → 统计翻倍。乱去重 → 真数据被删。

**怎么修**：分两级。
- **整行完全重复**：每一列都一样，删掉几乎总是安全的 → `--dedupe`
- **按列重复**（只有客户号相同，其他列不同）：**只提示，不删**。
  Excel 的"删除重复值"最大的坑就在这——勾错列就静默删掉真数据。
  处理前先备份（视频里反复强调），或用条件格式先标红人工过一遍。

## 14. 复合列：一格塞了多个字段

**长什么样**：`张三 13812345678`、`张三-销售部-北京`、`2025-05-11 14:30:00`、`北京市朝阳区XX路12号`。

**为什么会有**：系统导出图省事、人填表图方便、Excel"分列"之前的历史遗留。

**不修会怎样**：无法按任何一个字段筛选、分组、匹配。想统计"哪个城市单子多"？城市埋在地址串里，做不了。

**怎么修**：找"整列大多数值都能被同一分隔符切成相同段数"的列。
注意两个反例：
- **每段全是纯数字**的多半是日期或编号（`2026-01-05`），不是复合字段——别拆
- **分段数不稳定**的是自由文本（备注、地址详述），不是结构化数据——拆不了

脚本 `--split-col 列名 --delim "分隔符"`，原列保留、拆出的列追加在后面。

---

## 15. 文本里藏着结构化信息

**长什么样**：`订单号A20260315A01` 里藏着日期和流水号、`联系人：李四（邮箱：lisi@x.com）` 里藏着邮箱。

**为什么不修会怎样**：这些信息本来能变成可用字段（手机号、邮箱、日期），埋在文本里就等于丢了。

**怎么修**：对应 Excel 的"快速填充（Ctrl+E）"。脚本用正则识别整列高频模式：
`手机号`、`邮箱`、`身份证`、`URL`、`日期串`。
`--extract "列:手机号"` 提取成新列。

注意：**纯日期列不需要提取**（清洗时本来就会转 ISO），
这里抓的是"订单号2026年3月5日A01"这种混合文本——常规日期解析认不出来的才算数。

## 16. 同一实体的多种写法

**长什么样**：
- `北京分公司` / `北京分公司(总部)`
- `SYD` / `Sydney`
- `有限公司` / `有限责任公司`
- `张三` / `张三 `（尾随空格）

**为什么不修会怎样**：分组统计把一家公司拆成两行，VLOOKUP 匹配不上。
这是"数据看着都对、结论全是错的"的头号来源。

**怎么修**：按置信度分级，**不自动合并**：
- **高**：只是空格/全角/括号/大小写不同 → 可以放心统一
- **中**：一个是另一个加尾缀（`北京分公司` vs `北京分公司(总部)`）→
  **有些报表里这确实是两个统计主体**，必须人工确认
- **低**：疑似缩写（SYD/Sydney）→ 是否等价完全取决于业务，不要猜

## 17. 假达标：类型一致 ≠ 洗干净了

**长什么样**：一张没洗过的表，每列类型都很一致（全是文本），自检"100% 达标"。

**为什么危险**：这是最会骗人的状态。指标全绿，数据其实没法用——
`1.2万` 整列都是文本，类型当然一致。

**怎么修**：自检要同时看两件事：
1. **达标率**：目标类型的值占多少（清洗后验证用）
2. **残留空间**：文本列里还有多少值其实能解析成数字/日期（清洗前判断用）

两者结合，才能区分"真的干净"和"还没洗"。脚本输出总完成度与逐列明细，
未洗的表会明确提示"还有 N 列藏着可解析的数字/日期"。

## 检查清单

拿到一张陌生表格，按顺序过一遍：

- [ ] 编码对不对？（GBK 还是 UTF-8）
- [ ] 表头在第几行？
- [ ] 有没有合并单元格？
- [ ] 数值列是不是文本？（能不能 SUM）
- [ ] 有没有中文单位？
- [ ] 日期格式统不统一？
- [ ] 有没有合计行混在数据里？
- [ ] 一个 sheet 里有几张表？
- [ ] 有没有占位符？（`--`、`无`、`待定`）
- [ ] 有没有重复行？是整行重复还是按列重复？
- [ ] 有没有一格塞多个字段的复合列？
- [ ] 有没有同一实体的多种写法？（会拆散分组统计）
- [ ] 报告里的"需要你确认的值"看过了吗？

## 附：为什么不用 pandas

pandas 很好，但在脏表场景有三个硬伤：

1. **合并单元格读进来是 NaN**，要额外处理
2. **类型推断会"帮倒忙"**——`1.2万` 整列推断成 object，`0123` 被转成 `123`（工号、邮编就这么废了）
3. **需要 pip install**，国内源慢、企业环境常装不上

本技能用标准库直接解析 xlsx（zip + XML），
代价是只覆盖数据层、不还原格式，换来的是**零依赖、可控、可审计**。
真需要 pandas 时，清洗完的 CSV 再 `read_csv` 即可。
