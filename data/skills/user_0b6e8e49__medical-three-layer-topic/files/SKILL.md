# 医生 IP 三层选题

## 任务边界

只负责按科室/专业方向建立三层关键词库、生成短视频选题和导出本地 CSV。用户只需提供科室/专业方向；选题数量默认 30，生成模式默认 `mixed`。

不生成完整脚本、账号定位、患者画像、营销策略或个体诊疗建议。不读取真实病历，不上传数据，不连接外部服务。

## 固定流程

1. 提取科室/专业方向。表达不明确时只追问一次。
2. 读取 [三层方法](references/three-layer-method.md)。
3. 确定数量、模式和输出目录；默认目录为当前工作区的 `outputs/medical-three-layer-topic/`。
4. 查找 `关键词库_<科室>.csv`。不存在时先建库，存在时直接复用。复用前检查每层关键词数量是否低于软底线（L1≥50、L2≥30、L3≥50）。低于软底线时先提示用户决定是否扩充，不强行生成。
4.5. **操作可见化**：建库完成后，向用户展示：
   - 三层关键词摘要（每层挑 8–10 个代表性词，按分类分组）
   - **L1×L2 组合覆盖度仪表盘**（已覆盖组合数/理论有效组合数/覆盖率），特别标注覆盖率 >60% 的高频 L1 关键词
   - 仍有大量未覆盖 L1×L2 方向时，主动告知「还可以从这些角度继续深挖」
   用户可在此环节提出排除某类话题或增加某方向，调整后继续。跳过此步骤的唯一例外是用户明确说「直接生成不用确认」。
4.6. **覆盖度预警**：检查 L1×L2 组合覆盖率。
   - 单个 L1 的 L2 组合已用 >60%：提示「XX 方向快拍完了，要不要扩充新场景？」
   - 单个 L1 的 L2 组合已用 >80%：拒绝在该 L1 上继续产出，必须建议扩充 L2 场景或转战其他低频 L1
   - 不接受在已饱和的 L1×L2 组合上强行生成语义换壳的内容
5. 生成策略采用「广度 + 深度矩阵」：
   - **广度层**：确保所有尚未覆盖的 L1 至少出一条（首轮优先填补空白）
   - **深度层**：对高价值 L1（高频疾病、患者痛点集中），系统性地穷举未使用的 L1×L2 组合，从 L3 中选最匹配的提问角度
   - **组合去重**：同一 L1×L2×L3 的三层组合只出一条；L1×L2 相同但 L3 角度语义高度相似的只保留一条。去重依据是三层关键词组合，而非标题字面
   - `mixed/newbie/pitfall/compare/live` 模式：按方法文档润色为口播化标题（必须满足标题钩子标准），过滤、去重
   - `burst` 模式：仅做基础可读性处理，保留组合原貌，跳过精细润色。仍执行医疗安全必杀红线，但不做输出前 5 项检查
6. 最终筛选前必须读取 [医疗安全规则](references/medical-safety.md)。`burst` 模式下只过滤必须舍弃的 8 条红线（治疗承诺/个体诊断/处方用药/手术替代/延误就医/虚构证据/恐吓/变相推介），不执行输出前 5 项检查。其他模式全量过滤。不合格候选直接舍弃并补充生成。若连续两轮补充后合格数仍不足目标数，下调预期数量并告知用户当前可生成的合格选题上限，不强行凑数。
7. 使用 [CSV 工具](scripts/csv_store.py) 写入词库、选题结果和本地历史。
8. 重新读取结果 CSV，确认表头、行数和中文内容后再交付。
8.5. **词库扩充引导**：选题交付后，检查以下信号并主动提示用户后续策略：
   - 某 L1 的未用 L2 场景 < 5 个 →「XX 方向快拍完了，要不要加几个新场景继续？」
   - 整体可用 L1×L2 组合 < 目标量 × 3 →「词库组合空间偏紧，建议扩充 L2 场景或 L1 关键词」
   - 某高频 L1 已充分覆盖（>8 条选题）→「XX 方向拍了 N 期，建议转战这几个还没怎么碰的方向：（列出 3-5 个低频 L1）」

## 建立关键词库

生成内部 JSON，顶层为 `keywords`，每行包含 `layer`、`keyword`、`category`、`weight`、`status`。三层分别使用 `L1`、`L2`、`L3`，默认权重为 `5`，状态为 `启用`。

```bash
python3 scripts/csv_store.py library \
  --input <临时关键词JSON> \
  --specialty <科室或专业方向> \
  --output-dir <输出目录>
```

内部 JSON 只是脚本输入，不作为用户交付物；使用完即删除临时文件。

## 生成并导出选题

内部 JSON 顶层为 `topics`，每行必须包含：`title`、`layer1`、`layer2`、`layer3`、`mode`。

```bash
python3 scripts/csv_store.py topics \
  --input <临时选题JSON> \
  --specialty <科室或专业方向> \
  --output-dir <输出目录> \
  --date YYYY-MM-DD
```

如果 `python3` 不存在，再尝试 `python`。不安装第三方依赖。

## 输出契约

最终文件名：`医生IP选题_<科室>_YYYYMMDD.csv`。

固定表头顺序：

`序号,科室/专业方向,选题标题,第一层关键词,第二层关键词,第三层关键词,生成模式,生成日期`

只向用户报告合格选题数和 CSV 绝对路径，不展示内部评分或临时 JSON。词库和 `选题历史.csv` 保留在同一输出目录，用于后续积累和去重。

> **文件名说明**：输出文件使用中文命名（如 `医生IP选题_内分泌科_20260720.csv`），方便在 Excel/WPS 中直接识别内容。如果你的系统对中文路径兼容性较差（如某些 CI 环境），可替换为英文文件名如 `doctor_ip_topics_<specialty>_YYYYMMDD.csv`。脚本内部处理已做 Unicode 归一化，macOS/Windows 中文版下直接双击即可打开。

> **连连看提示**：导出的 CSV 中「第一层关键词」「第二层关键词」「第三层关键词」三列可直接用于手动选题。在 Excel 中随机各取一个关键词、组合成新标题，就是「三层关键词连连看」的玩法——选一个疾病 × 选一个人群/场景 × 选一个患者最想问的问题 = 一条新选题。词库 CSV 也可导入 Excel 做关键词池管理，方便运营团队协作。

## 异常处理

| 情况 | 处理方式 |
|------|----------|
| 科室/专业方向表达不明确 | 追问一次，仍未明确则要求用户确认后再继续 |
| 关键词库为空或不存在 | 按三层方法文档从零建库，不跳过 |
| 复用词库某层关键词低于软底线 | 提示用户当前数量，由用户决定是否扩充后继续 |
| 候选组合大规模不成立 | 检查是否某层关键词范围过窄，必要时建议扩充该层 |
| 安全过滤后合格选题不足目标数 | 补充生成一轮；仍不足则告知用户当前上限，按实际数量输出 |
| `python3` 命令不存在 | 降级尝试 `python`，都不存在则报错并提示安装 Python 3 |
| 输出目录不可写 | 报错并提示用户检查目录权限 |
| 选题历史文件损坏 | 脚本拒绝写入并保留原文件，需用户手动处理后再运行 |
| 写入过程遇到临时故障（磁盘满、云同步锁冲突） | 脚本内置 3 次自动重试（指数退避 1s→2s→4s），仍失败则提示具体错误原因和解决建议 |

## 模式

- `mixed`：混合问题角度。综合各类提问方式，覆盖最广。
- `newbie`：入门、判断与注意事项。适合刚确诊或刚发现症状的患者。
- `pitfall`：误区与风险识别。纠正常见错误认知和危险做法。
- `compare`：差异与选择条件，不宣布唯一优劣。帮助患者理解不同选项。
- `live`：适合直播问答的短问题。口语化、快节奏、一问一答。
- `burst`：爆量模式。生成目标数量四倍的候选标题，仅过滤医疗安全必杀红线（8 条必须舍弃规则），标题保留组合原貌不做精细润色。输出 CSV 供用户自行圈选，圈选结果可再次输入进行精加工。适合「先看有什么方向再定做哪个」的选题规划场景。burst 模式不执行标题钩子标准中的口播化要求，因粗筛阶段重在广度而非精度。

模式只限制第三层提问角度和润色深度，不改变第一层内容对象和第二层使用语境。

维护或发布此 Skill 时，使用 `evals/trigger_cases.json` 检查触发边界，使用 `evals/output/cases.jsonl` 检查输出质量。
