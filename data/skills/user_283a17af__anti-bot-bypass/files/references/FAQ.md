## 一、场景化 FAQ（按你遇到的现象分类）

### （一）入门与判层

### Q1：目标站返回 200，但正文几乎没有内容 / 只有一段 JS
**A**：大概率是 SPA（单页应用），真实数据在 XHR/JSON 接口里。先不要开浏览器，按这个顺序：
1. 用浏览器 F12 → Network → Fetch/XHR 找接口
2. 搜 HTML 里的 `__NEXT_DATA__`、`window.__INITIAL_STATE__`、`application/ld+json`
3. 找到接口后直接用 `curl_cffi` 请求，成本最低
4. 找不到再升级到 L3/L5 渲染

**例如**：抓 B 站热门榜时，直接请求 `https://api.bilibili.com/x/web-interface/ranking/v2?rid=0&type=all` 就能拿到 JSON，比渲染页面快 100 倍。

### Q2：浏览器能打开，但脚本 403/429
**A**：脚本被识别为"非浏览器"。最常见的是 TLS 指纹或 HTTP2 指纹不对。优先试：
```python
from curl_cffi import requests as r
r.get(url, impersonate="chrome")
```
如果通了，说明纯 TLS 层问题，不用开浏览器。

**例如**：某 Cloudflare 保护的电商站，裸 requests 返回 403，换成 `curl_cffi` 的 `impersonate="chrome"` 后 200，说明只是 TLS/HTTP2 指纹被识别，不需要开浏览器。

### Q3：为什么建议"先找 API 再考虑渲染"？
**A**：成本差 100 倍。渲染一个页面要启动浏览器、加载 JS、等待网络空闲，单次几十到几百毫秒且吃内存；直接打 JSON 接口是毫秒级、可高并发。能用 L0 就别上 L3，**每升一级成本涨 5~50 倍**。

### Q4：探针建议 L5，是不是必须上真实浏览器？
**A**：探针的建议是"起点"，不是"终点"。如果目标站强指纹 + 行为分析 + 登录态缺一不可，L5 成功率最高；但如果只是 JS 挑战，L3 就够了。**被拒才升级**，不要直接跳到 L5。

### Q5：探针报告怎么读？
**A**：重点看三行：
- `[命中厂商]`：识别到 Cloudflare/Akamai/瑞数… 及强/弱证据
- `[内容层信号]`：首屏可见文本 < 300 多半需要 JS 渲染；有 `字体反爬`/`签名参数` 线索
- `[建议起点: Lx]`：最终判层 + 理由列表（每条理由都带了"为什么"）

> 报告末尾固定输出阶梯：`L0 找接口 → L1 curl_cffi → L2 住宅代理 → L3 patchright → L4 camoufox → L5 真实浏览器 → L6 商业API`。

### （二）报错与排障

### Q6：跑探针出现一堆看不懂的英文 / 报错
**A**：正常情况下探针**不会**输出英文堆栈——所有异常都被 `friendly_error()` 翻译成中文并带 `[Exxx]` 编号。如果你看到了英文，几乎只有两种可能：
- 用的还是旧版 `probe.py`，请更新到 v1.0.5+；
- 触发了 `[E999]` 兜底（极罕见），按提示加 `--timeout` 或换网络重试即可。
具体编号含义见文末「四、错误代码速查表」。

### Q7：换了好几个代理 IP 还是 403
**A**：可能目标看 **ASN/IP 类型**（数据中心代理 vs 住宅代理），或 **cookie 与 IP 绑定**（cf_clearance 换 IP 即失效）。先确认：
- 换的是住宅/移动 IP 还是机房 IP？（住宅优先）
- 之前拿到的清关 cookie 是否跟着新 IP 一起用了？
- 是否保持了同一 UA + IP + cookie 三件套一致？

### Q8：抓下来中文乱码 / 全是问号
**A**：编码不匹配。探针内部已自动按 `utf-8 → gbk → latin-1` 降级，正常不会出现。若你自己的脚本乱码：
```python
# 优先读响应声明的 charset，失败再 fallback gbk
raw = resp.content
text = raw.decode(resp.encoding or "utf-8", errors="replace")
if "�" in text[:500]:           # 还有乱码就换 gbk
    text = raw.decode("gbk", errors="replace")
```

### Q9：怎么判断拿到的是真实数据还是"影子封禁"假数据？
**A**：**200 ≠ 成功**。影子封禁（Akamai/瑞数常见）会返回 200 但内容是假数据或挑战页。判定口诀：
1. 首屏可见文本 < 300 字符且命中重型厂商 → 高度可疑
2. 拿**人工浏览器看到的真实值**做基准，抽样对比你的结果是否一致
3. 不一致就说明被喂了假数据，必须升级到 L4/L5 真实浏览器

### Q10：为什么同一个站今天能抓明天不能？
**A**：风控会漂移。常见原因：IP 段进黑名单、目标更新 JS 挑战、TLS 指纹库更新、cookie 过期。**应对：先重跑探针重新判层**，不要直接拿昨天的模板硬试。

### Q11：误判厂商怎么办？比如把 CDN 当成 Cloudflare
**A**：探针的厂商匹配分"强证据"（cookie/body 命中）和"弱证据"（仅响应头）。弱证据会提示"可能只是用了 CDN"，**不会强制升级**。若仍误判：
1. 用 `--save` 落盘 HTML 人工看
2. 把真实页面特征反馈到 `references/vendors.md`
3. 记住：最终按**内容**判定，不看状态码

### （三）浏览器与指纹

### Q12：用了 curl_cffi 还是 403，但浏览器能开
**A**：说明不止 TLS 层。可能是：① HTTP2 SETTINGS 指纹；② JA3/JA4 之外的层（如 AKAMAI 的 sensor_data）；③ 需要特定 cookie。下一步：
- 换 `impersonate` 版本（`chrome120`/`edge101`…）
- 带上浏览器里已有的 cookie 再试
- 仍不行 → 上 L3（patchright/nodriver）真正执行 JS

### Q13：L3 和 L5 怎么选？
**A**：**能 L3 就不 L5**。L3（patchright/nodriver/camoufox）是无头浏览器但能执行 JS、过 JS 挑战，成本低；L5（真实浏览器 CDP）要复用你本机 Chrome，成本高但最像人。规则：纯 JS 挑战用 L3；需要登录态 + 强行为分析 + 拟人交互才上 L5。

### Q14：怎么控制请求频率才不被封？
**A**：核心是"像人"：
- 同域名并发 ≤ 1
- 相邻请求间隔约 2~5 秒，抖动用**重尾分布**（`random.lognormvariate(math.log(2.5), 0.4)` 秒）——均匀随机 `random.uniform(1,3)` 是行为分析站点的识别特征（见反模式第 12 条）；仅网络层重试退避可用均匀抖动
- 每次请求随机 UA（但同一会话内 UA 要固定）
- 收到 429/403 立即指数退避（5s → 15s → 45s），**不要换 IP 硬刚**
- 低峰时段跑批量任务

### Q15：代理 IP 怎么选？数据中心 / 住宅 / 移动？
**A**：
| 类型 | 成本 | 匿名度 | 适用 |
|---|---|---|---|
| 数据中心代理 | 低 | 低（易被标记 ASN） | 仅测试 / 无防护站 |
| 住宅代理 | 中 | 高 | 大多数反爬站首选 |
| 移动代理 | 高 | 最高 | 极严风控 / 小量高价值 |

> 量小场景直接上 L5 真实浏览器 + 自己网络，可能比买代理更省。

### Q16：字体反爬（数字变成方块/乱码）怎么还原？
**A**：站把数字映射成 Unicode 私有区字符，靠专属 woff 字体显示。还原方法：
1. 下载页面引用的 woff/woff2
2. 用 `fonttools` 解析 cmap，得到「私有区码点 → 真实字符」映射表
3. 把抓到的文本按映射表替换回来

> 这是 L7 层（展示层），与访问层无关，见 `mechanisms.md §7`。**急着要数据的话，直接 L3 取渲染后文本最省事**。

### Q17：遇到无限 `debugger` 反调试怎么过？
**A**：两类办法：
- **跳过**：DevTools 里对 debugger 行点 "Never pause here"，或用 `addInitScript` 在页面加载前 `Object.defineProperty` 覆盖 debugger
- **hook**：用 `响尾蛇`/Frida 类工具 hook `Function` 构造函数，让 debugger 失效
- **直接渲染**：L5 真实浏览器手动过一次，比逆向更划算

### （四）验证码与登录

### Q18：出现验证码能不能自动识别？
**A**：分场景——
| 验证码类型 | 处理方式 | 是否允许 |
|---|---|---|
| 公开页偶发的无感 Turnstile / 简单图片验证码 | 用 L5 真实浏览器 + 手动过一次，复用登录态 | 允许 |
| 登录 / 支付 / 实名环节的身份核验验证码 | **禁止自动识别** | 红线 |
| 高敏感站点的行为验证（3D 滑块、点选） | 建议放弃或换数据源 | 灰色 |

### Q19：登录后才能看的数据能爬吗？
**A**：**不能作为通用方案**。判定口诀：「不登录就看不到 = 不能爬」。
- 你自己账号登录后的数据：合规四查通过、ToS 允许前提下，可用 L5 复用登录态少量采
- 别人的账号 / 绕过登录墙：拒绝
- 替代：找公开 SEO 聚合源（职友集、看准网、官方报告）

**例如**：想抓 BOSS 直聘岗位薪资，但该站必须手机号登录 + 过滑块才能看详情——属登录墙 + 身份核验验证码，直接拒绝；替代是抓「职友集」上同一岗位公开薪酬区间。

### Q20：Cloudflare Turnstile 怎么过？
**A**：Turnstile 是无感验证，真人浏览器访问会自动出 `cf_clearance` cookie。做法：
1. L5 真实浏览器手动访问一次通过验证
2. 取出 `cf_clearance` cookie
3. **保持同一 IP + 同一 UA** 复用该 cookie 继续请求
4. 注意：换 IP 会让 clearance 失效，需重新过

### （五）合规与数据

### Q21：robots.txt 说 Disallow 怎么办？
**A**：**遵守**。 robots 是站点明示的抓取边界，Disallow 路径原则上不采。若业务确需，先与用户确认授权情况再决定。探针报告里会显式提示 `⚠ 该站 robots 禁止全部抓取`。

### Q22：抓图片 / 文件（不是文本）怎么搞？
**A**：直接下载即可，注意两点：
- **防盗链**：带 `Referer` 和原站 `User-Agent`，否则 403
- **频率**：图片也是请求，一样要限速
```python
import urllib.request
req = urllib.request.Request(url, headers={"Referer": page_url, "User-Agent": UA})
data = urllib.request.urlopen(req, timeout=20).read()
```

### Q23：数据存数据库还是文件？
**A**：看规模。小量（几百条）存 JSON/CSV 最省事；中等以上（万级）用 SQLite/PostgreSQL；超大规模才上 ES/数据仓库。**无论存哪，个人联系方式（姓名/电话/地址）原则上不采、不存、不传**，避免触碰《个人信息保护法》。

### Q24：抓取速度多快算"礼貌"？
**A**：起步建议：同域名并发 ≤1、间隔 1~3 秒带抖动、429/403 立即退避、低峰跑批量。详见 Q14。

### Q25：拿到数据后怎么验证没被污染？
**A**：三步抽样校验：
1. 取 5~10 条关键字段，与人工浏览器看到的值对比
2. 检查是否有"整齐到反常"的占位值 / 重复值（影子封禁特征）
3. 对数值字段做分布校验（如价格区间是否合理）

### （六）工具与协作

### Q26：这个 skill 能独立运行吗？还需要装什么？
**A**：探针 `probe.py` 只依赖 Python 标准库，**独立可运行**。高级绕过依赖外部工具：
- `curl_cffi`：L1 TLS 伪装
- `patchright` / `nodriver` / `camoufox`：L3/L4 浏览器伪装
- `web-access`：L5 CDP 复用本机 Chrome
- `scrapling`：自适应抓取框架

本 skill 给你"判层 + 模板"，执行时调用这些已有工具，不重复造轮子。

**例如**：你刚拿到目标 URL，不需装任何环境，直接 `python scripts/probe.py https://target.com` 就出判层报告；若探针建议 L1，再去 `pip install curl_cffi` 也不迟。

### Q27：本 skill 和 web-access / scrapling 怎么配合？
**A**：分工明确，不冲突：
- **L0~L1**（找接口 / TLS 伪装）：直接用 `curl_cffi` 或 `scrapling` 的 `Fetcher`
- **L3**（JS 挑战 / 渲染）：`scrapling` 的 `DynamicFetcher` 或 `patchright`/`nodriver`
- **L5**（登录态 / 强行为 / 拟人）：交给 `web-access` 复用你本机 Chrome 的 CDP
> 简记：轻活 scrapling，重活 web-access，判层交给本 skill 的探针。

### Q28：环境自检（env-check）怎么用？
**A**：装完 skill 第一步就跑：
```bash
python scripts/env-check.py
```
它会检测 Python 版本、网络连通性、curl_cffi 等可选依赖、本机浏览器，输出**红/黄/绿**中文报告 + 修复建议。全绿说明环境 OK，可以开始探针；有红项按提示修即可，不用自己瞎猜。

### （七）2026 新机制速答

### Q29：过了 Turnstile 拿到 cf_clearance，为什么翻几页还是被封？
**A**：大概率遇到了 **Cloudflare Precursor**（2026-07-13 GA）——会话级持续行为验证，取代了老的 JSD。它全程给会话行为评分，中途掉分会动态升级挑战甚至收回通行证，**"过一次挑战 = 全场安全"已失效**。它靠生理级特征识人：真人轨迹有腕部旋转弧度、生理手抖、认知识别延迟（~200ms）；而「高斯噪声 + 均匀随机延迟」的仿真恰恰是最显眼的 bot 特征。对策：L5 真实浏览器人工操作/行为回放 > 参数化仿真；延迟用重尾分布；每会话翻页别太深（详见 site-cases.md 案例 I）。

### Q30：Web Bot Auth 是什么？以后 UA 伪装还有用吗？
**A**：Web Bot Auth（RFC 9421 + Ed25519 签名）是 IETF 推动的 **agent 加密身份标准**（Cloudflare/Amazon/Akamai/OpenAI/Google 支持，Google 已测 `agent.bot.goog`）：agent用密钥对自证身份，站点验签后决定放行与配额。趋势是「**匿名 bot 察觉成本趋零，持证 agent 才有配额**」——UA 伪造、IP 白名单这类"匿名混入"策略在带头厂商处将逐步失效。当前对自用低频抓取影响尚小（暂不强制），但做产品化 agent 要提前布局签名身份；配合 DataDome KYA、HUMAN Verified AI Agent 看，"诚实声明身份 + 走授权通道"是长期更省钱的路线（见 vendors.md「AI Agent 身份认证浪潮」）。

## 二、反模式清单（不要做）

| 反模式 | 典型场景 | 为什么错 | 正确做法 |
|---|---|---|---|
| **一上来就开 Playwright 裸跑** | 用户说"帮我抓这个网页"，直接写 `p.chromium.launch()` | headless 检测点 dozens 个，裸跑 90% 被识别 | 先跑探针，L1 能过就不要开浏览器 |
| **遇到 429 就换 IP 硬刚** | 抓电商价格第 5 页突然 429，立刻切代理继续 | 会扩大封禁面，可能把整段 IP 拉黑 | 先减速、退避、检查触发原因 |
| **默认 verify=False** | 本地跑脚本图省事写 `verify=False` | 中间人攻击风险，且有些站靠证书链做指纹 | 默认校验证书，仅 `--insecure` 降级 |
| **解析 HTML 不写自适应选器** | 写死 `div:nth-child(3) > span.price` | 页面一改就挂，维护成本高 | 用 Scrapling `auto_save` / 多备选选择器 / 哨兵页校验 |
| **把登录态拿去绕过登录墙** | 想抓 BOSS 岗位详情拿自己 cookie 绕登录 | 属"绕过登录/鉴权获取非公开数据"，红线 | 只采公开页；登录态仅用于自己账号的公开数据 |
| **把验证码识别用于登录/支付/实名** | 登录页弹极验滑块，想用打码平台自动过 | 违法 + 红线，个人也禁止 | 仅用于公开页偶发验证，且优先 L5 手动过码 |
| **不读 robots.txt 直接全站扫** | 写循环把整站 `/page/1`~`/page/9999` 全抓 | 法律风险 + 触发风控 | 先查 `/robots.txt`，Disallow 路径不采 |
| **抓到个人联系方式存下来** | 爬招聘网站顺手把手机号/邮箱落库 | 违反《个人信息保护法》 | 姓名/电话/地址等原则上不采、不存、不传 |
| **拿到 200 就当成功** | 看到 status 200 直接入库，不管内容真假 | 影子封禁会喂假数据，200 是陷阱 | 用人工基准值抽样校验数据真实性 |
| **同一会话乱换 UA / IP** | 一个采集任务里随机换 UA 和代理 | UA-IP-cookie 不一致会立刻被风控判异常 | 同一会话内固定 UA + 粘滞 IP + 复用 cookie |
| **对 4xx 盲目重试** | 403 也塞进重试循环反复请求 | 4xx 是确定性拒绝，重试只会加速封禁 | 仅对网络层失败 / 5xx 重试，见 probe 自动重试逻辑 |
| **用均匀随机延迟冒充人类节奏** | `random.uniform(1,3)` 打遍天下 | Precursor 等生理级行为分析重点识破「高斯噪声+均匀延迟」 | 延迟改重尾分布（对数正态）+ 模拟认知识别延迟；高价值会话用行为回放（见 Q29） |

## 四、错误代码速查表（探针报错对应）

探针所有报错都带 `[Exxx]` 编号，按编号查：

| 编号 | 含义 | 一句话修复 |
|---|---|---|
| E001 | DNS 解析失败 | 检查 URL 拼写 / 换网络 |
| E002 | TLS 证书校验失败 | 加 `--insecure`（仅调试）或目标证书确有问题时 |
| E003 | 连接超时 | 加大 `--timeout`，换网络/代理 |
| E004 | 网络层不可达 | 防火墙/VPN/代理异常，换网络 |
| E005 | 连接被重置 | 减小并发 + 随机延时，探针已自动重试 |
| E006 | 代理连接失败 | 检查 `--proxy` 地址与格式 `http://host:port` |
| E007 | 编解码异常 | 内部已降级 gbk/latin-1，可忽略 |
| E008 | JSON 解析失败 | 目标返回非 JSON（挑战页），结合状态码判断 |
| E009 | 触发频次限制 | 降速 + 退避，不要硬刚 |
| E010 | URL 格式无效 | 以 `http://` 或 `https://` 开头 |
| E011 | 文件写入被拒 | 换有写权限的 `--save` 目录 |
| E012 | 文件/路径不存在 | 检查 `--save` 路径 |
| E013 | TLS 伪装库异常 | 重装 `pip install -U curl_cffi -i 清华源` |
| E999 | 未预期异常（兜底） | 加 `--timeout` / 换网络，仍不行反馈给我 |
