# 已验证站点经验库（脱敏真实案例）

> **这是本 skill 的差异化资产**：绝大多数反爬 skill 只讲"原理 + 模板"，但真实站点的坑只有踩过才知道。
> 本文件记录多个**真实站点**的诊断结论与生效方案（已脱敏，不泄露具体 URL 与数据）。
> 遇到同类站点时，先来这里查，省去重新跑探针 + 试错的成本。
>
> 格式：`站点类型 | 防护判定 | 生效方案 | 关键陷阱 | 验证日期`

## 二、详细案例（可复用的判断逻辑）

### 案例 A：视频平台热门榜 —— L0 直连成功

- **现象**：用户要"今日前十热点"，浏览器能看，脚本不知道从哪抓。
- **判定**：公开页面，不登录，频率低 → 合规通过；预判数据是 SPA，优先找接口。
- **生效**：直接调榜单 JSON 接口（`/x/web-interface/ranking/v2`），20ms 内拿到标题 + bvid。
- **陷阱**：某些接口需要带 `Referer` 和真实 `User-Agent`，否则返回 412。
- **结论**：**80% 的"反爬"其实是数据在 XHR 里**，先找接口再谈绕过。

### 案例 B：瑞数系政务站 —— L3 起点 + 无限 debugger

- **现象**：首请求 202/412，页面疯狂 `debugger`，脚本卡死。
- **判定**：`$_ts.nsd` / `clearInterval(_$` 命中 → 瑞数 vmp。注意首请求 202/412 是"三次请求模式"特征，不是错误。
- **生效**：L3 浏览器（patchright/nodriver）加载后等挑战完成；遇到无限 debugger，用 CDP `Runtime.terminateExecution` 或 hook `Function` 跳过。
- **陷阱**：瑞数版本迭代快，清关 cookie 与 IP+UA 强绑定，换 IP 即失效。
- **结论**：不要把 202/412 当成失败，那是瑞数的握手流程。

### 案例 C：电商价格字体反爬 —— L7，调用原函数最快

- **现象**：抓到的价格是 `&#xea2d;` 这种私有区字符乱码，页面显示正常数字。
- **判定**：`@font-face` + 大量 Unicode 私有区字符 → 字体映射反爬。
- **生效**：**捷径 = 在浏览器上下文里让页面自己解码**，直接 `page.eval_on_selector(".price", "el => el.textContent")` 拿渲染后文本。
- **陷阱**：硬扣字体映射表是数天工作量，但调站内渲染函数只要数分钟。
- **结论**：第 7 层的最优解往往不是逆向，而是"借它的函数"。

### 案例 D：Akamai 影子封禁 —— 200 但假数据

- **现象**：请求返回 200，状态码一切正常，但数据明显是旧的/假的。
- **判定**：`_abck` / `bm_sz` cookie 命中 → Akamai Bot Manager。影子封禁特征：**不拒绝你，但给你假数据**。
- **生效**：L4（camoufox + 住宅 IP + 会话预热），清关 `_abck` 后保持稳定。
- **陷阱**：**200 ≠ 成功**，必须用"人工浏览器看到的真实值"做基准校验数据真实性。
- **结论**：Akamai 最阴险的不是拦你，是骗你。

### 案例 E：招聘薪资 —— 红线拒爬，转公开聚合

- **现象**：用户想抓 BOSS 直聘采购工程师薪资区间。
- **判定**：必须手机号登录 + 过极验滑块才可见 → 命中「绕过登录墙」+「对抗身份核验验证码」两条红线。
- **生效**：**拒绝**，转向无需登录的公开聚合源（职友集/看准网/官方薪酬报告）获取同口径数据。
- **陷阱**：即便技术上 L5 能手动过一次码再复用登录态，那本质仍是绕过登录墙，违规。
- **结论**：口诀——「不登录就看不到 = 不能爬」。

### 案例 F：电商搜索页自动化降级 —— 转 WebSearch + 实价锚定

- **现象**：脚本抓京东/ZOL 商品搜索页，拿到的是"请使用高版本浏览器"空壳页，且无 JS 挑战特征。
- **判定**：不是反爬，是**对自动化 UA/TLS 的静默降级**（返回无害空页而非拦截）。
- **生效**：放弃直爬，改用 WebSearch 多源交叉 + 以用户实价（如单条 ¥619）为锚校准口径。
- **陷阱**：**单条 ≠ 套装**、**UDIMM ≠ SO-DIMM**、**现价 ≠ 历史价**、**自营 ≠ 第三方**——口径错了数字差几倍。
- **结论**：当结构化源不可得时，搜索引擎 + 人工实价校验是更稳的兜底。

### 案例 G：Cloudflare AI 流量分类 —— agent 抓取被归 Agent 类

- **现象**：browser-use / 浏览器驱动 agent（如 Claude/Gemini 驱动 Chrome）访问带广告的电商/媒体页，被 Cloudflare 直接拦截，即便 TLS/指纹都过得去。
- **判定**：2026-07 起 Cloudflare 把流量按行为分 Search/Agent/Training 三类；**browser-use agent 属 Agent 类**。2026-09-15 起新域名广告页默认屏蔽 Agent（与 Training）。
- **生效**：要么目标页非广告页、要么站点主动放行 Agent 类；长期看合法抓取路径是"诚实 UA + 经 Pay Per Crawl/授权渠道"，而非纯指纹伪装。
- **陷阱**：Agent 类流量被屏蔽不报明显挑战，可能表现为静默 403/edge 拦截，易误判为"其他层问题"而乱改 TLS/指纹。
- **结论**：2026 年风控战场从"指纹"延伸到"你是哪种自动化"——agent 身份本身可能成为拦截理由，要主动声明诚实 UA 并走授权通道。

### 案例 H：Kasada 时间绑定 token —— 换 IP 即 429

- **现象**：过 Kasada 挑战后拿到 `KP_UIDz` cookie，前几次请求正常，之后突然稳定 429 + `x-kpsdk-ct` 错误头。
- **判定**：`x-kpsdk-*` 头命中 → Kasada。token **时间绑定 + IP 绑定**：T=0 生成的 payload 过 60s 提交被拒；中途换出口 IP 也破坏 IP 绑定验证。
- **生效**：L5 真实浏览器过挑战后，**锁定同一出口 IP 直到 token 生命周期结束**再批量抓；别在挑战后切代理。
- **陷阱**：把 429 当成"IP 被封"盲目换 IP 会陷入死循环——根因是 token 与 IP 绑定，换 IP 反而触发校验失败。
- **结论**：Kasada 的 token 是 IP 绑定的，混合架构里"过挑战用浏览器、抓取用 HTTP"必须保证两者同一 IP（见 toolbox.md 混合架构）。

### 案例 I：Cloudflare Precursor —— 过了 Turnstile 翻几页仍被封

- **现象**：L3 过了 Turnstile 拿到 `cf_clearance`，首页正常；翻到第 3~5 页突然被弹回挑战页或静默 403。重新过挑战后，现象原样复现。
- **判定**：`cf_clearance` 命中 + **中途掉分** → 大概率站点开启了 **Precursor 持续验证**（Cloudflare 2026-07-13 GA，取代 JSD）。它给整段会话的行为流持续评分：鼠标轨迹、键盘节奏、页面可见性全在采集；「高斯噪声 + 均匀随机延迟」这类老式参数化拟人恰恰是它的重点识别特征。
- **生效**：① 换 L5 真实浏览器人工操作关键页，或回放人工录制的真实轨迹（保真度 > 数学合成）；② 延迟改**重尾分布**（对数正态）并模拟认知识别延迟（~200ms）；③ 降低单会话翻页深度（每会话只翻 2~3 页更像人），多会话分散任务。
- **陷阱**：把中途被封误判为"IP 被拉黑"去狂换代理——无效且烧钱。根因在**行为流**，不在 IP；换完 IP 现象照旧。
- **结论**：2026-07 之后，Cloudflare 站要把「会话行为一致性」当作独立的一层来经营，"过挑战 = 安全"的假设已失效（机制详见 mechanisms.md §第 6 层）。

## 三、怎么往这个库里加新案例

1. 跑 `scripts/probe.py` 拿到层级判定
2. 记录：`站点类型 | 防护判定 | 生效方案 | 关键陷阱 | 日期`
3. 脱敏：不写具体 URL、不写抓到的真实数据
4. 把"反常现象"（如 200 假数据、空壳降级页）作为重点陷阱写出来——这是别人没有的经验
