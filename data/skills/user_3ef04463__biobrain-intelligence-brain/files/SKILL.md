# Intelligence Brain — 公司级AI情报引擎

## 一句话看懂

**把你公司所有AI部门每天产生的信息变成能用的洞察——不只是"存起来"，是消化、连接、推理，从两个互不相关的报告里挖出你不知道的关键联系。**

信息存起来只会腐烂。像食物一样，不消化就会发臭。Intelligence Brain做的就是把信息吃进去、消化掉、变成能指导行动的洞察。

---

## 为什么要用这个？

你的AI部门每天都产出信息：品牌部的日报、销售部的数据、财务部的报表……这些信息散落在不同文件夹里。看每份单独都正常，但之间的联系才是关键。

比如品牌部说"小红书互动率降了15%"，销售部说"知识星球转化率涨了22%"。单独看都是两件不相关的事。放在一起就是一条策略线索：免费平台获客效率在下降，付费阵地的人在增加——该调整资源分配了。

Intelligence Brain就是做这件事的。不是存信息，是挖联系。而且挖出来的不是"有意思"的发现，是能立刻变成行动的建议。

这是一个在7部门AI公司里真实运行过的情报引擎。不是概念设计。

## 3分钟快速上手

### 理解这套系统的思路

Intelligence Brain像一个八步消化管道。信息从入口进、经过处理、最终变成洞察从出口出。24小时内必须完成，过期的信息跟没信息一样没用。

```
吃进去 → 拆解 → 消化 → 分类 → 合并 → 吸收 → 清理 → 升华
 步骤1    步骤2   步骤3   步骤4   步骤5   步骤6   步骤7   步骤8
```

### 八步管道（用人话解释）

| 步骤 | 做什么 | 大白话 |
|------|--------|--------|
| 1. READ 采集 | 把今天所有部门产出收进一个队列 | 把今天的快递全拿进来 |
| 2. PARSE 解析 | 从原始文字里提取结构化信息 | 别管长文，先看谁发的、什么时候、关于什么 |
| 3. DECOMPOSE 拆解 | 拆成一条条原子事实 | 把段落拆成声明、数据、动作 |
| 4. ORGANIZE 分类 | 给每条信息打标签、定密级 | 这条归品牌部、这条是内部数据 |
| 5. MERGE 合并 | 比对已有的信息，找重复、找矛盾 | 这篇文章跟上周那篇说的是同一件事吗？ |
| 6. USE 应用 | 把处理后信息分发到需要它的部门 | 品牌部拿走品牌相关的，销售部拿走销售相关的 |
| 7. DELETE 清理 | 删掉已经处理过的原始文件 | 别把吃过的食物留在桌上发臭 |
| 8. EXTRAPOLATE 升华 | 交叉推理，挖出隐藏联系 | 这是核心——从两个不相关的文件里推到第三个结论 |

步骤1-7用免费AI模型（省钱），步骤8用付费模型（这一步质量不能省，直接影响决策）。

## 核心能力：跨文件推理（"One More Thing"）

这是整个引擎最有价值的部分。不是从某个文件里读到的，是从多个文件的**缝隙**里挖出来的。

### 例子

```
文件A（品牌部日报）: "小红书内容互动率下降15%"
文件B（销售部日报）: "知识星球付费转化率提升22%"

跨文件推理：
  免费平台引流效率↓ + 付费阵地转化↑
  → 决策：增加知识星球内容密度，减少小红书发布频率
  → 变现漏斗权重调整
```

从两个独立报告里推到一条策略建议——单看哪份报告你都得不到这个结论。

### 什么情况触发跨文件推理？

- 3个以上部门在同一周报告了相关变化
- 某个数据变化超过20%（上或下）
- 平台政策变动影响多个部门
- 一个系统故障暴露出结构性问题（不只是偶然bug）

### 推理结果怎么管理？

**智慧图谱（WISDOM_GRAPH）**：一张动态的知识网。每个"发现"是一个节点，节点之间的连线代表推理出来的关系——因果关系、相关关系、支持关系、矛盾关系。

**行动管线（ACTION_PIPELINE）**：把推理结果变成可执行的任务。按紧急程度分四级，每级最多4条——强制你做减法，只做最重要的。

**"One More Thing"**：最顶层的洞察——连接了两个从来没被放在一起想的领域。一句话能说清楚，有实际可操作性，不是废话。

## 信息分级（什么数据用什么AI）

每条信息进入引擎后先评级。评级决定了用便宜AI还是贵AI处理：

| 级别 | 标签 | 例子 | 用什么AI |
|------|------|------|---------|
| 🔴 绝密 | TS | API密钥、密码 | 只用本地，不上云 |
| 🟠 机密 | C | 财务数据、策略 | 付费模型 |
| 🟡 内部 | I | 部门日报、笔记 | 免费模型 |
| 🟢 公开 | P | 发布内容 | 任意模型 |

这不只是安全——更是省钱。给内部日报用付费模型是烧钱。

## 神经网络链（AI之间的"神经系统"）

AI部门之间怎么通讯？Intelligence Brain设计了一套三层通道架构，确保断一条不影响全局：

- **直接管道（sessions_send）**：最快，AI直接互相喊话
- **文件管道（共享文件夹）**：AI把要说的写成文件，对方有空时来看
- **云端管道（在线文档）**：跨设备也能通

AI部门分布在星型拓扑里：数据中心是中央节点（不是瓶颈，是路由），所有部门通过它互连。

**设计铁律**：
- 每条通讯路径至少3条独立通道（不依赖单一手段）
- 没有单点故障——任何一条通道断了系统继续跑
- 所有通讯都有日志可查
- CEO不是消息中转站——AI部门之间自己对话

## 自动资源发现（"半个月狩猎一次"）

引擎不只是被动处理信息——它还主动寻找新资源。

每月1号和16号自动执行：
1. 搜索网上新出的免费AI平台、模型、工具
2. 跟已有的资源清单对比
3. 评估：调用次数限制、质量、国内能不能用、好不好接入
4. 发现有价值的就出报告，附接入步骤

每6小时自动检查已有免费资源有没有改规则（模型下架、限制变严、需要新认证）。

## 安全自检（红线自检）

每天23:00自动执行：

1. **密钥泄漏扫描**：检查所有文件里有没有真的API密钥（不能有）
2. **核心文件完整性**：关键文件有没有缺失或损坏
3. **密级合规检查**：绝密数据有没有不小心上了云端
4. **AI标记检查**：所有对外发布内容有没有按规定标AIGC（AI生成）
5. **越权检查**：有没有部门访问了不该访问的数据

发现问题自己处理——绝密数据泄漏自己立刻清除并检查git历史、缺文件自己补、密级违规自己挪文件。

## 常见问题 FAQ

**Q：是数据库吗？和知识库有什么不同？**
A：知识库是图书馆——存了就完了，等你去查。Intelligence Brain是消化系统——主动把信息变成洞察。它不仅告诉你"有什么"，还告诉你"这两个看似不相关的信息放在一起意味着什么"。

**Q：需要人工操作吗？**
A：布好之后不需要。管道可以定时自动跑（每天凌晨消化昨天所有产出）。唯一需要人工的是：当推理结果建议尝试新方向时，你来拍板。

**Q：信息太多会不会爆炸？**
A：不会，因为第7步（DELETE）会定时清理。处理过的原始文件24小时后删除，只保留精炼后的洞察。不会堆垃圾。

**Q：跨文件推理会不会"想太多"（过度推断）？**
A：每条推理都标注了置信度（高/中/低），来源清晰，可以追溯。而且交叉推理只在多个文件真的有关联时触发，不是硬凑。

**Q：和opc-os-core什么关系？**
A：intelligence-brain是opc-os-core里"数据中心部门"的独立版本。如果你用了opc-os-core，这一套已经在里面了。如果只想要情报引擎（不想要整套公司系统），单独用这个就行。

**Q：我能自己调整推理逻辑吗？**
A：能。推理规则和优先级都是开放的Markdown文件，你可以按自己的业务需求改。

## 运行时稳定性保障（QP 韧性体系）

本技能为 Prompt 型技能，稳定性通过以下机制保障：

### 输出一致性校验
- 同一输入多次运行时，核心结论应一致（允许表达方式差异）
- 若输出出现显著矛盾，优先回溯最后一次修改的源头
- 引用型数据以原始来源为准，不因模型采样差异改变结论

### 异常输入降级链
```
正常输入 → 完整流程
    ↓ 关键信息缺失
    追问补充（1轮）→ 仍不足？→ 标注「信息不足」+ 给出最小可行输出
    ↓ 超出能力边界
    硬边界拦截 → 明确告知「不在能力范围」+ 建议替代方案
    ↓ 模型采样不稳定
    核心结论不变 → 仅标注「表达可能存在微调」
```

### 重试与恢复指引
| 场景 | 处理 |
|------|------|
| 输出明显偏离工作流程 | 用户可追加「请严格按工作流程重新执行」触发重试 |
| 数据引用不一致 | 以首次引用来源为准，后续引用追加「已核实与首次一致」 |
| 中间步骤遗漏 | 用户可指定步骤号要求补执行 |
| 外部依赖不可用 | 标注「外部依赖暂不可用」+ 使用缓存/已知数据替代，不静默跳过 |

### 用户干预入口
- 任何步骤输出不满足预期时，直接指出问题即可触发修正
- 不需要重新描述全部需求，模型保留上下文并增量修正
- 连续 2 轮修正失败 → 建议缩小范围或拆分子任务
