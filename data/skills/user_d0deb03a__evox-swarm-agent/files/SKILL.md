# EvoX 蜂群式 Agent 协作系统

> **三原则：拆得更碎、执行隔离、文件为证。**

---

## 触发条件

当任务同时满足以下3个条件时加载本 skill：

1. **可拆解**：能拆分为2个以上独立子任务
2. **需并行**：子任务间无依赖或弱依赖，可同时执行
3. **有产出**：每个子任务有明确的文件级交付物

**不适用场景**（反向示例）：
- ❌ 单一对话问答（无需拆解）
- ❌ 纯翻译/格式转换（无独立子任务）
- ❌ 紧急任务（并行调度耗时>直接执行）
- ❌ 子任务强耦合（B必须等A完整输出才能开始）

---

## Phase 1：蜂群拆解

### 1.1 拆解方法

| 方法 | 适用场景 | 示例 |
|------|---------|------|
| **维度拆解** | 多角度分析同一对象 | 竞品分析→每个竞品一个任务 |
| **串行拆解** | 有依赖链的任务流 | 调研→分析→报告（A→B→C） |
| **混合拆解** | 部分独立+部分依赖 | 3个调研并行→结果汇总→报告 |

### 1.2 原子任务定义

每个原子任务必须包含：

```json
{
  "task_id": "A01",
  "title": "具体任务标题",
  "type": "research | analysis | generation",
  "input": "输入描述（如有依赖，标注依赖的task_id）",
  "output_file": "workspace-relative路径，如 reports/A01-竞品A分析.md",
  "depends_on": []
}
```

**规则：**
- `output_file` 必须指定，路径相对于 workspace 根目录
- `depends_on` 为空数组表示可并行执行；非空则串行等待
- 单次最多拆解 **10个** 原子任务（超出则考虑分批执行）

### 1.3 输出

将原子任务清单以JSON格式输出，确认后进入 Phase 2。

## Phase 2：并行执行

### 2.1 派发规则

1. **无依赖任务同时派发**：一次调用多个 `sessions_spawn`
2. **有依赖任务串行执行**：等待依赖任务完成后，用其输出作为输入
3. **单次最多并发 5 个子 Agent**（超出则分批）

### 2.2 子 Agent Prompt 模板

每个子 Agent 的 prompt **必须包含以下三要素**：

```
## 任务
{任务标题}

## 输入
{输入描述}

## 输出要求
1. 将完整报告写入文件：`{output_file}`
   使用 write 工具写入。文件内容必须完整、自包含。
2. 报告格式：Markdown，包含评分/分析/建议等结构化内容。
3. 验收标准：文件存在且内容≥500字。
```

### 2.3 等待机制

使用 `sessions_yield` 等待子 Agent 完成事件。**严禁轮询。**

```
sessions_yield → 等待完成事件到达 → 读取结果
```

**超时处理**：如果 `sessions_yield` 返回后仍有子 Agent 未完成：
- 检查其 `output_file` 是否已写入
- 如已写入 → 视为完成
- 如未写入 → 进入重试（见 2.4）

### 2.4 重试机制

| 条件 | 处理 | 上限 |
|------|------|------|
| 子Agent未写入output_file | 重新派发，prompt中强调"必须使用write工具写入文件" | **最多3次** |
| 子Agent写入的文件内容为空 | 重新派发，prompt中指定最低字数要求 | **最多3次** |
| 3次重试仍失败 | 降级处理：尝试从子Agent的completion event中提取内容 | — |
| 降级也无内容 | 标记该任务为"失败"，在最终报告中注明 | — |

## Phase 3：程序化汇合

### 3.1 汇合步骤

1. **逐文件读取**：遍历所有原子任务的 `output_file`，用 `read` 工具读取
2. **完整性检查**：确认每个文件存在且非空
3. **结构化组装**：按任务清单顺序拼装为最终交付物
4. **标注来源**：每个章节标注 `[来源: {task_id}]`
5. **冲突标记**：内容矛盾时保留双方观点，标注 `⚠️ 专家意见分歧`

### 3.2 最终交付

- 用户指定格式（如DOCX）→ 生成文件，提供 workspace 路径
- 用户未指定 → Markdown 文档，写入 workspace

---

## Phase 4：经验沉淀

任务完成后，将以下经验写入 `memory/YYYY-MM-DD.md`：

```
## EvoX协作经验
- 任务类型：{类型}
- 拆解方式：{维度/串行/混合}
- 子Agent数：{N}
- 成功/失败：{结果}
- output_file策略：{命名规则、是否全部成功}
- 优化建议：{下次改进点}
```

## 自检清单

**拆解阶段：**
- [ ] 任务确实需要蜂群拆解？（满足触发条件的3个条件？）
- [ ] 每个原子任务的 output_file 已指定？
- [ ] 依赖关系已标注在 depends_on 中？
- [ ] 总任务数≤10？并发数≤5？

**执行阶段：**
- [ ] 每个子Agent prompt 包含三要素（任务/输入/输出要求）？
- [ ] 使用 sessions_yield 等待（非轮询）？
- [ ] 重试次数未超过3次？

**汇合阶段：**
- [ ] 所有 output_file 已读取？
- [ ] 无"主Agent重新理解"导致的失真（直接引用文件内容）？
- [ ] 失败任务已标记？

**沉淀阶段：**
- [ ] 经验已写入 memory 文件？
