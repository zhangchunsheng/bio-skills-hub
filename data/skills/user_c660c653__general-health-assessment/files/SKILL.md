# 通用健康评估（全运动类型）

## Overview

> **定位声明：这不是一个"报告生成器"，而是一套"基于实测数据的结构化诊断流程"。**
> 它不套模板、不堆指标，而是先对用户数据做强制判定（体成分异常 / 强度倒挂 / 运动模式与动作质量 / 有氧能力结构 / 女性周期阶段 / 多源冲突），再生成带真实计算与可执行建议的成品。最终产出的是**诊断结论 + 行动项**，而非泛泛的"健康报告"。

将普通运动人群或久坐人群的**个人体测数据** + **运动/活动数据**（运动手表、App、体测设备），转化为一份带具体计算、可视化与可执行建议的专属运动健康深度评估报告（HTML）。核心价值在于用真实数据揭穿常见误区——例如"练得不少但体脂高""以为自己在轻松动、其实一直在阈值区硬撑""动作模式不当却没意识到关节风险"。

> 本技能是「骑行健康评估」的通用化变体：**去掉了踏频、码表心率、FTP 功率等骑行专属维度**，保留并复用体成分、强度倒挂、恢复、损伤防护、女性周期、饮食补给等通用逻辑；运动数据改由「运动手表 / App / 体测设备」提供，运动模式维度替代踏频。

## When to Use

- 用户说"帮我做一份健康评估""帮我分析运动数据""做一份运动健康报告"
- 用户提供体测数据（身高体重、体脂率、腰围、静息心率）求解读
- 用户提供运动手表 / App 截图（华为运动健康 / Garmin Connect / Keep / 悦跑圈 / Apple Watch 等）求分析
- 用户提供同一活动的多个数据源（如手表 App + 运动 App）希望交叉验证
- 用户想"认识自己的运动状态"或想帮朋友/客户做评估
- 用户关注减脂、塑形、精力提升、睡眠恢复、久坐改善

## 首次使用引导（新手必读）

如果你是第一次用，请先看这 3 步：

1. **准备数据**：需要两类——① 体测数据：年龄、身高、体重（核心必需），最好补充体脂率、腰围（来自体脂秤/体检）；② 运动数据：一次运动的「心率区间分布、时长、距离/步数」，去运动手表或 App 截一张图即可（华为运动健康 / Garmin Connect / Keep / 悦跑圈等）。没有数据卡也能直接用，但建议先打开 `assets/inquiry-form.html` 填一遍生成数据卡，后面断了也能续接。
2. **一句话触发**：直接说「帮我做一份健康评估」或「分析我的运动数据」就能唤起本技能，不需要懂任何专业术语。
3. **看不懂就问**：报告里的 Z2/Z4、极化模型、VO₂max 等词，第一次出现我会用大白话解释；任何看不懂的地方直接追问，我会展开讲，不会让你卡住。

> 本引导只为降低上手门槛，不替代后面的数据采集与计算流程。

## Data Validation & Error Handling

当用户数据不全、格式有问题时，**必须明确指出缺什么、错在哪**，而不是沉默跳过或自己假设值；**凡看不清的字段一律标"不确定"，严禁编造或脑补**：

| 问题类型 | 处理方式 |
|---|---|
| **核心数据缺失**（年龄/身高/体重） | 明确告诉用户"缺少 XXX，这是核心计算必需项，请补充后再继续"，暂停计算等待用户回复 |
| **心率区间分布缺失（已确认有心率设备 / B 路）** | 告诉用户"心率区间 Z1–Z5 占比是最关键的诊断依据，没有它无法判断强度倒挂。请从运动手表/App 找到分布截图发给我" |
| **无心率设备（A 路）** | 不要求心率数据，跳过心率区间分析；在报告中明确标注"本报告不含心率区间与强度倒挂诊断（无心率数据）"，其余诊断照常给出，并提示可后续用 RPE / 功率管理强度或补测静息心率后重算 |
| **单位不明**（体脂率写"25"不知是 % 还是 kg；腰围无单位） | 告诉用户"您填的 XXX 格式有疑问（可能是 % 还是 kg？/ cm 还是 m？），请确认单位" |
| **截图无法读取/打不开** | 先请用户「重新拍一张清晰的截图」（多数情况是模糊或截断）；仅当确实无法重拍，再请对方补该字段的关键数字，并标注来源——**不要求对方手抄全部数值** |
| **字段模糊 / 辨识不清**（截图能打开但某个数字看不清） | 对该字段标注"不确定"，说明具体是哪个字段无法辨识；非核心项可在报告中留空并注明，核心计算项则请用户重拍或手填，**绝不凭猜测填入** |
| **女性月经数据不完整** | 告诉用户"周期化训练需要至少：周期天数、最近一次月经第一天日期、经期天数。缺少任一项会影响建议准确性" |
| **数值明显不合理**（负数体重、身高>250cm、体脂率>60%、静息心率>120 等超出生理范围） | 主动拦截：告知"XXX 数值超出合理生理范围（如体重不应为负），请核实后重新填写"，不得带入计算或自动假设修正值 |

每次指出问题时，**同时给出正确格式示例**（如"体脂率请填百分比，如 24%"），降低用户修正门槛。

**对话中断如何恢复（强制"恢复模式"）**：本技能无平台级自动存档，但 `assets/inquiry-form.html` 生成的「数据卡 .html」即为结构化存档。当用户说"继续/恢复/接着上次/我重传数据卡"等恢复信号、并附上数据卡 .html 或粘贴数据时，**必须进入恢复模式**：

1. 直接读取已有数据卡，**严禁重复索要已填字段**，开场只说"已读取你的数据卡，我们接着上次的分析"；
2. 若用户此前已推进到某分析步骤，从断点续接；若无法判断断点，则在确认数据齐全后直接进入分析，不重走完整的询问流程；
3. 恢复后首个输出先复述关键已填数据（1–2 行），让用户确认无误，再继续。

> 关键：恢复体验的目标是"重传即续接、不重走流程"。任何让用户在恢复时重新回答一堆已答过的问题，都视为本技能的严重失误。

**减少中断的预防措施**：收集阶段即引导用户用 `inquiry-form.html` 生成并保存数据卡 .html（这是用户侧唯一可靠存档）；若对话较长、担心被截断，可按模块（体测→运动数据→分析→报告）分步进行，每个模块结束给出小结，用户凭数据卡即可无缝续接。

## FAQ

**Q：我只有手表 App 截图，没有专业设备，能用吗？**
可以。手表 App 数据（华为运动健康 / Garmin Connect / Keep 等）同样支持，只是室内模式会包含热身冷身、平均值被拉低——我会标注记录范围并修正。

**Q：我没有体脂率和腰围，还能出报告吗？**
年龄、身高、体重是核心必需项，缺少无法继续。体脂率和腰围是第二优先级，缺失时标注"该项未提供"——不影响核心诊断（强度倒挂），但体成分评估会受限。

**Q：我没有运动手表 / 测不了心率，能做吗？**
可以，走 A 路。静息心率非必需，报告直接跳过心率区间与强度倒挂诊断（因无心率数据无法判定），但体成分 / 运动模式 / 损伤防护 / 女性周期 / 饮食补给等其余诊断照常给出。强度管理改以 RPE 谈话测试（能聊天=Z2、微喘=Z3、喘不上气=Z4+）或功率区间（若有 FTP）替代，并会说明利弊：缺精确强度分区，仍安全有效，但无法量化"强度倒挂"。后续若有手表或补测静息心率，可重算心率维度。

**Q："强度倒挂"是什么意思？**
指你大比例时间卡在 Z4 阈值区（健康应 ≤5%），而 Z2 有氧区占比极低（健康应 ≈80%）。这导致"练得多却体脂高"——一直在高强度消耗糖原，而非有氧燃脂。

**Q：我没有功率计/跑步功率，能做有氧能力评估吗？**
可以。无功率设备时不输出功率六区间，改由心率区间 + 可选简易有氧测试（如 3 分钟台阶试验后心率、心率恢复 HRR）估算有氧能力，并在报告中标注"非功率实测"。

**Q：我是女性，月经数据必须提供吗？**
不强制。不提供则报告不含月经周期与训练周期化部分，其余诊断不受影响。提供后我会基于周期阶段给出更精准的训练适配建议。

**Q：多数据源数据冲突怎么办？**
我会先做交叉验证（比对时长与平均心率），标注每个数据源的记录范围，再下结论——不会简单取平均值。

**Q：这是医疗诊断吗？**
不是。这是运动健康评估，旧伤防护属于运动建议。如有身体不适，请及时就医。

**Q：报告多久能拿到？**
数据齐全的情况下当次对话即可生成。如需补充数据，会先暂停等你补完再继续。

## Common Pitfalls（常见误区与避坑）

生成报告前，主动提醒用户以下高频误区——这些"坑"会导致数据分析失真，但不属于"数据缺失"，普通提示不会覆盖：

1. **把室内热身/冷身算进"有效运动"**：会拉低平均心率与强度判定，误判强度。应标注记录范围，仅用主运动段。
2. **只看平均心率、忽略区间分布**：平均正常可能掩盖"大半时间在 Z4 硬撑"的强度倒挂。必须以区间占比为准。
3. **单次体脂秤数据当"标准"**：BIA 受饮水/进食/时段影响大，应取多次空腹均值，单次仅作参考。
4. **用"220−年龄"硬套最大心率**：个体差异极大，应以实测峰值或储备心率法（HRR）校准区间——本技能 B 路（有心率设备）心率区间已默认采用 %HRR（Karvonen），需先确认静息心率 RHR 已提供；无心率设备（A 路）则不输出心率区间，改以 RPE 谈话测试 / 功率管理强度。
5. **以为"动得越累越减肥"**：高强度占比过高反而抑制有氧燃脂（强度倒挂），减脂应拉回 Z2。
6. **动作模式不当被忽视**：跑步跨步过大、力量训练代偿、长期单一姿势，会造成关节慢性劳损——比"强度"更隐蔽，须结合运动类型与旧伤提示。
7. **月经只记"有没有"、不记周期天数**：周期化需具体天数才能按比例推算阶段，缺天数则阶段判断失效（见 references 周期章节）。

## Workflow

> **长对话预防（降低中断概率）**：若对话较长、担心被平台截断，按"体测 → 运动数据 → 分析 → 报告"分模块推进，每个模块结束给出小结；用户凭数据卡 .html 即可无缝续接，无需重走流程。

### Step 1 — 收集基础体测数据（必填核心项）

用 AskUserQuestion 或直接给清单请用户填写，按优先级：

**第一优先级（核心计算必需）：** 年龄（算最大心率/区间）、身高(cm)、体重(kg)（算 BMI）、**运动类型（决定心率区间基准，见 Step 3）**

**心率数据分支（先确认，决定 B 路 / A 路，见 Step 3）：** 在收集运动数据前，先问用户是否有运动手表 / 心率设备能测心率——
- **有心率设备（B 路）**：补「静息心率/晨脉(bpm)」——骑行/跑步用 %HRR 储备心率法**必需**；游泳/其他运动类型也建议提供（用于趋势与恢复监测）。
- **无心率设备（A 路）**：静息心率**非必需**，直接跳过心率区间分析（见 Step 3 替代方案）；其余体成分 / 运动模式 / 损伤防护 / 女性周期照常给出，并说明利弊。

**第二优先级（体脂与体型）：** 体脂率(%)、腰围(cm)、臀围(cm→腰臀比)
**第三优先级（运动与损伤）：** 运动损伤史（部位/性质/是否愈合）、运动类型（跑步/快走/健身/游泳/球类/瑜伽等）、每周频率与单次时长
**可选：** 是否有运动手表/体测设备（部分型号不支持 HRV，须先确认设备能力）、睡眠情况、饮食大致情况、目标（减脂/塑形/精力/疗愈）

**女性专属（仅当性别=女时收集，不强制、标注敏感信息）：** 月经是否规律、周期天数（正常 21–35，平均 28）、最近一次月经第一天日期、经期天数、是否有经前综合征(PMS)/痛经、是否用 App 记录（华为健康/FitrWoman/Wild.AI）。—— 用于「月经周期与训练周期化」分析（见 Step 4 #12）。询问表 assets/inquiry-form.html 已内置「月经周期（仅女性）」卡片，女性可自愿填写。

> 用户若说"不用搜"——不要翻找其文档/历史记录，直接索要数据即可。

**强制交付物（防中断）**：基础数据收集完成后，引导用户用 `assets/inquiry-form.html` 生成并**保存数据卡 .html**（点"下载数据卡"即可）。明确告知用户"请留存这份数据卡，万一对话断了，重传它我就能直接接着做，不用重新填"。这是用户侧唯一可靠存档，也是恢复模式的前提。

**批量收集（收集多位客户数据）**：若要为多位客户收集数据做健康评估，直接把技能资产中的 `assets/inquiry-form.html`（通用健康数据收集表）发给客户填写。该表纯前端、不联网、无统计/管理界面：客户填完表单（或上传运动数据截图）后点「下载数据卡（含截图）」，会生成一份自带截图的自包含 .html 文件，直接发你即可——截图已嵌在文件里，你打开就能看、能读数字；也可点「复制文本」发纯文字版（不含图）。你拿到 .html 或数据卡文本后，作为本报告技能的输入逐位生成专属评估。

### Step 2 — 收集运动数据（多数据源支持）

**截图优先**：朋友从手表/App/体脂秤直接发「运动详情」「心率区间」「身体成分」截图即可，你用 Read 读取本地图片路径（或聊天内 @image 附件）提取数字，**无需对方手抄**。也接受粘贴的文本/数字。**先识别数据源类型**：
- **运动手表/码表**（Garmin / 华为 / Apple Watch 等）：记录全程，心率区间为金标准
- **运动 App**（华为运动健康 / Keep / 悦跑圈 / Garmin Connect）：室内模式记录全 session（含热身冷身），平均值会被拉低
- **跑步机/智能设备/骑行台**（若有功率则含 FTP/TSS）：只统计"实际运动段"，反映真实强度

提取字段：
- 距离/步数、总时长、平均配速/速度
- 平均心率、最大心率
- **心率区间分布 Z1–Z5 的占比与时间（最关键）**
- 运动类型（跑步/快走/力量/游泳等）
- **若有功率数据（跑步功率计/骑行台）**：FTP(W)、TSS、体重设定（可选维度，见 Step 3.6）

若只给单次运动数据，结论须注明"基于单次样本推断"。若同一 session 有多个数据源，进入 Step 3.5 交叉验证。

> **图片源数据强制回读确认（防读图错误——数据失真的头号来源）**：当用户通过截图/图片提供数据（手表 App、体脂秤、体检报告、运动设备屏显等），**提取数字后、进入 Step 3 计算前**，必须先把从图片识别出的全部关键字段与数值以清单回读给用户核对：
> - 逐条列出「字段名 = AI 读出的数值（来源图：如图1-华为心率区间）」
> - 明确请用户确认"以上数值是否准确、有无识别错误"
> - **用户确认前，严禁进入 Step 3 计算**；用户指出错误则当场修正后重新确认
> - 用户仅回复"对的/没问题"且无具体纠错，视为确认通过；若用户说"你看着填"或长时间不确认，再次提醒而非默认带入
> - 常见误读须重点提示用户对账：数字颠倒（145↔185）、单位混淆（% 与 bpm、kg 与 g）、小数点/千分位错位、把"平均"误当"最大"
> 此环节不可跳过——图片读取存在 OCR/视觉误读风险，是整份报告数据失真的首要来源。

### Step 3 — 计算核心指标

- BMI = 体重(kg) / 身高(m)²
- 腰臀比 = 腰围 / 臀围
- 最大心率 MHR：优先用设备**实测最大值**，否则 220−年龄（注明公式误差 ±10-15bpm）
> **前提：心率区间分析仅 B 路（有心率设备、提供心率区间分布）执行。** 若用户无心率设备（A 路），跳过本段的心率五区间计算，不强行估算静息心率；改为基于 RPE 自觉强度 / 功率区间（若有）/ 运动模式与体成分给可执行建议（见下方「A 路替代方案」）。明确告知用户「因无心率数据，本报告不含心率区间与强度倒挂诊断；其余诊断照常给出」，并说明利弊（缺精确强度分区，改用 RPE 谈话测试 / 功率 / 运动模式管理，仍可安全有效）。

- **心率区间按运动类型选择百分比基准（关键，仅 B 路）**：
  - **骑行 / 跑步 → 储备心率法 %HRR（Karvonen）**：需静息心率 RHR（B 路已收集）。靶心率 = (MHR − RHR) × 区间% + RHR。
    - Z1 恢复 50–60% / Z2 有氧 60–70% / Z3 Tempo 70–80% / Z4 阈值 80–90% / Z5 无氧 90–100%（均为 HRR）
  - **游泳 → 最大心率法 %MHR，但用「泳池特定最大心率」**：泳池最大心率 = 陆上最大心率 − 10~13 bpm（水温 / 横卧体位 / 静脉回流使水中最大心率更低，不能直接套陆上最大），再按 Z1 50–60% … Z5 90–100% MHR 划分；心率在游泳中为**辅助**（配速 / 划频 / 划水质量为主）。
  - **其他（快走 / 健身 / 球类 / 瑜伽 / 未指定运动类型）→ 最大心率法 %MHR**：Z1 50–60% / Z2 60–70% / Z3 70–80% / Z4 80–90% / Z5 90–100% MHR。
  - 说明：骑行与跑步用手表默认 %HRR 更准（%MHR 对有氧区常偏差 5–10 bpm，fit 运动员低静息心率时偏差更大）；游泳因水中最大心率偏低须用泳池特定最大；其余通用场景用 %MHR。

- **A 路替代方案（无心率设备 / 无心率区间分布）：** 不输出心率五区间，无法判定「强度倒挂」，须在报告注明。强度管理改用：
  - **RPE 谈话测试**：能完整聊天 = Z2 有氧区；微喘但能短句 = Z3；喘不上气 = Z4+。减脂以「能聊天不喘」的 Z2 为主。
  - **功率区间**（若有 FTP / 骑行台）：以功率六区间控强度，比心率更准。
  - **运动模式 / 体成分** 仍可输出动作质量、损伤防护与体成分评估，其余诊断不受缺心率影响。
- 脂肪量 = 体重×体脂率；瘦体重 = 体重−脂肪量
- 标准体重参考 = BMI 22 × 身高(m)²

### Step 3.5 — 多源数据交叉验证（同一 session 有多数据源时）

**关键陷阱**：手表 App 的全 session 平均值（含热身冷身）会比实际运动段平均值低 15-25 bpm——这是同一 session 的不同切片，**不是矛盾**。实测案例：华为 App 记录 40 分钟 / 平均 HR 125（含热身冷身），跑步机/骑行台记录 22.5 分钟 / 平均 HR 146（纯运动段）；后者才是真实强度。

**验证动作**：
1. 比对时长：运动段时长 < 手表 App 时长 → 差值即热身冷身
2. 比对平均心率：运动段 HR ≈ 户外/设备 HR → 确认"实际运动强度一致"
3. 报告须明确标注每个数据源的**记录范围**，避免被低温平均值误导

### Step 3.6 — 有氧能力基线计算（可选·若有功率/FTP 或跑步功率数据）

若用户提供 FTP（功能性阈值功率，W）或跑步功率/骑行台导出功率：
- **功率六区间（Coggan 模型，基于 FTP%）**：Z1<55% / Z2 55–75% / Z3 75–90% / Z4 90–105% / Z5 105–120% / Z6>120%
- **相对功率 W/kg** = FTP / 体重(kg)；分级：休闲<1.5 / 爱好者 2.0–2.5 / 竞技>3.0（仅当提供功率时输出）
- **TSS**：正常 Z2 运动 22 分钟 ≈8-12；远高于此 → 佐证运动段处 Z4 高强度
- 功率比心率更准（不受温度/情绪/咖啡因影响），有功率时以功率为主、心率为辅

**无功率设备时的替代估算**：用 3 分钟台阶试验后心率、心率恢复(HRR)、或基于运动手表的有氧训练负荷估算有氧能力，并在报告中标注"非功率实测，置信度中等"。

### Step 4 — 深度分析（详见 references/analysis-framework.md）

> **分析前强制判定清单（降低 AI 自由发挥、保证结论与数据一致）**：在写任何一段 prose 结论前，先逐项勾选并给出判定依据（引用原始字段）。没有数据支撑的判定一律标"无法判定"或"数据不足"，不允许直接写 prose。
>
> | 判定项 | 判定规则 | 必填依据 |
> |---|---|---|
> | 体成分异常 | BMI≥23.9 或体脂/腰围/腰臀比任一超标 | 身高、体重、体脂率、腰围、臀围 |
> | 强度倒挂 | Z4 占比>5% 且 Z2 占比<70%（严格） | 心率区间分布 Z1–Z5 |
> | 运动模式/动作质量待优化 | 运动类型单一或动作模式存在代偿/疼痛风险（结合旧伤） | 运动类型、旧伤史、主观疼痛 |
> | 有氧能力结构（可选） | 提供 FTP 时，Z4+Z5+Z6 占比过高 或 W/kg 分级与健康目标不符 | FTP、体重、功率区间分布 |
> | 女性周期阶段 | 最近一次月经第一天 + 周期天数 → 推算当前阶段 | 月经数据 |
> | 多源冲突 | 同一 session 不同源平均心率/时长差异>10% | 多源数据 |
>
> 每项判定后必须写明：**判定结果 + 依据数据 + 是否影响后续建议**。只有清单完成后，才进入下面的 prose 深度分析。

重点诊断，按价值排序：
1. **体成分评估**：BMI/体脂/腰围/腰臀比对标健康标准，判定肥胖/中心性肥胖/正常。
2. **运动能力 vs 体成分矛盾**：运动量（时长/频率/距离）是否达标 vs 体成分是否健康。常见"运动型体成分不佳"——练得多但体脂高。
3. **心率区间分布诊断（核心反直觉洞察）**：检查"强度倒挂"——Z4 占比过高（健康应≤5%）、Z2 过少（健康应≈80%）。这是"练得不少却体脂高"的常见根因。
4. **运动模式与动作质量分析**：结合运动类型（跑步步频/跑姿、力量训练动作模式、久坐人群活动模式）与旧伤，提示代偿与关节劳损风险，给出动作优化建议。
5. **最大心率校准**：设备实测值显著低于公式值时，重算所有区间。
6. **损伤防护**：结合运动类型与旧伤部位，给护具/动作模式/负荷管理建议。
7. **恢复监测**：晨脉、HRV（部分手表/型号不支持直读，须先确认设备能力；不支持时改用静息心率趋势、运动后心率恢复 HRR、睡眠与主观疲劳替代）、睡眠。
8. **有氧能力维度诊断**（可选·若有 FTP）：给出功率六区间表 + W/kg 分级 + 基于功率的"慢运动"目标（Z2 区间具体功率值），明确"有功率以功率控强度、无功率以心率"。
9. **多源数据冲突识别**（若多数据源）：先做 Step 3.5 交叉验证再下结论；若发现某数据源平均值被热身冷身拉低，须修正先前误判。
10. **饮食结构与训练补给分析**（若有饮食记录）：用三大营养素速览表判定蛋白/碳水/脂肪是否达标；重点指出运动人群高频的"蛋白吃够了、但碳水严重不足且脂肪偏油炸"这一结构性缺口；按 ACSM/AND/DC 立场给出碳水目标（训练日 4–7 g/kg、非训练日 130–200g）；若有训练计划，生成练前/练中/练后补给方案；给出三条日常调整（碳水移入训练窗口 / 油炸换蒸烤 / 保留优质餐）。计算标准见 references/analysis-framework.md 第十一节。
11. **维生素矿物质补充评估**（若有补充剂评估需求）：基于 IOC 运动员补充剂共识、GSSI 女性运动员专文、中国 DRIs 2023，按"风险画像"给优先级判断——维生素 D、铁、钙、镁/B族/复合维/蛋白粉（不盲补）。强调"先做营养评估+血液标志物再补，禁止盲目补充"。标准见 references/analysis-framework.md 第十二节。
12. **女性月经周期与训练周期化**（仅性别=女且已收集月经数据时启用）：①以"最近一次月经第一天=Day 1"推算今日所处周期阶段；②给出四阶段训练适配——黄金窗口排 VO₂max 间歇与力量加重，PMS 降量；③处理周期长度差异；④经后疲劳科学解释；⑤联动铁评估。强调私密性与"非医疗诊断"。标准见 references/analysis-framework.md 第十三节。

### Step 5 — 生成 HTML 报告

基于 assets/report-template.html 填充，输出到工作区并 present_files。报告须包含：

1. **核心指标卡**（BMI / 体脂 / 腰臀比 / 腰围 / 静息心率 / 最大心率）。A 路（无心率设备）不列出静息心率 / 心率区间相关卡，并在卡旁标注"无心率数据，心率维度未评估"。
2. **反直觉洞察卡（Aha 卡）**：紧接核心指标卡之后，必须填充 report-template.html 中的 `aha-*` 占位符。选本轮数据中最反直觉的一项（优先顺序：强度倒挂 > 运动型体成分不佳 > 运动模式不当 > 有氧能力结构问题），用"你以为 / 实际上 / 为什么"三段式 + 可视化对比条呈现，制造一眼记住的 Aha 时刻。禁止把洞察平铺直叙地塞进综合诊断。
3. **体成分评估**（BMI 定位可视化条）。
4. **饮食结构与训练补给分析**（有饮食数据时，含三大营养素速览 + 训练补给方案）。
5. **维生素矿物质补充评估**（有补充剂评估需求时，含按优先级判断表 + 验血建议）。
6. **运动数据深度解读**（B 路：心率区间分布条 + 运动模式/动作质量 + MHR 校准前后对比；A 路无心率数据，省略心率区间条，仅给运动模式/动作质量与 RPE / 功率强度管理建议）。
7. **综合诊断**：用 Step 4 判定清单支撑核心结论。
8. **修正后周训练计划**：必须用 if-then 条件分支呈现（见 Key Principles「if-then 条件建议」）。
9. **损伤防护升级**、**HRV 说明**（若设备支持，否则给替代恢复监测方案）、**月经周期与训练周期化**（仅女性且提供月经数据时：含周期阶段时间线色块日历 + 四阶段训练适配 + 25 天短周期提醒 + 铁联动）、总结与行动项、参考文献。

结构标准见 references/report-standards.md。

> **数据缺失时的表达升级**：若用户缺少某字段，先明确标注"未提供"，再基于已有数据给出"最可能推断 + 置信度/不确定性说明"（例如"未提供体脂率，按体重与腰围估算体脂约 32%，置信度中等，建议体脂秤实测后修正"）。严禁编造、估算或脑补替代，但允许在透明标注不确定性的前提下给出方向性推断，以提升分析深度。

### Step 6 — 交付前自检（保证结论与输入数据一致）

生成最终 HTML 报告前，必须执行以下自检清单；任何一项为"否"时，先修正再交付：

1. **结论-数据一致性**：报告中的每个诊断结论（强度倒挂、运动模式待优化、体成分异常、周期阶段等）都能在原始数据或 Step 4 判定清单中找到依据。→ 是 / 否（否→删除或改写）
2. **数字可追溯**：报告中每个数字（BMI、Z4 占比、FTP、W/kg、TSS、周期阶段等）都能溯源到用户输入或计算过程。→ 是 / 否（否→标"不确定"）
3. **反直觉洞察卡已填充**：报告开头已按"你以为 / 实际上 / 为什么"呈现最突出的反直觉洞察，且未与综合诊断简单重复。→ 是 / 否
4. **建议已 if-then 分支化**：训练计划与饮食/补给建议已按用户场景（每周 2 次 / 4–5 次、有旧伤、女性经期等）给出条件分支，而非一套通用方案。→ 是 / 否
5. **术语已解释**：首次出现的专业术语（Z2/Z4、极化模型、VO₂max 等）已附大白话说明。→ 是 / 否
6. **边界声明已包含**：报告页脚/结尾已标注"非医疗诊断，旧伤防护为运动建议，不适请就医"。→ 是 / 否
7. **女性数据隐私**：若含月经周期分析，已强调私密性与"非医疗诊断"。→ 是 / 否 / 不适用
8. **建议可执行**：每条建议都对应一个可量化/可执行动作（如"Z2 心率区间 120–135 bpm 运动 45 分钟"），而非空泛口号。→ 是 / 否
9. **图片数据已回读确认**：凡来自截图/图片的数字，均已以清单回读用户并经确认（或用户明确声明"数值无误"）；**未经确认的图像读数未进入任何计算或报告**。→ 是 / 否（否→退回 Step 2 补回读）

> 本自检即评测反馈中提到的"自动校验"机制：技能无法运行外部校验脚本，但通过强制清单把一致性检查嵌入交付流程，最大限度降低 AI 理解偏差导致的结论失准。

## Key Principles

- **用真实数据说话，拒绝空框架**。必须带入其具体数值与计算。
- **新手友好 · 术语即时解释**。面向纯新手时主动给第一步引导（数据去哪找、怎么触发）；专业术语（Z2/Z4、极化模型、VO₂max 等）首次出现必须附一句大白话解释，不假设用户已懂。
- **数据可追溯 · 写前必回读 · 看不清标"不确定" · 缺数据给推断+置信度（强制流程）**。输出中任何数字都必须能溯源到用户提供的原始记录；撰写每段结论前必须回读原始数据确认，不得凭记忆或推断填充；截图或字段模糊看不清时，明确标注"不确定"并说明缺失项，**绝不允许编造、估算或脑补替代**；若用户缺少某字段但分析又需要它，则在透明标注"未提供"的前提下，给出"最可能推断 + 置信度/不确定性说明"，以提升分析深度而不越界。
- **图片源数据强制二次确认（防读图错误）**。凡从截图/图片读取的数字（手表 App、体脂秤、体检报告、运动设备屏显等），在带入 BMI/心率区间/功率/FTP 等任何计算前，必须先把「字段 = AI 读值（来源图）」清单回读用户核对，确认无误方可进入分析；不得擅自将未确认的图片读数直接用于计算。图片误读（145→185、% 与 bpm 混淆、平均当最大等）是数据失真的头号来源，此环节不可跳过。
- **交付前强制自检（结论-数据一致性）**。生成最终报告前必须跑一遍自检清单：每个结论都有数据依据、每个数字都可溯源、每条建议都可执行。
- **洞察张力 · 反直觉点必须 Aha 化**。核心洞察（强度倒挂、运动型体成分不佳、运动模式不当等）禁止平铺直叙，必须用"你以为 / 实际上 / 为什么"的认知反差结构 + 可视化对比呈现，制造让用户一眼记住的 Aha 时刻。
- **if-then 条件建议**。训练计划、饮食/补给、损伤防护等建议必须按用户实际场景给出条件分支（如"每周只能运动 2 次 → ... / 每周能运动 4–5 次 → ... / 有旧伤 → ... / 女性处于经期 → ..."），避免一套通用方案。
- **诊断 > 罗列**。核心洞察是"强度倒挂""运动模式不当""运动型体成分不佳"等反直觉发现，不是堆指标。
- **不医疗诊断**。旧伤防护为运动建议，非医疗诊断；不适请就医。
- **保护隐私**。数据仅用于本次报告，不主动外传。
- **交付深度可按对话要求裁剪**。同样的输入，可根据对话中指定的范围只输出对应模块（如仅核心结论、或完整报告、或含进阶维度），而非固定全量输出。
