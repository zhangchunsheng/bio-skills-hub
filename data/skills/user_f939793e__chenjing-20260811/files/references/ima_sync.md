# Sync Output to IMA (同步到 IMA 笔记 / 知识库)

This reference explains how the tutor skill pushes its generated deliverables — the bedside
English learning notes and/or the full teaching dossier assembled per `references/ima_output.md`
— into the user's IMA. IMA content is user privacy — only push when the user wants it saved,
and never expose note body in a group-chat context.

Two destinations are supported:
- **IMA Notes (个人笔记):** the working, verified path — create a new note via `import_doc` with
  the Markdown dossier as content. Best for learning notes and quick capture.
- **IMA Knowledge Base (知识库):** for durable, shareable teaching material. Use the `ima-skill`
  knowledge-base module (`create_media` → upload → `add_knowledge`, or attach an existing note
  via `add_knowledge` with `media_type=11`). Requires the user to specify a target knowledge base.
  If unsure, default to Notes and offer knowledge-base as an option.

## Preconditions

1. The `ima-skill` package is installed (provides the `ima_api.cjs` helper).
2. IMA OpenAPI credentials are configured (env `IMA_OPENAPI_CLIENTID` / `IMA_OPENAPI_APIKEY`,
   or files at `~/.config/ima/client_id` and `~/.config/ima/api_key`).
3. The user's IMA is reachable.

If any precondition fails, **skip the sync, deliver the notes locally**, and tell the user
exactly what is missing (e.g., "IMA 未连接 / 缺少凭证，笔记仅生成本地，未同步").

## Step A — Check credentials

```bash
test -f ~/.config/ima/client_id && test -f ~/.config/ima/api_key && echo "IMA_OK" || echo "IMA_NO_CREDS"
```

If `IMA_NO_CREDS`, inform the user how to set up at https://ima.qq.com/agent-interface
and stop the sync (do not fabricate).

## Step B — Locate the helper

```bash
SKILL_DIR="$(ls -d ~/.workbuddy/skills/ima-skill 2>/dev/null)"
API_HELPER="$SKILL_DIR/ima_api.cjs"
test -f "$API_HELPER" && echo "HELPER_OK" || echo "HELPER_MISSING"
```

If `HELPER_MISSING`, the `ima-skill` package is not installed — fall back to delivering
the notes locally and suggest installing `ima-skill`.

## Step C — Build the note content (Markdown)

The note content is the learning-notes Markdown produced by the skill (see
`assets/learning_notes_template.md`). Rules before sending:

- **First line must be a single `# Title`** — IMA derives the note title from it. Use a
  descriptive title such as `# 医学英语查房笔记｜<Disease> (<Specialty>)`.
- **UTF-8:** content is generated by the agent in UTF-8, but still validate; non-UTF-8
  causes irreversible garbled text in IMA. Sanitize any illegal bytes before sending.
- **No local images:** `import_doc` supports Markdown only, not local image paths
  (`file:///...`, `/Users/...`, `C:\...`). Strip such references and tell the user.
- Keep total size reasonable; if it exceeds IMA's limit (error `100009`), split into
  multiple `append_doc` calls.

## Step D — Create the note (import_doc)

Write the markdown to a temp file, then call:

```bash
NOTE_MD="/tmp/teaching_rounds_note.md"   # the generated learning notes
API_PATH="openapi/note/v1/import_doc"
PAYLOAD=$(printf '{"content_format":1,"content":%s}' "$(python3 -c "import json,sys; print(json.dumps(open('$NOTE_MD',encoding='utf-8').read()))")")

node "$API_HELPER" "$API_PATH" "$PAYLOAD" 2>/tmp/ima_err
```

- On success, stdout contains `note_id` — report it to the user ("已同步到 IMA 笔记：<note_id>").
- On failure, read `/tmp/ima_err`:
  - `-100` / `20004`: auth/key error → tell user to check IMA credentials.
  - `100009`: too large → split content and use `append_doc`.
  - `100005`: no permission → confirm it is the user's own notes.

Optional: to file under a specific notebook, add `"folder_id":"<folder_id>"` to the payload
(after listing notebooks via `openapi/note/v1/list_notebook`, first `cursor:"0"`).

## Privacy

- In a group/team chat context, show only the note title and a short summary — **never** the
  note body.
- Treat notes as the user's private data; do not read or modify their existing notes unless
  the sync explicitly creates a new one.
