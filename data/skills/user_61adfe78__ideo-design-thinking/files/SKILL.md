# IDEO 设计思维诊断与行动

## 目标

把模糊创新问题转化为可验证假设与最低成本行动。把设计思维作为降低不确定性的学习系统，而非固定五步法、创意表演或成功保证。

## 激活后立即执行

1. 盘点用户已给出的目标人群、情境、行为证据、现有方案、约束、指标、风险与未知，不重复询问。
2. 判断答案是否已经确定。若属于法规执行、成熟工艺复制、紧急处置、精确复现或纯生产交付，停止使用设计思维主流程并转对应专业方法。
3. 识别一个主症状和必要次症状，从下表选择最小充分组合，通常为 1–4 项能力。
4. 仅在答案会改变方法选择、实验设计或高风险边界时提问，最多提出 3 个高信息增益问题；可先形成工作版本就先做。
5. 对会改变路线、投入或风险的关键建议，写明“假设｜证据｜证伪点｜下一步”。
6. 给出继续、修改或回跳、升级专项验证、停止投入的条件。
7. 首轮至少交付一项可立即使用的产物，不得只介绍方法、展示路由或连续提问。

## 症状路由

| 症状 | 主能力 | 常见搭配 |
|---|---|---|
| 愿景模糊、功能清单或唯一解法已锁定 | 01 可检验简报 | 03、02、06 |
| 只凭用户喜欢、技术能做或商业可行之一推进 | 02 三约束动态整合 | 06、01 |
| 用户说喜欢却不用，现场出现绕过、遗漏或放弃 | 03 行为证据推导需求 | 09、07、04 |
| 主流访谈同质，行业惯例遮蔽机制 | 04 极端用户与类比 | 03、06 |
| 资料堆积无洞察，选项过少或过多 | 05 双循环 | 01、02、06 |
| 团队停留在文字争论，准备昂贵开发 | 06 情境原型 | 02、05、07 |
| 单点正常但端到端体验失败 | 07 旅程与蓝图 | 03、06、08 |
| 地方知识或一线实施决定结果 | 08 共创与质量门 | 06、10 |
| 认同目标却不持续行动 | 09 行为嫁接与反馈 | 03、07、06 |
| 工作坊有效但回岗失效，试点难扩散 | 10 组织承载嵌入 | 08、02 |

不得机械运行十项能力。症状超过四类时，按安全风险、决策影响和当前证据缺口排序，只保留本轮最小充分组合，并列出暂缓能力。

## 十种能力摘要

1. **可检验简报**：写清“帮助谁在什么情境中发生什么可观察改变”，分开硬约束、软约束和假设，设置期限、成功标尺与重写条件。
2. **三约束动态整合**：分别审查需求性、可行性与延续性的假设和证据；任一关键维缺证据，不进入规模化。
3. **行为证据推导需求**：按“行为或遗漏→局部阻碍→需要→机会假设→复验”推理；自述只作补充，轶事不直接外推。
4. **极端用户与类比**：沿关键维度取两端样本，提取结构机制而非复制表象，再回主流情境验证。
5. **发散/汇聚与分析/综合双循环**：区分增加选项、减少选项、拆解事实、构成意义；保留反常证据与淘汰理由。
6. **恰好足够的情境原型**：每轮只回答一个关键问题，选择最低成本媒介；得到下一条有决策价值的反馈即停止打磨。
7. **旅程与蓝图**：按用户真实时间边界定位关键时刻，并连接前台、后台、成本、容量和责任主体。
8. **共创与质量门**：让受影响者和实施者获得实质影响，同时保留安全、可靠性、可用性、效果、法律和伦理责任门槛。
9. **行为嫁接与反馈**：形成“已有触发→最小新动作→低摩擦→即时反馈→重复与恢复”的闭环，以真实行为判断。
10. **组织承载嵌入**：连接真实项目、业务所有权、内部教练、领导、预算、激励、回岗、扩散与结果测量。

执行任何能力前，读取 [references/methodology.md](references/methodology.md) 中对应执行卡，保留触发、输入、关键顺序、输出与停止条件。

## 证据协议

区分以下证据等级，只标注会改变决策的关键陈述：

- **B｜书中证据**：书中案例、动作链或结果报告；不等于严格因果证明。
- **P｜当前项目事实**：用户提供、可观察、可测量或可核验的项目材料；注明来源与时间范围。
- **I｜专家推断**：由 B 与 P 推演出的假设、类比或建议；必须附证伪点。
- **U｜未知**：缺少且可能改变决策的信息；说明最低成本补证方式。

不得把 B 当作当前项目事实，不得把 P 自动解释为因果，不得把 I 写成结论。需要案例、反例、证据强弱或“不可推出结论”时，读取 [references/cases-and-failures.md](references/cases-and-failures.md)。

## 输出模式

### 轻量模式

用于风险低、信息集中且能在短答中闭环的任务，可包含一项能力或两项紧密相邻能力。输出：

- 暂定判断
- 关键依据
- 可立即使用的产物或下一步
- 停止条件
- 仅在必要时附 1–2 个会改变路线的问题

### 完整模式

用于证据冲突、规模化、多方协作或高风险边界。按需裁剪：

```markdown
## 决策摘要
- 当前症状：
- 选用能力及理由：
- 暂定方向：

## 已知与未知
| 内容 | B/P/I/U | 把握度 | 对决策的影响 |

## 建议与证据账本
| 建议 | 假设 | 当前证据 | 证伪点 | 下一步 |

## 最小行动计划
| 动作 | 负责人 | 成本或时限 | 产物 |

## 转向与停止条件
- 继续：
- 修改或回跳：
- 升级专项验证：
- 停止：
```

不得为填满模板补造内容。

## 引用与边界

- 涉及术语歧义、伦理、权力、商业、规模化、文化、平台、AI 或 2009 年语境时，读取 [references/glossary-and-boundaries.md](references/glossary-and-boundaries.md)。
- 把定性观察、极端用户和类比用于发现机制，不用于估计市场比例、发生率、风险率或因果效应。
- 把人本与伦理正当分开；检查未直接使用但受影响的人、知情参与、退出权、隐私、操控、歧视、无障碍、长期伤害与生态代价。
- 不得用低保真原型降低医疗、工程、安全、隐私、法律或伦理验证门槛。
- 共创不得转嫁专业责任；参与人数、投票、故事感染力和工作坊次数均不是质量证据。
- 规模化须重新验证容量、文化、基础设施、网络效应、外部性、维护与责任闭环。
- 面向平台、数据与 AI 议题时，补查数据权力、隐私、算法中介、自动化决策和高仿真输出造成的完成错觉。
- 不模仿或冒充蒂姆·布朗，不声称代表 IDEO，不承诺设计思维必然成功。

## 高风险固定格式

涉及工程安全、信息安全、财务、法律、隐私、临床、无障碍、统计因果或高风险伦理判断时，固定写明：

1. 设计思维可处理范围
2. 禁止执行事项
3. 需要移交的专项专家或验证
4. 恢复探索所需的前置证据

提示风险后，不继续给出危险现场试验步骤。

## 防漂移自检

- [ ] 是否复用了用户已有信息，且问题不超过 3 个？
- [ ] 是否只选择 1–4 项匹配能力，并说明相邻能力分工？
- [ ] 是否能先做就先做，而不是等待完美信息？
- [ ] 关键建议是否包含假设、证据、证伪点与下一步？
- [ ] 是否区分 B、P、I、U？
- [ ] 是否交付了可立即使用的产物？
- [ ] 是否给出继续、转向、升级或停止条件？
- [ ] 是否补上伦理、权力、商业、规模与专项验证边界？
- [ ] 是否避免人物模仿、权威代言和成功保证？
