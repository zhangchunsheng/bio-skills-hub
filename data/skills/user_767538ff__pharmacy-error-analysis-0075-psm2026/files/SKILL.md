# 西药房差错分析技能

## 概述

本技能为西药房差错事件提供系统化根因分析能力。输入差错事件描述后，综合运用瑞士奶酪模型、5Why、鱼骨图（5M1E）等多种方法，定位差错发生的环节、追溯根本原因、生成可落地的改进方案，并输出符合药学期刊三线表规范的结构化 Word 报告。

分析遵循《用药错误管理指导原则》"非惩罚性、聚焦系统"原则——不追责个人，重在识别系统性防线薄弱点。

## 触发条件

当用户出现以下意图时触发本技能：
- 描述一起西药房差错事件（处方审核、调剂、核发、药品管理环节），询问"为什么会发生/怎么改进/如何避免"
- 提供差错经过、近差事件，要求做根因分析、RCA、原因分析
- 要求生成差错分析报告、整改方案、质量改进报告

## 工作流程

### 第一步：差错事件信息采集与补全

用户输入差错事件后，先判断信息是否充分。一份可分析的差错事件至少需要以下要素（缺失时主动追问，避免臆测）：

- **发生时间与地点**（如"门诊西药房 3 号窗口，8 月 6 日上午"）
- **差错类型**（如调剂差错、发药对象差错、效期差错；若不明，对照 `references/差错分类.md` 引导用户归类）
- **事件经过**（从处方传入到差错发现的全过程，含时间节点）
- **涉及药品**（处方药品 vs 实际发出药品，含规格剂型）
- **危害等级**（A～I 级；若不明，参照 `references/差错分类.md` 开头危害等级定义协助判定）
- **发现方式**（患者反馈、自查、系统拦截等）

若用户已提供结构化信息，直接进入第二步；若仅口语描述，提取已知要素并对缺失关键项（尤其涉及药品、发生经过）追问 1～2 轮，不可缺省关键事实。

### 第二步：差错类型界定与危害分级

1. 对照 `references/差错分类.md`，明确差错所属**环节**（处方审核/调剂/核发/药品管理）与**具体类型**（如"调剂环节-药品品种差错"）
2. 据危害等级定义判定等级（A～I）
3. E 级及以上差错须启动正式根本原因分析（RCA）；高警示药品、麻精药品相关差错无论等级均按重大事件处理

### 第三步：根因分析（综合多方法）

综合运用以下方法，输出多角度分析结论：

#### 3.1 事件经过还原（时间线）
按时间节点还原事件全过程，标注每个环节的执行情况，识别"防线首次失效点"。

#### 3.2 瑞士奶酪模型——防线失效分析
对照西药房四道防线逐层评估状态：

| 防线层级 | 评估问题 |
|---------|---------|
| 处方审核防线 | 处方本身是否合理？审核是否到位？是否拦截？ |
| 调剂防线 | 取药是否正确？是否使用核对手段？货位/包装是否合理？ |
| 核对防线 | 是否执行双人核对？核对是否逐项？是否流于形式？ |
| 用药交代防线 | 是否向患者交代药品信息？患者能否即时识别异常？ |

每道防线标注状态（有效/部分失效/失效）并说明分析依据。多重防线同时失效是系统性问题的强信号。

#### 3.3 5Why——深度追溯
从直接行为出发连续追问"为什么"，直至触及系统原因（制度缺失、信息化不足、流程设计缺陷）。通常 3～5 层即可到达根本原因，避免停留在"人员疏忽"层面。

#### 3.4 鱼骨图——要因归集（5M1E）
按人、机、料、法、环、测六大维度归集所有可能要因，确保不遗漏系统性因素。参考 `references/改进措施库.md` 各维度常见因素。

#### 3.5 原因界定
区分三层原因：
- **直接原因**：导致差错发生的直接行为
- **潜在原因**：使差错有机会发生的条件
- **根本原因（系统原因）**：使防线系统性失效的深层因素，是整改的核心靶点

### 第四步：改进建议生成

1. 据根因分析结论，识别差错涉及哪些维度（通常多维度叠加）
2. 从 `references/改进措施库.md` 选取对应措施，优先"高预期效果 + 低落地难度"快速落地
3. 对照 `references/法规制度.md` 核查措施合规性，并在报告中引用依据条款
4. 每条措施明确：维度、措施内容、落地难度、责任人、完成时限
5. 高警示药品、麻精药品相关改进须满足强制规范要求

### 第五步：结论与跟进计划

- 结论须点明根本原因与整改核心方向，强调"系统改进而非个人追责"
- 跟进计划列出可追踪的整改事项与时限
- 建议整改后追踪 3 个月评估同类差错是否下降（闭环验证）

### 第六步：输出报告

将分析结果整理为结构化 JSON（结构参照 `assets/report_input_template.json`），调用脚本生成 Word 报告：

```bash
# 在隔离 venv 中运行（python-docx 已预装路径见下）
python scripts/generate_report.py --input <分析结果.json> --output <报告.docx>
```

执行环境要求：
- Python 解释器：`C:\Users\79154\.workbuddy\binaries\python\envs\default\Scripts\python.exe`
- 依赖 python-docx（已预装于上述 venv）

若用户仅需对话式分析（不导出 Word），则在回复中以 Markdown 表格呈现分析结果，跳过脚本调用。

## 报告结构

生成的 Word 报告包含以下部分，全部采用三线表（无竖线，仅顶线/表头下线/底线），中文字体 Microsoft YaHei：

1. **标题与元信息**（报告日期、编制人、科室）
2. **一、差错事件概述**（事件编号、时间、地点、类型、等级、经过、涉及药品人员）
3. **二、根因分析**
   - 2.1 事件经过还原（时间线）
   - 2.2 瑞士奶酪模型——防线失效分析表
   - 2.3 5Why——深度追溯表
   - 2.4 鱼骨图——要因归集表（5M1E）
   - 2.5 原因界定表（直接/潜在/根本原因）
4. **三、改进建议**（5M1E 维度措施表 + 法规依据列表）
5. **四、结论与跟进计划**（结论 + 跟进事项表）
6. **页脚**（法规依据声明 + 内部使用提示）

## 参考资源

本技能内置三份参考库，分析时按需加载：

- **`references/差错分类.md`**——西药房差错分类参考库（处方审核/调剂/核发/药品管理四环节，含危害等级 A～I 定义）。界定差错类型与等级时加载。
- **`references/改进措施库.md`**——5M1E 六大维度改进措施知识库（含落地难度与预期效果）。生成改进建议时加载。
- **`references/法规制度.md`**——药学法规制度条款摘录（《医疗机构药事管理规定》《处方管理办法》《医疗机构药学服务规范》《用药错误管理指导原则》《高警示药品管理指导原则》等）。核查措施合规性与报告引用时加载。

## 使用注意

- 分析须基于事实，缺失关键信息时主动追问，禁止臆测编造事件细节
- 严守"非惩罚性"原则，聚焦系统原因而非个人追责
- 危害等级判定直接影响分析深度，E 级及以上须启动正式 RCA
- 高警示药品、麻精药品差错无论等级均按重大事件，须核查专区存放、警示标识、双人核对
- 改进建议须可落地、可追踪，每条明确责任人与时限
- 法规条款以现行有效版本为准，引用时标注具体条款编号
- 报告仅供内部质量改进使用，涉及法律责任提示须在结论中明示
