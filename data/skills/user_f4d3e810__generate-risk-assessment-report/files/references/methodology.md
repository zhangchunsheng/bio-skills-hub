# 风险评估方法

## 1. 核心概念

- **固有风险**：不考虑现有控制时的风险。
- **控制**：改变风险可能性或影响的措施。
- **剩余风险**：考虑已证实有效的控制后的风险。
- **风险偏好**：组织愿意主动承担的风险类型和水平。
- **风险容忍度**：特定目标或指标可接受的偏离范围。
- **风险容量**：组织客观上能够承受的最大风险。
- **KRI**：用于预警风险暴露变化的关键风险指标。

不要混用偏好、容忍度和容量。报告撰写者不能代替有权机构批准风险接受。

## 2. 风险陈述

标准格式：

> 因【原因/脆弱性】，在【条件】下可能发生【风险事件】，导致【一个或多个目标影响】。

示例：

> 因关键原材料由单一境外供应商供货且无合格替代源，在地缘限制或物流中断时可能发生断供，导致生产停线、延期交付和违约赔偿。

不良写法：

- “供应链风险较高”：没有原因、事件和影响。
- “库存不足”：可能是现状或原因，不是完整风险。
- “加强供应商管理”：是措施，不是风险。

## 3. 5×5 示例矩阵

组织没有既定标准时，可用于草案或示范排序，但必须标注“分析假设”，不得据此作正式风险接受决定。正式决策前应由有权主体确认口径。

### 可能性

| 等级 | 定性描述 |
|---:|---|
| 1 | 罕见：在评估期内仅在极端条件下可能发生 |
| 2 | 较低：有可能但缺少近期先例 |
| 3 | 可能：存在合理发生路径或行业先例 |
| 4 | 较高：已出现预警、未遂或重复事件 |
| 5 | 几乎确定：正在发生或短期内高度可能发生 |

不要擅自给出年度百分比。只有在有历史频率、模型或权威基准时才量化概率。

### 影响

按对象选择财务、运营、合规、人员安全、环境、数据、客户和声誉等维度。默认取最严重维度，避免平均值稀释致命影响。

| 等级 | 通用描述 |
|---:|---|
| 1 | 轻微：局部、短期、可在常规权限内恢复 |
| 2 | 较小：有限中断或损失，需要部门级处置 |
| 3 | 中等：影响关键目标，需要跨部门处置 |
| 4 | 重大：显著偏离目标，需要高管介入或监管报告 |
| 5 | 灾难性：人身伤亡、重大违法、业务生存或不可逆影响 |

财务金额阈值、停机时间、人员伤害和监管后果必须由组织/项目口径定义，不能套用通用金额。

### 分级

示例：分数 = 可能性 × 最大影响等级。

| 分数 | 示例等级 |
|---:|---|
| 1—4 | 低 |
| 5—9 | 中 |
| 10—16 | 高 |
| 17—25 | 极高 |

低概率高影响、红线、法律禁止和重大伦理/安全事项可覆盖分数。矩阵是序数型排序工具：

- 不把分数解释为概率或金额；
- 不将多个风险分数相加或平均；
- 不用分数比较无共同标准的不同主体；
- 不凭一分差异制造虚假精确性。

战略、财务、安全、网络等跨领域风险只有在使用同一批准矩阵、相同时间跨度和一致影响口径时才能直接排序；否则应分领域评价。

总体风险判断不生成简单综合分。依次考虑：

1. 红线、法律禁止和不可逆后果；
2. 最大单项影响和前 N 项优先风险；
3. 相关性、集中度、共同失效和风险传导；
4. 合理不利情景下的承受能力；
5. 证据缺口、控制有效性和结论置信度。

## 4. 多维影响

默认使用各维度最大值。只有在组织正式规定权重时才用加权值，并同时展示最大单项影响，防止重大安全或合规后果被平均。

风险速度、持续时间、可探测性、不可逆性作为单独标签。除非正式方法明确规定，不把它们乘入矩阵分数。

## 5. 控制有效性

### 设计有效性

检查：

- 对应的是风险原因、事件还是后果；
- 是否明确责任、频率、阈值、权限与升级；
- 是否覆盖正常、异常和应急场景；
- 是否存在职责冲突、绕过路径或单点依赖。

### 运行有效性

证据可包括：

- 样本、系统日志、审批记录、复核记录；
- 培训签到与考核；
- 演练、恢复测试、渗透测试；
- 盘点、抽检、校准、维护记录；
- 内外部审计和整改关闭证据。

抽样证据应说明评估期间、控制总体、抽样方法、样本量、例外和覆盖范围；样本强度随控制频率、风险等级和评估期调整，不机械规定统一样本数。

“有制度、已认证、负责人表示已执行”仅能证明设计或主张，不能自动证明运行有效。

### 剩余风险

优先由评估团队在验证控制后重新评价可能性和影响。若只有控制描述而无运行证据：

- 剩余风险标为“无法可靠确定”；或
- 经授权采用保守假设，明确假设来源与敏感性。

不得使用通用“控制有效率”自动折减分数。

## 6. 风险之间的关系

至少检查：

- 共同原因：同一人员、系统、资金、地区或供应商；
- 传导路径：一个风险触发另一个风险；
- 集中度：单一客户、供应商、平台、账户或技术；
- 自然对冲：风险方向相反但有效性需证据；
- 同时性：多个风险在压力情景下共同恶化。

组合风险用网络、情景或集中度描述，不用简单总分。

## 7. 处置与接受

| 方式 | 适用情况 | 必备内容 |
|---|---|---|
| 规避 | 超越红线或收益不值得承担风险 | 停止/替代方案、退出条件 |
| 降低 | 控制可降低可能性或影响 | 行动、责任人、日期、验证 |
| 转移/分担 | 保险、合同、外包或合作可分担损失 | 转移范围、除外条款、对手方风险 |
| 接受 | 位于偏好内或处置成本不合理 | 批准者、依据、监测和触发器 |

风险转移通常不转移声誉、监管和业务连续性责任。

## 8. 情景与压力测试

重大风险情景至少写明：

- 触发事件与早期信号；
- 基准、合理不利和极端但可行情景；
- 影响路径和时间轴；
- 流动性、产能、客户、人员、合规和恢复影响；
- 控制失效假设；
- 应急资源、决策权限、恢复目标和退出条件。

模型参数必须有来源。没有可靠概率时不输出精确发生率；没有可靠损失数据时使用区间、敏感性或定性等级。

使用金额时必须说明口径：单次情景损失、年度期望损失、最大可能损失或压力情景损失，不能混用。

## 9. 证据置信度

建议使用：

- 高：原始记录完整、来源独立、时间与范围匹配；
- 中：证据部分完整或主要来自经批准内部材料；
- 低：主要为自述、过期、范围不匹配或存在冲突。

置信度不改变风险本身，而改变结论可靠性。高风险+低置信度通常需要补充调查或保守决策。
