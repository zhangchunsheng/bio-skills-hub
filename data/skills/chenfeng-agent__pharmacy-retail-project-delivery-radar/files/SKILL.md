# 药房零售项目交付风险

这是面向企业客户的按次交付 PaySkill，**无免费版本**。它只对已付款订单交付完整结果，付款前不输出分析主体、建议或报告。

## 适用范围

- 行业：药房零售
- 任务：项目交付风险。从里程碑、依赖和资源识别交付风险。
- 行业判断锚点：商品、批号、处方、库存、效期与合规
- 交付物：里程碑状态、依赖、影响、触发信号、负责人和回滚动作

## 付费前置检查

调用本 Skill 前，Agent 必须检查当前宿主是否已安装并启用 `weixinpay` 插件：

- 已安装并启用：可以继续请求付费服务。
- 未安装或未启用：提示“当前 Agent 暂不支持微信支付付费能力”并立即终止；不得发起订单，也不得降级为免费输出。

## 唯一生产入口

```text
POST https://pay.chenfengai.cn/api/pharmacy-retail-project-delivery-radar
```

请求体必须是：

```json
{"input":"待处理的企业材料","mode":"industry"}
```

单次价格：6.99 元（CNY，服务端金额 699 fen）。首次请求会返回 HTTP 402、官方 `WeixinPay-Required` 和 `X-Out-Trade-No`。

## 微信 Agent Pay 工作流程

以下四步是本 Skill 的强制支付服务链，Agent 不得跳过：

1. 请求资源：按上方格式调用唯一生产入口，并保存原始请求体。
2. 处理 HTTP 402：从响应中提取并保存 Header `WeixinPay-Required`（支付码）和 `X-Out-Trade-No`（订单号）。任一字段缺失都必须停止，不得交付结果。
3. 发起支付：将 `WeixinPay-Required` 的值作为 `paymentCode` 调用 `weixinpay_pay`，向用户申请微信支付授权。不得手工生成二维码、订单号或支付证明。
4. 支付成功后必须重新请求：保持第一次请求体完全不变，重新调用同一 URL，并同时携带原 `WeixinPay-Required` 和原 `X-Out-Trade-No` Header；只有服务端查单验证成功并返回 HTTP 200 后，才可把付费内容交付给用户。

服务端 HTTP 402 响应体中的官方提示语应为：

```text
本次使用微信支付，请将 WeixinPay-Required 的值作为 paymentCode 交给 weixinpay_pay，以向用户申请支付授权。
```

本 Skill 不生成二维码、不读取私钥、不绕过平台支付。支付成功后若未执行第 4 步重试，就不能视为完成调用。

异常与退款：未付款、订单过期、金额或币种不匹配、请求摘要变化、支付状态未知、模型超时或结果保存失败时，服务端不交付结果；恢复原订单或调用退款接口，并记录可查的退款状态，不创建第二笔订单。

## 处理与质量门槛

1. 先确认材料的时间范围、单位、来源和适用对象；缺失时标为待补。
2. 按药房零售的业务口径提取证据，区分事实、计算、判断、建议和未验证假设。
3. 只在输入材料支持的范围内计算或归纳，不补造数字、客户承诺、审批、资质、法律结论或个人敏感属性。
4. 输出可执行的负责人、截止时间、验收标准和升级条件；没有原文依据的字段必须明确写“待确认”。
5. 输出前检查：是否覆盖基线日期、变更记录、验收标准和关键资源，是否保留来源定位，是否存在相互矛盾的数字，是否把建议误写成已批准事项。

## 输出结构

1. 已确认事实与来源
2. 关键指标或判断（列出计算口径）
3. 风险、异常与影响范围
4. 建议动作、负责人、期限和验收标准
5. 待补材料、人工复核项和停止条件
