# 实验报告撰写与归档全流程指南

本文件填补 `neuroresearch` 在"团队内部 / 实验流程层面"产出物的覆盖空白。
覆盖 5 类文档：标准实验报告、周报、月度进展、失败记录（negative result log）、数据归档（data handover）。

## 一、定位与区别

| 文档 | 受众 | 用途 | 频率 | 字数 |
|------|------|------|------|------|
| **Standard Lab Report** | PI、同组、合作者 | 单次完整实验复盘/交接 | 按需 | 1500-3000 字 |
| **Weekly Report** | PI、同组 | 周进度、问题、计划 | 每周一次 | 300-800 字 |
| **Monthly Progress** | PI、依托单位 | 月度里程碑、消耗统计 | 每月一次 | 800-2000 字 |
| **Failure Log** | 自己、同组、AI | 失败实验复盘 | 失败即录 | 300-1000 字 |
| **Data Handover** | 组员、PI、留存 | 数据完整性交接 | 节点必交 | 表格 + 元数据 |

> 与论文、开题报告的区别：实验报告 = 过程中间产物（细节、失败、过程数据），论文 = 完成后精修产物（成功、精炼、文献对齐）。两者数据内核一致但表达密度不同。

## 二、Standard Lab Report 模板（标准实验报告）

> 适用于"本次实验完成 + 需要详尽记录 + 可能有后续行动"。

### 2.1 模板结构
```
# 标准实验报告 · <实验简称>

| 字段 | 内容 |
|------|------|
| 项目 | <项目名 / 课题编号> |
| 课题组长 | <PI> |
| 实验人 | <姓名> |
| 实验日期 | YYYY-MM-DD 至 YYYY-MM-DD |
| 实验地点 | <实验室 / 房间号 / 平台> |
| 数据存放 | <文件路径 / Zotero Tag / 元数据 ID> |
| 伦理批号 | <IACUC / IRB 编号> |
| 分组与编号 | <列表> |
| 主要试剂 | <货号 + 公司> |
| 主要抗体 | <Clone + 货号 + 公司> |
| 主要设备 | <型号 + 编号> |

## 1. 摘要（150-300 字）
    一段叙述，含背景、问题、主要发现、结论。

## 2. 引言（200-500 字）
    文献基础 + 本次实验拟回答的"小问题"。

## 3. 方法（详尽可复现）
    3.1 模型与分组（含 n 值与功效分析依据）
    3.2 实验流程（按时间顺序）
    3.3 检测指标与方法
    3.4 数据处理与统计
    3.5 试剂、抗体、设备清单
    3.6 SOP 偏离记录（任何偏离标准流程的步骤必须记！）

## 4. 结果
    4.1 客观结果（图 + 表 + 数值 + 误差 + n）
    4.2 统计结果（检验类型、统计量、p 值、效应量、置信区间）
    4.3 原始数据索引（指向存储路径）

## 5. 讨论（200-500 字）
    5.1 本次结果的小结论
    5.2 与预期 / 既往数据的对比
    5.3 局限与改进方向
    5.4 下一步计划（具体到实验编号）

## 6. 附件
    - 原始数据（数据 .csv / .fcs / .czi / .lif / 原始图像）
    - 脚本（.R / .py / .ipynb）
    - 图脚本与版本号
    - 实验视频（如有）
    - 数据生成过程日志
```

### 2.2 必含硬元素清单
- [ ] **批号**：每个试剂、抗体、设备的具体货号
- [ ] **n 与功效分析依据**：每组 n、来源、计算依据
- [ ] **SOP 偏离记录**：偏离标准 SOP 的任何步骤（含原因、影响评估）
- [ ] **原始数据存储路径**：可追溯、可复现
- [ ] **统计完整**：检验类型 + 自由度 + 检验量 + p + 效应量 + 95% CI
- [ ] **图表**：图编号自洽（"图 X.Y"），每个图表有自含的图注（self-contained caption）
- [ ] **时间戳**：实验起止日期 + 数据采集日期
- [ ] **数据存放路径**：可指向 Zotero、OneDrive、本地项目目录

### 2.3 关键写作红线
- ❌ **不要选择性报告**：失败的实验必须写进报告（即便是"失败总结"）
- ❌ **不要数字精度漂移**（如某处写"2.0 倍"另一处写"2.04 倍"——精度必须一致）
- ❌ **不要用"可能有 / 可能是"**：客观记录观察，避免推测
- ❌ **不要遗漏原始数据**：原始数据必须可访问
- ❌ **不要混淆图注与图**：图注独立、含统计标注

## 三、Weekly Report 模板（周报）

```
# 周报 · YYYY-MM-DD ~ YYYY-MM-DD

PI: <PI 姓名>
报告人: <姓名>
项目: <项目名>

## 本周完成
- [完成项 1：含 n 与产出]
- [完成项 2]
- [完成项 3]
- 实验编号: <编号清单>

## 进行中
- 实验 X：进度的 X / X 步
- 数据分析 X：完成了 X / X 部分

## 卡点 / 问题
- 问题 1：陈述 + 拟解决途径
- 问题 2：陈述 + 需 PI 决策

## 下周计划（具体到动作）
- [ ] 实验 X：完成 / 重复 X
- [ ] 数据分析：完成 X
- [ ] 论文撰写：完成 X

## 数据异常 / 失败
- 实验 X：失败原因 + 是否重做

## 试剂 / 抗体 / 动物消耗
- 试剂 X：剩余 X（应补 X）
- 抗体 X：剩余 X
- 动物 X：已用 X / 月度计划 X
```

要点：
- **不要只写"做了实验"**，要写"完成了哪一步、n 是多少、出了什么结果"
- **卡点要诚实**——周报的真价值在于让 PI 早期知道卡点
- **下周计划落到具体动作**——避免"继续实验"这种空话

## 四、Monthly Progress 模板（月度进展）

### 4.1 模板结构
```
# 月度进展 · YYYY-MM（第 X 月/共 X 月）

PI: <PI 姓名>
报告人: <姓名>
项目: <项目名> · 期限 YYYY-MM-DD 至 YYYY-MM-DD

## 1. 本月里程碑 vs 计划
| 计划里程碑 | 是否完成 | 实际完成情况 | 偏差原因 |
|------------|----------|--------------|----------|
| <目标>      | ✓/✗    | <细节>       | <原因>   |

## 2. 本月完成实验清单
- 实验 X（含 n、产出）
- 实验 Y（含 n、产出）

## 3. 关键数据 / 结果
- 关键结果 1（图 / 表 + 一句话结论）
- 关键结果 2

## 4. 试剂 / 动物 / 设备
| 类别 | 消耗量 | 月度预算 | 剩余 | 备注 |
|------|--------|----------|------|------|
| <试剂> | X | X | X | <加急/补货> |

## 5. 卡点与风险
- 卡点 1：方案与 PI 已沟通 / 待 PI 决策
- 卡点 2：<具体>

## 6. 成果 / 撰写 / 报告
- 论文：草稿进度（仅在节点汇报，避免过度频繁）
- 报告：本月完成 X 份

## 7. 下月目标
- [具体目标 1]
- [具体目标 2]

## 8. 经费进度
- 本月支出：X 万 / 年度预算 X 万 / 完成度 X%
```

### 4.2 月报关键
- **里程碑对照表**：必须显现"计划 vs 实际"偏差（不要只说"按计划进行"）
- **消耗统计**：试剂/动物/设备消耗是 PI 关心的硬约束
- **风险与决策点**：列出"本月需要 PI 决策的 X 件事"
- **下月目标要 SMART**：具体 / 可衡量 / 可达 / 相关 / 时限

## 五、Failure Log 模板（失败记录 / 阴性结果）

> **目的**：科研诚信、组内知识传承、避免重复失败、AI 训练 / 决策依据。

```
# 失败记录 · YYYY-MM-DD

| 字段 | 内容 |
|------|------|
| 项目 | <项目名> |
| 实验人 | <姓名> |
| 实验日期 | YYYY-MM-DD |
| 失败等级 | 失败（数据不可用） / 部分失败（数据可用，但未达预期） |

## 1. 假设
    本次实验预期假设（明确可证伪陈述）。

## 2. 实验设计简述
    2.1 模型、分组、n
    2.2 操作步骤
    2.3 阳性 / 阴性对照设计
    2.4 主要指标

## 3. 实际结果
    3.1 客观观察（图 / 表）
    3.2 与预期对比

## 4. 分析：可能的失败原因
    4.1 技术原因（如抗体失败、试剂失活、操作误）
    4.2 生物学原因（如动物模型不适合、剂量不当、时间点错误）
    4.3 设计原因（如对照组设计缺陷、统计功效不足）

## 5. 决策
    - [ ] 重做（修改设计）
    - [ ] 重做（修改操作）
    - [ ] 终止（不可行）
    - [ ] 转向（换方法）

## 6. 教训与改进
    - 教训 1
    - 教训 2
    - SOP 修订建议（要写具体到哪一步）
```

### 5.1 为什么要写失败记录
1. **避免重复失败**：组员下一次遇相似情况，可前车之鉴
2. **科研诚信**：阴性结果也是结果，不允许"失败实验不记录"
3. **AI 长期学习**：失败案例是 skill 改进的依据
4. **元分析**：若干失败记录可启发新机制

### 5.2 Failure Log 频率建议
- 每次失败即录；最低限度每月归档一次未记录的失败
- 月底回顾本月失败列表

## 六、Data Handover 模板（数据归档）

> 适用于"换组员、毕业季、合作时"——保证完整可移交。

```
# 数据归档 · <项目名>

日期: YYYY-MM-DD
移交人: <姓名>
接收人: <姓名>（如有）

## 1. 目录结构（推荐）
project_root/
├── 01_protocols/        # SOP、IACUC、方法论文档
├── 02_raw_data/         # 原始数据（不可修改！）
├── 03_processed/        # 处理后的中间数据
├── 04_figures/          # 最终图表（300 dpi PNG + SVG）
├── 05_scripts/          # 分析脚本（R / Python / ImageJ）
├── 06_logs/             # 实验日志、失败记录、原批注
├── 07_meta/             # 元数据（动物、抗体、试剂编号）
└── 08_NOT_README.md     # 数据使用指南
```

### 6.1 数据四件套规则
- **数据**：原始（Excel/CSV/FCS/CZI/LIF/PNG）+ 处理后（CSV/TIFF）
- **脚本**：分析 / 出图脚本 + 版本（R / Python / ImageJ Macro）
- **图表**：最终矢量 PDF / SVG + 高清 PNG + 源文件（AI / PPTX）
- **注释**：每个文件夹 + 每个脚本均含 README + 注释

### 6.2 文件命名
- 严格遵循 `references/citation-formatting.md` 通用规则
- **不应**包含空格 / 中文（路径兼容性问题）
- 推荐：`YYYY-MM-DD_experimentID_objective_shortdesc.ext`
- 反例："实验 1 大鼠脑组织 WB.tif"

### 6.3 README 模板
```
# <项目名称>

## 1. 项目目标（2-3 句）
## 2. 目录结构（每个文件夹用途）
## 3. 关键文件路径
## 4. 实验批次表（n、日期、操作者）
## 5. 已发表论文 / 报告（DOI / 路径）
## 6. 复现方法（关键依赖项）
## 7. 待办 / 关键卡点
```

### 6.4 元数据 YAML 模板（项目根目录）
```
project: <name>
pi: <name>
duration: YYYY-MM-DD to YYYY-MM-DD
ethics_approval: <IACUC/IRB ID>
animal_model: <C57BL/6J, etc>
antibody_clones: <list>
software:
  R: <当前版本，以实际为准，如 4.6.0>
  python: <当前版本，以实际为准，如 3.13.12>
data_storage: <path>
publications: <DOI list>
contacts: <email>
```

## 八、写报告的硬规范（红线）

### 8.1 真实性
- ❌ 编造数据
- ❌ 选择性报告（只展示"漂亮"数据）
- ❌ 篡改图像（IB / IF / IHC）
- ❌ 删除失败 / 离群点不交代
- ❌ 重复使用同一图（不同实验编号）

### 8.2 完整性
- [ ] 原始数据可访问（路径或存储位置）
- [ ] 脚本可复现（R / Python 版本号 + seed）
- [ ] 元数据完整（动物 / 抗体 / 试剂编号）
- [ ] 失败记录同步记录（与论文无关但必须留底）

### 8.3 复现性
- [ ] 任何"做过一次成功"的实验，下次能复现（参数记清楚）
- [ ] 跨批次的数据有 batch effect 控制记录
- [ ] 试剂 / 抗体更换时记录衔接关系

## 九、报告周期与产出节奏建议

- **Standard Lab Report**：每完成一项完整实验产出 1 份（如一次完整 WB 实验 + 一次 IF + 一次 RT-qPCR 算一份）
- **Weekly Report**：每周五固定时间产出（不超过 30 分钟）
- **Monthly Progress**：每月最后一个工作日产出（约 1-2 小时）
- **Failure Log**：每次失败即录（不超过 15 分钟）
- **Data Handover**：学期末 / 毕业季 / 换组员 / 节点产出（约 4-8 小时整理）

> 数据归档建议每月做增量备份，季度做完整备份到 Beyond Compare / OneDrive / 课题组 NAS。
