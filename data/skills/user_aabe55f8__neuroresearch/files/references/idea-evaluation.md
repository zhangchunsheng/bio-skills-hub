# 研究设想 / 假说评估框架

> 借鉴 HKUST Dial *Supervisor-Skills · idea-evaluator* 的方法论（评分骨架 + 致命缺陷早筛 + 范式突破探针），**改写为神经科学语义、适配 NSFC 申报与机制假说论证**。仅为方法论移植，非逐字复制；示例一律用通用占位（分子X / 细胞A / 通路Y / 代码X），不写死任何用户特定、未公开课题内容（遵循 SKILL.md 核心原则第 11 条）。

本框架用于在**投入数月实验 / 锁定论文 scope / 提交标书前**，对一个初步研究设想或假说做结构化评估：新颖性（真实检索核验）、致命缺陷早筛、五维打分、范式突破探针、可行性与风险、诚信门，最终给出三档裁决。目标是**在弱设想消耗资源前先杀掉它**，把有潜力但未成熟的设想塑形成更强版本。

## 何时使用

- 用户有初步想法 / 假说，问"这个方向值不值得做""评估一下这个 idea""创新性够不够""H1701 还是 H0910 哪种更适配"等。
- 在锁定论文 scope、开题、标书定稿前做外部体检。
- 用户在两个候选方向间取舍，需要结构化权衡。
- 用户怀疑 scope 蔓延、想做外部检查。

## 何时不用

- 设想已实现、正在写论文 → 用 `manuscript-and-submission.md` 模拟审稿。
- 用户要的是"从零头脑风暴新想法" → 正常对话即可（见 `literature-review.md` §二 空白→假设）。
- 用户要评估标书代码投向 → 用 `nsfc-code-strategy.md`（本框架只评估"想法本身"，代码适配交专门策略）。

## 核心流程

### Step 0：先冻结设想（一句话故事）

读用户的设想描述，用一段话判定它读起来是 **Novel Problem（新问题）/ Novel Mechanism（新机制）/ New Setting（新场景/新模型）**。能否用一句话讲清故事？若讲不清，设想本身还不够清楚，请用户重述。

> 同步 `literature-review.md` §二「假设句式模板」：`"在 [模型] 中，[干预] 通过 [机制] 影响 [结局]，表现为 [可测量指标] 的改变。"`——能套进此句，设想才可被评估。

### Step 1：致命缺陷早筛（提前门，先于打分）

先跑早筛，至多标出 2 个致命缺陷；每个写明"缺陷 + 检测规则 + 具体防御"。

**神经科学典型致命缺陷（10 类，附检测规则）：**

| # | 缺陷 | 检测规则 | 防御 |
|---|------|---------|------|
| F1 | 新颖性不成立（已有高度重叠工作） | 环境有检索能力时，**必须真实检索**：取设想的 2–3 组关键词（核心机制×疾病×模型），命名 3–5 篇最接近工作，说明差异轴（作用对象 / 机制 / 粒度 / 场景设置）；仅标题相似≠重复，重复须"连一条差异轴都找不到" | 重新定位差异轴，或缩窄到未被覆盖的子方向 |
| F2 | 核心机制被自己的数据反驳 | 用户附件/自报数据已显示核心机制被基线或简单对照匹配/超越 → **自动 CRITICAL** | 不辩护、不编乐观阈值；重设假说 |
| F3 | 因果推定无支撑（相关当因果） | 仅相关性/富集分析，无 rescue / 敲除 / 过表达验证却称"机制" | 补机制验证实验或降级为"参与" |
| F4 | 模型不匹配（物种/病理阶段错配） | 用健康动物模型回答慢性退行问题，或用体外单层回答体内互作 | 换匹配模型 / 补体内验证 |
| F5 | 伦理/IACUC 不可行 | 所需操作超出机构伦理批件范围，或无法获批 | 改方案 / 找替代终点 |
| F6 | 样本量/统计功效不足且不可补 | 预登记功效分析显示 n 远小于检出效应所需，且资源无法扩大 | 改主要终点 / 联合多中心 |
| F7 | 量表/行为学终点不可信 | 所用认知/神经功能终点缺乏验证、信效度不明 | 换已验证终点或补验证 |
| F8 | 转化距离被夸大 | 仅体外/急性动物数据却声称"治疗潜力/临床转化" | 改为"潜在干预靶点" |
| F9 | 与领域共识硬冲突无解释 | 断言直接违背公认范式却无新证据 | 补对立证据或重写主张 |
| F10 | 范围蔓延（scope creep） | 同时追 3+ 条独立机制，无统一核心问题 | 收敛到单一可检验核心 |

**早停规则**：任一缺陷被标为 CRITICAL（单独即可致拒、生命周期内不可修复），**立即**输出裁决"Reject and Pivot"，只给 §1（初印象）、§2（含 CRITICAL 缺陷）、§7（裁决）；**不跑**后续五维打分/探针/可行性。无 CRITICAL 则继续 Step 2。

> 新颖性判断：检索结果仅支持元数据级判断（谁做了什么、在哪）；**不得**从检索摘要摘具体数字或方法细节。"未检索到"≠新颖，标注"unverified; literature check required"。无检索能力时，新颖性判据标"待文献核查"。

### Step 2：生命周期与能力匹配

将设想映射到 6 类之一（Application / Foundational / Cross-Disciplinary / Frontier / Data-Intensive / Novel Technique），对照用户声明的可用资源（周有效工时、技能深度、理论 vs 应用强项、团队/平台）。若生命周期短于用户 realistic 执行窗口，标 mismatch 旗。

### Step 3：五维打分（神经科学语义）

每维 **1–10**，默认从 **5** 起评，移动须给证据（用户陈述的贡献 / 已核验文献）。标出 2–3 个天花板最高的维，建议论文/标书重点强调。

| 维度 | 神经科学语义 | 起评 5 的抬升依据 |
|------|------------|------------------|
| **Higher（更高）** | 机制解释力 / 疗效或表型改善幅度 | 用户数据引文 / 机制论证成立（标"机制推定的，待数据确认"） |
| **Faster（更快）** | 实验周期 / 表型读出速度 / 建模成本时间 | 同上 |
| **Stronger（更强）** | 可重复性 / 稳健性 / 抗干扰（批次、性别、年龄） | 同上 |
| **Cheaper（更省）** | 样本量 / 试剂耗材 / 动物数成本 | 同上 |
| **Broader（更广）** | 跨疾病 / 跨模型 / 转化通用性 | 同上 |

打分纪律：证据两类可抬分——用户报告的实测结果（引之），或成立且命名的机制论证（标"机制推定"并给出验证实验）。扎实但未验证的机制可到 8–9；既无数据也无机制则留 5（"无依据"）。若亮眼增益疑似来自外周因素（试剂批次、强基线对照、选择性样本），该维封顶至隔离出核心机制为止。

### Step 4：范式突破探针（4 问）

| 探针 | 问题 | 用户设想 |
|------|------|---------|
| First Principles | 是否挑战领域视为理所当然的隐藏假设？ | |
| Elephant in the Room | 是否触及人人看到却无人愿碰的问题？ | |
| Technology Cycle | 是否借技术周期转折（如新单细胞/空间组学使旧问题可行）？ | |
| Hamming's Rule | 若此问题自解，领域会实质改变吗？ | |

≥2 个"是" → 有颠覆潜力，建议深化（见 `literature-review.md` §二 空白类型）。

### Step 5：可行性与风险

对照用户声明资源（平台、动物房/细胞房、数据获取、工程技能、时间线）评估：

| 风险 | 级别 | 缓解 |
|------|------|------|
| 平台（动物房/测序/成像） | | |
| 数据（可及性/需昂贵标注/私有） | | |
| 技术（是否匹配技能栈） | | |
| 时间线（编码+实验+写作+返修 是否落在生命周期内） | | |

任一风险高 → 显式标出并给缓解建议。

### Step 6：诚信门（静默运行，失败才在输出浮现）

每条标 `[inspection]`（LLM 可从产出文本自验）/ `[attestation]`（LLM 声明已跑，用户仍负责）：

1. `[inspection]` 每维分数引用用户贡献的具体证据，无"拍脑袋"分。
2. `[inspection]` 可行性声明引用用户声明资源，非泛泛假设。
3. `[inspection]` 新颖性声明要么引具体 prior work，要么标"待文献核查"。
4. `[inspection]` 致命缺陷具体且可行动，"这可能不行"不算缺陷陈述。
5. `[inspection]` 裁决与打分一致：Strong Accept 需 ≥2 维在 8+ 且 0 个 CRITICAL。
6. `[attestation]` 生命周期预测由领域近期节奏推理，用户应自行 sanity-check。

### Step 7：最终裁决

- **Strong Accept**：立即执行。≥2 维 8+、无致命缺陷、能力匹配绿、生命周期契合。
- **Accept with Revisions**：先按建议收缩 scope。部分维弱、可修缺陷、或生命周期可缩短的 mismatch。
- **Reject and Pivot**：不追此版本。被 prior 工作主导、能力 mismatch 不可修、或 >1 致命缺陷。

高分为"机制推定"而非"数据based"时，裁决补"worth pursuing, pending the validation experiment"并点名该实验。
