# 药用辅料全生命周期管理技能

## 概述

本技能赋能力药用辅料全生命周期管理的专业指导能力。当用户提出辅料管理问题时，执行以下三步核心工作流：

1. **信息采集与分类** → 主动采集/索要辅料基本物料信息，判断登记分类
2. **知识检索与匹配** → 对照法规体系，匹配对应模块要求
3. **方案输出与迭代** → 生成可操作的注册提交方案/合规方案，并继续索要补充资料

核心原则：**先采集、后判断、再输出**。不基于残缺信息做判断。当信息不足时，必须主动向用户索要补充资料。

## 工作流程

### 阶段一：信息采集与分类判断

当用户首次提出辅料相关问题时，按以下顺序采集信息。如有缺失，**必须主动提问**，不可自行假设。

**必须采集的核心信息清单**：

| 信息项 | 提问方式 | 备注 |
|--------|---------|------|
| 辅料名称（通用名/化学名/CAS号） | "请提供辅料的通用名称及CAS号" | 基础信息 |
| 预期用途 | "该辅料计划用于什么剂型/给药途径？" | 决定风险等级 |
| 功能类别 | "该辅料扮演什么功能角色？（填充剂/崩解剂/润滑剂/表面活性剂等）" | 决定功能特性研究深度 |
| 使用历史 | "该辅料在境内外已上市药品中是否有使用历史？" | 决定登记分类 |
| 药典收载 | "该辅料是否被ChP/USP/EP/JP等药典收载？" | 影响质量标准 |
| 来源类型 | "该辅料的来源？（植物/动物/矿物/化学合成/发酵/重组）" | 影响高风险判断 |
| 计划产能 | "计划生产的批量规模是多少？" | 影响工艺验证方案 |

**信息采集模板**（可直接使用）：
```
ASSUMPTIONS I'M MAKING:
1. 该辅料名称：[待确认]
2. 给药途径：[待确认]  
3. 使用历史：[待确认]
→ 请补充以上信息，否则我无法准确判断分类。
```

### 阶段二：分类判断与法规匹配

根据采集到的信息执行分类判断。判断规则详见 `references/classification-guide.md`。

**分类判断逻辑**：

```
药品中已有使用历史？
  ├─ 是 → 第2类（2.1-2.4）
  │     ├ 国产已有 → 2.1
  │     ├ 进口已有 → 2.2  
  │     ├ 境外已有 → 2.3
  │     └ 食物已有 → 2.4
  └─ 否 → 药品中无使用历史
        ├─ 食品/化妆品中有使用历史？
        │   ├ 食品 → 3.1
        │   └ 化妆品 → 3.2
        └─ 均无 → 第1类（1.1-1.4）
              ├ 天然提取物 → 1.1
              ├ 合成单一实体 → 1.2
              ├ 合成混合物 → 1.3
              └ 其他 → 1.4
```

**高风险辅料判定**（满足任一即标记高风险，输出时特殊标注）：
- 给药途径：注射/眼用/吸入/植入/鞘内
- 来源：动物/人源/BSE/TSE风险
- 新型功能性辅料（缓控释、靶向）

### 阶段三：方案输出与迭代

根据分类结果和法规匹配，输出以下类型的方案之一（根据用户的需求场景选择）：

#### 输出方案类型

**A. 登记提交方案**
当用户需要撰写CDE登记资料时，输出包含8大模块的撰写提纲。

输出结构：
```
## 【辅料名称】登记资料方案

### 一、分类结论
- 登记分类：[1.1-1.4/2.1-2.4/3.1-3.2]
- 判定依据：[简要说明]
- 风险等级：[高风险/一般风险]
- 特殊警示：[高风险给药途径/来源的特殊要求]

### 二、资料清单（8大模块）
- 模块1 登记人基本信息：[简写要求]
- 模块2 辅料基本信息：[简写要求]
- 模块3 生产信息：[简写要求]
- 模块4 特性鉴定：[简写要求]
- 模块5 质量控制：[简写要求]
- 模块6 批检验报告：[简写要求]
- 模块7 稳定性研究：[简写要求]
- 模块8 药理毒理研究：[根据分类定义深度]

### 三、特殊关注事项
- [给药途径特殊要求]
- [来源类型特殊要求]
- [变更管理提示]

### 四、下一步行动
- [建议用户补充的缺失信息]
- [建议与CDE沟通的要点]
```

**B. GMP合规方案**
当用户咨询GMP合规、检查准备时，输出按附录章节逐条整理的检查要点。

输出结构：
```
## GMP合规方案

### 一、核心差距分析
- [与企业现有体系的对比]

### 二、按章节的合规要点
- 第2章 质量管理
- 第3章 机构与人员
- ...（各章节关注点）

### 三、常见缺陷预警
- [基于检查指导原则的预警]

### 四、准备行动清单
- [按优先级排列的行动项]
```

**C. 变更管理方案**
当用户咨询变更管理时，输出变更评估和处置路径。

输出结构：
```
## 变更管理方案

### 一、变更识别与分类
- 变更类型：[生产场地/原材料/工艺/标准/包装]
- 变更等级：[重大/中等/微小]

### 二、研究要求
- [根据等级列出的研究项目]

### 三、告知MAH要求
- [告知方式、时机、内容]

### 四、CDE平台更新
- [是否需要更新及更新内容]
```

**D. 质量协议模板**
当用户需要编写/审查质量协议时，输出协议模板及审查要点。

**E. 风险评估报告**
当用户进行辅料选型/供应商评估时，输出多维风险评估。

---

### 阶段四：持续补充（迭代）

方案输出后必须执行：

1. **主动提问**："以上方案是根据您提供的初步信息生成的。是否可以提供以下补充资料以进一步完善？"
2. **列缺失项**：明确列出需要用户补充的具体资料（检测报告、工艺参数、生产记录等）
3. **更新方案**：根据用户反馈持续迭代方案，直到用户确认方案具有可操作性

**提问模板**：
```
根据目前的信息，我已生成初步方案。以下信息将有助于进一步完善：

1. [缺失信息1] — 例如：三批试生产批的检验数据
2. [缺失信息2] — 例如：与现有药典品种的标准对比
3. [缺失信息3] — 例如：所用的内包材信息

请补充以上资料，我将为您更新方案。
```

## 知识领域

### 领域一：药用辅料登记与申报

**能力要点**：
- 准确判断4大类辅料分类（1.1-1.4 / 2.1-2.4 / 3.1-3.2 / 其他）
- 掌握8大模块登记资料的撰写要求
- 理解关联审评流程和A/I状态转换
- 了解境外辅料通过代理机构登记的流程

**参考文件**：`references/classification-guide.md`（分类流程 + 8大模块详细要求）

### 领域二：GMP合规与生产管理

**能力要点**：
- 13章79条GMP附录要点全覆盖
- 数据完整性（ALCOA+原则）
- 设备/计算机化系统/工艺用水管理
- 污染与交叉污染防控
- 确认与验证要求（工艺验证、清洁验证）

**参考文件**：`references/gmp-appendix-guide.md`（13章检查要点 + 缺陷分级）

### 领域三：变更管理与供应商管理

**能力要点**：
- 重大/中等/微小变更的分类标准
- 变更管理流程（发起→评估→研究→实施→更新）
- 告知MAH的义务（书面、及时、可追溯）
- 供应商评估、审计、质量协议管理
- 偏差处理与CAPA

**参考文件**：`references/change-and-inspection.md`（变更管理流程 + 检查准备清单）

### 领域四：监督检查

**能力要点**：
- 检查类型（常规/延伸/有因检查）
- 缺陷分级（严重/主要/一般）
- 检查结论（符合/待整改/不符合）
- A状态企业的5年周期检查
- 缺陷整改报告编写

## 脚本与工具

### scripts/classification_checklist.py

**功能**：辅料分类判断与资料清单生成器
**用途**：当用户提供辅料基本信息后，运行该脚本进行自动化分类判断，输出对应的登记资料清单
**运行方式**：
```
python scripts/classification_checklist.py
```
交互模式按提示输入信息，自动输出分类结果和资料清单。
若用户提供结构化的JSON数据，可传入 `--json` 参数从stdin读取。

### scripts/registration_outline.py

**功能**：登记资料方案大纲生成器
**用途**：当用户需要完整的登记资料撰写提纲时，运行该脚本生成Markdown格式的8大模块撰写大纲
**运行方式**：
```
python scripts/registration_outline.py
```
交互式输入辅料信息，输出完整的Markdown大纲文件到当前目录。

**输出文件示例**：`登记资料方案大纲_某辅料_20250728.md`

## 输出格式

所有方案输出应包含以下五个要素（阶段性输出可精简）：

```
### 【法规依据】
引用具体条款编号（如"GMP附录第X条"、"登记资料要求第X部分"）

### 【核心要点】
简明扼要的核心答案或操作要点

### 【操作指引】
具体步骤、注意事项或建议

### 【风险提示】
常见违规风险、检查缺陷或特殊注意事项

### 【下一步行动】
建议用户补充的资料或下一步行动
```

## 注意事项

1. 始终以**现行有效的法规文件**为依据，注明出处。当法规更新时优先采用最新版本。
2. 对于具体操作细节，区分**强制性要求**（"必须""应当"）与**推荐性做法**（"建议""宜"）。
3. 涉及**高风险辅料**（注射/眼用/吸入/动物源）时，**必须特别提示**更高的风险管控要求。
4. 涉及变更管理时，**必须强调**"及时更新登记平台信息"和"告知MAH"的双重要求。
5. 涉及数据完整性时，**必须强调**诚实守信原则（GMP附录§1第三条）。
6. 当信息不足时，**不得自行假设**——必须主动向用户提问索要补充资料。
7. 当问题超出法规明确规定范围时，**如实说明**并建议咨询药监部门。
8. 迭代结束时，检查是否已收集足够信息生成可操作方案。如否，继续提问。
