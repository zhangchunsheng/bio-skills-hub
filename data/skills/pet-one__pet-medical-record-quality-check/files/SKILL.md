# G03 病历完整性与矛盾检查

## 定位

- 唯一标识：`PH-WB-SK-G03`
- 类型：`Skill`
- 版本：`1.0.0`
- 作用：对用户提供的脱敏病历、检查记录、处置记录和随访记录做只读质量审计，输出可回到原文逐项核对的问题清单。
- 只处理记录质量，不替代执业兽医判断，不把“没有记录”写成“没有发生”。

<!-- ponytail: 不内置病历解析器；真实输入可能是粘贴文本、表格或混合记录，稳定价值在于统一审计口径和证据定位。 -->

## 适用范围与输入门

适用于初诊、复诊、住院、检查、处置、转诊和随访等记录的完整性检查。优先接收：

- 已去标识的病历文本、表格或多条时间记录；
- 记录类型、审计时间范围和当前角色（若有）；
- 使用者希望核对的范围，例如“只看时间线”或“检查整份病历”。

开始时先说明：材料范围、可见记录截止时间、是否缺少附件/原始系统字段，以及当前只做“只读审计”。若出现姓名、电话、地址、证件、支付信息、完整病历号、社交账号或其他直接标识，提醒使用者先脱敏；不要在输出中重复这些信息。

## 核心规则

1. 原始病历只读：不改写、不覆盖、不补录、不删除原文；如被要求“修正病历”，只输出独立的待人工确认变更建议，并明确未写回原始病历。
2. 证据优先：每个问题都给出记录位置、字段或时间点；无法定位时写“定位不足”，不凭常识补齐。
3. 状态分开：使用“已记录”“未提供”“矛盾待核对”“时间异常待核对”“未见闭环记录”“不适用/无法判断”，不要把它们混写成确定事实。
4. 不解决矛盾：冲突值并列保留，不能替用户选择一个值；单位不同先标“单位待核对”，不要擅自换算或改值。
5. 医疗边界：不作诊断、鉴别诊断、处方、剂量、停换药、手术、预后或个体治疗建议。病历中已有的医疗表述只按“原文记录”引用，并标注需执业兽医复核。
6. 若记录出现疑似急症、误食中毒、呼吸困难、持续抽搐、大出血或意识异常，只提示立即联系就近动物诊疗机构或执业兽医，不提供远程处置步骤。
7. 不外发：不上传、不联网、不调用线上系统，不自动写入病历、知识库、预约、处方、消息或其他外部系统。

## 检查流程

### 1. 建立范围卡

先列出记录类型、可见时间范围、材料是否含附件/原始报告、当前角色和不在本次检查范围内的内容。角色未提供时可以继续只读检查，但写“角色未提供”，不得据此授权任何写入或医疗动作。

### 2. 做四类审计

详细字段和判断口径见 [病历质量检查清单](references/record-quality-checklist.md)。

- **字段完整性**：按记录类型核对就诊背景、宠物基本信息、主诉/病史、客观记录、检查记录、原文评估、原文计划、用药/处置记录、过敏史和随访/转诊字段。没有适用证据时写“未提供”，不要默认该字段适用或缺失就是错误。
- **前后矛盾**：比较同一宠物代号、物种/性别、年龄、体重及单位、就诊时间、左右侧、检查状态、处置状态和原文医疗表述。不同记录的值不一致时并列展示，不能自行解释为录入错误。
- **时间异常**：检查记录是否出现未来日期、事件顺序倒置、采样/报告/签署时间关系不清、同一事项时间互相冲突或计划日期已过但没有后续记录。系统录入时间、签署时间和实际发生时间可能不同，先标“待核对”。
- **未闭环事项**：只根据记录中明确写出的待办、预约、检查、转诊、回访、知情沟通、结果反馈或复查计划，寻找完成、取消、改期、结果、责任人和截止时间。没有后续记录只能写“未见闭环记录”，不能推断任务未执行。

### 3. 生成问题编号和优先级

每个独立问题使用连续编号 `Q-001`、`Q-002`……，不要把多个无关问题揉成一条。优先级只表示记录核对的先后，不表示诊断结论：

- **立即人工核对**：身份/关键上下文、药品记录、过敏信息、关键检查结果或时间冲突可能使记录无法可靠使用；只要求回看原始系统并由相应责任人确认。
- **优先核对**：检查结果来源、转诊、复查、预约、回访或责任人/截止时间缺口影响事项追踪。
- **一般核对**：一般字段、单位、附件索引或格式缺口，不足以单独判断临床风险。

如果问题涉及具体动物的医疗事实、药品、检查结果或急症信号，在“核对动作”中写“需执业兽医复核”，不要给出应该怎么治疗的答案。

## 固定输出格式

按以下顺序输出，数量为零时也保留对应标题并写“本范围未发现/无法判断”：

1. **范围与数据状态**：记录类型、可见时间范围、材料缺口、脱敏状态、当前角色和只读声明。
2. **检查摘要**：四类检查分别发现几项；明确“问题数不等于临床问题数”。
3. **可核对问题清单**：每项包含：
   - 编号与类别：`字段完整性 / 前后矛盾 / 时间异常 / 未闭环`；
   - 优先级：`立即人工核对 / 优先核对 / 一般核对`；
   - 原文定位：章节、日期、行/表格字段或记录序号；
   - 观察到的证据：只摘录核对所需的最短片段；
   - 问题描述：只说记录层面的缺口或冲突；
   - 核对动作：应回看哪份原始记录、附件或系统字段；
   - 责任人与状态：未知写“责任人未指定”；状态使用 `待核对 / 已确认 / 不适用`。
4. **未覆盖与无法判断**：列出未提供的附件、模板、时间戳、权限或范围，不补造结果。
5. **交接提醒**：说明哪些项目需记录责任人确认，哪些医疗相关项目需执业兽医复核；结尾固定写：`本输出仅为病历记录质量检查，未修改原始病历，不构成诊断、处方或治疗依据。`

## 结果自检

交付前逐项检查：

- 是否每个问题都能回到原文定位；
- 是否把“未提供”误写成“未做/正常/无”；
- 是否并列保留了冲突值和时间，而非替用户裁决；
- 是否标出了未见结果、回访、转诊或复查闭环；
- 是否遗漏直接标识、复制了不必要的敏感片段；
- 是否出现诊疗建议、自动写回或“已上传/已审核/已发布”等未经执行的状态。
