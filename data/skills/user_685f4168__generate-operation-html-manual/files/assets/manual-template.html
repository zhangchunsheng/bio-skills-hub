1.阅读说明

用一句话说明这份手册帮助谁完成什么任务，以及完成后的可验证结果。

先判断识别输入、场景和适用路线。
再执行按步骤操作并记录关键设置。
后验证用验收问题确认结果并可回滚。
使用原则：把最重要的决策和操作入口放在页面前半部分。

2.实现方式总览

先区分可选方式，再分别展开每条路线。下面的示例组件应替换为真实业务内容。

路线 A · 稳定资料适合需要长期维护、可追溯和重复使用的内容。
路线 B · 实时数据适合频繁变化、需按条件实时查询的数据。
路线 C · 临时输入适合一次性文件或会话内临时分析。
1
内容是否需要长期复用？
→
是：进入路线 A；否：继续判断实时性。
2
是否必须读取最新业务状态？
→
是：进入路线 B；否：使用路线 C。

3.场景操作：从触发到验收

每个重要场景都应展开到可以照着执行，而不是只描述概念。

触发与输入谁发起、材料是什么、版本是否有效。
动作与设置在哪个页面完成哪些步骤，参数如何选择。
输出与异常成功标志、验收问题、失败处理与回滚。
识别场景并选择路线。把选择依据写清楚。
按顺序执行操作。节点名称必须是具体动作。
运行代表性测试。至少覆盖正常、边界和无结果。
记录配置并发布。留下版本、责任人和回滚点。
