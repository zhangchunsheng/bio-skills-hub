# 多标准 ISO 体系评估陪跑助手 · 交互示例

## 场景 A：ISO 9001 认证陪跑
**用户**：我们要做 9001 认证，帮忙理一下还差什么。公司制度在 `D:/docs/体系文件` 里。

**助手**：
1. 确认标准 `iso9001`，先跑差距分析：
   ```
   python scripts/analyze_gap.py D:/docs/体系文件 --standard iso9001 --out gap_9001.md
   ```
2. 读取报告，告诉用户：必需程序覆盖 9/14，缺失高压线【设计和开发控制】【生产和服务提供控制】。
3. 一键生成缺失程序：
   ```
   python scripts/generate_document.py --standard iso9001 --type QMS-PF-005 --org "示例科技" 
   python scripts/generate_document.py --standard iso9001 --type QMS-PF-007 --org "示例科技"
   ```
4. 进入模拟审核，围绕 `design_control`、`production_control` 提问。

## 场景 B：条款解读 + 证据
**用户**：ISO 27001 的 8.2 风险评估要准备啥？

**助手**（读 `iso27001_framework.json`）：
- 8.2 要求组织按计划的时间间隔执行信息安全风险评估。
- 证据清单：①《信息安全风险评估程序》；②评估方法/风险准则；③《资产清单》；④《信息安全风险评估报告》。
- 关键审核点 `risk_assessment`：✓ 建立评估程序与准则；✓ 完成资产识别与评估形成报告。

## 场景 C：模拟审核
**助手（扮演审核员）**：请说明贵公司如何识别重要环境因素，并形成控制计划？
**用户**：我们有个清单……
**助手点评**：答得方向对，但缺"评价准则"与"与目标的关联"证据，审核员很可能开一般不符合项。标准应答应补充：识别维度、打分准则、重要环境因素如何转化为目标/管理方案。

## 场景 D：存量文档转换（把旧文件改造成标准评价格式）
**用户**：我们前几年自己写了一份《质量手册》，你帮我转成符合 9001 审核用的格式吧。（附 `质量手册.txt`）

**助手**：
1. 调用转换脚本，自动匹配最合适的 9001 程序模板并回填：
   ```
   python scripts/convert_document.py 质量手册.txt --standard iso9001 --org "示例科技" --out ./converted
   ```
2. 读取产物 `QMS-PF-009_质量手册.md`，向用户说明结构：
   - 原文章节已按「目的 / 范围 / 职责 / 工作程序」回填，每段标注「（源自原文「x」）」可溯源；
   - 缺的章节用模板默认内容兜底，标注 `[模板默认内容——请结合实际修订]`；
   - 四个附录：A 未归类原文 / B 自动识别的记录表单 / C 关键审核点合规声明 / D 转换溯源报告（条款覆盖 + 高压线缺口）。
3. 提醒用户人工复核：① 所有 `[模板默认内容]`；② 附录 A 的未归类原文是否遗漏重要信息；③ 若这是"手册类"文档，建议按程序文件拆分后逐一转换（脚本已给出提示）。
4. 如果用户想精确控制目标模板，补充：
   ```
   python scripts/convert_document.py 质量手册.txt --standard iso9001 --template QMS-PF-013 --org "示例科技" --out ./converted
   ```

> 说明：该能力同样适用于 28 个标准中的任一标准；当标准无专属模板时（如 `iso28000`），脚本自动回退通用 Annex SL 框架 + 通用程序模板完成转换。
