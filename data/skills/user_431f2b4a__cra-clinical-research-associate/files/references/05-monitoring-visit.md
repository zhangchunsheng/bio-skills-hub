# W4 · 监查访视包

一次访视的完整闭环：**计划 → 方式选择 → 准备 → 现场 → 报告 → 跟进**。

## 一、访视前准备

1. 取该院**最新监查要求**（→ `references/10-hospital-guide.md`）：预约方式与提前量、报到流程、报告时限与提交对象、主题/命名要求、是否需《监查申请表》。
2. 核对资料：方案与现行版本、上次监查报告与遗留问题、待核数据质疑、本次重点（首例？关键数据？）。
3. 预约：多数机构要求**提前预约**（常见提前 1 周），邮件告知 PI 与机构办并抄送相关人员。
4. 现场物品：证件、委托函、监查计划、SDV 清单（见 `references/shared/sdv-checklist.md`）、上次遗留清单。

## 二、监查方式与基于风险的监查（RBM）

> **法规依据（现行）**
> - **GCP 2026 第四十条**：申办者应当**基于风险**对临床试验全过程进行质量管理，监督措施的**范围和程度应当符合目的，与临床试验的复杂性和风险相称**。
> - **GCP 2026 第四十一条（三）**：应在**每个阶段和环节采用基于风险的方法进行质量控制**；**在临床试验中，监查和数据管理是主要的质量控制活动**；申办者应当**委派合格的监查员**对临床试验实施监查。
> - **GCP 2026 第四十二条**：申办者应当对临床试验进行**风险管理**（识别可能对关键质量因素产生有意义影响的风险，评估可能性、可被检测程度、对参与者保护和结果可靠性的影响）。
> - **ICH E6(R3)**：以 **RBQM（基于风险的质量管理）** 为核心；并将**远程监查**等数字化方式纳入 GCP 框架。

**监查方式（按方案与监查计划确定，不是自由裁量）**

| 方式 | 适用 | 注意 |
|---|---|---|
| 现场监查 | 关键数据、首例、问题中心、核查前 | 仍是默认与最可信方式 |
| 中心化监查 | 全中心数据趋势、指标化异常筛查 | 依托 EDC/统计指标，不替代现场 |
| 远程监查 | 低风险中心、常规复核、不可抗力 | **须经方案/监查计划允许**，并保证数据安全与可追溯 |

**基于风险的监查动作要点**
1. **识别关键数据与关键流程**（如入排、主要终点、ICF、随机/盲态、IP 管理、SAE 上报）。
2. **对风险分级**：发生可能性 × 可检测程度 × 对参与者保护与结果可靠性的影响。
3. **监查强度与风险相称**：高风险 → 提高频次/扩大范围/现场核查；低风险 → 可减少范围或采用远程/中心化。
4. **把 RBM 结论写进监查报告**：本次为何查这些、为何没查那些——**这是核查会问的问题**。
5. 出现新的风险信号时**动态调整**监查计划，并留痕。

> ⚠️ RBM ≠ 减少监查。**减少的必须是低风险项，关键数据与关键流程不能因 RBM 而免查**；若方案或公司 SOP 有更严规定，从其规定。

## 三、现场流程

1. **报到**：按院内要求先到机构办报到（部分机构要求先到机构办、再到 PI 处），完成监查登记。
2. **SDV 源数据核对**：按 `references/shared/sdv-checklist.md` 逐项核对，重点 ALCOA+、关键数据与 CRF 一致性。
3. **ICF 专项核查**（核查头号重点，见下）。
4. **与研究者沟通**：确认入组进度、AE/SAE、方案偏离、药品与样本情况，记录待办与责任人。
5. **药品与样本抽查**：数量、温控记录、回收/销毁（详见 `references/07-data-supplies.md`）。
6. **数据治理与计算机化系统抽查**：稽查轨迹、账号一人一号、权限与授权分工表一致、电子签名合规（详见 `references/07-data-supplies.md` 子模块 6）。

## 四、ICF 专项核查（必须逐受试者核）

- 签署**时间早于任何试验相关操作**（含筛选检查、停药）；
- 使用的是**伦理批准的现行版本**；
- 签署页、日期、联系方式完整；**受试者本人签字**（代理人情形按伦理批准程序）；
- 版本更新后是否按条件**重新知情同意**。

> 发现 **ICF 重大缺陷**（如先检查后签署、版本错误）→ 触发**受试者守护红线**：明确提示「需立即上报」并给出对象（申办方 / 伦理 / 机构）。

## 五、访视后报告

- 提交时限与对象**按该院要求**（常见监查后 5 个工作日内；有的要求先登记、有的发机构邮箱、有的按"项目名称+第 XX 次监查小结"命名）。
- 报告结构见 `references/shared/monitoring-report-structure.md`。
- **必须带出上次遗留问题**及其闭环状态——这是最容易被核查挑毛病的地方。
- 报告统一带 ALCOA+ 脚注（→ `references/13-doc-output.md`）。

## 六、遗留问题跟进（M2 顺带记账）

出报告时**自动登记**：遗留问题清单、责任人、期限；并推算**下次访视窗口**。不向用户索要，从对话与报告中提取。

## 输出形态

- 监查准备清单（含院内要求 + SDV 清单）
- 监查计划/风险要点回顾（RBM 依据）
- SDV 核对表（逐项 Y/N/NA/待核）
- ICF 核查结论（含风险提示）
- 监查报告 / 监查小结草稿 + 遗留问题跟进表

## 边界

- **院内没有监查报告模板**——模板在申办方/CRO 手里。正确姿势：`references/10-hospital-guide.md` 取院内要求（时限/命名/提交方式）＋ 用户上传的公司模板 → 融合产出。**用户没给模板时给通用合规版，不追着要。**
- 只出动作与清单，不引具体医院规矩（引 `references/10-hospital-guide.md`）、不自造条款（引 `references/01-gcp-knowledge.md`）。
- **监查方式的选择权在方案与监查计划**，本技能只给依据与建议，不替申办方决定。
