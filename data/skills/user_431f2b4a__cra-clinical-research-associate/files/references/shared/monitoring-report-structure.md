# 监查报告结构（通用骨架）

> 各申办方/CRO 模板不同；**以公司模板为准**，本骨架用于无模板时的通用合规版。
> **院内不提供监查报告模板**——院内只规定"何时交、交给谁、怎么命名"。

## 建议结构

1. **基本信息**
   - 项目名称 / 方案编号、研究中心、监查类型（首次 / 常规 / 关闭）、监查日期、监查员姓名
2. **本次监查范围与方式**
   - 现场 / 中心化 / 远程；核查的受试者数量与编号（**注意：不记录受试者可识别信息**）
   - 核查的重点模块
   - **基于风险的监查（RBM）逻辑**：本次识别的关键数据/关键流程与风险点、**为何这样确定监查范围与强度**（依据 GCP 2026 第四十至四十二条 / E6(R3) RBQM）——**核查必问，不要省略**
3. **受试者与入组状态**
   - 筛选/入组/完成/退出数量，与上次对比
4. **核查发现**
   - **知情同意**核查结论
   - **源数据与 CRF 一致性**（SDV）结论
   - 试验用药品与生物样本
   - AE/SAE 与方案偏离
   - 按"符合项 / 待改进项 / 重大问题"分级，重大问题给出依据与建议
5. **上次遗留问题的闭环情况**（逐条：问题 / 上次结论 / 本次状态）
6. **本次新建遗留问题**
   - 问题描述 / 影响 / 建议措施 / 责任人 / 要求完成期限
7. **结论与建议**
8. **附件**：SDV 核对表、照片/复印件清单（如适用）
9. **ALCOA+ 脚注**：来源 + 版本 + 日期 + 生成时间

## 命名与提交（按院要求，示例）

- 常见命名：`项目名称 + 第 XX 次监查小结`
- 常见提交：发机构指定邮箱 / 平台上传 / 先到机构办登记
- 常见时限：监查后 5 个工作日内（**以该院最新要求为准**）

## 红线

- 不写入受试者可识别信息。
- 不隐瞒重大发现；发现重大合规风险必须明确提示上报对象。
