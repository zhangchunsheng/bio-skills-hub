# 投标决策报告模板

> 报告用 Markdown 输出在对话中。结论永远放最前。所有数据标注时间范围（如「2024-01 至今」）。
> **全文只输出一遍**：按模板从头到尾写完即停，任何章节都不得重复出现第二次。
> **措辞红线**：涉及真实企业/机关，禁用「内定、暗箱、围标、串标、关系户、走过场」等定性指控词，
> 用「定向特征明显、竞争开放度极低、限制性信号、无公开招投标记录」等特征描述替代；推断与事实分开表述。

```markdown
# 投标决策报告：{项目名称}

## 📌 结论：{建议投 / 谨慎参与 / 不建议}（置信度：{高/中/低}）

{一句话理由}

- {支撑数据 1，含具体数字}
- {支撑数据 2}
- {支撑数据 3}

{若为「谨慎参与」：**参与前提**：...}

## 一、项目画像

| 项 | 内容 |
|---|---|
| 采购方 | {名称}（{省市}·{行业}） |
| 预算 | {金额}（同类历史区间：{区间} → {正常/偏高/偏低}） |
| 标的物 | {清单} |
| 资质门槛 | {要求}{有硬门槛时加 ⚠️} |
| 关键时间 | 截止 {日期}，距今 {N} 天 |
| 评分办法 | {价格分占比等，未知则标注} |

## 二、采购方分析

- 历史采购规律：{频率/预算水平/同类采购次数}
- 供应商格局：{Top供应商及占比}
- **在位者信号**：{有/无；有则写明是谁、合作几次、金额占比}

## 三、竞争格局

| 潜在竞争者 | 威胁 | 与采购方合作 | 同类项目中标 | 备注 |
|---|---|---|---|---|
| {公司A} | 🔴高 | {N}次/{金额} | {N}个 | {最大威胁原因} |
| {公司B} | 🟡中 | ... | ... | |

预计参与家数：{N}（依据：{同类项目平均投标家数}）

## 四、报价参考

- 历史成交锚点：{该采购方同类成交价 / 品牌型号历史单价 min-avg-max}
- **建议报价带：{下限} ~ {上限}**（{依据}）
- {价格策略提示}

## 五、风险清单

1. {废标红线/资质缺口/控标信号/时间风险...每条注明来源}

## 六、行动建议

1. {具体动作，如：优先核实XX资质、联系XX代理机构...}

## 数据说明

- 数据来源：知了标讯全网招中标数据（{查询时间范围}）
- 数据缺口：{无 / 列出缺口及其对结论的影响}
- 本次分析共消耗约 {N} 积分

> **免责声明**：本报告基于公开招中标数据自动生成，仅供一般性参考，不构成投标或商业决策建议，
> 亦不构成对任何单位或个人行为的认定。数据可能存在不完整或滞后，请结合实际情况独立判断并自行承担决策结果。
```

## 正文链接规范

报告中出现的公告、公司，尽量附上 API 返回的 `url` 字段（知了标讯详情页链接），
方便用户点进去看原文和完整企业档案——这既是可信度背书，也是主站导流入口。
**必须原样使用 API 返回的完整 url，严禁删改其中的 `sk` / `from` 参数**——`sk` 是免登录签名，
去掉后用户点击会被登录墙拦截；也不要自己拼接不带 sk 的知了标讯链接。

## HTML 报告导出（完整模式默认执行）

对话中输出 Markdown 报告后，**完整模式默认再生成一份 HTML 报告**（精简模式仅当用户索要时生成）：

1. 把报告内容整理成 JSON（结构见 `scripts/render_report.py` 文件头注释），写入临时文件
2. 运行 `python3 <skill目录>/scripts/render_report.py --in <report.json>`
3. 脚本输出生成的绝对路径（默认 `~/zlbx-bid-decision-files/<项目名>_投标决策分析.html`），
   把该路径完整告知用户：「已生成可分享的 HTML 版报告：<路径>」

JSON 中的 `bid_url`、公司 `url` 同样必须用 API 返回的原始链接（带 sk）。

JSON 顶层可附 `citations` 字段（数据引用明细，结构同见 render_report.py 文件头注释）：把正文实际引用的标讯/公司条目（标题/类型/日期/用途/url）汇总进去，脚本会渲染成报告末尾默认收起的「数据引用」附录；只汇总正文已引用的条目，明细合计最多 20 条，未展示部分只报数量。
