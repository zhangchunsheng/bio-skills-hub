# pharma-weekly-recap｜医药生物行业周报

> 用大白话说：**每周六早上，自动把这一周医药圈发生的事整理成一份周报。**
> 卖方出了哪些深度报告、谁被首次覆盖了、哪家公司在回购或减持、
> 涨得最凶和跌得最惨的股票分别是谁、为什么——四大块一次做完。

---

## 它解决什么问题

周一到周五你忙着看盘、开会、跑调研，一周下来会漏掉很多：

- 这周卖方**发了哪些值得看的深度报告**？（不是标题党，是页数 ≥ 15 的真东西）
- **哪家公司被首次覆盖了**？这是最高优先级的卖方信号
- **大股东在增持还是减持？** 谁在回购？这些产业资本动作比研报诚实
- **涨幅榜、跌幅榜前十是谁**，各自因为什么涨、因为什么跌
- 想回看某一周发生了什么，得翻好几个 App

这个 skill 一条命令搞定，也可以挂在定时任务上每周六自动跑。

---

## 核心思路：五路并发采集，一次汇总成稿

```
先算好日期 ──► A 卖方深度报告（页数≥15）  ─┐
               B 新推荐 / 首次覆盖 / 上调   ├─► 汇总成稿 ──► 落盘 + 展示
               C 增减持 / 回购 / 股权激励  ─┤
               D 周涨跌幅 Top10 / 跌幅 Top10 ─┘
                                    └─► E 涨跌原因（依赖 D，最后跑）
```

A、B、C、D 四路**互不依赖，并发跑**；E 要等 D 出结果才能开始。
每路最多 30 条，按日期降序。

---

## 四个红线（写稿时的硬约束）

1. **零编造** —— 每个数字、每份研报、每则公告都要能在采集到的素材里找到出处
2. **空数据如实标注** —— 某模块确实没有就写「本周无相关信息」，不留空、不敷衍
3. **口径写清楚** —— 周涨跌幅是周五收盘相对上周五收盘；如果用了滚动「近一周」口径必须注明
4. **涨跌原因要交叉验证** —— 至少 2 个独立来源才写进报告；只有一个来源就标「据 XX 报道」；
   查不到就写「本周未检索到明确催化事件」，**绝不臆测**

---

## 三个最容易忘、但很关键的点

### 1. 禁止用「深度」当筛选词

大量高质量报告（首次覆盖、专题研究）标题里根本没有"深度"两个字，
这么筛会**系统性遗漏**。判断深度用**页数 ≥ 15**，这是唯一硬性条件。

### 2. 数据源要检查，但断了也要继续

`comein-mcp-all`（进门）和 `mx-ds-mcp`（东财妙想）**两个都断开也要继续执行**，
各路自动降级到联网检索，并在周报「数据说明」里注明。**不要因为源断了就空着不写。**

### 3. 中间素材别删

`tmp/{session_id}/` 下的 01~05 号素材**生成后不要删除**，留着便于核对复查。
周报里出任何数字争议，都要能回溯到这几份原始素材。

## 怎么跑

用户说「生成医药周报」「本周医药行业复盘」「医药一周回顾」等即可触发。
默认取**本周（周一至周五）**；用户明确说「上周」时加 `--offset -1`。

挂定时任务（每周六 07:00）：

```
automation_update  mode=create  scheduleType=recurring
rrule=FREQ=WEEKLY;BYDAY=SA;BYHOUR=7;BYMINUTE=0
```

**修改或删除定时任务必须用 `automation_update`，不能用 shell 或数据库命令。**

不适用：单只个股深度分析、实时行情查询、非医药行业。

---

## 输出长什么样

- 周报文件（落盘 + `present_files` 展示）
- 四大模块：卖方深度报告 / 新推荐与首次覆盖 / 增减持回购股权激励 / 涨跌幅前十及原因
- 深度报告再拆**个股深度**与**行业赛道专题**两张表
- 回复正文给**≤10 条核心要点摘要**（最值得看的 1~2 条主线、最值得看的首次覆盖、
  产业资本方向性信号、涨跌幅第一名及原因、数据完整性提示）
