# 06 变更管理与全生命周期

> 用途：回答「模型更新要重新注册吗」「PCCP/PACMP/变更注册怎么选」「算法漂移怎么监控」。
> 核对基准日：2026-08-27

## 1. 三种变更管理机制对比（核心决策表）

| 机制 | 地区 | 性质 | 核心逻辑 |
|---|---|---|---|
| **PCCP**（预定变更控制计划） | 美国 FDA | 预批式 | 首次申报时预规划更新路径，范围内更新无需新申报 |
| **PACMP**（上市后变更管理协议） | 日本 PMDA | 预批式 | 与监管预先约定变更方案，受监督执行 |
| **变更注册** | 中国 NMPA | 后审式 | 重大变更触发重新注册/变更注册；创新通道试点灵活方案 |

**选型建议**：
- 计划持续学习/高频迭代的产品 → **FDA 优先**（PCCP 最成熟，迭代周期"周/天"级）；
- 日本市场 → 主动与 PMDA 谈 PACMP；
- 中国市场 → 变更保守，**提前与审评中心沟通变更策略**，评估创新通道灵活方案试点。

## 2. 变更分类判定（通用框架）

**重大变更（需重新注册/申报）**：
- 算法架构改变（模型结构、训练范式）
- 预期用途扩大（新适应症、新人群）
- 核心性能指标显著变化（敏感度/特异性漂移超阈值）
- 运行环境重大升级（硬件/平台）
- 训练数据来源/规模重大变化（NMPA：核心权重重新训练）

**轻微变更（体系控制，无需立即申报）**：
- 不影响核心临床功能的 Bug 修复
- UI/界面优化
- 文档更新

## 3. 变更影响评估（IA）三步

1. **影响范围**：变更影响哪些功能、人群、临床决策？
2. **风险重评**：变更后安全有效性风险是否超出原批准范围？
3. **验证方案**：需要哪些回归测试/临床验证来证明变更安全？

## 4. 算法漂移监控（上市后核心）

| 漂移类型 | 含义 | 监控手段 |
|---|---|---|
| 数据漂移（Data Drift） | 实际输入分布偏离训练分布 | 输入分布统计监控、告警阈值 |
| 概念漂移（Concept Drift） | 目标关系随时间变化 | 性能指标定期重估（敏感度/特异性） |
| 模型退化 | 长期运行性能下降 | 真实世界数据对照、金标准抽查 |

**建议**：建立上市后性能监测（RWPM）体系——实时捕捉数据漂移与性能退化，触发时按变更管理流程处理。

## 5. 全生命周期节点控制

```
需求提出 → 数据准备 → 开发训练 → 验证 → 注册申报 → 上市 → 变更 → 退役
   │          │          │        │       │         │      │      │
 预期用途    数据集     GMLP    独立验证  三地路径    监测   变更控制  数据清理
 分类界定    合规      文档     临床证据  PCCP计划   漂移   影响评估  责任交接
```

## 6. 变更管理实操检查清单

- [ ] 建立版本控制规范（如 NMPA 要求 V1.0.0.0 命名）
- [ ] 变更分类判定（重大/轻微）——用工具 `change` 命令辅助
- [ ] 重大变更：走重新注册/变更注册或 PCCP 计划
- [ ] 轻微变更：体系内记录、回归测试
- [ ] 上市后漂移监控体系（数据/概念/模型退化）
- [ ] 变更文档归档（审计证据）
