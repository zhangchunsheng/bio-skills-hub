# prompt.md —— 可复用 Prompt 模板库

本文件沉淀两个可复用逻辑：**需求提取逻辑**（把用户灵感解析成 6 问字段）与**确认话术生成逻辑**（把缺失/模糊项转成选择题与追问）。两个模板均用 `{{变量}}` 占位，供 Skill 在实际对话中填充后调用。

---

## 一、需求提取逻辑（Requirement Extraction）

**用途**：把用户任意形式的灵感/设定，结构化抽取为"爆款基因 6 问"字段。
**输入**：`{{user_input}}`（用户原话，可能是一句话、一段设定、或已有文档路径）。
**输出**：结构化 JSON（见字段表），缺失项标 `null`，禁止脑补关键设定。

### Prompt 模板

```
你是一名网文爆款结构分析师。请把用户的创作输入，严格抽取为以下 6 个字段。
只做抽取与归类，不创作新设定；缺失或模糊的字段填 null。

=== 用户输入 ===
{{user_input}}

=== 抽取字段（严格按此键名输出 JSON） ===
{
  "emotion_tag":    "情绪标签（单一主情绪，如：打脸爽文/极致虐恋/脑洞系统/爆笑反套路/悬疑惊悚）。只能选最主导的一个；若用户给多个，取最强信号那个，其余进 notes。",
  "genre":          "题材与风格（如：都市现实/现代言情/古言/悬疑/科幻）。",
  "protagonist":    "主角设定（性别+身份+初始处境，如：女性前豪门弃妇/男性外卖员）。双主角请写双人。",
  "contrast_point": "主角最大反差点（表面 vs 真实，如：被虐弃妇→隐藏身份大佬）。",
  "core_conflict":  "核心冲突（一句话贯穿全本的矛盾，如：复仇雪恨/爱情阻碍/成长突破）。",
  "chapters":       "计划章节数（整数；未提填 null）。",
  "notes":          "用户附带的其他有效信息（配角、世界观、参考作品等，可多条）。"
}

=== 判定约束 ===
- emotion_tag 主情绪唯一，不可堆多个。
- contrast_point 必须是一个"可成立"的反差（表面与真实能形成张力），否则标 uncertain。
- core_conflict 必须能支撑全本，否则标 uncertain。
- 不确定项不要编造，标 null 或 uncertain，交给确认话术处理。

=== 输出格式 ===
仅输出 JSON，不要解释。
```

### 字段定义速查

| 字段 | 含义 | 取值约束 |
|------|------|----------|
| emotion_tag | 主情绪标签 | 唯一，不可多 |
| genre | 题材风格 | 自由文本 |
| protagonist | 主角设定 | 性别+身份+处境 |
| contrast_point | 反差点 | 表面↔真实张力 |
| core_conflict | 核心冲突 | 可贯穿全本 |
| chapters | 章节数 | 正整数或 null |

## 二、确认话术生成逻辑（Confirmation Script）

**用途**：根据提取结果中 `null` / `uncertain` 的字段，生成选择题或追问，引导用户补全。只问缺失项，不重复已确认项。
**输入**：上一步的 JSON（记为 `{{extracted}}`）+ 可选 `{{prior_settings}}`（用户已有设定）。
**输出**：一组话术（每个待定字段一条），含选项与"可自填"提示。

### Prompt 模板

```
你是网文创作引导助手。基于以下已提取的爆款基因字段，对仍为 null 或 uncertain 的字段，
生成确认话术。每个字段生成 1 条，格式：题干 + 2-4 个选项 + "或你直接描述"。

=== 已提取字段 ===
{{extracted}}

=== 用户已有设定（若有，优先沿用，不要推翻） ===
{{prior_settings}}

=== 生成规则 ===
1. emotion_tag 缺失：给出 5 类主情绪选项（打脸爽文 / 极致虐恋 / 脑洞系统 / 爆笑反套路 / 悬疑惊悚），并提示可自填。
2. genre 缺失：按 emotion_tag 推荐 2-3 个适配题材。
3. protagonist 缺失：问性别+身份+初始处境，给常见人设选项。
4. contrast_point 为 uncertain：请用户确认"表面人设 vs 真实底牌"，给出反差示例。
5. core_conflict 为 uncertain：请用户确认贯穿全本的核心矛盾，给示例。
6. chapters 缺失：给 50/100/150/200 档位建议（爽文偏短、言情偏长）。
7. 若字段已全部齐全，输出"基因已锁定，可进入规划阶段"，不强行追问。

=== 话术风格 ===
简短、像做选择题；每条带编号；不解释为什么，直接给选项。

=== 输出 ===
按字段顺序列出待确认话术（Markdown 列表）。
```

### 确认话术示例（emotion_tag 缺失时）

> **Q1 主情绪标签？** 这部小说的"主情绪"只能有一个，选最贴合的：
> - A. 打脸爽文（压抑→反转→碾压）
> - B. 极致虐恋（误会→拉扯→崩溃→追悔）
> - C. 脑洞系统（金手指→逆袭→正反馈）
> - D. 爆笑反套路（预期打破→神转折）
> - E. 悬疑惊悚（谜团→试探→真相）
> 或你直接描述想要的爽点。

## 三、复用说明

- 两个模板解耦：先跑"需求提取"得 JSON，再跑"确认话术"补 null。
- 变量填充来源：用户当前消息、`references/examples.md` 的案例可作少样本示例、`references/rules_*.md` 的规则可作选项生成依据。
- 当用户已带完整设定时，需求提取应直接复用，确认话术应输出"已锁定"提示，跳过追问。
- 这两段 prompt 可被 Skill 在阶段一直接拼装调用，也可被脚本 `emotion_curve.py` 之外的规划步骤引用。
