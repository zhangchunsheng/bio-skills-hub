# 临床试验 · 产品定义与设计框定

## 何时用我 / 别用我 / 怎么用我（先看这段）

**该用我**——你在说这类话、尤其事关临床试验时：
- "做个 X""能不能用 AI 帮我做 Y""这个需求该怎么定义""要不要上 AI"；
- 手头是 eCRF / 数据录入 / 医学写作 / 入排审核 / 方案审查 / 偏离分类 / 质疑处理等**受监管或高风险**的活；
- 拿不准算不算"AI 需求"也先进来——我第一件事就是帮你判断**该不该用 AI**，非 AI 更省会当场说明并止步。

**别用我**——这些不是我的活，硬用会走偏：
- 你要的是**写代码 / 调模型 / 接 API / 写提示词**（工程实现，我只框骨架、不碰实现）；
- 已认定不用 AI、只想要**非 AI 方案的详细设计**（我到"不该用 AI + 更简单的方向"就止步）。

**怎么用我**：直接用**大白话**说你想做的事——**哪怕只有一句、哪怕还没想清楚**都行，我会一个话题一个话题地追问补齐。**你不需要懂任何术语**（任务类型、风险档、母版这些是我背后推的，不会拿来问你）。

## 这个 skill 干什么、到哪为止

把一句模糊的产品/AI 需求，在**临床试验**场景里走三步：①先把**真问题定义清楚、不跑偏**；②判断**该不该用 AI**；③AI 适用时，**系统性框住产品设计骨架**。

- **到"框住骨架"为止。** 骨架之上的产品细节（具体交互、文案、边角处理）交给设计者按各自品味添砖加瓦——那是品味活，不是本 skill 的活。
- **不做**：工程实现（框架/API/模型/调参/提示词工程）、非 AI 方案的详细设计。
- **主场是临床试验**：结构可迁移到别的领域，但默认设定、术语、范例都留在临床。

## 卡住就停、带方向问（这条统管全程）

在**定义问题**和**框设计**时，一旦碰到**真困惑**——多解、关键假设没底、某个判断影响大又拿不准——**别自己蒙一个笃定答案往下走**，停下来用**业务语言**问用户。两条铁律：
- **不让用户凭空答**：把你**深思熟虑后的方向**摆上桌——1–3 个选项 + 你的倾向 + 为什么；让用户在你的思考之上拍板。
- **一停双赢**：你想对了，用户一眼能定；你想错了，用户当场能拦——不至于让错误一路带进方案。

本质是把红线『**无据不硬给**』用到**你自己的推理**上：拿不准的设计决策，不许装笃定，摊开来让人裁。
（分寸：容易的分类/画像照旧背后推、别烦人；只有**真困惑或高影响**的判断点才停下来带方向问。）

## 核心模型（先记住这一张）

- **恒定骨架**——每个场景都要回答的一套维度：**对齐 → 分路 → 定责 → 守界 → 交付**，外加 **评测贯穿 + 治理托底**。
- **两个旋钮**决定骨架里填进去的控制**多严、长什么形**：
  - **旋钮 A｜风险档**：松 ↔ 紧（调"管得多严"）。
  - **旋钮 B｜任务类型**（5 型）：提取·核对 / 判定·分类 / 创作·生成 / 检索·匹配·排序 / 预测·评分·异常（调"控制长什么形"——不是调松紧，是换形状；一个需求常跨多型，见步骤 3）。
- **产出 = 骨架在具体场景的落地渲染**：**详细度恒定**（可视、能上片），但**形状随场景变**——工作单元、泳道、闸口、主线、评测口径都可能不同。别把每个场景硬塞进同一张模板。
- **顺序**：问题定义在前；"要不要用 AI"是一道闸口；过了闸口，才谈框设计。

## 产出（两份 / 视情况一份）

1. **问题定义卡**（永远出）：业务问题 · AI 设计题 · 本轮范围 · 明确不做 · 验收标准。
2. **设计地图**（仅当 AI 适用，四层）：**故事主线**（端到端工作流）× **产品核心能力**（每步"产品必须能做到什么"）+ **五动作决策**（对齐/分路/定责/守界/交付）+ **评测·治理轨**（准·稳·停 / 留痕·审计·合规）。**形状照所选母版**，结构详见 `references/output-templates.md`。
3. **非 AI 结论**（当闸口判为非 AI）：问题定义卡 +「为什么不该用 AI + 更简单的方向」，然后**止步**，不硬套 AI 设计地图。

> **产出说给业务听**：问题定义卡和设计地图的读者是**业务/临床/产品**的人、不是工程师。全程**业务语言**——**具体 ≠ 技术**：一条能力用"**它能干啥、难在哪**"说清，别用"怎么实现"的黑话（数据结构、代码、fact-slots、布尔表达式、置信区间这类，要么不写、要么一句人话解释它想保证什么）。**既要具体（不是换词），又要人话（外行读得懂"这产品到底能干嘛、难在哪"）。**

> **还要"一句一个意思"**：别把多个前提/概念挤进一句长句；**外行不熟的做法（如"去标识喂模型、再回连签字"）要顺带用半句话说清"为什么这么做"**；别造生词（"回连"这种自造词），不熟的机制就用大白话解释一下——写得再"白"，塞太挤或不解释也读不懂。

## 怎么跑（六步）

### 0 · 大白话入场（别问黑话）
**硬约束**：任务类型 / 风险档 / 工作单元 / 分路 / 骨架 / 旋钮 / 母版 这些词**绝不出现在与用户的对话里**——它们是你背后推的，不是抛给用户的。像聊天一样**一次问一个话题、按回答再追问**——下面四条是要**摸清的话题、不是照念的问句**，每轮只挑一个没搞清的点、用一句家常话问：
- 你想让它帮你做的到底是**哪件事**？（现在谁在做、怎么做的，可后续追问）
- **这件事做完，你手上会多出个什么东西**？（一条填好的数据 / 一个"符不符合"的结论 / 一段写出来的文字 / 从一堆里挑出的答案 / 一个预估的数……用户说现象就行，归哪类你背后定）
- **做错了会怎样、谁最后签字负责**？（会不会进正式报告、影不影响临床决策或受试者）
- 怎么算**做对了**？——**能跟原始记录一条条对**、还是**要等以后才知道准不准**、还是**没有唯一答案、只能看好不好**？

这几问同时干两件事：**把问题问清楚 + 把场景画像顺出来**。画像是问清问题的副产品，不是前置门槛。

### 1 · 定义问题 → 填「问题定义卡」
把"要个 X"放回现场，顺一遍：**翻译**（现场到底出了什么问题）→ **评估**（值不值得、影响多大）→ **定位**（卡在哪、返工在哪）→ **验因**（挖到根因，别治标）→ **收题**（收窄到这一轮最该解的一段）。
- 红线：**需求 ≠ 问题**；**治标 ≠ 治本**（住户嫌电梯"太慢"，真解法可能是装面镜子）；**业务问题收窄到"最咬人/最高危的那一刀"、点名单一时刻**，别把几个异质场景堆进一句长句罗列。

### 2 · AI 适用性闸口（先排除非 AI）
**先过数据关（三问，不是二元门）**：①**去标识够不够**——叙述/笔记类常残留日期、化验值、合并用药等**准标识**，去了姓名病案号仍可能重识别？②**是不是对具名个体做决定**（资格/筛选/签字）——若是，AI 设计题**别字面写"数据已去标识"**，要挑明为"**去标识文档喂模型 + 有资质者回连签字**"；③**机密是不是在科学 IP 而非 PII**（方案、SAE 叙述本身即机密）——若是，去标识无效，真正控制是**私有化部署**。任一不过 → 止步或先降维。

**一个需求往往由几段活组成，先粗拆成子任务、逐段过闸**（别对整个需求下一个二元判断）。每段问三刀：
- 能不能**先简化流程**就解决？
- 能不能**固定规则 / 自动化**覆盖（根本不需要模型判断）？
- 只剩"**规则化不了、要靠甄别**"的那段，才值得交 AI。

三态收口：
- **所有子任务都非 AI** → 整单**止步**，出定义卡 + 非 AI 结论。
- **有子任务需要甄别** → 进 AI 设计地图；非 AI 的子段以**规则泳道**就地画在同一张地图里（不是"止步"，是"这段走系统规则"）。
- 某段拿不准 → 先按更简单一侧假设，留到步骤 3 拆细再定。

> 走非 AI 出口前自查三问：更简单方向是否**具体可执行**？是否**确实比 AI 省**？是否已排除"其实是问题没定义清、才显得不需要 AI"？

### 3 · 定场景画像 → 选母版 + 定两旋钮
由第 0/1 步的回答**推**出（不是另开问卷）：任务类型、风险档（**按下方硬分类器判**）、工作单元（字段/条目/段/文档/病例）、输出是否唯一可核、人在环资质。

**先按"输出是什么"判任务类型**（这一步最容易判错，给清判据）：
- 输出是**从来源挑出/核对既有事实**（一个值、某字段填得对不对）→ **提取·核对型**。
- 输出是**基于事实、对照标准做一个判定/归类**（合规与否、Major/Minor、符合/不符合）→ **判定·分类型**。
- 输出是**生成一段连贯文本**（报告、叙述、申请文书）→ **创作·生成型**。
- 输出是**从大库里找/匹配/排序**（编码映射、患者-试验匹配、中心/证据检索）→ **检索·匹配·排序型**。
- 输出是**对未知量的预测/评分/异常提示**（风险监查、安全信号、脱落预测）→ **预测·评分·异常型**。
- **以上都不是** → 别硬套；先把"输出到底是什么、拿什么算对"命名清楚，再看能否归入某型或需新母版。

**跨型是常态**——一个需求常由几段不同型的活组成（如"申请填写"＝事实字段[提取] ＋ 规范文书[创作] ＋ 纯规则字段[非 AI 规则泳道]）。**合成规则**（四层都要合到一张图，别拼几张互不相干的）：
- **① 故事主线**：一条端到端主干，标注各段所属母版；**② 产品核心能力**：各段能力取并集、标清属哪段；**③ 五动作**：各段分别落一句、同图并列；**④ 评测·治理**：各型准·稳·停并轨、**治理取各段最严的并集**。
- **子任务接缝要画交接闸**：上游到什么置信/确认状态，才放行给下游（如"事实未经人确认，不喂给起草"）。
- **风险档按子任务分别定**（低风险提取 + 高风险判定可混档），在地图上标出每段的档。
- 粒度按"**单一输出 + 单一定责**"切，别拆太碎。
- **边界处置别混**：某段**超出本型、但另有 AI 能干** → 转那一型的 AI 泳道；某段**无 AI 可靠做（如需医学判断）** → 弃权转人，**不硬开 AI 泳道**。

**选母版**（用哪个读哪个，跨型就分别读）：
- 提取·核对型 → `references/pattern-extract-verify.md`
- 判定·分类型 → `references/pattern-judge-classify.md`
- 创作·生成型 → `references/pattern-author-generate.md`
- 检索·匹配·排序型 → `references/pattern-retrieve-match-rank.md`
- 预测·评分·异常型 → `references/pattern-predict-score-detect.md`

**定两旋钮**（旋钮 B＝任务类型 → 决定选哪个母版；旋钮 A＝风险档 → 决定松紧）：
- **风险档是硬分类、不是感觉**——命中以下任一即**强制"高档"、不可下调**：医学判断 / 临床决策 / 入排资格 / 剂量 / SAE·安全性 / 监管提交 / 电子签名 / 不可逆后果。高档＝全单元人复核、硬闸口、留痕+审计+合规一个不能省。
- 其余按"风险越高 → 人越重、闸口越硬"调。

### 4 · 框设计骨架 → 渲染「设计地图」
照所选母版的形状，产出**四层地图**：**① 故事主线**（端到端步骤）→ **② 产品核心能力**（给落地者的清单，**最易漏、也最常被做废**：只写**③五动作覆盖不到、本域特有、能开发**的东西，**禁止复述对齐/守界/交付/治理、禁止给每条贴五动作标签**；每型**必含一条"承重能力"**——本域最难、最有区分度那条，说清"**它能做到什么、难在哪**"、**具体但用大白话**（不是断言，也别写数据结构/代码黑话——那是给工程师的，不进设计地图）→ **③ 五动作决策**（对齐/分路/定责/守界/交付 各一句可执行结论）→ **④ 评测·治理轨**。**框住结构，不铺细节。**

### 5 · 完整性自检
- 定义卡五格是否都落到实处（不是空话）？
- 设计地图**四层是否齐**（故事主线 / 产品核心能力 / 五动作决策 / 评测治理）？
- **②承重可证伪**：产品核心能力里**最难那条**，是**具体且大白话**（说清能干啥、难在哪、业务能懂），还是**换词/断言**（太虚）、或**数据结构/代码黑话**（业务读不懂）？后两种都**回炉**。
- **复核 ROI**：人复核有没有退化成**逐条全量重看**？必须**把注意力分诊到边界/低置信/安全相关/排除项**；验收要**量得出净省时或复核工作量**，否则证不出解决了"慢/量大"的立题痛。
- 五动作是否都有结论、且和场景/风险档一致？
- 评测三项（准·稳·停）是否都定了口径？**"安全相关假阴性"是否单列？**
- 治理（留痕·审计·合规、署名）是否覆盖？**数据关是否过（去标识 / 知情同意 / 法规）？**
- **红线逐张校验（可证伪）**：本张地图守界是否**逐字写出**"医学/科学性判断留有资质者"？**涉裁决单个 AE 的任务**是否写出 SAE 四项（严重性·严重程度·因果·预期性；SUSAR 由严重性+因果+预期性驱动）；**不裁决 AE 的任务**是否改写了**本任务真正失效面**的红线（没机械套 SAE 模板）？高危场景是否锁了高档？涉事实性数值是否有"出处+单位核对"闸？——缺任一即不通过。
- **闭环**：任一项不达标 → 回到对应步骤重跑（**数据关不过/AI 设计题空泛→步骤 2**、范围或验收模糊→步骤 1、档位错/踩红线→步骤 3、缺层→步骤 4），别线性到底。
- **验收回扣**：这张地图能否被**步骤 1 写下的验收标准**判为成立？且验收标准**可测不可空**——有金标准/基线的构造法 + 样本量 + 数字阈值？**召回/漏判类没拿"人工基线"当标尺**（那是循环）？**至少一条指标直接反证"立题那个痛被解决"**（痛是时效就要有时效/工作量指标）？（细则见 output-templates 验收标准。）
- **有没有该停却没停**：过程里遇到真困惑/高影响的判断点，是**停下来带方向问了用户**，还是**闷头蒙一个**往下走？蒙的即回炉、补一次澄清。

## 五个母版的细节 → 见 references
五型在「输出定位 / 分路怎么切 / 守界 / 评测的准·稳·停 / 定责 / 治理 / **产品核心能力(②)**」上各长什么形，分别写在母版文件里。选定类型后读对应母版；跨型按子任务分别读、别糊成一张。

## 通用红线（每型都适用；都要在守界里显性写出、在自检里逐张校验）
- **医学 / 科学性判断 → 一律留给有资质的人**（研究者/专家）；AI 只整理支持事实与依据，不替判、不定论。**涉裁决单个 AE 时**：其严重性、严重程度、因果、预期性 AI 一概不下判——**其中 SUSAR 快报由 严重性(seriousness)+因果+预期性 驱动，严重程度(severity/强度)不驱动 SUSAR，别混**。**不裁决单个 AE 的任务**（入排、方案审查、RMP 质量等）**别套 SAE 红线**，改写本任务真正的失效面红线。
- **安全是非对称的**：凡分类/判定影响受试者安全或合规上报，**漏报（假阴性）远比误报危险**——默认走更严一侧、人先判，宁可过度上报、不可漏报。评测里"安全相关假阴性"单列重点盯，别被"过度停"掩盖。
- **数值忠实度**（指进入临床产物的**事实性**数字：剂量、化验值、p 值、样本量、终点等；**预测型输出的分数不在此列**）：必须带**精确出处 + 单位/口径核对**；无源或不匹配一律挡下，不得由模型生成或换算。

## 红线自检（反模式）
- 把"要个 X"直接当问题（没回过现场）。
- 治标当治本（装镜子）。
- 把不确定当确定，或把确定当不确定（该用死规则的塞给模型，或反过来）。
- 无据硬给（提取型编一个值 / 判定型无据硬判 / 创作型编一段圆过去）。
- 该用非 AI 却硬上 AI。

## 常见踩坑速查（索引式：一句话 + 去哪看细节）
把散落全程的避坑点集中成一张速查表方便回查；**细节仍在原处就地展开**（这样你做到那一步时才被提醒，不必先背完一摞规则），这里只给"一句话 + 位置"。

| 坑 | 一句话记住 | 细节在 |
|---|---|---|
| 把"要个 X"当问题 | 需求 ≠ 问题，先回现场翻译一遍 | 步骤 1、红线自检 |
| 治标不治本 | "电梯太慢"的真解可能是装面镜子 | 步骤 1 |
| 该用非 AI 却硬上 | 先问能不能简化 / 规则化 / 自动化 | 步骤 2、非 AI 出口三问 |
| 去标识以为够了 | 叙述类残留准标识；对具名个体决定要"去标识喂模型 + 回连签字"；机密在科学 IP 则须私有化部署 | 步骤 2 数据关三问 |
| 任务类型判错 | 先按"输出是什么"判；跨型是常态，要合成到一张图 | 步骤 3 判据 + 合成规则 |
| 风险档凭感觉 | 医学判断/入排/剂量/SAE/监管提交等一律强制高档、不可下调 | 步骤 3 硬分类器 |
| ②核心能力写废 | 只写五动作覆盖不到、本域特有、可开发的；承重那条要"具体但大白话" | 步骤 4、各母版②节 |
| 复核退化成全量重看 | 注意力要分诊到边界/低置信/安全相关；验收要量得出净省时 | 步骤 5 复核 ROI |
| 机械套 SAE 红线 | 只有"裁决单个 AE"才套 SAE 四项；不裁决 AE 的任务改写本任务真正失效面 | 通用红线、各母版〔红线〕 |
| 该停却闷头蒙 | 真困惑/高影响的判断点，停下来带方向问用户 | "卡住就停"整节、步骤 5 |
