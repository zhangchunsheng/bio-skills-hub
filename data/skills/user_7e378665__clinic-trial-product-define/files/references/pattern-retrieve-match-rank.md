# 母版 · 检索·匹配·排序型

## 何时用
输出是**从一个大库/本体里找出、匹配或排序**——不是从本次来源挑事实（提取型）、不是对照标准判定（判定型）、也不是成文（创作型）。工作单元多为 **一次查询 / 一个待匹配项**。典型：医学编码映射（MedDRA / WHODrug）、患者-试验匹配招募、中心推荐、方案/SOP/证据检索。

> **关键难点**：答案在**外部库**里、不在病例来源里，所以提取型那套"无来源位置→不放行"直接空转；难在跨大语料先检索定位、再择优排序。

## 地图形状
- **工作单元**：一次查询 / 一个待匹配项。
- **主线**：理解查询 → 检索候选 → 排序/匹配 → 给 top 结果+理由 → 人确认。
- **分路**：① 精确匹配（规则/字典命中）② 语义检索排序（模型）③ 多高分并列 / 低分 → 待人。
- **闸口**：无命中 / 低置信 / 多个高分并列 → 不硬选，转人工。

## 五动作形态
- **对齐**：目标库/本体及**版本**、查询字段、匹配粒度与口径。
- **分路**：精确命中 / 语义检索排序 / 并列或低分待人。
- **定责**：系统跑精确匹配与过滤；AI 给候选+排序+理由、不越阈值硬选；人确认最终匹配。
- **守界**：无命中 / 低置信 / 多并列 / 超出库覆盖 → 转人工，不硬配。**〔红线〕匹配若触及医学判断（如据编码/检索结果下临床结论）→ 留有资质者，AI 只给候选与理由、不下判；涉事实性数值须带出处+单位核对。**
- **交付**：top-N 候选 + 每条匹配理由/证据 + 置信，人采纳/改选。

## 评测（准·稳·停）
- **准**：precision@1 / 编码一致性 / 匹配正确率（不是"与来源一致"，是"和金标准映射一致"）；有金标准就比金标准。
- **稳**：同查询、结果与排序不漂移。
- **停**：低置信/并列能弃权转人工；并查**漏召回**（该匹配的没匹配上）。

## 治理
留痕（库版本 | 查询 | 候选与分数 | 人工终选）+ 合规可核项；检索来源与库版本可追溯。**地板**：影响招募入组/编码上报者不得置低档、并列一律待人。

## 产品核心能力（②）
**承重（最难）**：**该按哪些条件去找/去比、怎么把需求翻成一次靠谱的查询、以及"该找出来的没漏掉"怎么保证**。其余：分不出高下或没把握时**转人工**；每条推荐**给得出"为什么是它"的理由**；用的是**哪个版本的库**要留痕。〔别写黑话〕

## 范例（MedDRA 编码）
把不良事件术语映射到 MedDRA PT：AI 给 top 候选+理由+置信，精确命中自动、低置信/并列转编码员；评测=编码一致性；留 MedDRA 版本。
