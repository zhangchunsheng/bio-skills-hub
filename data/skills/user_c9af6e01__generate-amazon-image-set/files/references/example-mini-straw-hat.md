# 已验证案例：4.5 cm 迷你草帽

公开图文案例：<https://www.quietphoenix.top/archives/generate-amazon-image-set>

## 案例目的

验证从非独立 SKU 实拍、规格字段和多规格参考图出发，生成并验收一套 Amazon MAIN、Listing 和 PC A+ 图片的流程。

本案例只说明方法。执行新任务时必须重新建立产品事实锁，不得沿用本案例的商品尺寸、材质、数量或用途。

## 输入证据

| 字段 | 已确认内容 | 证据级别 |
| --- | --- | --- |
| 商品类型 | 手工编织迷你草帽，DIY 装饰摆件 | `DOCUMENT_CONFIRMED` |
| 目标规格 | 外径 4.5 cm，内径 2.1 cm | `DOCUMENT_CONFIRMED` |
| 外观 | 浅自然草色、草编纹理、浅帽冠、短帽檐 | `IMAGE_OBSERVED` |
| 典型用途 | 小黄鸭、小熊和迷你手工作品装饰 | `DOCUMENT_CONFIRMED` + `IMAGE_OBSERVED` |
| 包装数量 | 未确认 | `UNKNOWN` |
| 品牌 | 未确认 | `UNKNOWN` |

目标规格没有独立白底实拍。商品身份由目标规格、同链接多规格实拍和用途参考共同约束，因此成图仍需与实际样品复核。

## 交付范围

- MAIN：1 张，2000×2000。
- Listing：7 张，分别负责使用场景、纹理细节、尺寸、创意应用、迷你比例、多角度结构和工艺桌氛围。
- PC A+：4 张，分别负责 Hero、编织细节、迷你比例和创意用途。
- Mobile：用户明确不需要，因此不生成。

## 关键返工记录

### MAIN 比例错误

第一版虽然满足单件白底，但帽冠和帽檐更像成人可佩戴草帽，与 4.5 cm DIY 装饰品不一致。

处理方式：标记为 `FAIL`，在修订说明中锁定“浅帽冠、短帽檐、小开口、迷你工艺品比例”，并明确排除成人帽造型。修正版才作为后续图片的产品身份锚点。

### 附属图出现额外商品

一张 Listing 氛围图和一张 PC A+ Hero 初稿出现多顶草帽，可能让买家误解包装数量。

处理方式：标记为 `FAIL`，要求“整个画面恰好一顶草帽”，允许小黄鸭作为道具，但禁止道具佩戴第二顶草帽。旧稿退出最终交付。

### A+ 生成尺寸与交付尺寸不同

模型支持的横幅尺寸为 1472×608，而选定 Premium A+ 模块可能要求 1464×600。

处理方式：分别记录：

- `generation_size`: 1472×608。
- `delivery_size`: 1464×600，需以 Seller Central 实际模块为准。

在最终模块和裁切结果未确认前，视觉构图可以 `PASS`，但最终上传尺寸保持 `BLOCKED`。禁止拉伸图片以伪装成目标尺寸。

## 验收结论

- MAIN 的单件、白底、无文字、无 Logo、无包装和无道具检查通过。
- 尺寸图中的 4.5 cm 和 2.1 cm 与输入事实一致。
- 所有附属图引用同一 MAIN 作为商品身份锚点。
- 多场景图片只表达用途，不承诺包装数量或道具随商品提供。
- PC A+ 构图通过；最终上传尺寸需在实际模块中确认。

## 可复用经验

1. 白底合规不代表商品身份正确，比例和结构仍需单独验收。
2. 道具上的第二件商品也会形成数量误导，不能只检查主体区域。
3. 低质量档可以生成可用草稿，但文字、尺寸和产品结构必须逐张检查。
4. 先通过 MAIN，再用 MAIN 锚定后续版位，可以减少跨图漂移。
5. 生成尺寸和交付尺寸必须分开记录，模块未确认时保持 `BLOCKED`。


## 当前模块适用性

本案例保留仅 PC 的历史制作范围。若用于 Premium Full Image 模块，必须补齐独立重排的移动图 (最低 600x450)、桌面图 (最低 1464x600) 和两端替代文本，按当前尺寸合同重新验收后才可作为完整上传素材。
