# SaMD 与 SiMD 注册路径

## 1. 概念界定

| 类型 | 定义 | 典型示例 |
|---|---|---|
| SaMD | 独立软件医疗器械（Software as a Medical Device），自身即为器械 | 影像 AI 诊断 APP、心电分析软件 |
| SiMD | 软件驱动器械 / 器械内软件，嵌入硬件中实现医疗功能 | 起搏器软件、胰岛素泵控制算法 |
| 组合器械 | 硬件 + 软件 + 云协同，软件是器械功能不可分割的部分 | 连续血糖监测（CGM）+ APP + 云端趋势分析 |

## 2. 判定三要素
1. **预期用途**：是否用于疾病诊断、治疗、监测、缓解？
2. **决策影响**：是否直接驱动临床决策或器械动作？
3. **独立性**：软件是否可脱离硬件独立实现医疗目的？

## 3. 软件安全分级（IEC 62304）
- **A 级**：不可能造成伤害或健康损害。
- **B 级**：可能造成非严重伤害。
- **C 级**：可能造成严重伤害或死亡。
- SaMD / SiMD 多数为 B/C 级；C 级需要最完整的生命周期文档。

## 4. 注册路径映射

| 市场 | SaMD 路径 | SiMD / 组合器械路径 | 关键法规 |
|---|---|---|---|
| 中国 NMPA | 二类/三类注册，按《医疗器械软件注册审查指导原则》 | 随整机注册，软件作为组成部分 | 《医疗器械软件注册审查指导原则》 |
| 美国 FDA | 510(k)、De Novo、PMA（依风险） | 随器械一同提交，网络安全文档单独成卷 | FDA Software as a Medical Device Guidance |
| 欧盟 MDR | Annex VIII 分类，技术文档含软件生命周期 | 与器械整合评价，网络安全列通用安全要求 | MDR Annex I GSPR、MDCG 2019-11 |

## 5. 文档清单要点
- 软件描述 / 预定用途声明
- 软件安全分级与理由
- 软件生命周期过程（开发 / 维护 / 风险管理 / 配置管理）
- 验证与确认报告（V&V）
- 网络安全文档（威胁建模、SBoM、漏洞管理）
- 软件版本与变更历史
- 与硬件/云端接口说明
