# 生物多样性保护助手

## 概述

此技能提供生物多样性保护领域的专业知识、工作流程和在线服务集成，帮助完成从监测评估、项目合规核查到 TNFD 自然信息披露的各类保护任务。

**重要特性**：本技能**不依赖任何连接器配置，安装即用（零配置）**。在线能力通过技能内置脚本（`scripts/mcp_client.py`）直接调用山水自然保护中心的「生物多样性风险助手」服务；脚本已内置公共 Key（基础功能兜底，由服务端限流），用户无需任何配置即可使用。如需更强功能与更高配额，可联系山水自然保护中心申请私有 Key。

## 前置条件

### 无（零配置即可使用）

- **公共 Key（内置兜底）**：已写入 `scripts/mcp_client.py`，开箱即用，提供基础功能（服务端限流控制）。安装后无需任何操作。
- **私有 Key（可选增强）**：请联系山水自然保护中心获取。获得后保存到本技能目录的 `state/api_key.txt`（单行纯文本），即可自动升级为更强功能与更高配额；也可改用环境变量 `BIODIVERSITY_MCP_TOKEN` 或调用时加 `--token` 参数。
- **Key 优先级**：`--token` 参数 > 环境变量 > `state/api_key.txt`（私有 Key）> 内置公共 Key。

### Key 升级引导（AI 必须遵守）

1. 用户直接提出联网需求（如合规核查、TNFD 披露建议）时，**无需先检查或索要 Key**——直接调用 `scripts/mcp_client.py`（无 Key 时自动使用内置公共 Key）。
2. 若工具列表或调用结果中提示"当前模式：公共 Key（基础功能）"，可顺带告知用户：申请私有 Key 可解锁更强功能（联系山水自然保护中心），但不阻塞当前任务。
3. 若用户主动提供私有 Key（如"我的 Key 是 xxx"），将其**保存到本技能目录的 `state/api_key.txt`**（目录不存在则创建，文件内只写 Key 本身，不加引号），并提示用户"已保存，之后自动使用私有 Key"。
4. 若调用返回 `HTTP 401` 且提示当前为公共 Key 模式：公共 Key 可能已被服务端更新或触发限流，建议用户申请私有 Key。

> 安全要求：不得在对话中明文回显完整私有 Key；不得将私有 Key 写入任何会被分享/上传的文件。

## 核心能力

### 1. 生物多样性监测与评估

执行生物多样性监测计划并评估生态系统健康状态。

**工作流程：**
- 确定监测目标和指标（物种丰富度、均匀度、栖息地质量）
- 选择适当的监测方法（样线法、样方法、相机陷阱、声学监测）
- 收集和分析野外数据
- 计算生物多样性指数（Shannon指数、Simpson指数、物种多度）
- 生成监测报告和趋势分析

**使用场景：**
- "帮我设计一个生物多样性监测方案"
- "分析这片森林的物种多样性"
- "计算Shannon多样性指数"

### 2. 保护区规划与管理

规划新的保护区或优化现有保护区的管理。

**工作流程：**
- 进行保护优先级评估（物种丰富度、特有性、威胁程度）
- 使用GIS工具进行空间分析（栖息地连通性、核心-缓冲区划分）
- 制定保护区管理计划（目标、活动、监测方案）
- 评估气候变化对保护区的影响
- 制定社区参与和可持续融资策略

**使用场景：**
- "帮我规划一个自然保护区"
- "这个保护区应该如何划分核心区和缓冲区"
- "制定保护区管理计划"

### 3. 物种调查与数据分析

执行系统的物种调查并进行数据分析。

**工作流程：**
- 设计调查方案（采样方法、采样强度、重复次数）
- 识别目标物种（使用形态学或DNA条形码）
- 记录物种分布和环境数据
- 进行统计分析（多变量分析、物种分布模型、种群趋势分析）
- 使用工具：R、Python（pandas、numpy、scikit-learn）、QGIS

**使用场景：**
- "设计一个鸟类调查方案"
- "分析植物群落数据"
- "建立物种分布模型"

### 4. 保护项目工作流

管理保护项目的完整生命周期。

**工作流程：**
- 项目设计（目标、活动、时间表、预算）
- 利益相关者参与（社区、政府、NGO、捐赠者）
- 实施监测（进展跟踪、适应管理）
- 影响评估（前后对比、对照组设计）
- 报告和传播（技术报告、政策简报、科学论文）

**使用场景：**
- "帮我制定一个保护项目计划"
- "设计保护项目的监测框架"
- "撰写保护项目报告"

### 5. 在线服务：项目合规核查 / TNFD 披露 / 公益增量建议

通过 `scripts/mcp_client.py` 调用「生物多样性风险助手」在线服务（无需连接器）。

**调用方式**（AI 执行，`<skill_dir>` 为技能所在目录）：

```bash
# 列出可用工具（也可用于检查 Key 是否配置成功）
python scripts/mcp_client.py list

# ① 项目合规风险核查（功能1）
python scripts/mcp_client.py call check_project_compliance --name "项目名称" --lng 116.4 --lat 39.9
python scripts/mcp_client.py call check_project_compliance --name "项目名称" --address "省市区详细地址"
python scripts/mcp_client.py call check_project_compliance --name "项目名称"

# ② TNFD 自然信息披露建议（功能2，对齐 TNFD LEAP）
python scripts/mcp_client.py call nature_disclosure_advice --name "项目名称" --lng 116.4 --lat 39.9

# ③ 生多公益增量项目建议（功能3）
python scripts/mcp_client.py call biodiversity_increment_suggestions --context "项目/企业背景描述"

# ④ 获取生物多样性专家知识框架全文（功能4）
python scripts/mcp_client.py call get_biodiversity_expert_skill
```

**参数说明：**

| 工具 | 参数 | 说明 |
|------|------|------|
| `check_project_compliance` | `name`（推荐）、`lng`/`lat`（可选）、`address`（可选） | 优先按名称匹配本地环评项目库；查不到且无坐标时，服务会要求按 TNFD LEAP 的 Locate 步骤向用户追问坐标或地址，拿到后带 `lng`/`lat` 重新调用 |
| `nature_disclosure_advice` | 同 `check_project_compliance` | 返回事实数据作为披露依据，披露文案需结合 `delegate.skill_content` 生成 |
| `biodiversity_increment_suggestions` | `context`（必填） | 项目/公益背景描述越具体越好 |
| `get_biodiversity_expert_skill` | 无 | 单独取专家知识框架全文 |

**返回结构解读（重要）**：工具返回为 `delegate` 结构，包含三个部分，AI 必须三者结合再回答：

```json
{
  "data": { ... },                    // 事实数据（查询结果，可能为空对象）
  "delegate": {
    "instruction": "...",             // 对 AI 的指令（如要求追问坐标）
    "skill_content": "..."            // 领域知识/兜底建议素材
  }
}
```

- `data` 为空**不代表无结果**——必须继续结合 `delegate.skill_content` 和用户提供的上下文给出兜底回答，不得拒答；
- `delegate.instruction` 若要求追问坐标/地址，先向用户追问再带 `lng`/`lat` 重新调用；
- "是否涉嫌违规"等判断由 AI 结合 `delegate.skill_content` 自行推理，服务只提供事实数据；
- 涉及写操作或敏感判断时，输出需附上依据来源说明。

**工作流程建议（TNFD LEAP 对齐）**：Locate（定位）→ Evaluate（评估）→ Assess（评价）→ Prepare（准备），技能内容已内嵌在 `delegate.skill_content` 中，按此流程组织输出。

## 注意事项

- 始终基于最新的科学证据和最佳实践
- 考虑当地社区的需求和权利
- 强调适应性管理和长期监测的重要性
- 在涉及数据收集时，确保符合伦理和法律规定
- 推荐开源工具和开放数据以促进可重复性
- 在线服务返回的事实数据仅作参考，最终合规/披露结论需由专业人员结合法规确认
- 妥善保管私有 Key：不写入代码、不粘贴到聊天窗口以外的公开渠道；内置公共 Key 仅提供基础功能（服务端限流），请勿尝试绕过限流
