# 04 目标市场数据法

> 用途：回答「出海欧盟/美国/新加坡/日韩的数据要求」。
> 核对基准日：2026-08-27

## 1. 欧盟——GDPR + EHDS

| 维度 | 要求 |
|---|---|
| 基础 | GDPR：健康数据属特殊类别（第 9 条），处理须明确同意/必要医疗服务等法定依据 |
| **EHDS** | 《欧洲健康数据空间条例》**2025-03 生效**：健康数据跨境流动与二次使用更高标准 |
| 跨境传输 | 向欧盟外传输：充分性认定 / SCC 标准合同条款 / 其他保障措施 |
| 医疗器械联动 | MDR/AI Act 与数据合规并行（AI 训练数据须 GDPR 合规） |
| 德国参考 | 德国 DSK（2025-09）跨境传输敏感健康数据"两步法"指南（先评估接收国保护水平，再选传输工具） |

**出海要点**：在欧盟处理患者/受试者健康数据 → 数据保护影响评估（DPIA）+ 合法依据 + 跨境传输机制（SCC 常用）。

## 2. 美国——HIPAA 升级 + 州法

| 维度 | 要求 |
|---|---|
| HIPAA | 2026 安全规则**重大升级**：强制多因素认证（MFA）+ 强加密；覆盖受保护健康信息（PHI） |
| 州法 | 加州 CCPA/CPRA 等州法对健康数据也有要求；生物特征/健康数据类州法增多 |
| 传输 | 美国无联邦统一数据出境审批，但 PHI 传输须 HIPAA 合规（商业伙伴协议 BAA） |
| 提示 | HIPAA 只管"受覆盖实体及其商业伙伴"，设备厂商等需判断是否在范围内 |

**出海要点**：明确是否属 HIPAA 覆盖范围（与医院合作常需签 BAA）；强加密 + MFA 落地。

## 3. 新加坡——PDPA

- PDPA（2021 修订）：健康数据属敏感个人数据，处理限制更严；
- 跨境传输：接收方须提供与 PDPA 相当的保护（标准合同条款/集团规则常用）；
- 医疗 AI/健康应用：AI Verify + 模型 AI 治理框架（PDPC）参考；
- 数据泄露通报：72 小时内向 PDPC 通报（达到危害门槛）。

**出海要点**：与新加坡医院/机构合作 → 数据保护条款 + 跨境传输合同。

## 4. 日本——APPI

- APPI（2022/2025 修订）：健康/医疗属"需特别注意的个人信息"；
- 跨境传输：接收国须有充分保护（EEA/英国在列）或合同/同意；
- 医疗 AI 器械：PMDA 路径（DASH/PACMP）与数据合规并行。

## 5. 韩国——PIPA + AI 基本法

- PIPA（2023 修订）：健康/基因属敏感信息，处理须单独同意；
- AI 基本法（2026-01 生效）：医疗 AI 属高影响 AI（注册/透明度/人工监督）；
- 跨境：数据本地化倾向强（部分数据须境内处理）。

## 6. 出海数据合规通用五步

1. **数据地图**：列出出海业务涉及的数据类别（健康/个人/员工）；
2. **本地化识别**：各市场是否有数据本地化/跨境限制；
3. **合法依据**：各市场处理健康数据的法定依据（同意/必要等）；
4. **跨境机制**：SCC/充分性/合同条款逐市场确认；
5. **安全落地**：加密（三重）、MFA、DPIA、事件响应预案。

## 7. 医械出海特别注意

- 医疗器械注册数据、不良事件报告、真实世界数据（RWD）跨境均涉数据合规；
- 海外临床基地：受试者数据本地处理 + 有限跨境回传；
- 云服务选型：目标市场数据驻留要求（如中国境内、欧盟内）影响云部署架构。
