# 伏笔追踪

## 三级优先级

| 优先级 | 含义 | 处理 |
|---|---|---|
| P1 | 主线关键伏笔，必须持续追踪 | 每章检查是否推进 |
| P2 | 重要支线伏笔，需要阶段性回收 | 每 5 章检查 |
| P3 | 氛围或细节伏笔，可合并或删除 | 可主动合并或废弃 |

## 四态状态机

```
埋设（未回收）
  ↓
推进中（章节中显式或隐式推进）
  ↓
已回收（章节中明确揭示或解决）
  ↓
废弃（确认不再回收，标记为废弃原因）
```

可双向：已回收 → 废弃（回收方式不满意）；推进中 → 废弃（放弃该线索）。

## 记忆文件中的标准写法

```markdown
## 伏笔追踪

| ID | 优先级 | 埋设章节 | 内容 | 状态 | 预计回收 | 备注 |
|---|---|---:|---|---|---|---|
| F001 | P1 | 001 | 顾闻识别码出现在黑匣子中 | 未回收 | 第8-10章 | 必须由顾闻主动揭示 |
| F002 | P1 | 001 | 静默航线真实任务 | 未回收 | 中后段 | 涉及历史真相 |
| F003 | P2 | 002 | 内务局为何阻止调查 | 未回收 | 第6章 | 林澈需突破封锁 |
```

## 自动校验工具

```bash
# 列出未回收伏笔
python3 scripts/validate-novel-memory.py memory/novels/{slug}.md \
  --show-unresolved --by-priority

# 检测 P1 伏笔长期未推进
python3 scripts/validate-novel-memory.py memory/novels/{slug}.md \
  --check-p1-stale --stale-threshold 10
```

输出示例：

```text
=== 未回收 P1 伏笔（共 3 个）===

F001（埋设于第 1 章）— 已 7 章未推进，**建议在第 8 章回收**
F002（埋设于第 1 章）— 已 7 章未推进，**建议在中后段回收**
F005（埋设于第 5 章）— 已 3 章未推进，**保持当前节奏**
```

## 续写时的伏笔检查清单

每章开始写之前，确认：

- [ ] 本章是否涉及已埋设的 P1 伏笔？是否需要推进？
- [ ] 本章是否涉及已埋设的 P2 伏笔？是否可推进或回收？
- [ ] 本章是否埋设新伏笔？埋设后立即追加到记忆文件
- [ ] 本章是否有 P1 伏笔回收？回收后立即更新状态

每章写完后：

- [ ] 在记忆文件中更新本章伏笔状态变化
- [ ] 输出「本章一致性自检 - 伏笔推进」卡片

## 智能伏笔推荐（v3.x 预留）

P3-01 智能伏笔推荐：根据章节节奏与历史伏笔埋设点，预测 P1 伏笔的最佳回收窗口。

当前版本：手动判断（基于经验 + 校验工具辅助）。

## 协作中的伏笔分配

多人协作时，建议：

- 主线作者持有 P1 伏笔清单
- 支线作者持有 P2 伏笔清单
- P3 伏笔可自由发挥
- 回收决策需主线作者确认
- 废弃决策需说明原因

详见 `references/collab-workflow.md`。
