# 多人协作工作流

## 适用场景

- 两人以上的写作团队
- 一人主导主线，多人写支线
- 跨作品的共用人物/势力维护

## 角色分工

| 角色 | 职责 |
|---|---|
| 主线作者 | 主线剧情、核心人物、P1 伏笔、最终合并 |
| 支线作者 | 支线剧情、配角、P2 伏笔 |
| 世界观维护者 | 硬规则、势力图、地点设定 |
| 风格审计者 | 风格一致性、AI 痕迹分、对白风格 |
| 编辑 | 错别字、语病、节奏、节拍 |

## 工作流约定

```text
每位协作者的日常：
  1. 拉取最新主线（git pull 或文件同步）
  2. 读取记忆文件，确认 P1/P2 伏笔进度
  3. 在自己负责的章节写作
  4. 完成后立即更新记忆文件中的对应字段
  5. 提交（git push 或文件同步）
  6. 等待主线作者审核
```

## 冲突解决决策树

```text
场景：支线作者 A 修改了硬规则 #3

主线作者：
  ├─ 同意修改
  │   ├─ 在记忆文件中更新硬规则 #3
  │   ├─ 通知所有协作者
  │   └─ 评估是否需要回溯修改已写章节
  │
  └─ 拒绝修改
      ├─ 在写作群说明拒绝原因
      ├─ 提议替代方案
      └─ 由支线作者决定是否调整章节
```

## 设定合并规则

### 人物设定合并

```markdown
#### 人物合并决策（A 提议修改林澈）

A 提议：林澈的母亲在第 5 章出现，身份是星港内务局前成员
理由：强化林澈的动机矛盾

主线作者审核：
  - [ ] 是否与硬规则冲突？
  - [ ] 是否影响已埋设伏笔？
  - [ ] 是否影响其他人物设定？

决策：
  - [x] 同意，需在第 5 章前 1 章铺垫（如第 4 章档案中出现母亲旧照片）
  - [ ] 修改建议：把"前成员"改为"前调查员"，与世界观更一致
  - [ ] 拒绝，原因：{列出}

最终设定：
  林澈的母亲：星港内务局前调查员（第 4 章铺垫 → 第 5 章出现）
```

### 世界观硬规则合并

```markdown
#### 硬规则合并决策（B 提议新增硬规则）

B 提议：硬规则 #4「星际航行最长 30 天」 → 修改为「星际航行最长 45 天」
理由：第 30 章主角需要 40 天航行，触发剧情冲突

决策流程：
  1. 主线作者评估影响：列出受影响的章节（涉及航行的所有章节）
  2. 世界观维护者评估一致性：是否会破坏其他硬规则
  3. 编辑评估节奏：40 天航行是否会拖慢节奏

最终决策：
  - [x] 同意，硬规则 #4 修改为「最长 45 天」
  - 同步修改：硬规则 #5「超过则触发时空畸变」 → 修改为「超过 30 天则触发轻度畸变，45 天以上触发严重畸变」
  - 受影响章节：第 30-35 章需回溯微调
```

## 协作中的冲突解决具体流程

### 流程 1：伏笔冲突

```text
场景：支线作者 A 在第 12 章回收了 P1 伏笔 F005，但主线作者原本计划在第 18 章回收

处理：
  1. A 在写作群发起讨论："我在第 12 章回收了 F005，是因为 {理由}"
  2. 主线作者评估：第 12 章回收是否影响其他伏笔链路？
     - 若无影响：同意，但需调整后续章节大纲
     - 若有影响：拒绝，提议替代方案
  3. 决策结果写入记忆文件的「伏笔追踪」表
```

### 流程 2：人物对白风格冲突

```text
场景：风格审计者发现第 15 章对白偏离林澈的对话风格

处理：
  1. 风格审计者运行 dialogue-style-check.py 标注段落
  2. 把段落发到写作群
  3. 章节作者调整或主线作者改写
  4. 调整后重新校验
  5. 调整记录写入人物卡的"修订记录"字段
```

### 流程 3：时间线冲突

```text
场景：两章时间不一致

处理：
  1. 任一协作者发现时间冲突
  2. 在写作群发起讨论
  3. 主线作者决策：保留哪一版
  4. 修改后立即更新记忆文件时间线表
  5. 检查所有引用此时间的章节
```

## 协作工具栈（推荐）

| 工具 | 用途 |
|---|---|
| Git 私有仓库 | 版本管理、协作同步 |
| 飞书 / 钉钉 / 企业微信 | 实时沟通、写作群 |
| 本技能生态 / CodeBuddy | Copilot写作 |
| Notion / 腾讯文档 | 大纲与设定共享 |
| Baidu 网盘 / OneDrive | 备份与跨设备同步 |

## 协作中的禁用行为

- 不直接覆盖他人设定（必须先在写作群讨论）
- 不私自修改硬规则（必须经主线作者 + 世界观维护者同意）
- 不在未通知情况下回收 P1 伏笔
- 不私自添加跨作品引用

## 协作结束（项目完结）

1. 主线作者确认全卷/全书完结
2. 完整备份（包含所有 chapters、characters、memory、backups）
3. 生成最终导出包（详见 `references/export-to-docx.md`）
4. 在 `CHANGELOG.md` 中记录完结日期
5. 协作者各自归档本地副本
