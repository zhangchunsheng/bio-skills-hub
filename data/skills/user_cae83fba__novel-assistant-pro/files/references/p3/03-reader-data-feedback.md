# P3-03 读者数据反馈接入

> v3.x 路线图。接入读者画像（留存/弃读/章节评分）反向调整节拍。

## 目标

让创作从"凭感觉"升级到"数据驱动"。基于真实读者数据，调整后续章节。

## 数据源

| 数据源 | 接入方式 | 数据维度 |
|---|---|---|
| 平台后台（起点中文网/番茄小说/晋江文学城等） | API 或导出 CSV | 章节字数、读者评分、留存曲线 |
| 自有站点 | 部署前端埋点 | 阅读时长、章节完成率、跳出点 |
| 读者评论 | 爬虫或人工汇总 | 满意度、疑问点、批评 |
| 调研问卷 | 飞书/腾讯文档 | 深度反馈 |

## 反馈循环

```text
第 1 章发布
  ↓
读取第 1 章数据（评分 / 留存 / 评论）
  ↓
对比预期（开篇留存分 ≥ 28）
  ↓
差异 > 阈值 → 触发"风格调整"
  ↓
风格调整：
  - 提示用户：第 2 章需加强 X 维度
  - 自动调整节拍目标
  - 输出诊断报告
```

## 数据接入脚本

```bash
# 接入起点中文网后台数据
python3 scripts/import-reader-data.py \
  --platform qidian \
  --work-id 123456 \
  --output reader-data/{slug}-q1.json

# 数据格式
{
  "chapter": 5,
  "stats": {
    "rating": 8.5,
    "completion_rate": 0.85,
    "avg_reading_time": 120,  # 秒
    "comment_count": 23
  },
  "comments_sample": [
    "节奏太快",
    "林澈的对话很到位",
    "钩子设置好"
  ]
}
```

## 反馈分析

```bash
# 基于读者数据生成调整建议
python3 scripts/feedback-analyze.py \
  --reader-data reader-data/{slug}-q1.json \
  --memory memory/novels/{slug}.md \
  --output reports/feedback-001.md
```

输出：

```markdown
=== 读者反馈分析（第 5 章）===

评分：8.5/10（高于平均 7.8）✓
完成率：85%（高于平均 75%）✓
平均阅读时长：120 秒（高于平均 100 秒）✓
评论：23 条（正面 18，中性 4，负面 1）

诊断：
  - 第 5 章表现优秀，与"开篇留存"评分一致
  - 主要正面反馈：林澈对话、钩子
  - 唯一负面反馈：节奏略快

建议：
  - 保持当前的对话风格
  - 在第 6 章适当放缓节奏
  - 在第 7 章可适度加速
```

## 数据维度

| 维度 | 衡量 |
|---|---|
| 评分 | 读者主观打分 |
| 留存 | 读者是否继续读下一章 |
| 完成率 | 读者是否读完本章 |
| 阅读时长 | 在本章停留多久 |
| 评论情感 | 正面/中性/负面 |
| 跳出点 | 读者在哪段/句/字跳出 |

## 与自动调优的结合

```text
读者反馈 → 反馈分析 → 风格调整建议 → 风格 DNA 更新 → 后续章节自动应用
```

详见 P3-05 多模型协作框架。

## 隐私与合规

- 数据采集需用户授权
- 数据本地存储（不上传第三方）
- 符合平台的数据使用规范
- 读者评论去标识化（保护隐私）
