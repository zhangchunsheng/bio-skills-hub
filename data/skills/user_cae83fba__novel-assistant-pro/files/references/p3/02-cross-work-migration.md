# P3-02 跨作品知识迁移

> v3.x 路线图。用户授权下，新作品可继承已完结作品的人物原型/势力原型。

## 目标

让多作品创作更高效：相同的"江湖门派"设定，可在多部作品中复用。

## 复用层级

| 层级 | 复用内容 | 难度 |
|---|---|---|
| 1（基础） | 人物姓名、势力名称 | 低 |
| 2（中等） | 人物性格、势力结构 | 中 |
| 3（高级） | 人物弧光、世界观规则 | 高 |
| 4（深度） | 完整的人物 + 势力 + 章节大纲 | 极高 |

## 迁移流程

```text
场景：用户写了《星港尽头》（科幻），现在写《星港起源》（前传），希望复用林澈、顾闻

技能：
  1. 询问用户：要迁移哪些元素？
     - [1] 仅人物姓名
     - [2] 人物 + 性格
     - [3] 人物 + 性格 + 弧光
     - [4] 完整人物 + 势力
  2. 询问用户：新作品与旧作品的关系
     - [1] 完全独立（仅同名）
     - [2] 平行宇宙（不同世界观）
     - [3] 前传/后传（同一世界观）
     - [4] 衍生（同一世界观 + 部分人物复用）
  3. 自动生成新作品的人物卡（继承选中的元素）
  4. 提示用户：需要调整的字段
  5. 用户确认后写入新作品记忆文件
```

## 引用机制

```markdown
### 人物：林澈

> 来源：《星港尽头》第 5 章，跨作品引用

- 身份：星港事故调查员
- 年龄：28 岁
- 性格：克制、追问
- 对话风格：短句、克制
- 典型台词：「证据不会消失，只会被人放错地方。」

#### 跨作品差异

- 《星港尽头》：核心主角
- 《星港起源》（前传）：青年时期，第 3 章出现
- 《星港余波》（后传）：第 8 章成为导师
```

## 冲突检测

迁移时检测：

| 冲突类型 | 处理 |
|---|---|
| 同名人物不同设定 | 询问用户优先级 |
| 同势力不同结构 | 合并 + 询问差异 |
| 跨作品引用关系 | 自动建立引用链 |

## 与多作品管理的关系

`references/multi-work-management.md` 中的"跨作品知识迁移"是简化版（手动）。P3-02 提供自动化。

## 实现阶段

| 阶段 | 内容 |
|---|---|
| 1 | 基础复用（仅姓名 + 性格） |
| 2 | 跨作品引用管理 |
| 3 | 冲突自动合并 |

## 风险

- 跨作品引用增加记忆文件复杂度
- 跨作品冲突需要人工决策
- 数据结构设计影响可扩展性
