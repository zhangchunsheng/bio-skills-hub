# 药物 / 靶点专题检索报告 · 固定格式规范（V1.1.1）

> 本文件是 **oncology-lit-search SKILL V1.1.1** 的「药物 / 靶点专题综合检索」报告标准模板。
> 任何靶点 / 药物 / 瘤种的全景检索，最终导出的 Word 报告**必须**严格遵循本固定结构，
> 由 `scripts/gen_drug_target_report.py`（JSON 驱动）生成，保证章节、列定义、排序规则、封面要素一致。
>
> 固定结构的来源：以 KRAS G12D 胰腺癌检索报告（2026-07-17 v2）的目录为基准，经用户二次校正固化：
> - 封面固定为 **6 个要素**（去掉"文献数量"）
> - 新增 **背景与流行病学** 为内容第一项
> - 临床数据汇总表 **按临床阶段降序**，多瘤种时 **按瘤种分表**
> - 重点药物详情 **按临床阶段降序**，III 期布局固定，耐药机制研究并入本节
> - **PubMed 核心文献列表移至报告最后**，以「参考文献」方式列出
> - **删除「改进措施」章节**

---

## 0. 首页（封面）— 6 个固定要素

报告首页必须包含以下检索元数据（居中、双列表格），**顺序与要素固定不变**：

| 检索元数据 | 内容 |
|------------|------|
| ① 检索主题 | 本次检索的主题（如"KRAS G12D 靶点药物在胰腺癌的临床数据"） |
| ② 检索时间 | YYYY-MM-DD（精确到日） |
| ③ 检索数据库及数据源范围 | 列出全部数据库与数据源，如：PubMed（NCBI E-utilities）；ASCO 2026 年会摘要库；AACR 2026；ESMO 2025；CSCO 2025；WebSearch 检索 |
| ④ 文献或数据发表的时间范围 | 如 2023-01-01 至 2026-07-17 |
| ⑤ 检索工具 | 如：PubMed E-utilities API；WebSearch；WebFetch |
| ⑥ 检索关键词 | 列出全部查询关键词（中英文，用"；"分隔） |

> 注意：封面**不再**包含"文献数量"要素。文献/摘要计数无需在封面体现。

---

## 1. 一、背景与流行病学

自由文本（可多段），建议覆盖：
- 靶点的生物学特征与突变频率（如 KRAS G12D 在 PDAC 中约 40%）
- 流行病学负担与未满足需求（5 年生存率、后线治疗 ORR/mOS 等）
- 当前标准治疗格局与靶向治疗空白

---

## 2. 二、临床数据汇总表

> 章节标题固定：`二、临床数据汇总表`
> 表头下方第一行标注检索主题。

### （一）总体汇总（按临床阶段降序）

**列定义（6 列，固定）**：

| 列名 | 填写规则 |
|------|----------|
| 品种 | 药物通用名（括号内可附研发代号，如 `Daraxonrasib (RMC-6236)`） |
| 开发企业 | 主要开发企业（本土企业标注中文名） |
| 最新进展 | 最高临床阶段 + 关键监管里程碑（FDA BTD / 快速通道 / NMPA IND）+ 日期 |
| 瘤种 | 主要适应症（PDAC / NSCLC 等，可多行） |
| 主要有效性结果 | ORR / DCR / mPFS / mOS 等核心指标，保留原始数字 |
| 主要安全性结果 | ≥3 级 TRAE 发生率 + 主要 AE 类型 + 是否有停药 / 死亡 |

**排序规则（降序）**：已上市 > III 期 > 注册性临床 > II 期 > I/II 期 > I 期 > IND > 临床前。
每条记录建议带 `phase` 字段（如 `"III期"`）以保证排序稳定；缺省时从"最新进展"文本推断。

### （二）按瘤种分列（条件出现）

当汇总表涉及 **≥ 2 个瘤种**时，在总体汇总之后，**再按各瘤种分别增加子表**：
- 每个子表标题：`{瘤种}（按临床阶段降序，N 个品种）`
- 列定义与排序规则同上
- 瘤种取每个品种"瘤种"字段的第一个瘤种作为分表依据

### 表格下方固定注脚

> 注：不同品种数据来源试验、基线、联合方案各异，不可直接横向比较；有效性保留原始数字，安全性以 ≥3 级 TRAE 发生率及主要 AE 类型为主。

## 3. 三、重点药物临床数据详情

> 章节标题固定：`三、重点药物临床数据详情`
> **按临床阶段降序排列**所有纳入的重点药物（通常 6-10 个）。

每个药物为一个 **Heading 2** 小节，标题格式：`{品种} — {开发企业}`。
正文**固定字段顺序**（缺项可省略，但顺序不变）：

1. **机制**：作用机制（结合口袋、ON/OFF 双态、选择性、降解剂等），1-2 句。
2. **主要研究者（PI）**：牵头 PI + 机构；会议报告人（如有）。
3. **试验注册**：CTR / ChiCTR / NCT 编号。
4. **关键会议数据**（可多个，按会议时间倒序）：
   - 小节标题：`{会议} {年份} {专场}（Abstract {编号}，数据截止 {日期}）`
   - 子弹项：入组情况 → 有效性（分剂量亚组）→ 安全性（DLT / ≥3 级 TRAE / 主要 AE / 停药死亡）
5. **III 期 / 注册临床设计**（如已开展或公示计划开展，**必须呈现**）：
   - 小节标题：`{III 期} 临床试验（{启动日期}）`
   - 子弹项：设计 → 入组规模 → 主要终点
6. **要点概括**：1-2 句定位（第几个进入 III 期、差异化优势、中国原研地位等）。

**III 期布局固定**：对已进入或计划 III 期的药物，第 5 项（III 期 / 注册临床设计）为必填字段，固定呈现设计 / 入组规模 / 主要终点。

### 耐药机制研究（本节子项）

在重点药物详情之后，设 **Heading 2** 小节 `耐药机制研究`，子弹列表按机制类型组织
（旁路激活 / 二次突变 / 表型转化 / 监测手段 / 联合策略等）。无相关内容时注明「暂无」。

> 早期临床 / IND 阶段药物保留在按阶段降序的药物列表中（位于列表末尾），不单独成段。

## 4. 四、非主流开发方向（不作为重点）

> 章节标题固定：`四、非主流开发方向（不作为重点）`

非小分子模态（TCR-T / siRNA / 疫苗 / 外泌体 / 抗体等）的开发方向，**不作重点**。
- 文字分析 1-2 段，说明其适用场景（辅助 / 维持治疗）与差异化价值
- 可选：非小分子模态在研汇总小表（列定义同 §2）

---

## 5. 五、会议数据汇总

> 章节标题固定：`五、会议数据汇总`
> 按会议分组（ASCO / ESMO / CSCO / AACR / WCLC），组内需有年份标注。

每个会议为 **Heading 2**，标题：`{会议} {年份}（{中文全称}，{年月}）`。
下方表格**列定义（5 列，固定）**：

| 摘要编号 | 药物/疗法 | 瘤种 | 关键数据 | 专场 |
|----------|-----------|------|----------|------|
| LBA3007 / 3007 / 915O | 药物名 | PDAC | ORR 41.9%, DCR 93.5% | Oral / Poster / LBA |

无结构化摘要数据时注明「该会议暂无结构化摘要数据」。

## 6. 六、总结与趋势判断

> 章节标题固定：`六、总结与趋势判断`
> **7 个固定子目录（顺序固定、不可删改）**，每个子目录以「段落（归纳概括）+ 要点」呈现，强调归纳概括能力（不是罗列原始数据）。
> 数据形态：`conclusion` 为字典，键与下列 7 项一一对应；每项为 `{ "paras": [段落...], "bullets": [要点...] }`。

| 序号 | 固定子目录 | 核心内容要求 |
|------|-----------|-------------|
| 1 | **治疗格局** | 与标准疗法（SoC）对照，凸显靶向疗法的优势（ORR / mOS / 范式转变）；必须点明对照基线 |
| 2 | **疗效梯队** | 按一线联合 / 后线单药 / 早期单药划分梯队；给出 NSCLC、PDAC 等关键瘤种的 ORR 排序（注明不可横比） |
| 3 | **竞争态势** | 全球在研数量、中国原研席位、中美双轨、已进入 III 期数量、模态分野 |
| 4 | **差异化策略** | 选择性 / 给药方式 / 联合定位 / 适应症优先级 / 注册地理布局的差异化 |
| 5 | **耐药挑战与应对** | 耐药机制（旁路 / 二次突变 / 表型可塑性 / 新发现）+ 应对策略（联合 / 监测 / 序贯 / 降解剂） |
| 6 | **监管进展（注册策略）** | 中美双轨注册；逐项列出各药 III 期 / BTD / 快速通道 / 申报状态（**内容与 V2.0 版本一致**） |
| 7 | **临床意义与展望** | 首个靶向突破口的意义 + 展望（获批窗口 / 新标准 / 生物标志物 / 耐药管理 / 适应症拓展 / 中国领跑） |

> `conclusion` 数据键名（与生成器 `CONCLUSION_SECTIONS` 对应）：
> `treatment_landscape` / `efficacy_tiers` / `competitive` / `differentiation` / `resistance` / `regulatory` / `outlook`
> 兼容旧版：若 `conclusion` 为列表（V1.1.1 及以前），生成器自动按旧式渲染，不报错。

## 7. 参考文献（置于报告最后）

> 章节标题固定：`参考文献`
> 原「PubMed 核心文献列表」移至报告**最后**，以**参考文献（编号列表）**方式列出。
> 每条保留 7 要素：PMID / DOI / 文献类型 / 英文标题 / 第一作者 / 期刊 / 年份。

编号格式示例：
`[1] Smith J 等. Title of the article. J Clin Oncol, 2026. DOI: 10.xxxx. PMID: 38123456. （Clinical Trial）`

## 通用规则（适用于全部章节）

1. **语言**：标题保留英文原文；摘要 / 要点用中文概括，关键数据保留原始数字（不翻译）。
2. **不可横比**：不同试验基线、方案不同，综合汇总表后必须加注脚说明。
3. **时间锚定**：必须覆盖到检索日当月的最新会议与文献（见 SKILL「多源综合检索流程」）。
4. **去重**：同一试验在多个会议 / PubMed 重复出现时，合并标注。
5. **文件命名**：`<主题>_检索报告_YYYYMMDD.docx`，保存至项目根目录。
6. **生成方式**：填充 `data.json`（schema 见 `gen_drug_target_report.py` 头部与 `--sample`），
   运行 `python scripts/gen_drug_target_report.py --input data.json --output report.docx`。

## 工作流（封装于 SKILL）

```
① 多源综合检索
   PubMed 并行(2-3) + WebSearch 多角度(4-6) + 五大会议 site: 搜索
   + 管线全景核查 + 补充检索（已知药物代号 / 监管 / 中文媒体）
        ↓
② 填充 data.json  （严格遵循本模板章节与列定义；封面用 6 要素）
        ↓
③ 生成报告
   python scripts/gen_drug_target_report.py --input data.json --output <主题>_检索报告_YYYYMMDD.docx
        ↓
④ present_files 呈现
```
