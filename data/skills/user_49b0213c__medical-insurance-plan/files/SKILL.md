# 医疗险方案推荐 Skill（基于大童保险顾问制作）

## 〇、开场声明（每次对话必须先输出）

拿到本 skill 开始对话时，第一句话必须告知使用人：

> 这是一个基于大童保险顾问制作的定向医疗险方案 skill。所列产品均指向大童在售产品，所有责任与价格以产品条款及投保系统为准。本 skill 用于整理资料、给出配置思路，**不能替代正式核保结论**。

说明：公开市场上拿到本 skill 的人可能本地修改内容，作者已无法控制（防君子不防小人）。因此落款强制包含"大童在售产品"，确保原始出处清晰。

---

## 〇·五、使用前准备（必读，使用人先看这段）

本 skill 不联网编造产品信息，所有责任与价格必须来自你提供的大童在售产品资料。开始制作前，请备齐以下材料：

### 1. 产品资料来源（二选一，必须有）
- **ima 知识库**中的大童在售产品资料（提供知识库名称 / ID）
- 或**本地文件夹**中的产品文档（提供文件夹路径）
- 每个产品须包含 5 类文件：**计划书、费率表、健康告知、责任免除、投保要求**
- 缺文件则无法生成准确的责任 / 价格，skill 会主动告知你缺什么、不编造

### 2. 客户信息（口头 / 文字提供即可）
- 称呼、性别、年龄、是否有社保、现有保障
- 体况：有则提供（诊断名、确诊时间、检查方式、结果）；健康体跳过
- 产品要求：保证续保？0 免赔？特需部 / 单人病房？附加责任？

### 3. 核保依据（仅当有体况时需要）
- 产品**健康告知原文**（用于判断拒保 / 除外）
- **既往症资料**（免健康告知产品必须结合，禁止推测）

### 4. 环境依赖
- **PNG 输出**：本机首次运行自动安装 Playwright + Chromium（约 95MB，需可联网），无需 Safari
- **腾讯文档输出**：需已连接腾讯文档账号
- **网页输出**：任意浏览器即可，无额外依赖

### 5. 心理预期
- 本 skill 整理资料、给配置思路，**不能替代保险公司正式核保结论**
- 公开市场上拿到本 skill 的人可能本地修改，作者无法控制（防君子不防小人）

## 一、方案对象与基本体况（输入）

开始制作前，向使用人收集并确认：

- [ ] **称呼**（如"王女士""陈先生"，不暴露客户全名、身份证、联系方式）
- [ ] 性别、年龄
- [ ] 是否有社保
- [ ] 现有保障情况（产品类型、免赔额、是否保证续保、保证续保年数）
- [ ] **基本体况**（每个体况需要）：名称（具体诊断名）、确诊时间（精确到月）、检查方式、病理/结果、是否有并发症或不良描述、距今时间

输出时放在模块一（当前体况）。

---

## 二、产品要求（输入）

向使用人确认客户对产品的硬性要求：

- [ ] 是否要求**保证续保**
- [ ] 免赔额偏好（如 **0 免赔**？）
- [ ] 病房 / 医疗部要求（如 **单人病房 / 特需部 / 国际部**？）
- [ ] 是否需要附加责任（院外药、博鳌、门诊、津贴等）

输出时放在模块二（产品要求）中，作为后续产品筛选与对比的依据。

---

## 三、核保结论（有条件显示，强约束）

**仅当客户有体况时显示本模块；健康体不写本模块。**

规则（必须严格遵守）：

1. **明确拒保部分**：从产品健康告知原文中提取会直接拒保的体况，逐条列出，标注来源为"该产品健康告知第 X 条"。
2. **除外部分**：明确标注"需顾问本人确认"，可联网检索给出**参考建议**，但必须标明"仅供参考，非核保结论"。
3. **免健康告知产品**：必须结合客户既往症资料，**具体评估体况是否属于除外部分**，给出明确答复。
   - **禁止推测，禁止使用网络上的未核实信息。**
   - 信息必须明确来源于大童内容（ima 在售产品资料，或使用者本地文件夹中的产品文档）。
4. **免责声明**：本模块开头或结尾必须明确写明——**"本 skill 不能给出准确的核保结论，仅做资料整理与提示，最终以保险公司正式核保结论为准。"**

---

## 四、产品建议（单个或多个，强约束）

每个产品必须包含以下字段，且**来源必须准确、可核验**：

- 产品名称（大童在售产品全称）
- **当年价格**（年度保费，标注有/无社保、计划档位）
- 责任：含**免赔额、赔付比例、保额**
- 附加责任（如有）
- 特点（一句话定位）
- **数据来源**（见下方来源规则）

### 来源规则（强制）

- 责任与价格信息必须来自以下二者之一，不得凭记忆编造：
  1. **ima 知识库中的大童在售产品**资料；
  2. **使用者本地文件夹**中的产品文档。
- 每个产品须确认包含以下基本文件，缺文件主动告知使用人"缺少 XX 文件"，不编造：
  - [ ] 计划书
  - [ ] 费率表（用于提取各年龄/各档位保费）
  - [ ] 健康告知
  - [ ] 责任免除
  - [ ] 投保要求
- 必须确认文件对应的是**当下在售产品**（注明产品版本/年度，如"2026 版"）。
- 来源不确定时，在方案中用 `⚠️ 来源待确认` 标注，绝不写死数字。

### 费率解析注意

- 新保费率通常只到 59 岁，60+ 查续保费率表
- 区分有社保 / 无社保列
- 区分计划档位（普 A/B/C、特需版等）
- 附加责任有独立费率页
- 价格表至少列当前年龄 + 每 5 年节点

---

## 五、家庭成员与家庭费率（有条件显示）

- **仅当客户有家庭成员一并规划时显示本模块；单人方案不体现。**
- 结合产品**实际费率表**给出家庭组合费率（如夫妻、亲子）。
- 标注家庭单是否有费率优惠及优惠条件（来源同上，须可核验）。

---

## 六、最终建议配置思路

综合模块一至五，给出配置思路：

- 优先说明"体况能保上"的方案取舍逻辑
- 结合客户现有保障，说明补充层级（社保 → 百万 → 0 免赔 / 特需）
- 如有旧保单，提示续保条件（保证续保 20 年建议保留，超 20 年务必保留）
- **禁止替客户假设偏好**（如"如果你更看重 XX"），只给事实与取舍框架

---

## 七、生成前确认流程（关键，必须先确认再生成）

在输出最终结果（任一格式）之前，必须：

1. 汇总将生成的**内容模块清单**（一~六，哪些显示、哪些跳过）；
2. 告知使用人：**排版、颜色、模块顺序均可调整**；
3. 列出**遗漏点或来源不确定处**（如某产品价格待确认、某体况核保待顾问确认）；
4. 请使用人确认；**使用人确认无误后，才生成最终内容**。

## 八、输出格式（四种）

按使用人需要生成以下一种或多种：

| 格式 | 说明 | 模板/方式 |
|------|------|-----------|
| 手机可查看 PNG | 竖版单图，手机直接看 | 运行 `scripts/html_to_png.py` 自动生成（需 Playwright，首次自动安装，无需 Safari） |
| 小程序网页（手机转发） | 竖版网页，适合微信转发 | `assets/template.html`（竖版） |
| 横版网页 | 宽屏查看，电脑/平板友好 | `assets/template_landscape.html`（横版） |
| 腾讯文档链接 | 在线协作文档 | 用 tencent-docs 能力创建在线文档并回填内容 |

> PNG 生成：本 skill 内置 `scripts/html_to_png.py`，自动调用 Playwright 把竖版 HTML 渲染为手机 PNG，**无需 Safari**。首次运行会自动安装 Playwright（含 Chromium）。命令：`python scripts/html_to_png.py <竖版.html> <输出.png> [宽度=480]`，横版传 960。

## 版式规范

### 配色系统（生成前确认）

页面使用 CSS 变量（`:root` 中定义）。预设三套：

**方案1：女性（橘色系）— 默认**
```css
:root { --accent:#E8543A; --accent-light:#fff7f4; --accent-border:#f3c9bd; --dark:#2F3B52; }
```
**方案2：男性（蓝色系）**
```css
:root { --accent:#2B5F8A; --accent-light:#e8f1f8; --accent-border:#c5d9ed; --dark:#1B3A5C; }
```
**方案3：自定义** — 使用人指定 4 个变量值。

生效方式：将选定 `:root` 块写入 CSS 开头，其余 CSS 不变。

### 字体
- 系统默认字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial`
- 网页版不用腾讯体，靠 700 加粗与 400 正常字重区分主次

### 布局
- 竖版：最大宽度 480px，移动端友好
- 横版：最大宽度 960px，双栏/宽表，电脑横屏友好
- 头部：`var(--accent)` 实色背景 + 白色文字
- 段落标题：左侧 4px `var(--accent)` 竖线

### 组件速查
| 组件 | class | 用途 |
|------|-------|------|
| 头部 | `.head` | 标题、摘要、日期、大童在售产品标识 |
| 体况列表 | `.cond` | 客户体况与基本信息 |
| 核保结论 | `.uw` | 每个体况的核保结论/免责 |
| 说明框 | `.box` | 解释说明、要求、建议 |
| 产品卡片 | `.card > .card-head + .card-body` | 产品介绍 |
| 价格表 | `table` | 费率对比 |
| 家庭费率 | `.family` | 家庭成员组合费率 |
| 页脚 | `.footer` | 免责 + 大童在售产品落款 + 品牌句 |

### CSS 关键规则
- 表格文字 12.5px，表头 12px
- `.price` 价格列使用 `var(--accent)` 加粗
- `.bad` / `.good` 用于除外（红）/可赔（绿）标记
- `.lab` 左侧标签列灰色底加粗
- 打印：`-webkit-print-color-adjust: exact` 保留背景色
- 所有颜色通过 `:root` CSS 变量统一控制，不要硬编码色值

## 合规红线

- **落款包含免责说明与"大童在售产品"出处标识；不附加个人品牌信息**（如姓名、从业年限、服务家庭数）。防公开后被改本地，确保出处清晰
- 产品名称、价格可出现在产品卡片与落款（须来源明确、当下在售）
- **不写投资收益率、不写绝对化承诺**（如"一定赔"" guaranteed"）
- **所有产品信息必须来源可核验**：ima 大童在售产品或本地文件夹，不得凭记忆编造、不得用网络未核实信息
- 明确声明：**本 skill 不能给出准确核保结论**
- 客户隐私：不在页面暴露客户全名、身份证号、联系方式
- 页脚免责：`仅供参考，以正式核保结论及投保系统报价为准`

## 文件检查前置（制作开始前）

必须确认 ima 知识库 / 本地文件夹中每个产品包含：计划书、费率表、健康告知、责任免除、投保要求。缺文件主动告知，不编造。

工作流：
1. 让使用人提供产品所在 ima 知识库名称/ID 或本地文件夹路径
2. 列出知识库/文件夹内容，逐一确认 5 类文件存在
3. 列出"已有文件清单"让使用人确认，再开始制作

## 生成的网页可以手动修改吗？

可以。HTML 为纯文本，用任意编辑器可改数字、文字、颜色。协作流程：WorkBuddy 生成 → 使用人下载修改 → 把路径发回继续迭代。
