# 临床药师药品不良反应监测与报告

## Overview

本 skill 把临床药师的不良反应日常工作标准化、提速化：把自由文本或 Excel/CSV 病例数据转化为结构化记录，辅助 MedDRA 编码与因果关系评价，并产出符合国内法规的四类报告草稿。核心设计原则是**数据准确、不可自由联想**——任何关于「某药有什么不良反应 / 频率 / 严重程度」的陈述，都必须能追到一个可核验的权威来源，否则显式标注「待人工核实」交药师终审。

## 不可违背的准确性红线（最高优先级）

1. 凡涉及某药品的不良反应清单、发生频率、严重程度、禁忌，**必须**依据权威来源（见 `references/authoritative_sources.md`），不得凭记忆生成。
2. 每条关键安全性陈述后附来源标注（来源名称 + 获取日期 + URL/版本）；追不到时写「⚠️ 待人工核实」，**不得**悄悄替换为看似合理的猜测或删除该项。
3. 区分「已知不良反应」（说明书【不良反应】已收录）与「新的 / 新的严重」（未收录），二者上报要求不同。
4. 不把不同厂家、不同剂型、国内与国外说明书混为一谈；跨国差异须显式说明。
5. AI 产出仅作起草与整理，**法定报告须药师/医师审核签字后提交**；不得替机构做「是否豁免上报」的最终法律判定。
6. 统计数字一律以 `scripts/structure_cases.py` 输出为准，禁止手工估算或臆测趋势。

## 标准工作流

### 步骤 0：判定报告类型与输入形式
- 报告类型四选一（可组合）：个例 ICSR / 季度·年度汇总 / PSUR / 聚集性·严重事件。
- 输入形式：自由文本描述，或 Excel/CSV 台账，或两者兼有。
- 据此选择 `assets/templates/` 中对应模板，并按本文「报告分支」执行。

### 步骤 1：数据接入与结构化
- Excel/CSV：运行 `scripts/structure_cases.py <文件> [--out 结果.json] [--top N] [--map 原始列=标准列]` 得到结构化记录与汇总统计（总例数、新的/严重例数及占比、按药品/SOC/关联性/转归分布）。列名自动识别，识别不到时用 `--map` 指定。
- 自由文本：从描述中抽取每例的药品（通用名+商品名+批号+用法用量+起止）、不良反应表现、发生时间、处置与转归、合并用药，整理为个案条目，再套用 ICSR 模板。
- 两者兼有：先用脚本做整体统计，再对重点个案用文本分支深挖。

### 步骤 2：MedDRA 编码
- 对每条不良反应表现，参考 `references/meddra_coding.md` 映射到 PT 与 SOC；AI 所拟 PT/LLT 仅作初拟，**最终编码须由药师用授权 MedDRA 工具确认**。在报告中并列保留原始文字与编码。

### 步骤 3：因果关系评价
- 参考 `references/causality_assessment.md`：个例报告给出 WHO 五分法结论并附 Naranjo 计分过程；对怀疑药与合并药分别评价。

### 步骤 4：权威来源核对（每次必走）
- 对每个出现的药品，按 `references/authoritative_sources.md` 的核对流程：锁定药品身份 → 调取最新核准说明书【不良反应】→ 区分已知/新的 → 交叉检索 CDR 信息通报与 WHO UMC → 标注来源；无法获取则标「待核实」。
- 严重、死亡、聚集性事件，额外确认是否存在已知安全信号。

### 步骤 5：报告生成
- 复制 `assets/templates/` 对应模板到工作目录，逐项填充；未核到的项保留「待核实」占位。
- 各报告分支要点：
  - **ICSR**：患者脱敏信息 + 可疑药品 + 反应过程（含 MedDRA）+ 处置转归 + 关联性结论 + 来源核验。
  - **季度/年度汇总**：以脚本统计为骨架，重点信号分析须引用权威来源，趋势判断基于数据。
  - **PSUR**：安全性结论逐条对应数据源；「非预期」须对照最新核准说明书；不下超越数据的获益-风险结论。
  - **聚集性/严重事件**：快速溯源批号与来源链，判断上报阈值，列明已采取/拟采取处置。

### 步骤 6：质量自检（提交前）
- [ ] 每条安全性陈述有来源或「待核实」标注？
- [ ] 已知/新的、一般/严重 分类是否符合 `references/regulatory_basis.md` 口径？
- [ ] 统计数字是否与脚本输出一致？
- [ ] 患者隐私是否脱敏？审核签字栏是否保留？
