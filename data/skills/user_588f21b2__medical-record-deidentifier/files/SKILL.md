# 病案去标识工具

> 一句话：**把病案号变成不可逆的研究ID，同一患者跨文件跨批次永远同一个ID，纵向研究直接拼数据。**
> 纯本机离线运行，无网络请求；研究者版自动删除姓名列；对照表与密钥由病案科留存。

## 技能定位与边界

**做**：病案号→研究ID（HMAC-SHA256）、病案号归一化、批量/增量转换、干跑统计、对照表输出。

**不做**（命中请改推其他技能）：

| 用户真实需求 | 该用哪个 |
|--------------|----------|
| 数据质控、指标统计、出报告 | 病案首页数据处理器 |
| 选题研判、研究方案、标书 | 病案首页科研助手 |
| 数据买卖、外传、绕过院内审批 | 拒绝 |

与「病案首页数据处理器」是**标准搭档**：先用本技能把病案号换成研究ID，
再把去标识后的数据交给数据处理器做质控与统计——后者已兼容 `研究ID` 作为替代主键，
重复检测、31 天再入院、患者去重照常工作。

## Activation Triggers

**TRIGGER**

- 用户说"去标识""哈希化""病案号换成研究ID""脱敏""做纵向数据准备""增量转换"
- 用户提供含病案号列的首页/出院明细表，关心伦理合规或数据外发
- 用户提到 key.bin、对照表、总对照表、PID 前缀的研究ID

**DO-NOT-TRIGGER**

- 要质控/统计/报告 → 病案首页数据处理器
- 文件里没有病案号或患者标识列（先确认主键字段）
- 要在线服务或云端处理 → 本技能只做本机离线，无此模式

## 契约（5 条 MUST）

1. **MUST 走 CLI**：`python {skill_base}/scripts/deid_cli.py <mode> <输入> [flags]`。
   禁止自写哈希脚本替代——归一化规则、密钥管理、防覆盖、伪数据行处理都在里面。
2. **MUST 显式传 `--out-dir`**。key.bin 与全部产物都落在导出目录，不允许落在默认位置。
3. **MUST 在结果里向用户复述安全三件套**：对照表、总对照表、key.bin 只留病案科，
   严禁随数据外发；key.bin 丢失则无法再产生一致的研究ID，必须多处备份。
4. **增量转换 MUST 默认沿用密钥**（`--key-mode reuse` 是默认值）。
   只在用户明确说"全新一套数据、与旧数据无关"时才用 `new`，并提醒新旧批次无法关联。
5. **研究者版 MUST NOT 含姓名列**：工具自动识别并删除（姓名/患者姓名/病人姓名），
   `--keep-name` 只影响对照表（病案科留存版），不改变研究者版。

## 黄金示例

**1 干跑统计（先看可行性，不产生任何文件）**

```bash
python {skill_base}/scripts/deid_cli.py scan "D:/首页数据" --id-col 病案号
# stdout JSON：total / uniq / ge2 / repeat_dist / ge2_ratio_pct / skipped
# 住院≥2次占比 <5% → 病案号可能是"每次住院唯一"，建议改 --id-col 患者ID 或 身份证号
```

**2 首次批量转换**

```bash
python {skill_base}/scripts/deid_cli.py convert "D:/首页数据" --out-dir "D:/去标识导出"
```

**3 增量转换（新增年份，老患者ID不变）**

```bash
python {skill_base}/scripts/deid_cli.py convert "D:/2026新数据" --out-dir "D:/去标识导出"
# --out-dir 与之前批次相同 → 默认沿用 key.bin → 老患者研究ID与之前完全一致
```

**4 强制换新密钥（仅全新无关数据集）**

```bash
python {skill_base}/scripts/deid_cli.py convert "D:/新项目数据" --out-dir "D:/新导出" --key-mode new
```

**5 自检 / 体检**

```bash
python {skill_base}/scripts/deid_cli.py selftest   # 28 项核心逻辑自检，exit 0 = 全过
python {skill_base}/scripts/deid_cli.py --doctor   # openpyxl 等依赖体检
```

## 模式与 flags

| 模式 | 作用 | 产物 |
|------|------|------|
| `scan` | 干跑统计，不产生文件 | stdout JSON |
| `convert` | 批量转换 | 研究者版文件 + 对照表 + key.bin + 总对照表.csv + 批量转换报告.txt |
| `selftest` | 核心逻辑自检 | stdout（exit 0 = 全过） |
| `--doctor` | 依赖体检 | stdout JSON |

| Flag | 说明 |
|------|------|
| `--out-dir DIR` | convert 必填。key.bin 与全部产物所在目录 |
| `--id-col NAME` | 病案号列名，默认 `病案号`（精确优先，其次包含匹配） |
| `--name-col NAME` | 姓名列名；默认自动识别（姓名/患者姓名/病人姓名）并从研究者版删除 |
| `--keep-name` | 对照表中保留姓名（仅病案科留存场景；研究者版始终不含姓名） |
| `--key-mode reuse\|new` | 默认 reuse（增量转换）；new 会把旧密钥备份为 key.bin.时间戳.bak |

**stdout JSON（成功时单行）**：`success` / `mode` / `files` / `total` / `blank` / `uniq` /
`ge2` / `key_reused` / `master_n` / `report` / `skipped` / `security`。
失败时 `{"success": false, "error": {code, message, suggestion}}`。

## Hard Constraints

1. **解读 `scan` 结果时的口径**：`ge2_ratio_pct < 5%` 强烈提示病案号=住院号（每次住院唯一），
   必须提示用户换 `--id-col`，否则纵向研究全部失效。
2. **增量转换前 MUST 确认导出目录**：key.bin 在哪个目录，哪批数据就能关联。
   用户换目录时提醒"先复制旧 key.bin 到新目录"（GUI 版有按钮，CLI 版手动复制即可）。
3. **MUST NOT** 把 key.bin、对照表、总对照表复制或引用进任何报告/外发材料。
4. **密钥丢失不可恢复**：不存在找回机制，HMAC 是单向的。提醒用户多处备份。
5. **失败处理**：`success:false` 时按 `error.suggestion` 修，最多重试 2 次；
   仍失败如实报给用户，不得静默改用自写脚本兜底。

## 常见陷阱（实测踩过的）

| 现象 | 原因 | 处理 |
|------|------|------|
| 新旧批次同一患者ID对不上 | 旧数据用 v1.3 以前版本转换，无归一化 | 用 v1.4+ 规则重跑旧批次（见工具附带指引） |
| 前导零病案号算了不同ID | `0841651` vs `841651` | 已内置归一化；确认用的是本技能而非手搓脚本 |
| 表头被当成一条记录 | 导出文件带标题行 | 已内置伪数据行跳过，报告里会注明跳过数 |
| 16 位以上数字精度丢失 | Excel 数字格式 | 提醒用户先把该列改为文本格式 |
| `.xls` 不支持 | 老格式 | 让用户先另存为 `.xlsx` |

## Exit Criteria

* ✅ `{"success": true, ...}` 且导出目录里存在 key.bin、总对照表.csv、批量转换报告.txt
  → 向用户交付并**必须复述安全三件套**（对照表/总对照表/key.bin 病案科留存，勿外发）。
* ❌ `success:false` → 按 suggestion 修，最多 2 次。
* 🛑 仍失败 → 如实报告，等用户决策。
