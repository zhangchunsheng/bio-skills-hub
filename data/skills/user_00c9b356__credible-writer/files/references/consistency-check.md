# 逻辑一致性检查

> 真笔第三支柱——确保文本前后逻辑自洽，规则与实例不打架，比喻与论点不分裂。
>
> **为什么需要**：去AI味管"像不像人话"，去幻觉管"数据准不准"，但两者都不管"文章自身是否自相矛盾"。
> 一个完美的去AI味、零幻觉的文本，仍然可能在逻辑上自相矛盾——判定规则说"选后者"，分项却把后者标为错误。

---

## 起源：一个真实 bug

> 某自检题的判定规则写"选后者=共生"，但四个分项中，后者选项的极性标注有的是"共生"有的是"寄生"——规则和实例打架。整条写作→转HTML→推送流水线都没有任何环节能拦住这个问题。

根因：**缺少逻辑一致性检查**。文本的每个部分都"看起来正确"，但放在一起时彼此矛盾。

---

## 七维一致性清单

### 维度 1：判定规则-选项一致性

**检查对象**：含"判定规则 + 选项"结构的文本（自检题、评分卡、问卷、规则手册）。

**规则**：如果正文给出了一条判定规则（如"选 A = X"），那么所有选项的极性标注必须与该规则一致。

| 判定规则 | 正确的选项极性 | 错误的选项极性 |
|---------|--------------|--------------|
| 选前者 = 正面 | 前者标"正面"，后者标"负面" | 前者标"正面"，后者也标"正面" |
| 选后者 = 共生 | 后者标"共生"，前者标"非共生" | 后者标"共生"，某项后者标"寄生" |
| 分数 > 3 = 高 | >3 的标"高"，≤3 的标"低" | >3 的标"高"，但 4 分标"中" |

**检查方法**：
1. 提取所有判定规则句（含"选…=…""…为…""…则…"等句式）。
2. 对每个选项，验证其极性标注是否与规则一致。
3. 如果规则说"选后者"，检查所有分项的"后者"位置是否都是同一极性。

**红旗信号**：
- 规则句说 A，但实例里 B 位置也是 A 的极性。
- 规则句用"前者/后者"，但选项顺序在不同题中不一致。
- 规则句的极性词（正面/负面/共生/寄生）与选项标注的极性词不匹配。

---

### 维度 2：标题-正文一致性

**检查对象**：所有有标题的文本。

**规则**：标题承诺的内容，正文必须覆盖；正文的核心论点，标题必须反映。

**检查清单**：
- [ ] 标题说"三个原因"，正文确实列了三个（不是两个或四个）。
- [ ] 标题提到的关键术语，在正文中以相同含义出现。
- [ ] 标题的语气（质疑/肯定/中立）与正文结论一致。
- [ ] 标题里的数字、范围、时间，与正文一致。
- [ ] 没有"标题党"——标题暗示的内容正文没讲。

**红旗信号**：
- 标题写"5 个误区"，正文只列了 4 个。
- 标题说"最新"，正文数据是两年前的。
- 标题说"深度分析"，正文只有 200 字概述。

---

### 维度 3：比喻-论点一致性

**检查对象**：使用比喻、类比、隐喻的文本。

**规则**：比喻所暗示的因果或特征，必须与论点一致，不能比喻支持 A 而论点说 B。

**示例**：
```
❌ 比喻："这就像人体的免疫系统——遇到威胁自动激活"
   论点："需要人工干预才能启动"
   → 比喻说自动，论点说人工，矛盾

✅ 比喻："这就像人体的免疫系统——遇到威胁自动激活"
   论点："无需人工干预，系统自动响应"
   → 一致
```

**检查清单**：
- [ ] 比喻的核心特征（自动/手动、快/慢、开放/封闭）与论点一致。
- [ ] 比喻的范围与论点匹配——不会用"局部"比喻说"全局"的事。
- [ ] 同一文本中多个比喻之间不矛盾。

---

### 维度 4：术语一致性

**检查对象**：全文。

**规则**：同一概念在全文中用同一个术语，不混用近义词；不同概念不用同一个术语。

**检查方法**：
1. 建立术语表：扫描全文，列出所有专业术语和核心概念。
2. 检查是否有同义混用（如"模型/算法/系统"指同一东西）。
3. 检查是否有歧义复用（同一词在不同地方指不同东西）。

**常见问题**：
- 前文叫"共生关系"，后文改叫"互利关系"——读者不知道是不是同一概念。
- 前文"寄生"指生物学意义，后文"寄生"指商业模式——同一词两个意思。
- 中英混用不统一：有时用 "Skill" 有时用"技能"有时用"技能包"。

**检查清单**：
- [ ] 核心概念首次出现时定义，后续保持一致。
- [ ] 中英术语统一（选一种为主，另一种括注）。
- [ ] 缩写首次展开，后续保持。

---

### 维度 5：证据-论断匹配

**检查对象**：含数据和论断的文本。

**规则**：引用的证据必须实际支撑论断——不能证据说的是 A，论断却下 B 的结论。

**这不同于去幻觉**：去幻觉检查"数据是否真实"，一致性检查检查"真实的数据是否真的支持你的结论"。

**示例**：
```
❌ 证据："研究显示 70% 的用户更喜欢界面 A"
   论断："因此界面 B 更适合市场推广"
   → 证据支持 A，论断推 B，矛盾

✅ 证据："研究显示 70% 的用户更喜欢界面 A"
   论断："因此应优先推广界面 A"
   → 一致
```

**检查清单**：
- [ ] 每个论断引用的证据，其方向与论断一致。
- [ ] 证据的限定条件（样本量、时间、范围）在论断中被尊重。
- [ ] 没有选择性引用——只挑支持论断的证据，忽略矛盾证据。

---

### 维度 6：自检题/测试题对称性

**检查对象**：含自检题、测试题、评分卡的文本。

**规则**：如果有多道同类型题，它们的结构必须对称——选项数量一致、极性方向一致、评分规则一致。

**检查清单**：
- [ ] 每道题的选项数量相同（除非明确说明不同）。
- [ ] 评分规则在所有题中一致（如"选 A = 正面"在每题都成立）。
- [ ] 选项顺序的逻辑一致——如果第 1 题是"正面在前"，第 2 题不能突然变成"负面在前"。
- [ ] 每道题的分值权重一致（除非明确说明不同）。
- [ ] 题目数量与"判定规则"的阈值匹配（如"5 题中选 3 题以上"确实有 5 题）。

**红旗信号**（这就是触发本维度的原始 bug）：
- 判定规则说"选后者=共生"，但某些题的"后者"选项极性标成了"寄生"。
- 规则说"选 A 得 1 分"，但某道题没有 A 选项。
- 规则说">3 分为高风险"，但题目只有 2 道，满分 2 分。

---

### 维度 7：前后不自相矛盾

**检查对象**：全文。

**规则**：文本前面说的话，后面不能直接否定（除非有明确的"但是/更新/修正"转折）。

**检查方法**：
1. 提取全文所有断言性陈述（"X 是 Y""X 会 Y""X 导致 Y"）。
2. 检查是否有两条断言互相矛盾。
3. 如果有转折，检查转折是否明确标注。

**常见问题**：
- 前文"这个方法简单易用"，后文"需要注意复杂的配置步骤"——矛盾。
- 前文"不需要编程基础"，后文"需要了解基本的 Python 语法"——矛盾。
- 前文"完全免费"，后文"高级功能需要付费"——不算矛盾（有限定条件），但需要检查限定是否清晰。

**检查清单**：
- [ ] 全文断言性陈述之间不直接矛盾。
- [ ] 如有修正/转折，已用"但""然而""需要注意"等标注。
- [ ] 条件性陈述的限定范围前后一致。

## 发布前必过流程

> 以下流程是**硬门**：不通过则不交付。适用于所有输出，尤其是要走流水线（写作→排版→发布）的内容。

### 人工检查（LLM 执行，每次输出必做）

1. **通读一遍**，带着"这段话和前面说的矛盾吗？"的问题读。
2. **提取所有判定规则**，逐条验证选项极性是否一致（维度 1 + 6）。
3. **核对标题-正文**数量和关键词是否匹配（维度 2）。
4. **检查术语**是否全文统一（维度 4）。
5. **检查每个证据**的方向是否支持论断（维度 5）。

### 脚本检查（机械扫描，推荐每次输出运行）

运行 `scripts/check_consistency.py`，脚本会自动检查：
- 判定规则句 vs 选项极性位置是否自洽
- 术语是否全文统一
- 输出 PASS / WARN，有 WARN 时退出码为 1

```bash
python scripts/check_consistency.py <文件路径或目录>
```

### 严重等级

| 等级 | 含义 | 处理 |
|------|------|------|
| PASS | 未发现一致性问题 | 可交付 |
| WARN | 发现潜在一致性矛盾 | 必须人工复核后才能交付 |
| FAIL | 发现确定性矛盾（如规则与选项直接打架） | 禁止交付，必须修正 |

---

## 与其他两支柱的关系

| 支柱 | 检查什么 | 不检查什么 |
|------|---------|-----------|
| 去AI味 | 文本是否像 AI 写的 | 数据是否准确、逻辑是否自洽 |
| 去幻觉 | 数据是否真实有据 | 文本是否像 AI 写的、逻辑是否自洽 |
| **一致性检查** | **文本内部逻辑是否自洽** | 数据是否真实（那是去幻觉的活）、文本是否像 AI 写的 |

三根支柱**互相独立、互不替代**。一个零幻觉、零AI味的文本仍可能逻辑自相矛盾——这就是一致性检查存在的理由。
