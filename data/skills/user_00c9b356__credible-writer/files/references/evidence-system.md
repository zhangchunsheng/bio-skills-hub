# 证据标注系统

> 去幻觉核心——确保每个数据有据可查，每个观点经得起辩驳。

---

## 一、证据等级

| 等级 | 含义 | 来源类型 | 示例 |
|------|------|----------|------|
| 🥇 一级 | 最可靠 | 官方文档、GitHub仓库、学术论文（有DOI）、政府/监管机构公告、权威数据库 | Anthropic官方博客、GitHub仓库README、Nature论文 |
| 🥈 二级 | 较可靠 | 权威媒体、行业报告、公司官方博客（非公告类）、知名研究机构 | TechCrunch、Gartner报告、McKinsey Insights |
| 🥉 三级 | 需谨慎 | 社区内容、个人博客、公众号文章、知乎回答、Reddit | 知乎高赞回答、技术博客、Medium文章 |
| ❓ 待验证 | 无法确认 | 无法找到原始来源、来源链接失效、数据与其他来源冲突 | "听说""据传""有人说" |

### 判断规则
1. **优先使用一级证据**——如果有一级来源，不用二级
2. **核心数据必须至少二级**——影响结论的数据不能用三级来源
3. **三级来源只用于辅助**——提供背景信息，不支撑核心论断
4. **找不到来源就标❓**——不编造，不猜测

## 二、事实 vs 判断分离

### 事实（有证据支撑）
```
**事实**：Anthropic 于 2025年12月18日发布 Agent Skills 开放标准
- 证据：🥇 Anthropic 官方博客
- 来源：https://www.anthropic.com/news/agent-skills
- 置信度：95%
```

### 判断（逻辑推导或预测）
```
**判断**：Skill 化是 Agent 生态的必然趋势
- 依据：第一性原理拆解 + 历史类比（API → SDK → Plugin → Skill）
- 置信度：65%
- 辩驳风险：商业模式冲突可能阻碍趋势
```

### 分离原则
- 事实 = 可验证的客观陈述
- 判断 = 主观推导、预测、评估
- **永远不要把判断包装成事实**
- 如果不确定是事实还是判断 → 按判断处理

## 三、正反辩驳自检（Devil's Advocate）

对每个核心观点，执行以下检查：

### 步骤 1: 陈述观点
> "我认为 X 是正确的"

### 步骤 2: 构造最强反驳
> "反驳：X 不正确，因为 [最强理由]"

### 步骤 3: 评估反驳力度
- **强反驳**（有独立证据支撑）→ 必须在文中回应，或降低置信度
- **中等反驳**（有逻辑但缺证据）→ 标注为"已知风险"
- **弱反驳**（纯推测）→ 记录但不影响置信度

### 步骤 4: 回应或调整
- 如果能回应 → 在文中加入反驳和回应
- 如果不能回应 → 降低该观点的置信度
- 如果反驳太强 → 考虑修改观点本身

### 辩驳检查清单
- [ ] 对每个核心观点，我能说出最强反驳是什么？
- [ ] 我能立即拿出证据回应这个反驳吗？
- [ ] 如果不能，我是否已降低置信度？
- [ ] 我是否在文中承认了已知的风险和局限？

## 四、置信度计算

### 公式

```
置信度 = (证据链完整度) × 0.4
         + (A/B级来源占比) × 0.2
         + (独立验证指数) × 0.2
         + (对抗验证未发现错误 ? 0.1 : 0)
         - (证据缺失惩罚) × 0.1
```

### 各维度说明

#### 证据链完整度（权重 0.4）
**定义**：核心判断中有完整证据链的比例

完整证据链标准（必须全部满足）：
1. 有至少2个独立A/B级来源
2. 来源可查证（有链接）
3. 证据直接支撑判断（不是间接推理）

| 状态 | 完整度 | 示例 |
|------|--------|------|
| 完整 | 100% | 2个独立🥇来源 |
| 较完整 | 70% | 1个🥇 + 1个🥈 |
| 部分完整 | 40% | 只有1个来源 |
| 不完整 | 0% | 无可靠来源 |

#### A/B级来源占比（权重 0.2）
**定义**：来源中一级(🥇)+二级(🥈)的比例

#### 独立验证指数（权重 0.2）
**定义**：核心判断被独立来源验证的数量
- 2个以上独立来源 = 100%
- 2个独立来源 = 80%
- 1个来源 = 50%
- 0个来源 = 0%

#### 对抗验证（权重 0.1）
**定义**：执行正反辩驳后是否发现错误
- 未发现错误 = 0.1
- 发现错误并已修正 = 0.05
- 发现错误未修正 = 0

#### 证据缺失惩罚（权重 0.1）
| 状态 | 惩罚 |
|------|------|
| 证据完整 | 0 |
| 部分缺失 | -10% |
| 严重缺失 | -20% |
| 证据冲突 | -15% |

### 强制规则
- 证据链完整度 < 50% → ❌ **不能给出置信度**，输出"证据不足"
- 证据链完整度 50-70% → ⚠️ 警告，建议补充证据
- 证据链完整度 > 70% → ✅ 可以给出置信度

### 计算示例

```
判断：说人话 skill 在中文去AI味领域最为成熟

证据：
- 🥇 GitHub 仓库显示 669 stars（一级证据）
- 🥇 评测集 80 条，双模型交叉判分（一级证据）
- 🥈 知乎文章分析（二级证据）

计算：
- 证据链完整度 = 85%（3个来源，2个独立🥇）
- A/B级占比 = 100%
- 独立验证指数 = 80%
- 对抗验证 = 0.1（未发现错误）
- 证据缺失惩罚 = 0

置信度 = 85%×0.4 + 100%×0.2 + 80%×0.2 + 0.1 - 0×0.1
       = 34% + 20% + 16% + 10% - 0
       = 80%
```

## 五、不同文体的证据要求

| 文体 | 证据等级标注 | 置信度计算 | 事实vs判断 | 正反辩驳 | 数据来源附录 |
|------|-------------|-----------|-----------|---------|-------------|
| 公文 | 不标emoji，文字注明 | 不需要 | 不需要 | 不需要 | 引用文件用文号 |
| 小红书 | 简短标注 | 不需要 | 不需要 | 不需要 | 不需要 |
| 学术 | 强制 | 强制 | 强制 | 推荐 | 强制（参考文献） |
| 报告 | 强制 | 强制 | 强制 | 强制 | 强制 |
| 博客 | 引用时注明 | 不需要 | 推荐 | 不需要 | 不需要 |
| 自由 | 按需 | 按需 | 按需 | 按需 | 按需 |

## 六、数据来源标注格式

### 行内标注
```
说人话 skill 已获 669 stars（🥇，来源：GitHub 仓库，2026-07-09）
```

### 脚注标注
```
说人话 skill 在评测中表现最佳^1。
^1 数据来源：MrGeDiao/shuorenhua GitHub 仓库，访问时间 2026-07-09，https://github.com/MrGeDiao/shuorenhua
```

### 附录标注
```
## 附录A：数据来源

| 序号 | 数据 | 值 | 来源 | 等级 | 验证时间 |
|------|------|-----|------|------|---------|
| 1 | 说人话 stars | 669 | GitHub | 🥇 | 2026-07-09 |
| 2 | anti-slop 版本 | v3.0 | GitHub | 🥇 | 2026-07-09 |
```

## 七、常见幻觉模式及防御

| 幻觉模式 | 表现 | 防御方法 |
|---------|------|---------|
| 编造数据 | "据统计，XX%的用户……"但没有来源 | 强制标注来源，找不到就删 |
| 混淆来源 | 把三级来源说成一级 | 明确标注等级 |
| 过度泛化 | "所有AI写作工具都……" | 改为"部分""多数"或给具体范围 |
| 时间错乱 | "2024年发布的"但实际是2023年 | 验证后标注访问时间 |
| 张冠李戴 | 把A项目的功能说成B的 | 逐项核对来源 |
| 因果倒置 | "因为X所以Y"但证据只显示相关性 | 标注为"可能相关"而非"因果" |
| 信心膨胀 | 证据不足但写得像板上钉钉 | 降级表述，标注置信度 |
