# VTE 病历会诊工作流（vte-clinical-workflow）

## 概述

本复合技能融合两个能力：**病历 OCR 脱敏**（来自 medical-ocr）与 **VTE 循证诊治**（来自 vte-treatment-assistant v4.0）。用户上传病历资料后，本技能先完成「识别 → 提取 → 脱敏 → 结构化汇总」，再据此生成个体化 VTE 会诊意见。

**固定主流程（Step 0–4 不可跳过、不可颠倒）：**

```
⛔ Step 0  强制前置检查 — IMA 连接器 + VTE 知识库（硬阻断）
①  Step 1  病历脱敏提取 — OCR 识别 + 脱敏 + 11 段结构化汇总
②  Step 2  VTE 诊治       — 按 v4.0 标准生成会诊意见（最新证据优先）
③  Step 3  强制蒸馏       — 每轮对话后写入 memory + 更新权重（SkeMex）
④  Step 4  推荐阅读       — 按长期记忆分档推荐知识库资料（EduMex）
```

## ⛔ Step 0：强制前置检查 —— IMA 知识库依赖（硬阻断）

> **本技能强制依赖 IMA 知识库。未连接时不得进入 Step 1/2，必须立即停止并引导用户连接。此规则优先级最高，不可绕过。**

### 0.1 连接检测

按顺序执行以下两项检测，任一失败即判定「未连接」：

1. **连接器检测**：尝试调用 ima-mcp 连接器工具 `mcp__ima-mcp__get_knowledge_base_list`（或 `search_knowledge_base`）。若能正常返回知识库列表 → 已连接。
2. **凭证检测**：运行 `node scripts/check_ima.cjs`，检查 IMA 凭证（环境变量 `IMA_OPENAPI_CLIENTID`/`IMA_OPENAPI_APIKEY`，或 `~/.config/ima/client_id` + `api_key`）。返回 `{"ok": true}` → 凭证就绪。

### 0.2 未连接时的处理（硬阻断）

**立即停止执行，输出以下指引，不得继续任何 OCR 或诊治步骤：**

## ① Step 1：病历 OCR 识别、提取与脱敏

### 1.1 加载脱敏流程规范

读取 `references/medical-ocr/medical-ocr.md` 作为本步骤的**权威执行规范**（含方向校正、三引擎 OCR、阅读顺序重建、患者合并/拆分、脱敏规则、11 段门诊模板、隐私扫描清单）。

### 1.2 OCR 脚本调用

- **优先**：若本机已安装 `medical-ocr` 技能（`~/.workbuddy/skills/medical-ocr` 或 `~/.codex/skills/medical-ocr`），直接加载它执行。
- **兜底（自包含）**：若未安装，使用本技能自带的 `ocr/` 目录脚本，流程一致：

  1. **方向校正（必做）**：`python ocr/scripts/orient_images.py --input "<图片/文件夹>" --output "<工作目录>/_oriented"`
  2. **OCR + 脱敏**（手机翻拍病历默认 PaddleOCR）：
     `python ocr/src/medical_ocr.py --input "<工作目录>/_oriented" --output "<工作目录>/_ocr_raw" --format md --ocr-engine paddleocr`
     - 依赖缺失时按 `ocr/requirements.txt` 安装（RapidOCR/基础项），PaddleOCR 用 `ocr/scripts/install_paddleocr.ps1` 建隔离环境；首次运行需联网下载 PP-OCRv5 模型，之后可离线。
  3. 需要交叉核对时用 `--ocr-engine rapidocr` 或 `easyocr` 跑第二遍。

### 1.3 脱敏与结构化（硬门槛）

1. **患者隐私脱敏**：删除姓名、身份证号、联系方式（电话/手机）、住院号/就诊卡号/医保卡号、住址、医院/机构名称及简称、就诊时间/打印时间、费别、就诊医师、科别（可能含院区地理线索）、术者姓名（术式后括号内带称谓的人名）。**删除后不保留 `___` 或 `_` 占位**。保留临床检查日期、手术日期与用药时间线。
2. **隐私残留扫描（交付前硬门槛）**：扫描 `姓名/生名/姓各` 等标签变体、已知医师姓名碎片、手写签名、身份键残留；未通过不得进入 Step 2。
3. **结构化汇总**：将脱敏结果改写为「## 门诊脱敏病例输出模板」的 11 段结构（患者基本信息/主诉/现病史/既往史/过敏史/个人史与家族史/体格检查/辅助检查/诊断/治疗方案/病情评估与建议）。缺失内容写「无记录。」，推断内容标注「推测」。
4. **文件命名**：用主要诊断命名（如 `深静脉血栓形成.md`），不含姓名、日期、卡号；统一输出到用户指定目录。

### 1.4 关键数据确认门

OCR 易在数值与药名上出错。**影响治疗决策的关键数据**（肌酐、D-二聚体、药物剂量、血管名称）在进入 Step 2 前必须与用户核对确认；无法确认的写入「人工复核提示」，不得猜测。

## ② Step 2：VTE 诊治（严格按 v4.0 标准）

### 2.1 加载 v4.0 引擎

读取 `references/vte-v4/vte-treatment-assistant.md` 作为本步骤的**权威诊治引擎**，严格按其三引擎闭环流程执行：

- **Phase 0** SkeMex 技能记忆读取（`references/vte-v4/skill_memory/`）
- **Phase 0.5** EduMex 学习状态读取（`references/vte-v4/edumex/`）
- **Phase 2** 逐项核实 11 项关键参数（年龄/性别/身高/体重/术前术后/手术/抗凝禁忌/合并抗栓/肝功/肾功/D-二聚体；儿童加基础疾病、剂型、校正年龄；转换场景加当前抗凝药、转换原因）
- **Phase 3** 查询 IMA 知识库生成治疗策略（`mcp__ima-mcp__search_knowledge`，至少 2-3 个角度；**强制遵守下方 2.2「指南时效性优先」** 与转换期 Iron Rule 3.X/3.Y/3.Z）
- **Phase 3.5** 抗凝转换引擎（若涉及药物转换）
- **Phase 4** 结构化输出与参考文献
- 输出后**强制**执行 Phase 5/6/7（对应下方 Step 3、Step 4）

### 2.2 🔒 指南时效性优先（Iron Rule，不可绕过）

> **当检索到同一指南/共识系列的新旧版本时，强制采用最新版本，绝不以旧版替代新版。此规则优先级高于其他所有推理，不可绕过。**

1. **版本识别**：每次读取知识库文档，先检查标题/摘要中的发布年份与版本号（例：NCCN V1.2026 vs 更早版、ACCP 9th vs 10th、ASH 2018 vs 更新版、CSCO 2019 vs 更新版、法国 CAT 2023 vs 更早版、ESVS 2021）。
2. **冲突即用新版**：同系列新旧推荐不一致 → **一律采用最新版意见**；旧版仅作历史对照，标注「[已被 XX 年版更新]」。
3. **输出显式标注**：凡涉及新旧差异的推荐，必须写明「此项依据 [最新指南名称 + 年份]；[旧版名称 + 年份] 曾有不同推荐（简述），已被最新版更新取代」。
4. **无法判断新旧时**：以发布年份较晚者为准。

**常见指南系列对照（供版本识别）：**

| 指南系列 | 旧版本 | 最新版本（优先采用） |
|----------|--------|---------------------|
| NCCN 癌症相关 VTE | 旧版 | **2026 V1** |
| CSCO 肿瘤相关 VTE | 2019 | 库内如有更新版则用更新版 |
| 法国 CAT 指南 | 2019 | **2023 更新版** |
| ACCP（Chest） | 9th (2012) | 10th (2016+) |
| ASH/ISTH 儿科 VTE | — | **2026** |
| ESVS 静脉血栓 | — | 2021 |

### 2.3 信息核实与确认门

Step 1 得到的脱敏病历作为输入，进入 v4.0 Phase 2 的 11 项参数核实。**必填项（年龄、性别、身高、体重、抗凝禁忌、肾功能）缺失时必须向用户补齐；患者信息确认无误后才进入 Phase 3**，防止错误信息导致不当治疗建议。

## ③ Step 3：强制 SkeMex 蒸馏（每轮对话必做）

> **每当本技能产出一份较长会诊意见（或任何实质诊疗建议）后，本轮对话必须立即完成蒸馏：写入技能 memory 并更新权重。不可跳过、不可「下次再说」。**

### 3.1 蒸馏触发（强制）

本轮满足以下任一即触发，**当轮完成**：
- 已产出完整会诊意见（总结版 + 详细版）
- 用户纠正了推荐（剂量/药物/疗程/分型）
- 用户追加关键信息改变了策略
- 出现知识库未覆盖、靠推理解决的罕见场景

### 3.2 双路径蒸馏（按 v4.0 Phase 6）

**第一遍 · 意图判定**（CREATE / PATCH / NONE）：
- **CREATE**：发现新的可复用临床模式 → 新建技能条目
- **PATCH**：已有条目需修正/补充 → 修补
- **NONE**：平庸交互 → 不写（但仍须完成 3.3 权重 Assess）

**第二遍 · 生成/更新**：
- CREATE：写入 `references/vte-v4/skill_memory/{general|task_vte|action_tools}.json`，条目字段：`id / branch / trigger / content / evidence / source_date / source_case / utility / adoptions`
- PATCH：更新已有条目的 `content` 或 `utility`
- 追加 `references/vte-v4/skill_memory/evolution_log.md`

### 3.3 权重更新（SkeMex Assess，每轮必做）

对**本轮实际采用过**的技能记忆条目，按用户反馈更新 `utility`（0–1）：

| 反馈信号 | 效用更新 |
|----------|----------|
| 用户直接采纳（未纠正） | +0.05 ~ +0.10 |
| 用户部分修正 | +0.00 ~ +0.03 |
| 用户推翻重做 | -0.10 ~ -0.20 |
| 被检索但未影响最终输出 | +0.00 |

- `utility ≥ 0.8` 且正面采纳 ≥5 次 → 标记「成熟 ⭐」；`utility < 0.3` → 标「待验证」；`< 0.1` 或连续 5 次负面 → 淘汰。
- 完成后回报用户：「本轮已蒸馏 N 条、权重调整 M 条」。

### 3.4 治理（Govern，按需）

每 20 次交互或每周执行一次：合并相似条目、降级低效用、淘汰负效用、晋升成熟条目；每个分支容量上限 50 条，超出淘汰最低效用者。

## ④ Step 4：推荐阅读（按长期记忆分档）

> **每次会诊意见交付后，必须附带 1–3 条「知识库内」延伸阅读推荐。档位由长期记忆中的用户专业背景决定。**

### 4.1 读取长期记忆

读取 `references/vte-v4/edumex/learning_state.json` 的 `learner_profile.specialty`（为空则从对话判断并回写）。二分类：

| specialty 值 | 含义 | 推荐档位 |
|-------------|------|---------|
| `vascular_surgery` | 血管外科专家 | **advanced** — 较新文献、最新指南、Meta 分析、前沿 RCT 精读 |
| `non_vascular` | 非血管外科专业 | **beginner** — 大指南导读、基础 PPT、核心概念讲义 |
| 空 / 未判定 | 首次使用，先询问用户专业背景 | 按回答定档并写入长期记忆 |

### 4.2 分档推荐规则

- **血管外科专家（advanced）**：优先推荐知识库内**较新的文献与指南**——如 NCCN 2026 V1 CAT 指南、法国 CAT 2023 更新版、最新 RCT 精读笔记（Abelacimab AZALEA-TIMI 71、DEFIANCE 2025）、VTE 合并 CKD 微循环专家共识。**避免推基础 PPT。**
- **非血管外科专业（beginner）**：优先推荐知识库内**相对基础的内容**——大型指南导读/概述、基础 PPT（如「VTE 常用抗凝药物和辅助检查方法」「从临床需求看 VTE 精准抗凝」）、综述讲义。**避免推前沿争议文献。**

### 4.3 输出格式

```
📚 延伸阅读推荐（来自 VTE 知识库）
- 《资料标题》—— 一句话说明为什么适合你（按专业背景）
- ...
```

> 推荐只从**已加入的 VTE 知识库**内选取（本次检索命中或既往确认存在的资料），不得虚构条目；库内无合适档位资料时如实说明并建议补充。
