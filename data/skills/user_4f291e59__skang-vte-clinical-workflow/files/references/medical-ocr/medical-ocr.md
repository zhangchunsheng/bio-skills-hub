# Medical OCR

## 功能

将纸质门诊病历扫描件识别为结构化文档，支持：

- 图片方向自动校正：OCR 前先按 EXIF + 文本框几何 + 方向分类器把照片转正（`scripts/orient_images.py`）
- OCR 文字识别（RapidOCR 本地引擎）与坐标阅读顺序重建，多页合照先按纸张页块恢复阅读顺序
- 可选 EasyOCR 中文识别后端（`--ocr-engine easyocr`），用于 `佘/余`、`腘/国`、`胫/轻/径` 等中文医学字形混淆较多的图片
- PP-OCRv5 中文本地后端（`--ocr-engine paddleocr`），安装在 skill 的隔离环境中，用于罕见医学汉字、化验单位、低清/倾斜图片和既往已出现明显错字的病例
- PDF 按患者自动分组
- 单张图片或图片文件夹逐张输出；若一张照片误拍入多个患者，必须先按患者拆分为多份病历再脱敏
- 批量图片在脱敏前先抽取患者姓名与就诊卡/医保卡/身份证等身份键核对；同一患者的多张照片或重复病例必须先合并为一份病历，再按就诊时间和检查时间线整理
- OCR 常见错误自动纠正
- 化验单医学格式归一化：校验小数点、升降箭头、`×10^9/L`、`×10^12/L`、`fL`、`μmol/L`、`mg/L` 等数量级与基本单位；无法由项目名称和参考范围共同确认时转人工复核，不猜值
- 敏感信息脱敏（医院/机构名称及简称、姓名、就诊卡号、身份证号、就诊时间、打印时间等直接删除，不保留下划线占位），并删除费别、医保就诊卡、就诊医师和科别信息；科别可能包含院区或区县等可定位地理线索
- 术者姓名脱敏：手术方式/手术名称后，或以“术”结尾的术式后，括号内带“医生/医师/主任/教授/大夫/先生”等称谓的人名必须删除
- 智能分段（主诉、现病史、诊断、处理等）
- 清理 OCR 版面空格：删除中文词句中间、中文与中文标点之间的无意义空格；不得删除任何文字，且保留英文缩写、单位和 Markdown 排版所需空格
- 水印、页码、医院页眉、时间页眉、重复基本信息清理

## 隐私与安全

- 仅在本机执行 OCR 和脱敏，不把病历内容发送到外部服务。
- 不在对话中展示未脱敏原文或患者身份信息。
- 输出文件名不得使用患者姓名、身份证号、就诊卡号等身份信息。
- 对外发送、上传或分享输出结果前，必须先向用户确认。

## 执行流程

1. 检查并安装依赖。
2. **图片方向校正（OCR 前置必做步骤）**：任何图片进入 OCR 前，必须先运行 `scripts/orient_images.py` 把照片转正，输出到独立的 `_oriented` 目录，OCR 只读取校正后的图片。详见「图片方向自动校正」章节。
3. 初始化 OCR 引擎：手机翻拍的门诊病历默认直接使用 PaddleOCR（PP-OCRv5）；RapidOCR 仅用于清晰印刷件的快速初筛或作交叉核对的第二结果。
4. 读取输入：
   - PDF：转为图片后 OCR，再按患者标识分组。
   - 图片文件：单图 OCR；若同图存在多个患者，按不同患者基本信息拆成多份输出。
   - 图片文件夹：按文件名排序，**串行**逐张 OCR；不得用并行 subagent 分发图片，避免同一患者跨图信息割裂和脱敏口径不一致。
   - 批量任务默认「先处理第 1 张 → 交用户审核 → 确认后再逐张处理其余」。
5. OCR 后先执行阅读顺序重建：多张纸拍在同一照片时，按页块从左到右/从上到下读取，同一患者 1-5 张纸必须先合并成完整病历。
6. 若同一批图片中患者姓名与就诊卡/医保卡/身份证等身份键相同，视为同一患者；必须先合并为一份病历，按就诊时间、检查日期和页码整理时间线，再进入脱敏输出。
7. 若同一照片中出现第二个不同患者姓名/基本信息，必须在脱敏前切分为独立患者病历，文件名使用匿名后缀（如 `诊断名_A`、`诊断名_B`），不得使用患者姓名。
8. 若原图倒置或多页合照，先按页码（第 1/3、2/3、3/3）和病历段落顺序恢复页面顺序；不要让第 2、3 页的诊断、处理、处置意见跑到主诉/现病史前。
9. 执行后处理：OCR 纠错、水印/页码/医院页眉/打印时间/费别/就诊医师/重复内容清理、段落分段。
10. 执行脱敏：医院/机构名称及简称、姓名、就诊卡号、身份证号、就诊时间、电话、住址、科别等直接删除，不在原位置保留 `___` 或 `_`。临床检查日期、手术日期和用药时间线应保留；挂号、打印、就诊登记及过敏记录日期应删除。
11. 删除术式后括号中的术者姓名，例如 `...吻合术（张医生）` 应输出为 `...吻合术`。
12. 清理 OCR 插入的无意义中文空格，例如 `静脉 切开` 应输出为 `静脉切开`；不要删除文字。
13. 执行脱敏后医学一致性检查：检查机构删除后遗留的虚词或残句、姓名字段 OCR 变体（如“生名/姓各”）、手写签名碎片、化验角标和血管解剖词。明显可由上下文唯一恢复的才自动修正，否则写入匿名人工复核清单。
14. 当“处理/处置”和“处置意见”同时存在且冲突时，保留医生特别书写的“处置意见”，删除系统自动复制的开药/检查/检验类“处理”记录，避免把系统处置误当作实际医嘱。
15. **按门诊脱敏病例模板重排**：脚本产出的原始分段 Markdown 只是中间件，最终交付必须改写为「## 门诊脱敏病例输出模板」的 11 段结构。
16. **文件名使用主要诊断命名**，统一输出到用户指定的一个输出目录。命名规则见模板章节。
17. 检查输出数量与脱敏痕迹，报告摘要。

## 图片方向自动校正（OCR 前置必做步骤）

手机翻拍的病历常出现横放、倒置。**必须先转正再 OCR**，否则分段、阅读顺序和形近字纠错全部失真。

### 为什么不能用「哪个角度识别文字多」来判方向

RapidOCR / PaddleOCR 的检测与识别对方向不敏感：同一张图在 0/90/180/270 度下，识别文本量、字符数、平均置信度几乎相同（实测四个角度得分差 <1%），用文本量投票必然误判。

### 正确判据（`scripts/orient_images.py` 已实现）

1. **EXIF Orientation** 先做无损纠正（`PIL.ImageOps.exif_transpose`）。
2. **几何判横竖**：只跑文本检测，统计检测框宽高比。正立/倒置时文字行是横向长条（AR>2 的框数量多）；转 90/270 度时变竖条。以「宽框数量」较多者为基准方向。实测区分度极高（例：0 度 51 个宽框 vs 90 度 0 个）。
3. **方向分类器判正倒**：在基准方向上裁出文本条，交给 PP-OCR 的 `text_cls`（0/180 分类器）按置信度加权投票，决定是否再转 180 度。
4. 宽框数量差 <3、或正倒票差 <25% 时标记 `low_confidence`，提示人工确认。
5. 校正结果写入独立 `_oriented` 目录（保持原文件名）+ `_orientation_report.json`。

### 调用

```bash
python "$env:USERPROFILE/.workbuddy/skills/medical-ocr/scripts/orient_images.py" \
  --input "<图片或文件夹>" --output "<工作目录>/_oriented"
```

只依赖 `rapidocr_onnxruntime` + `pillow` + `numpy`，全程本机运行。

## 使用方法

Windows（本机已配置 managed venv，直接用其 python）：

```powershell
$PY = "$env:USERPROFILE\.workbuddy\binaries\python\envs\default\Scripts\python.exe"
$SK = "$env:USERPROFILE\.workbuddy\skills\medical-ocr"

# 1) 方向校正
& $PY "$SK\scripts\orient_images.py" --input "<原图文件夹>" --output "<工作目录>\_oriented"

# 2) OCR + 脱敏（手机翻拍病历默认 paddleocr）
& $PY "$SK\src\medical_ocr.py" --input "<工作目录>\_oriented" --output "<工作目录>\_ocr_raw" --format md --ocr-engine paddleocr
```

需要交叉核对时再用 RapidOCR 或 EasyOCR 跑第二遍，对比形近字：

```powershell
& $PY "$SK\src\medical_ocr.py" --input "<工作目录>\_oriented" --output "<工作目录>\_ocr_cross" --format md --ocr-engine rapidocr
```

也支持位置参数：

```powershell
& $PY "$SK\src\medical_ocr.py" "<输入路径>" --output "<输出目录>"
```

注意：`_oriented`、`_ocr_raw` 等为中间目录，交付前应清理或移出交付目录，只保留按模板改写后的最终脱敏病历。

## 参数

- `--input` 或位置参数：输入路径，支持 PDF、单张图片、图片文件夹。
- `--output`：输出目录，默认 `./output`。
- `--format`：输出格式，`md` 或 `docx`，默认 `md`。
- `--ocr-engine`：`rapidocr`、`easyocr`、`paddleocr` 或 `auto`；默认 `rapidocr`。`auto` 按 PaddleOCR → EasyOCR → RapidOCR 初始化回退。
- `--recursive`：处理文件夹时递归读取子文件夹；默认只处理顶层图片。

## OCR 引擎选择

- **手机翻拍的门诊病历（本项目最常见）：直接用 `paddleocr`**。实测同一张图 RapidOCR 会丢字、错字（`左髂动脉` → `左动脉`、`10mg` → `1Omg`、诊断分隔符错乱），PP-OCRv5 均正确；不要为省时间先跑 RapidOCR 再返工。
- 清晰、标准印刷件的快速初筛：可用 `rapidocr`。
- 两套引擎结果不一致的字，按下肢血管解剖与临床上下文判断；不能唯一确定的写入人工复核提示，不猜。
- 用户明确要求质量优先，或同一批次此前已出现多处医学错字：使用 `auto`，优先 PP-OCRv5。
- PaddleOCR 与 RapidOCR 结果冲突且无法由医学上下文唯一判断：再用 EasyOCR作第三结果，只标记人工复核，不按多数表决擅自改值。
- 不因为单个标点错误自动调用重型引擎；先用后处理规则修正可唯一确定的格式问题。

## 门诊脱敏病例输出模板（最终交付格式）

最终交付必须按下列 11 段结构改写。缺失内容写「无记录。」，不得编造；由上下文推断的内容要标注「推测」。

```markdown
# [门诊病历] 脱敏医疗报告 - 主要诊断/次要诊断

### 1. 患者基本信息 (De-identified Patient Profile)

* **年龄：** XX岁
* **性别：** 男/女

### 2. 主诉 (Chief Complaint)

* 一句话主诉，保留时程。

### 3. 现病史 (History of Present Illness)

* 按时间线分条列出：起病、外院诊治、本次发现、当前症状、用药情况。

### 4. 既往史 (Past Medical History)

* **慢性病史：** ...（无则写「无记录。」）

### 5. 过敏史 (History of Allergies)

* 否认药物及食物过敏史 / 具体过敏原。（删除「记录日期」）

### 6. 个人史与家族史 (Personal & Family History)

* **个人史：** 吸烟、饮酒等。
* **家族史：** 家族中有无 VTE 等病史。

### 7. 体格检查 (Physical Examination)

* **一般情况：** 身高、体重等。
* **专科检查：** 患肢肿胀、Homans 征、足背动脉搏动、伤口情况等。

### 8. 辅助检查 (Ancillary Examinations)

* **8.1 化验单结果 (Laboratory Results)**
  * D-二聚体、血常规、凝血、肝肾功等；无则写「本次就诊记录中无化验数据。」
* **8.2 影像学检查 (Imaging Studies)**
  * **YYYY-MM-DD 超声/CT/MRI：** 结论原文（保留检查日期）。

### 9. 诊断 (Diagnosis)

1. 主要诊断
2. 次要诊断

### 10. 本次就诊治疗方案 (Treatment Plan)

* **药物治疗：**
  1. **药名：** 每次剂量，频次，途径（作用说明）。
* **其他治疗：** 压力治疗、手术计划等。

### 11. 病情评估与建议 (Assessment & Recommendations)

* **处置意见：**
  * 风险告知、抗凝疗程、复查安排、监测指标等。
```

### 模板使用要点

- 药物写法统一为「每次 Xmg，每日 N 次，口服」，括号内注明作用（抗凝／消肿／改善微循环）。
- 「处理」中系统自动开单记录与医生手写「处置意见」冲突时，只保留处置意见。
- 现病史中的用药剂量与处置意见剂量不一致时，如实写出调整关系（例：由 10mg bid 调整为 10mg qd），不要抹平。
- 文末可追加一行匿名「人工复核提示」，只写问题类型和已做的上下文更正，不摘录身份信息。

### 文件命名规则

- 用**主要诊断**命名，可附次要诊断，例：`深静脉血栓形成2型糖尿病.md`、`人工血管血栓形成软骨肉瘤.md`。
- 只用中文诊断名，不含姓名、日期、卡号、原图文件名。
- 诊断名去掉标点和空格直接连写；名称过长时只保留前两个诊断。
- 同一诊断出现多例时追加数字后缀：`下肢深静脉血栓形成2.md`。
- 所有文件统一放入用户指定的**同一个输出目录**，不按图片再分子目录。

## 下肢血管术语复核

- 使用 `src/postprocess.py` 中的纠错表规范髂总/髂内/髂外动静脉、股总/股浅/股深动静脉、腘动静脉、胫腓干、胫前/胫后/腓动静脉、肌间静脉、大隐/小隐静脉等词。
- 对 `脑动脉/脑静脉`、`胖动脉` 等有歧义的 OCR 结果按同一行血管解剖序列判断，不得全局替换；股深动脉之后通常为腘动脉，胫后动脉之后通常为腓动脉。
- 使用有限血管词典校验下肢血管名称，至少覆盖：髂总/髂内/髂外动静脉、股总/股浅/股深动静脉、腘动静脉、胫前/胫后动静脉、胫腓干、腓动静脉、肌间静脉、大隐静脉、小隐静脉。词典外形近字（骼、胖、群、课等）必须回看原图或进入人工复核。
- 将 `骼总/内/外动静脉` 规范为 `髂总/内/外动静脉`，将 `胚腓干/径腓干/轻腓干` 规范为 `胫腓干`。
- 核对血管内径、血栓范围和药物剂量中的小数点与单位；混合字符不能确定时必须标记人工复核，不得猜测。
- 化验项目按项目名校验数量级：WBC/PLT/LY# 等细胞计数通常使用 `×10^9/L`，RBC 使用 `×10^12/L`，MCV 使用 `fL`，肌酐使用 `μmol/L`。这一规则用于发现 OCR/转码错误，不能脱离原图擅自改动数值。
- 将 `医学中心` 与 `医疗中心` 同样视为机构名称并脱敏，同时保留其后的临床诊断意见。
- 医院简称（例如仅由院名缩写形成的两三个汉字）同样属于机构信息；应删除简称但保留前后病史语义。
- 体征优先使用标准词：`可凹性水肿`、`Homans征`；影像方式使用 `MR`/`MRI`，不得依据形近字输出无医学语义的词。
- 每次扩充纠错表后运行 `python -m pytest tests -q`，并在真实输出中扫描错误变体和机构残留。

## 乱码与备用 OCR 安全检查

- 遇到“乱码”反馈时，先验证文件能否严格按 UTF-8 解码，并扫描 `U+FFFD` 替换字符和异常控制字符；若均不存在，应按 OCR 漏字/错字处理，而不是转码。
- 使用备用 OCR 引擎时，将其结果按未脱敏原文处理；若姓名、卡号等字段标签被错识导致脱敏器无法识别，不得保留、展示或交付该临时输出，应移入回收站。
- 只有两套 OCR 或诊断上下文能明确支持时才补回漏字；无法恢复语义的页尾碎片应删除或标记人工复核，不得编造处置内容。

## 检查输出

- 确认每张图片都经过方向校正，且 `_orientation_report.json` 中 `low_confidence` 的图片已人工确认。
- 确认最终交付文件全部为 11 段模板结构，文件名为中文主要诊断，且集中在同一输出目录。
- 确认中间目录（`_oriented`、`_ocr_raw`、`_ocr_cross`）未混入交付目录。
- 确认 Markdown 文件数量符合输入数量或患者分组数量。
- 抽查单张照片误拍入多个患者时，是否已拆为 `A/B` 等多份匿名病历；不得在同一 Markdown 中出现两个不同患者的 `主诉/现病史/诊断` 整套记录。
- 抽查既往史、过敏史是否保留完整语义；这些病史段落不得按日期拆成辅助检查段落。
- 抽查同一行内出现多个段落标题时是否已拆开，例如 `过敏史...个人史...辅助检查...` 不得整体留在过敏史内。
- 抽查输出文件中具体医院/机构名称或简称、姓名、就诊卡、身份、就诊时间、打印时间、科别及院区地理线索是否已删除，不应残留 `___` 或 `_` 占位。
- 抽查临床检查日期是否保留并与相应检查结果相邻；不得把检查日期与挂号、打印、过敏记录日期一并清除。
- 抽查输出文件中不得出现 `费别`、`医疗保险就诊卡`、`就诊医师`、`就诊医生签字`。
- 扫描 `姓名/生名/姓各` 等姓名标签变体、已知医师姓名及手写签名碎片；隐私扫描必须作为交付前硬门槛。
- 另生成只含匿名文件名和问题类型的人工复核清单，不摘录未脱敏病历正文。
- 抽查删除医生标签后不得残留已知医生姓名碎片。
- 抽查术式后括号中的术者姓名是否已删除，例如 `术（某医生）`、`术（某先生）`。
- 抽查中文正文中是否仍存在无意义空格，例如 `静脉 切开`、`沙 班`、`下肢 深静脉`；清理时不得删除任何文字。
- 抽查血管外科常见词：`佘康` 不得误留为 `余康/余律`；`腘静脉`、`胫后静脉`、`肌间静脉`、`大隐静脉` 等不得出现明显 OCR 错字。若 RapidOCR 错字较多，使用 `--ocr-engine easyocr` 复跑该图片。
- 抽查同一病例同时有 `处理：药品...` 与 `处置意见：...` 时，最终输出应保留 `处置意见`，删除系统开药记录。
- 检查是否存在未分类页面。
- 报告处理摘要，不展示患者身份信息。
