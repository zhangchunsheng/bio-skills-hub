# 边界情形处理协议（数据缺口 / 争议 / 假设隔离）

> 用途：当任务遇到**证据缺口、信源冲突、或用户前提无法独立验证**时，强制按本协议响应——不靠自觉。
> 来源：v4.3 合并自 `lessons_pending.md` P1-9（LBL-024 雪球单一信源 OS 拖尾假设、OA14.01 vs ESMO #9990 数据冲突教训）。
> 总原则：**诚实优于流畅**；任何不确定的内容在交付物中必须可被读者识别为"不确定"，而非混入事实层。

---

## 一、数据缺失三级响应

### (a) 直接证据缺失（我要用的数字找不到一手来源）
1. **显式声明**："⚠️ 无直接证据支持 [X]"。
2. **给最近代理证据（proxy）**：用最相关、可信度最高的相邻证据推断，并标注推断跨度（如"以 [Y 研究] 同类人群外推，置信度 🟡"）。
3. **附可确认清单**：列出验证该数字应查的官方源（CT.gov 登记号 / 公司公告日期 / 顶刊 DOI），供用户或后续轮次回填。
4. **禁止**：用记忆补全精确 HR/mOS、或直接把代理值当事实陈述。

### (b) 数据冲突（两来源不一致）
1. **并列呈现**：把两说都列出，不替用户"选边"。
2. **来源分级标注**：按 `source_whitelist.md` 三级标记各自等级（一级/二级/三级）。
3. **仲裁指向**：指明以**官方/监管/注册库**为准（如 CT.gov 历史版本、公司公告原文、大会官方摘要编号）；若冲突源于会议摘要 vs 全文，标注"待全文/官方议程仲裁"。
4. **我的倾向（可选）**：可在并列后附一句"基于 [依据] 暂取 [X]"，但必须保留另一说。

### (c) 用户前提不可验证（用户给的假设/数字我无法独立核实）
1. **"假设性输入"隔离框**：明确标注该前提来自**用户输入**，非我独立核实。
2. **不污染事实层**：在推导中把它作为变量/情景输入，而非既定事实；敏感性分析里把它设为可调滑块。
3. **标注待用户确认**：结尾列出"以下前提需您确认：[…]"。

## 二、争议双记录协议（用户观点 vs 独立判断）

当任务涉及**用户已有明确观点**（如雪球大 V 论断、用户个人判断）且可能与独立证据冲突时，必须双记录：

| 字段 | 内容 | 示例（LBL-024） |
|---|---|---|
| **用户/信源观点** | 对方主张是什么 | "024 OS 拖尾，HR 会持续改善" |
| **独立验证状态** | 🟢已证实 / 🟡部分印证 / 🔴无法验证 | 🔴 单一自媒体信源，无顶刊/注册库佐证 |
| **分歧点** | 冲突的具体数字/逻辑 | 拖尾假设缺生存曲线支持；竞品 AK112 已读出的 OS-HR 不支持此推断 |
| **我的独立判断** | 分析师立场（可修正用户） | 该假设需 🔴 标注，不得作为估值输入；以官方随访数据为准 |

**强制动作**：双记录表出现在交付物中，且对 🔴 项不得写入结论性陈述。

## 二·B 口头纪要/转写文本处理协议（★ v4.9 重建；原 v4.8 批次被 2026-09-01 整目录写入覆盖 ★）

> 触发条件：电话会/业绩会/访谈的**录音或第三方语音转写文本**作为信源。转写是"半可信"信息源，风险**双向**——
> **错误①：把"被转写弄错的真实信息"当噪音丢弃**。实战：映恩 DB-1312（百济 B7-H4 ADC，最高 13 亿美元真实交易）在转写中面目全非，agent 初判为转写错误，用户提醒后经官网核实为真——用户一次纠正挽回了实质性误判。
> **错误②：把"纯噪音"当真采信**。实战：映恩纪要年份系统性偏移 2 年（2024↔2026）。

### B.1 名词核正协议（四步，强制）
1. **先假设有误**：所有专有名词（药名/靶点/公司/合作方/试验名/会议名/指标缩写）默认不可信。
2. **逐一核正**：用一级信源（公司公告/中报管线表/官网/监管记录）对照核正；转写中的数字必须回中报/公告核对原文。
3. **不全判为错**：核正失败的名词标 🟡 存疑保留原文，不得静默丢弃——"转写错"与"我查不到"是两回事。
4. **交付物输出名词对照表**：转写原文 → 核正结果 → 依据，供用户审计。

### B.2 定性 vs 定量隔离（硬规则）
- 管理层口头疗效表述（"疗效很好""数据优异"）**禁止转换为任何数字**，只作方向性信号层，并标注（二级信源/管理层口径）。
- "主动澄清"句式（"并不是因为 X 不好"）单独解读其**预期管理价值**，不当作数据。
- 转写中的数字（如有）必须回一级信源核对后才能引用。

### B.3 结构性失真检测表（每次必查四项）
| 失真类型 | 检测动作 | 实战案例 |
|---|---|---|
| 年份偏移 | 全文年份与公开事件时间线比对 | 映恩纪要 2024↔2026 系统性偏移 2 年 |

### B.5 信源分级与衔接
- 核正后的会议口径 = **二级信源**；核正只纠错不升级。
- 竞争判断中管理层对竞品的口头评价**必须与对方公告原文交叉验证**（→ §二·C 口径偏差硬卡，见 `source_whitelist.md` §十）。
- 名词核正协议与本文件 §一（数据缺失）、§二（争议双记录）可叠加触发。

## 三、实战触发示例

- **LBL-024 雪球分析**：大 V 称"024 OS 拖尾"——属 (c) 用户/信源前提 + 二级以下信源 → 隔离为假设、标 🔴、附验证清单（官方生存曲线/注册库）。
- **OA14.01 vs ESMO #9990 冲突**：同一资产两处数据不一致 → 触发 (b) 并列 + 来源分级 + 大会官方摘要仲裁。
