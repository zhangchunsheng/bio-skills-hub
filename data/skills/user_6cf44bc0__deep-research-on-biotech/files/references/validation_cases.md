# 验证样例库（validation_cases.md）

> **v4.7 新建（落地 P1-8）**
> **为什么需要它**：`lessons_pending.md` 记录的是「待办教训」，一旦合并进 reference 就只剩一条 changelog，原始情境（当时到底错在哪、用户怎么纠正的）随之丢失。本文件反向保留**错误现场**，让每条硬卡/铁律都能追溯到它诞生的那次翻车。
> **怎么用**：
> 1. **动手前扫一遍同类任务的案例**——尤其是索引表里标 ⚠️ 的高频翻车点，比读抽象规则更快建立直觉。
> 2. **新错误发生时追加条目**（格式见文末），并在 `lessons_pending.md` 登记。
> 3. **不要把它当知识库用**：疗效基准查 `heme_registry.md`，估值参数查 `valuation_rnpv.md`。本文件只回答"前人怎么错的"。

## C1 · 亚盛 1351 机制窄化（P0）

- **任务**：2026-08-25 亚盛 APG-2575 + HQP1351 在 AML 的价值分析（3 份报告）
- **错误**：1351 的价值初锚定为「仅 FLT3 交叉抑制」，漏掉**多激酶抑制 → MCL-1 广谱下调**这条主轴。而后者才是 FLT3 非依赖、VEN 耐药 all-comers 的主战场。
- **用户纠正**：连续两次（MCL-1 下调 → 与 2575 合成致死）
- **修正**：三份报告全量补丁；机制轴由单轴改为双轴并联
- **沉淀**：`valuation_rnpv.md` §3.0 硬卡 A（机制全景枚举 checklist）
- **可复用判据**：**一个靶向药的价值锚点若只写了一条机制，默认就是窄化的。** 多激酶抑制剂尤其危险——"选择性"叙事会让人只盯主靶点，忽略被下调的下游生存蛋白。

## C2 · 康方 AK104 权益误设（P0）

- **任务**：2026-08-26 康方海外估值细化
- **错误**：AK104 海外初版误设为「伙伴主导」，实际**康方自持全球权益**（年报管线表可查）。权益一错，捕获率全线错。
- **用户纠正**：点名"AK104 有全球权益，肝癌二线、胃癌一线要给估值"
- **修正**：rNPV 16.4 → 24.1 亿；海外 AK112 由单包 55 亿拆为 5 个细节点（约 67 亿峰值）
- **沉淀**：`valuation_rnpv.md` §3.0 硬卡 B（权益/分成事实核查）
- **可复用判据**：**出海节点的权益归属不允许推理，只允许查证**（年报管线表 / 交易公告）。推理出来的权益设置无论多合理，都是错的——因为它决定了后续所有数字。

## C3 · 复宏汉霖 7 处数字错误（P0）

- **任务**：2026-08-30 复宏汉霖五节深度分析定稿后审计
- **错误**：报告**结构校验全 PASS**（标签平衡 / 锚点可解析 / 外部依赖 / 占位符），但逐表复核查出 **7 处**数字/口径错误，三类：
  1. CAGR 年限与括号标注矛盾（11–14% 实为 7 年期，标注却写 5 年）
  2. 跨节口径错配（峰值加总 vs 年度合计混用）
  3. 合并行被展开后重复计算
- **根因**：**结构校验与数字自洽是两个正交维度**，此前质检清单只有前者。
- **沉淀**：`delivery_selfaudit.md`（四关审计）+ 纪律「审计结果写入报告，禁静默改正」
- **可复用判据**：**任何汇总表、任何增长率、任何跨节引用，都要重算而非目测。** 脚本说 PASS 只代表 HTML 没烂，不代表数字对。

## C4 · 注册库列互换沿用数周（P0）

- **任务**：2026-08 管线监控（EU CTIS / CT.gov）
- **错误**：注册库多列表格经 WebFetch 转 Markdown 后，某试验的 **Trial start 与 Recruitment start 两列互换**；结果看起来完全合理，错误结论沿用了数周。
- **沉淀**：`ct_monitor_playbook.md` §2.3
- **可复用判据**：**结构化表格优先 `curl` 直读原始 HTML**，慎用 WebFetch。凡 WebFetch 结果与基线冲突，一律回原始 HTML 复核——不要相信"看起来合理"。

## C5 · 申办方单轨检索漏项

- **任务**：2026-08 多标的管线扫描
- **错误**：单用申办方名检索，漏掉**合作方申办、但用本公司药物**的试验。
- **沉淀**：`ct_monitor_playbook.md` §2.2
- **可复用判据**：每个标的登记**两组检索词**——公司名（含多变体）+ 核心药物代号，每次扫描跑满。

## C6 · BD 收入同质化年化

- **任务**：2026-08-30 收入桥建模
- **错误**：把首付款、里程碑、分成三类 BD 收入当作同质收入年化估值，**系统性高估**。
- **沉淀**：`financial_forecast_model.md` §3.1（三类三待遇）
- **可复用判据**：**首付款不计经常性；里程碑按概率加权期权；只有分成可给经常性倍数。** 另防高基数陷阱——次年按经常性 CAGR 建模，不做表观增速外推。

## C7 · 集采"利好/利空"笼统判断

- **任务**：2026-08-30 集采影响评估
- **错误**：同一家公司不同品种受集采影响方向相反，笼统结论"利好/利空"必错。
- **沉淀**：`financial_forecast_model.md` §九
- **可复用判据**：先分**守成者 vs 挑战者**（份额方向相反），再算毛利率冲击恒等式（例：77.1% 毛利率遇 50% 降价 → 54.2%，已无法覆盖 40% 研发率）。事件核查三问：发文主体 / 文件状态 / 品种范围。

## C8 · 血液瘤 SOC 每轮重搜

- **任务**：2026-08-25 r/r AML 深挖
- **错误**：AML SOC 基准（吉瑞替尼 CR/CRh 34%、mOS 9.3mo；VEN+HMA CRc 66%、mOS 14.7mo；挽救化疗 mOS 3–5mo）**全部临场拼装**，每轮重搜。
- **沉淀**：`clinical_readout_framework.md` §六-B（血液瘤 SOC 速查表）+ `heme_registry.md` §三（SOC 疗效基准速查，含 sonrotoclax+Aza 作为 2575 直接竞品的对照数字）
- **可复用判据**：**SOC 基准属于"查一次写下来"，不属于"每次重搜"。** 重搜既慢又容易拿到未核验数字。

## C9 · 三份报告静默改写

- **任务**：2026-08-25 MCL-1 机制纠正后的补丁
- **错误**：三份 AML 报告整节重写（判定 🔴→🟡），但文件内**无任何修订痕迹**——用户若读过旧版，无法感知结论已变。
- **沉淀**：`user_preferences.md` §三（修订日志规范）+ v4.7 §四（用户纠正传播协议）
- **可复用判据**：**结论变了而文件里看不出来 = 对用户的时间不尊重。** 修订必留痕，且要 grep 历史交付物同步打补丁。

## C10 · 从净利率直接下结论

- **任务**：2026-08-30 国内创新药企 vs MNC 经营质量横向对比（14 家 vs 19 家）
- **错误**：从净利率高低直接推断经营质量优劣，跳过了分解。
- **沉淀**：`financial_analysis.md` §一·B（MNC 基准法）
- **可复用判据**：**净利率是结果，不是原因。** 固定起点是恒等式三层分解：L1 毛利率 / L2 费用率 / L3 收入结构。跳过分解的归因都是猜。

## 追加新案例的格式

```markdown
## C<编号> · <一句话标题>（P0/P1/P2）

- **任务**：日期 + 任务名
- **错误**：具体错在哪（含当时的错误数字/结论）
- **用户纠正**：原文引用用户的纠正（有则写）
- **修正**：改成了什么（含修正后的数字）
- **沉淀**：落到哪个 reference 的哪一节
- **可复用判据**：一句话，让下一个人不用重蹈覆辙
```

**纪律**：追加后同步在 `lessons_pending.md` 登记；若属 P0（改变估值/结论的系统性错误），须立即合并进对应 reference 并 bump 版本，不等"攒够 3 条"。
