## 二、硬性要求

### 2.1 信息源管理（★ v4.7 修正：与 SKILL.md 三级分级对齐 ★）

> **修正说明**：本文件 v3.x 曾写「❌ 严格禁止：非官方渠道信息、自媒体、非权威媒体分析」。该表述与 SKILL.md v4.0 起实行的**三级分级**直接冲突（v4.0 已明确删除"禁止自媒体"一刀切，改为"标注 + 交叉验证"）。v4.7 对齐如下——**两者冲突时以本节为准（更晚、更具体）**。

- **一级 ✅ 官方**（优先，可直接引用）：ClinicalTrials.gov、EU CTIS、ChiCTR、FDA、NMPA-CDE、EMA、港交所披露易、沪深交易所、公司官网 IR、顶刊（NEJM/Lancet/JCO/Blood/Nature Medicine）、大会摘要（ASCO/ASH/AACR/ESMO）
- **二级 ⚠️ 权威**（可引用，**须标注来源**）：券商研报、主流财经媒体（Reuters/Bloomberg）、医院招募帖
- **三级 ⚠️ 自媒体**（可用但受约束）：公众号、雪球大 V、投资论坛——**必须标注"自媒体来源"** + 交叉验证 + 无法验证时标 🔴

**❌ 真正严格禁止的（三级分级下依然成立）**：
1. 编造、幻觉、脑补数据——任何数字无出处即不得写入交付物
2. 把三级来源当一级引用（不标注来源层级直接给数字）
3. 引用不给时间与出处（时点核验：搜索索引常误标年份）
4. 用自媒体单一来源支撑估值结论

### 2.2 数据准确性

- 无法确认的信息必须标注「**待核实**」——不编造、不推测，并给出验证建议
- 所有数据标注来源与日期；严格区分事实与推测
- 时点核验：财务数字以公告董事会审议日为准，不采信搜索索引年份

## 三、交付物修订日志规范（v4.3 新增，P1-7）

- **禁止静默改写**：对既交付报告做 post-hoc 修订（用户纠正、新数据回填、机制补丁）时，**结论/判定/置信度若有变更，必须可追溯**。用户若读过旧版，应能在文件内感知"结论变了"。
- **修订日志块（强制，置于报告顶部）格式**：
  ```
  > 📝 修订日志
  > - v1（YYYY-MM-DD）：初始版本，覆盖 [范围]，关键判定置信度 [🟢/🟡/🔴]
  > - v2（YYYY-MM-DD）：[触发源：用户纠正 X / 新数据 Y] → 修订 [§章节]；置信度 [旧→新]
  > - …（每次修订追加一行）
  ```
- **适用场景**：任何被二次修改的交付物（HTML/报告/模型），包括本技能自身 reference 文件的大版本修订（在 SKILL.md 版本演进与 `lessons_pending.md` 留痕）。
- **反例（本次教训来源）**：亚盛 1351 双轴机制纠正后，三份 AML 报告整节重写（判定 🔴→🟡）但文件内无修订痕迹——用户无法感知结论已变。此疏漏催生本规范。

## 四、用户纠正传播协议（★ v4.7 落地 P1-4 ★）

> **来源**：2026-08-25 亚盛 1351 机制纠正（MCL-1 下调）。当时手动 grep 三份历史交付物同步打补丁——做法正确但**靠自觉**，未协议化，下一次可能漏。

**触发条件**：用户纠正的是**框架性假设或关键数据**（机制轴、权益归属、PoS、峰值口径等），而非笔误/格式。

**四步硬动作（缺一视为未闭环）**：

1. **grep 历史交付物**：在工作区内检索同一假设/数字出现过的所有文件（`*.html` / `*.md` / `*.py`），列出受影响清单。
2. **逐份修订**：对每个受影响文件打补丁，并在文件内追加「修订日志」行（见第三节）。
3. **回复列清单**：回复中必须给出「已同步文件清单」——路径 + 改了哪节 + 置信度变化。用户据此核对覆盖范围。
4. **教训入库**：写入 `references/lessons_pending.md`（≥3 条或 P0 级时批量合并进对应 reference）。

**纪律**：
- 只改当前文件、不 grep 历史交付物 = **不完整修复**，同一错误会在别处继续存活。
- 改完不列清单 = 用户无法判断修复范围是否够，等于没改。
- 若受影响文件过多（>10 份）或跨工作区，先向用户报告范围与优先级，不要静默全改。

## 五、报告长度分级（★ v4.7 落地 P2-12 ★）

> **来源**：2026-08-30 估值类 300+ 行报告复盘——结论埋在正文里，用户要自己找。

| 长度 | 处理方式 | 结构要求 |
|---|---|---|
| **短**（<80 行） | 直接答，不套模板 | 结论 + 关键数字 + 来源，无需章节 |
| **中**（80–300 行） | 分章节，**结论前置** | 首屏给结论与关键数字，再展开论证 |
| **长**（>300 行，估值/全景/深度类） | **顶部必须加「本轮改了什么 / 执行摘要」置顶块（≤10 行）** | 含三要素：① 结论一句话 ② 关键数字（含与上一版差异）③ 本轮主要变更 or 审计发现；正文再展开 |

**理由**：用户不会从 300 行里自己找结论。长报告的置顶块不是摘要，是**导航与差异提示**。

## 六、工作偏好

### 报告频率
- **周报**：每周一推送竞争格局变化、论文更新
- **重大事件**：实时推送
- **月度深度分析**：每月末

### 报告详细程度
- 优先简洁明了；关键数据用表格展示；需要详细分析时再展开
- **详细计算拆解**必须展示分步过程，标注每个假设与来源，可做敏感性区间
- 同一数据多次假设调整（如 250 亿→230 亿）须**显式呈现调整轨迹**，不能只给终值

### 推送方式
- 主动推送 + 按需查询结合；重大发现主动提醒
