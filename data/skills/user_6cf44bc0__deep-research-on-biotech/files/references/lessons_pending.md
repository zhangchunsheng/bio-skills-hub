### 【已合并 2026-08-30】N5 结构化表格的 WebFetch 失真（→ `ct_monitor_playbook.md` §2.3）
- 教训：注册库多列表格经 WebFetch 转 Markdown 会出现列截断/错位/**互换**三类失真，且结果看起来完全合理。实证：某试验 Trial start 与 Recruitment start 互换，错误结论沿用数周。
- 落地：优先 `curl` 直读原始 HTML（多数详情页服务器端渲染，表格完整内嵌）；WebFetch 结果与基线冲突时一律回原始 HTML 复核。

- 落地：每个标的登记「公司名（多变体）+ 核心药物代号」两组词，每次扫描跑满。

### 【外部化决策】N7 长 HTML 单文件报告流水线 → **独立 skill，不并入本技能**
- 内容：分段写入（单次 Write >40KB 会丢参数）→ 脚本合并 → 六项结构校验 → 中间产物清理。
- **判断理由**：这是**跨领域通用工程能力**（不特定于生物医药投研），并入本技能会污染其"投研方法论"定位；且用户已在其他非医药报告（国内创新药企经营质量 v3.0）中重复踩到同一坑。
- 落地：已建 `~/.workbuddy/skills/long-html-report-pipeline/`（含 `scripts/merge_and_validate.py`）。本技能仅通过 `delivery_selfaudit.md` 引用其"数字自洽"部分（该部分属投研质量范畴，留下）。

### 【外部化决策】N8 具体监控参数不进技能
- 内容：监控项数、公司清单、NCT 编号、基线文件路径、脚本名、Python 路径、报告五章具体编号。
- **判断理由**：① 用户明确要求"不绑定具体公司或单次任务的参数"；② 这些值每次范围变更都会变，写进技能必然过期并造成误导；③ 它们的**唯一权威位置是基线文件与自动化任务配置**，技能只规定"以基线为准、禁硬编码"这一条元规则。
