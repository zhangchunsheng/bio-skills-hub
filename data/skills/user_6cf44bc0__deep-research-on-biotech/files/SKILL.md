## 第一性原理：四问脊柱

任何生物制药资产/公司的深度投研，归结为四个不可压缩的问题，加一条操作脊柱：

| 脊柱 | 问题 | 对应主线 | 主要 reference | 本轮验证样例 |
|---|---|---|---|---|
| **Q1** | 有效吗？（临床证据） | 读出时间/稳赢门槛、方案统计监管、CT 监控 | `clinical_readout_framework.md`(含 §六-B 血液瘤 SOC 速查表) `heme_registry.md`(血液瘤注册先例库) `protocol_stat_regulatory.md`；**管线持续监控已独立为技能 `biotech-clinical-monitor`（v1.0.0）——监控/周报/自动化任务类需求转该技能，其产出信号回流本技能做深度分析** | 四层门槛表；**SOC 速查表 + Topline 降级协议（v4.1）**；**血液瘤 SOC 分册 + 注册先例库（v4.3）** |
| **Q2** | 值多少？（估值） | 两分法 rNPV、财务前瞻、峰值测算、财报比率 | `valuation_rnpv.md` `financial_forecast_model.md` `peak_sales_model.md` `financial_analysis.md` `lessons_pending.md` | 两分法估值 + 事件→市值 delta 分解 + 市值对账卡（v4.1）；**前置双硬卡：机制枚举+权益核查（v4.2）** |
| **Q3** | 谁在做？（竞争与机制） | 分子机制竞品对标、竞争格局、管线追踪 | `molecular_mechanism_comp.md` | 同靶点 ADC / 双抗 与 SOC 对标；**机制性毒性硬卡（v4.4）** |
| **Q4** | 数据可信吗？（证据分级） | 信息源三级分级、时点核验、置信度标识、边界情形处理 | `source_whitelist.md` `edge_case_protocols.md`(数据缺口/争议/假设隔离) | 股东治理实证（以交易所公告口径为准）；业绩会原文检索 |
| **操作** | 怎么交付？ | 输出美学、敏感性模拟器、记忆沉淀、自动化 | `user_preferences.md` | 三滑块 what-if、深灰+翠绿 HTML 单文件 |

**致命陷阱（v4.0 强调）**：把所有资产按"峰值×单一系数"折算会忽略已商业化与在研的风险结构差异；把不同试验的 PoS 用一个全局系数替代会掩盖价值驱动来源。逐试验 rNPV + 四问脊柱是更诚实的拆法。

## 核心能力（按四问脊柱重组）

### Q1 有效吗——临床证据层

- **(A) 读出时间与稳赢门槛** → 加载 `references/clinical_readout_framework.md`
  - 读出时间推算（入组规模/事件数/入组速度/额外随访；OS 需 65-70% 死亡事件成熟，PFS 比 OS 早 6-12 月，ORR 最快）
  - SOC 对标四层门槛（及格/优秀/稳赢/梦幻，针对**具体对照臂**定制，不可套通用值）
  - HR 漂移与非比例风险、时间对齐比较、平台期风险（KEYNOTE-189/CheckMate-227 先例）
- **(D) 方案翻译/统计/监管** → 加载 `references/protocol_stat_regulatory.md`
  - 方案术语表、α 分配/成熟度、IIT→NDA/FDA 资格、DDI 机制（CYP3A/HLA-B*5801）
- **管线追踪 / CT 监控** → 已独立为技能 **`biotech-clinical-monitor`**（v1.0.0）：监控/周报/自动化任务转该技能（六类分类法 v3.0 + 周报规范 + 参考脚本）；其 P0 信号回流本技能做深度分析
  - 范围界定：三维分类法（主导方 × 注册属性 × 地域）+ 剔除/保留双清单，范围一律以基线文件为准，禁硬编码
  - 信息源：注册库官方 API > 详情页原始 HTML（防 WebFetch 列失真）> 公司公告/会议摘要交叉验证；申办方名 + 药物代号双轨检索
  - 变更判定：三证交叉验证 + 变更分级（P0 状态迁移 / P1 读出窗口 / P2 仅日期），无变化也须完整跑完并交付
  - ClinicalTrials.gov API（`lastUpdatePostDate`/`OverallStatus`/`EnrollmentInfo`）、EU CTIS 分步骤监测、自动化（`automation_update` 周度任务）
- **管线论文监督**：PubMed/顶刊检索、ASCO/ASH/AACR/ESMO 会议动态

### Q2 值多少——估值层

- **(F) 两分法 rNPV 估值** → 加载 `references/valuation_rnpv.md`（已用于多个标的的两分法估值与交互式 rNPV 建模实战）
  - **Part A（已商业化/临床已成功）**：收入 DCF，`Σ[收入×经营利润率]/(1+r_comm)ᵗ`，r_comm≈10-11%，PoS≈0.90-0.95
  - **Part B（在研，逐试验）**：`rNPV_trial = PoS_trial × Σ[峰值年化×爬坡衰减]/(1+r_pipe)^(t−今年)`，r_pipe≈12%
  - **PoS 逐项填写**：阶段基准（Ph1 7-10% / Ph2 16-20% / Ph3 55-65% / BLA 90%）+ 资产/靶点/机制调整（验证机制 +、First-in-class 监管激励 +、难治异质 −）；每个试验的 PoS **必须写依据**
  - **出海/全球两口径**：对外授权→royalty（12-19%）+里程碑 PV；保留全球权→净捕获率（默认 55%，暴露为敏感性变量，改 20-25% 即 royalty 路线）
  - **校准护栏**：①市值对账（rNPV≫市值先自查捕获率/峰值/PoS，勿直接喊低估）；②rNPV≠市值（中国 biotech 含执行/融资/地缘折价）；③USD→RMB 单位铁律（`$M/100×汇率`，防 ~100× 放大）；④时点核验
- **(E) 公司财务前瞻建模** → 加载 `references/financial_forecast_model.md`
  - 收入桥（自有产品+授权/里程碑+海外分成+其他管线，逐项枚举，含穿透性检查：海外收入/组合疗法搭档药是否漏算）
  - 净利润（毛利+研发+销售+行政+财务；IFRS 与 Non-IFRS 还原）
  - 出海授权交易结构（首付+里程碑+分成）、组合疗法收入归属（按适应症分别给 PoS）
  - 期权 vs 基础分离、base/bear/bull 敏感性
- **(C) 峰值销售测算** → 加载 `references/peak_sales_model.md`（标签人群→去重→方案接受率→份额→净价→峰值；韦恩图分流；医保时间差）
- **财报比率解读 / 经营质量横向对比** → 加载 `references/financial_analysis.md`（毛利率/ROE/PS、报告模板；**v4.6 新增 §一·B MNC 基准法**：净利率恒等式三层分解、基准带与异常值剔除、倍数法失真降权、四个反直觉判据、四维评分卡、基准快照）

### Q3 谁在做——竞争与机制层

- **(B) 分子机制与竞品对标** → 加载 `references/molecular_mechanism_comp.md`
  - ADC/双抗/TCE 结构拆解、on-target 毒性三通路、裸抗占位有效性、双抗 AND-gate/Dual-Shield
  - 同靶点竞品对标维度（分子形式/Fc 段/选择性/安全性排序）
- **竞争格局分析**：适应症靶点分布、在研管线进度比较、市场份额、差异化护城河
- **股东结构与治理分析**（v4.0 显式化）：控股股东持股路径、私有化/要约历史、关联交易（授权/分销/供货）、董事会构成、制衡机制有效性——对照港交所/沪深公告实证，不情绪化

### Q4 数据可信吗——证据分级层

- **信息源三级分级** → 加载 `references/source_whitelist.md`
  - 一级✅：CT.gov/EU CTIS/ChiCTR/FDA/NMPA-CDE/EMA/港交所披露易/沪深交易所/公司官网/顶刊（NEJM/Lancet/JCO/Blood/Nature Medicine）/大会摘要（ASCO/AACR/ESMO/ASH）/Reuters/Bloomberg
  - 二级✅：券商研报、主流财经媒体、医院招募帖——需标注来源
  - 三级⚠️：公众号、雪球大V、投资论坛——必须标注"自媒体来源"+交叉验证+无法验证标 🔴
  - **时点核验**：搜索索引常误标年份，财务数字以公告董事会审议日为准
- **业绩会原文检索**（v4.0 显式化）：港交所公告+公司官网 IR+公众号回放为官方渠道；逐字稿常不公开挂网，需标注媒体实录口径；优先抓管理层问答（集采/出海/分红/指引等议题）

## 响应规范

### 报告结构
- **交易决策型**：七段式（见上）
- **临床/机制/商业测算型**：试验参数表 → 读出时间线（含会议窗口）→ SOC 对照+稳赢门槛分层表 → 必要时人群韦恩图/分子结构图（show_widget SVG）→ 风险与模型漏洞 → 一句话总结

### 数据展示
- 关键数据用表格；所有数据标注来源与发布日期；严格区分事实与推测

### 置信度标识
- 🟢 高：官方出处、数据新鲜 ｜ 🟡 中：多方印证但非直接官方 ｜ 🔴 低：单一来源/自媒体未交叉验证/待核实

### 输出美学与格式（用户明确偏好，默认遵循）
1. 配色：深灰背景 + 翠绿终端色（#00E676 / #1E1E1E 系），适配 IDE 暗色主题
2. 交付物：纯 HTML/CSS/JS 单文件，内联样式/脚本，**无外部依赖**
3. 结构：编号列表、分章节、关键数据用表格
4. 计算：详细分步拆解，标注每个假设与来源，可做敏感性区间；多次假设调整（如 250亿→230亿）显式呈现
5. 风格：第一性原理推理，诚实指出模型漏洞与数据局限
6. 可视化：复杂对比用 show_widget 内联 SVG；可下载结果用 present_files
7. **敏感性模拟器**：财务/测算类交付物默认内置三滑块 what-if（如折现率/PoS 乘数/净现金），实时切换 Bear↔Bull
8. **修订日志块**：被二次修改的交付物顶部须含「修订日志」（v1 初始→v2 日期/改哪节/触发源/置信度变化），禁止静默改写结论（详见 `user_preferences.md` 交付物修订日志规范，v4.3）

### 信息缺失处理
- 无法确认的信息明确标注"待核实"或"无法确认"；不编造、不推测；提供验证建议

## 工作流程（四问驱动）

1. **定位任务类型**：研究型（Q1/Q2/Q3 单问或组合）vs 交易决策型（附加层）
2. **按四问脊柱选 reference 加载**（按需，不贪多）；**开工前两件事（v4.7）**：① 按 `source_whitelist.md` §九 领取本任务类型的检索组合并**跑满再开始分析**（边分析边补检索会漏，且容易被已有结论带偏）；② 扫 `validation_cases.md` 索引表中同类任务的案例
3. **执行**：临床研究流程（定位试验参数→读出推算→SOC 稳赢门槛→机制/峰值/估值）或按需查询流程；**构建任何 Part B 估值节点前，先过 `valuation_rnpv.md` §3.0 前置双硬卡（机制全景枚举 + 权益事实核查）**；**评估任何靶向药的 me-better 差异化空间前，先过 `heme_registry.md` §五 机制性毒性硬卡（on-mechanism vs off-target 分类）**
3·B **中报 + 业绩会双源分析标准工作流（v4.9 固化，映恩/康方/维立志博三次重复）**——凡输入含"中报 PDF + 业绩会纪要/PPT"即按八步执行：
   ① 三文档并行提取（pymupdf 双 PDF + zipfile 解析 docx `<w:t>` 节点，落盘 .txt）；
   ② 纪要按 `edge_case_protocols.md` §二·B 核正（先查 §B.4 同音字映射表，再补检索），输出名词对照表；
   ③ 按 `source_whitelist.md` §九 双轨检索竞争基准（SOC + 最强竞品 + 同适应症已批在位者），**竞品基准必须用公告/期刊原文**；
   ④ 分适应症做「我方数据 vs SOC vs 竞品」三维定位表（列明样本量/mFU/数据成熟度/位势判定）；
   ⑤ 数据门槛按 `clinical_readout_framework.md` §二 + §九 设定（内部锚→SOC 锚→竞品锚，线数匹配，随访不足用里程碑生存率反推）；
   ⑥ 管理层口头评价竞品 → 过 `source_whitelist.md` §十 口径偏差硬卡；
   ⑦ 分段写入 + 脚本合并 + 结构校验（标签/锚点/占位符/外部依赖/关键数字锚点）+ `delivery_selfaudit.md` 数字自审；
   ⑧ 诚实边界章节必含：跨试验比较声明、门槛为定性框架声明、口径偏差双记录。
4. **交付**：show_widget 内联图 + present_files 可下载报告；财务测算内置三滑块
5. **自审（v4.5 新增，含汇总表/增长率/跨节引用的量化交付物必做）**：交付前过 `references/delivery_selfaudit.md` 四关——逐表加总复核 / 增长率反算 / 跨节交叉对账 / 区间端点语义检查。发现错误须修正，并**把审计结果（发现几处、改了什么、哪些复核无误）写进报告的方法论局限章节，禁止静默改正**
6. **沉淀（三步硬动作，v4.2）**：
   - ① 大任务（15+ 工具调用）完成或发生用户纠正后，**立即**将教训写入 `references/lessons_pending.md`（待合并区，格式见该文件头部）——**不等用户触发**；
   - ② `lessons_pending.md` 累积 ≥3 条或出现 P0 级（改变估值/结论的系统性错误）时，批量合并进对应 reference 并 bump 版本；**同时把该次"错误现场"追加进 `validation_cases.md`**——合并进 reference 后只剩规则，原始情境会丢；
   - ③ memory 日志照常写入 `.workbuddy/memory/`。
