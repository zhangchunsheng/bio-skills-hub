# 依赖与运行说明 — 通用分析H5报告 (generic-analysis-h5)

本 skill 是"报告分析系统" backend 上的一个**驱动层**（一条命令 + 复用 backend 的解析/AI/H5 能力）。它不是零依赖的独立程序，而是"放进 backend 即可跑"的一套模块。

## 一、压缩包目录结构与文件落位

```
generic-analysis-h5/
├── SKILL.md                       # skill 定义与使用说明
├── 依赖与运行说明.md               # 本文件
├── 接入其他工具指南.md             # Codex / workbuddy / 纯命令行 接入方式
├── reference/
│   └── 操作文档-通用分析H5.md      # 原始逐步操作手册(权威流程, v1.0)
├── scripts/                       # ★ skill 自有代码，落位到 backend/
│   ├── generic_run.py             #   → backend/generic_run.py（内置多模态前置检测）
│   ├── cloud_doc_run.py           #   云文档全自动管线
│   ├── check_multimodal.py        #   多模态模型检测脚本（独立可跑）
│   └── write_session_analysis.py  #   会话分析结果写库
└── backend_shared/                # ☆ 运行依赖的共享底层(backend 通常已有；此处附上供审阅/补齐)
    └── app/
        ├── core/config.py
        └── services/
            ├── task_runner.py            # run_overall_only_pipeline(快速模式管线)
            ├── ai_service.py             # 多模态AI调用(图片预算/413降级/max_tokens=16384)
            ├── h5_export_generic.py      # ★ 唯一正确的H5生成器
            ├── ppt_parser.py             # PPT→页图+文本(soffice)
            ├── md_parser.py              # MD/ZIP解析(图片匹配)
            ├── prompt_loader.py          # 按 active_mode 加载提示词
            ├── prompt_config.json        # active_mode 必须为 generic
            └── prompts/generic_*.txt     # 通用分析提示词
```

> **落位原则**：`scripts/generic_run.py` 复制到 `backend/` 根目录（脚本靠自身位置定位 backend，**必须放在 backend 根目录**）。`backend_shared/` 按 `app/...` 层级镜像补齐；目标 backend 已有同名文件时**以 backend 现有版本为准**（本 skill 未修改这些共享底层的对外行为）。

## 二、运行前置

1. **Python 3.12**，装 backend 的依赖（FastAPI / SQLAlchemy / aiosqlite / httpx / openai / python-pptx / PyMuPDF / pydantic-settings 等，见 backend 的 `requirements.txt`）。
2. **`backend/.env`** 配置（键名大小写不敏感，对应 `app/core/config.py`）：
   ```env
   BASE_URL=https://<你的AI网关>/compatible-mode/v1
   API_KEY=sk-xxxx
   DEFAULT_MODEL=qwen3.7-plus     # 必须支持多模态(图文)！
   SOFFICE_PATH=C:\Program Files\LibreOffice\program\soffice.exe
   DATABASE_URL=sqlite+aiosqlite:///./data/analysis.db
   ```
   > `DEFAULT_MODEL` **必须是支持图像输入的多模态模型**（分析强依赖读图：PPT 页图/文档内嵌图里的
   > 表格与图表是最高优先级证据，纯文本模型会漏数据甚至瞎编）。`generic_run.py` 会在调 AI 前自动检测：
   > 模型名含视觉关键词（vl/vision/4o/omni/gemini 等）直接通过；判断不了时发一张 64x64 测试图探测；
   > 确认不支持或无法确认 → **直接停下不跑 AI**，按提示换模型（`--model` 覆盖 / 改 .env /
   > `--skip-multimodal-check` 强跳）。也可单独检测：`python scripts/check_multimodal.py`。
   > `.env` 里是**密钥，不随 skill 分发**，接手人需自行填自己的网关与 key。
3. **LibreOffice**：分析 `.ppt/.pptx` 时用 `soffice` 转页图；纯 `.md/.zip` 可不装。
4. **`app/services/prompt_config.json` 的 `active_mode` = `generic`**（本 skill 的前提；改成 `review` 会走述职规范提示词，输出 schema 对不上）。
5. **数据库**：`backend/data/analysis.db`。脚本启动时会 `init_db()` 自动建表，全新环境无需手工初始化。
6. **无需启动 uvicorn**：`generic_run.py` 直接调用底层模块建记录，不走 HTTP，因此不依赖后台服务（这也顺带消除了 `curl -F` 上传导致的中文文件名乱码）。

## 三、最小跑通命令

```bash
cd backend
python generic_run.py "D:\报告\26年中期述职-华东大区.zip"
```

预期输出（约 3-5 分钟）：

```
[1/4] 已建记录  分析ID=96  类型=md  存至 ...\uploads\96\26年中期述职-华东大区.zip
[2/4] 快速分析中(仅整体分析，多模态传图+文本，约3-5分钟)… id=96
      状态=completed  JSON长度=12607  维度命中 10/10
[3/4] H5 已生成: ...\data\exports\h5\96.html  (3.51 MB)
[4/4] 已复制到: ...\26年中期述职-华东大区-通用分析.html
```

**验收标准**：`维度命中 10/10`、H5 体积 > 1MB（说明图片已内嵌）、浏览器打开左侧有原文右侧有 10 个分区。

## 四、失败处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `[✗] 模型 xxx 未确认支持多模态` | DEFAULT_MODEL 是纯文本模型/名字无法判断 | 换多模态模型：`--model "<多模态模型>"` 或改 `.env`；确知支持可 `--skip-multimodal-check` |
| `overall_analysis 为空 {}` | AI 返回被截断 | 直接重跑 `python generic_run.py --id <id>` 段的分析；确认 `max_tokens=16384` |
| `已被存成 raw/error` | AI 没返回合法 JSON | 同上，重跑；报告过大时考虑拆分 |
| `维度命中 0/10` | `active_mode` 不是 generic | 改 `prompt_config.json` 后重跑 |
| H5 无图（MD） | ZIP 多包一层文件夹 | 脚本已自动上移；仍失败则手工把 `图片和附件` 放到 `uploads/{id}/{id}/` 下，再 `--h5-only` |
| 标题乱码 | 历史记录的 `ppt_path` 是乱码 | `--title "正确名.pptx" --h5-only` |
| API 超时 / 408 | 上游网关限制 | 检查 `.env` 的 `BASE_URL`；客户端超时已设 300s |

## 五、独立性保证

本 skill 只**新增** `backend/generic_run.py` 一个文件，**不修改** `gm_*`、`oms_*`、`h5_export_generic.py`、`task_runner.py`、`prompt_config.json` 任何一行——与 gm-cockpit、oms-cockpit 可共存于同一 backend，互不影响。
