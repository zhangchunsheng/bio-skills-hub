# 隐私与安全规则（Privacy and Safety）

本 Skill 是药物重整文书和证据整理辅助工具，**不是自动处方或自动治疗决策系统**。任何模型输出仅作为药师复核和医师讨论草稿，所有最终调整必须由药师与责任医师人工确认。

## 1. 临床安全硬性规则（12 条不可违反）

1. **不得根据诊断猜测患者正在使用的药物**。如资料未明确给出某药，不得补全。
2. **不得猜测或擅自补全**药名、剂型、规格、剂量、频次、途径、日期、停药时间、检验单位、过敏表现等。
3. **不得把 OCR 识别结果直接视为已核实事实**。OCR 结果必须标注 `evidence_status=direct_visible`，但仍需人工核对；不可识别或疑似错误 → `ambiguous`。
4. **不得把模型建议表述为已执行医嘱**。所有"建议"必须保持 `decided_by_role=pharmacist_suggestion`。
5. **不得未经责任医师确认自动决定**停药、加药、换药、恢复用药或患者特异性剂量调整。所有涉及方案调整的结果只能标 `建议讨论` 或 `待医师确认`，直到输入资料明确包含医师确认意见。
6. **不得伪造或自动填写**药师、医师签名。签字栏始终空白。
7. **不得因为字段缺失而删除整条药物记录**。应标记 `evidence_status=missing` 并写入 `open_questions`。
8. **涉及患者的调整建议，只能作为药师复核和医师讨论草稿**，不得以"已调整""已执行"等表述出现。
9. **正式表格生成前，必须区分四个层级**：`原始记录`（来自资料原文）/ `模型整理`（AI 提取）/ `药师核实`（人工）/ `医师确认`（签字）。
10. **真实患者资料只能在经医疗机构批准的本地或受控环境中处理**。不得在公网 API、明文聊天窗口或未授权文件中留存。
11. **不得把真实患者资料、姓名、住院号、电话、处方或检验结果放入 Skill 包、示例或测试数据**。Skill 包内仅允许虚构或充分脱敏数据。
12. **测试只能使用虚构或充分脱敏病例**。所有 open_questions、test_cases、scripts 自检用的 JSON 必须不含真实 PHI。

## 2. 阻断与告警（程序化）

`validate_evidence.py` 与 `validate_form_a1.py` 必须在以下情况返回非零退出码并打印明确错误：

- 任意结构化字段缺失 `source_id`、`page_or_image` 或 `evidence_status`。
- 任意冲突字段 `evidence_status` 不是 `conflict`。
- 任意关键药物字段（药品名称/用法用量/用药原因/开始时间/停止时间）在缺失来源时被填入。
- `patient_id` 缺失或两份资料的 `patient_id` 不一致。
- `suspected_other_patient=true` 时仍尝试生成表 A.1。
- `physician_confirmed=true` 但 `decided_by_role != "physician_confirmed"`。
- 表 A.1 签字栏出现非空白字符（除空格外）。
- 患者自带药品未在药品名称后追加 `*`。
- 出现真实姓名/电话/身份证号/住院号等 PHI 模式（脚本可通过正则模糊匹配告警）。

## 3. 患者身份标识处理

- 输入资料中如出现姓名、身份证号、电话、住院号等，模型工作产物中**仅在表 A.1 表头**保留。
- 表 A.1 表头字段填充必须严格来自资料原文，不得用模型推测。
- 任何中间文件、evidence 台账 JSON、日志中，如包含上述字段，必须在脱敏副本（仅用于审计）中处理，**正式交付物中可保留**。

## 4. 与外部世界交互的边界

- **不发送**：本 Skill 不得自动把患者数据发送到云端 LLM、公网 API、社交平台、邮件或消息系统。
- **不下载**：除 `python-docx` 渲染与本地 OCR/PDF 解析外，不下载任何患者数据相关资源。
- **不共享**：除非用户在受控环境中明确指示，结构化 JSON 与表 A.1 文档不得脱离本地工作目录。

## 5. 责任与免责

- Skill 输出仅供持证药师与执业医师在受控临床环境中使用。
- 因错误使用本 Skill 导致的医疗决策后果，由使用方机构与人员承担。
- Skill 维护者不承担因模型幻觉、OCR 错误、模板误用造成的临床风险。

## 6. 四层证据角色标记（程序与文档统一）

| 层级 | evidence_status / decided_by_role 取值 | 说明 |
|---|---|---|
| 原始记录 | direct_visible | 资料原文可读，未做推断 |
| 模型整理 | model_extracted | 由 AI 从原文提取并规范化 |
| 药师核实 | pharmacist_verified | 持证药师人工核对签字 |
| 医师确认 | physician_confirmed | 责任医师签字或口头确认 |

> 表 A.1 的"备注（药物重整建议及理由）"列必须区分清楚是哪一层；若含跨层信息，应分段标注。
