# 隐私与合规

## 一、直接标识符清单（默认剔除，且不写入任何输出）

工具在字段识别阶段就会标出下列字段并从分析数据中**整列移除**——它们不参与任何计算，
也不出现在 HTML 报告、字段映射表、质控清单、清洗后数据中：

| 标准字段 | 覆盖的常见列名 |
|----------|----------------|
| 姓名 | 姓名、患者姓名、病人姓名、name |
| 身份证号 | 身份证号/号码、证件号码、市民卡号、社会保障卡号、医保卡号 |
| 联系电话 | 联系电话、电话、手机号、患者电话 |
| 现住址 | 现住址、住址、家庭住址、户籍地址、联系地址 |
| 工作单位 | 工作单位、单位名称 |
| 联系人姓名 | 联系人、家属姓名、亲属姓名、监护人姓名 |
| 联系人电话 | 联系人电话、家属电话、监护人电话 |

**间接标识符**（出生日期、入院日期、出院日期、邮编级地区、罕见诊断）不在自动剔除范围内，
因为它们是指标计算必需的。这属于**准标识符**，在需要对外共享时应按 HIPAA 的
「安全港」或「专家判定」方法另行处理（如日期只保留年份、年龄 90 岁以上归并为一档）。

`--keep-identifiers` 可关闭自动剔除，但**除非用户明确要求并已知晓风险**，不要使用。
使用后工具会在报告「数据说明」区块留痕告警。

## 二、与去标识化工具的衔接

本技能与「病案首页科研助手」中的 `deidentify.py`（HMAC-SHA256 确定性哈希）配合使用：

```
原始首页数据（含病案号/姓名）
        ↓  deidentify.py（产出研究ID + 对照表 + key.bin）
去标识化数据（研究ID）
        ↓  本技能 report 模式
可外发的分析报告（只剩聚合指标，无个体信息）
```

**确定性哈希的价值**：同一病案号跨批次、跨年度生成同一个研究ID，
因此多年度分表可以安全合并后计算 31 天再入院率等纵向指标。
若数据里的 ID 列名为 `研究ID` / `患者ID` / `hash_id` 等，本工具能自动识别为标识列。

## 三、报告可外发性的判断

| 报告内容 | 可否外发 |
|----------|----------|
| KPI 卡片、图表、事实卡 | ✅ 聚合指标，无个体信息 |
| 质控问题清单里的**样例明细** | ⚠️ 病案号已默认打码（`****尾4位`），可随报告外发；`--show-ids` 生成的完整 ID 版本仅限科内回查使用 |
| 字段映射表 | ✅ 仅列名 |
| 清洗后数据 CSV | ❌ 明细级数据，按院内数据分级管理，不得外发 |

## 四、免责与合规声明模板

报告页脚已内置下列声明，对外提交的材料可整段复用：

```
【病案首页数据处理器免责声明】

1. 本工具在使用者本机离线运行，原始数据与中间结果不上传、不外传、不留存。
2. 报告中的指标为病案首页填报数据的统计描述，用于数据治理、质控与科研探索，
   不作为临床诊疗依据，也不等同于院内上报口径（上报口径以国家/省市平台规范为准）。
3. 病案首页属健康医疗数据，使用须遵守《个人信息保护法》《数据安全法》及本院数据管理制度。
   对外提供、论文发表或跨机构共享前，请完成去标识化与伦理审查
   （回顾性研究多可申请知情同意豁免）。
4. 工具默认剔除姓名、身份证号、联系电话、现住址等直接标识符，且不写入任何输出文件；
   病案号在报告与质控清单中默认打码（保留尾 4 位），需要完整 ID 回查时用 `--show-ids`
   生成科内版本。如确需保留标识符，由使用者自行承担合规责任。

严禁利用本工具编造、篡改统计数据。所有事实卡数字均由数据实算得出，不接受人工指定。
```

## 五、明确拒绝的行为

- 患者个体化诊疗或用药建议
- 编造、篡改统计结果（包括「把某个数改成好看一点」）
- 数据买卖、外传、跨机构共享原始明细
- 绕过隐私剔除把标识符写进报告
