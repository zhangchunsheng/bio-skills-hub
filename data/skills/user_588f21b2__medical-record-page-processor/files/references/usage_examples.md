# 使用场景示例

## 场景 1：年度全院首页数据体检（最常见）

> 用户：D 盘有我 2023–2025 三年的病案首页导出，看看数据质量怎么样，顺便出一个运行概况报告。

```bash
python {skill_base}/scripts/cli.py sample "./demo"            # 无数据时可先演示
python {skill_base}/scripts/cli.py profile "D:/病案首页数据" --outdir "./out"
# 检查 out/字段识别与数据概览.json：未识别列里有没有关键字段
python {skill_base}/scripts/cli.py report "D:/病案首页数据" \
  --outdir "./病案首页分析输出" --export-clean
```

**产出**：`病案首页分析报告.html`（KPI + 13 图 + 质控诊断 + 字段映射 + 免责声明）、
`质控问题清单.csv`、`字段映射表.csv`、`事实卡.json`、`清洗后数据.csv`。

**接着写解读**（第二步，必做）：
读 stdout 的 `kpi` 与 `charts[].facts`，写 2~4 句，用 `--annotation` 再生成一次。

---

## 场景 2：老系统 gb18030 CSV + 前 4 行是报表标题

> 用户：这个 CSV 用 Excel 打开是乱码，表头好像在第 4 行。

```bash
python {skill_base}/scripts/cli.py report "导出.csv" \
  --encoding gb18030 --header-row 3 --outdir "./out"
```

先不带 `--header-row` 跑一次 `profile`，看它自动定位到第几行（stdout 的
`warnings` 与报告「数据说明」区块会写「表头定位：xxx 第 N 行」），再决定是否手工指定。

---

## 场景 3：只要质控清单，不要报告

> 用户：帮我挑出病案首页里逻辑有问题的记录，我要发给各科室整改。

```bash
python {skill_base}/scripts/cli.py check "全院首页2025.xlsx" --sheet "首页" --outdir "./质控"
```

产出 `质控问题清单.csv`：规则编号、问题类型、命中条数、占比、**样例病案号+明细**、整改建议。
样例列可直接复制给临床科室定位原始病案。

---

## 场景 4：呼吸专科子集分析

> 用户：只要呼吸科的数据。

工具不按科室过滤，做法是先用 `--export-clean` 导出清洗后数据，
再用 Excel/其他工具筛出目标科室后重跑：

```bash
python {skill_base}/scripts/cli.py report "全院首页.xlsx" --outdir "./out" --export-clean
# 在 out/清洗后数据.csv 里筛选 出院科别 后另存为 呼吸科.csv
python {skill_base}/scripts/cli.py report "呼吸科.csv" \
  --outdir "./呼吸科分析" --title "呼吸与危重症医学科 2023–2025 运行分析"
```

> 若确需按科室批量出报告（如 12 个科室各一份），**不要**写循环调用 CLI 的脚本，
> 那会让输出目录与产物难以管理。改为一次出全院报告 + 科室对比图，
> 科室维度的差异在「科室人次 / 科室平均住院日」两张图里已经能看到。

## 场景 5：给科主任汇报用的口头版

报告是给数据的，汇报还需要话术。让 agent 基于 `事实卡.json` 输出一段 200 字口播稿：

> 2024 年出院 703 人次，同比 +2%；平均住院日中位 6 天、P90 16 天；
> 费用中西药费占 22.7% 为第一位；首页数据质量评分 83.6，
> 主要问题是 1.57% 的病例出院日期早于入院日期，需科室配合整改。

**每个数字都必须能在事实卡里找到出处。**

## 场景 6：科研前置检查

> 用户：我想用这批首页数据做回顾性研究，先看看数据能不能支撑。

```bash
python {skill_base}/scripts/cli.py report "研究数据.csv" --outdir "./科研前置检查" --export-clean
```

看三处：
1. `字段识别结果` 里关键暴露/结局字段（诊断编码、离院方式、费用）是否都识别到了；
2. `质量诊断` 里致命/严重问题的发生率和影响范围（决定要不要限制研究人群）；
3. `kpi.患者数（去重）` 与 `31天再入院率` 是否可信（后者依赖纵向 ID 已统一）。

结论确认后，把清洗后数据与质量诊断结论交给「病案首页科研助手」做研究设计，
其研究方案里的「数据质量」章节可直接引用本报告。

## 常见问答

**Q：为什么我的「手术率」是 100%？**
数据里可能所有病例都填了手术费（或手术编码列被整体赋值）。工具优先用手术编码/名称判定，
若两者都不存在才退回手术费>0。确认一下该院的手术费科目口径。

**Q：费用分项偏差 80% 怎么办？**
先确认是不是分项字段本身不完整。若数据里只有总费用和少数几个分项，
这个比例高是必然的，不影响总费用类指标；在解读里声明「费用结构分析仅覆盖已填报分项」即可。

**Q：报告里的「未识别列」要管吗？**
非关键字段（主诊医师、编码员、质控标志）不用管。若是关键字段（如主诊断被写成
`出院诊断名称(主)`），改表头或让维护者在 `fields.py` 补别名后重跑。

**Q：能画地图吗？**
本技能不内置地图（病案首页通常无地区字段，且地图渲染有合规要求）。
地理维度需求请用 smart-charts，并遵守其地图合规约束。
