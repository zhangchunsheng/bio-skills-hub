# 病案首页字段字典与识别策略

> 权威来源是 `scripts/fields.py` 的 `FIELD_SPECS`；本文件是它的可读镜像，
> 由脚本自动生成，两者不一致时以 `fields.py` 为准。

## 一、字段识别四步走

1. **规范化精确匹配**（置信度 `high`）
   列名做全角转半角 → 去空格/下划线/括号/冒号 → 转小写，再查别名表。
   这一步能解决绝大多数问题，包括最常见的「出院科室 」尾随空格。
2. **长别名包含匹配**（置信度 `medium`）
   仅当别名长度 ≥ 4 且非泛词时，允许「列名包含别名」或「别名包含列名」。
   例：`出院科室名称` 命中 `出院科室`；`入院科室名称` 命中 `入院科室`。
   长度 ≤ 3 的泛词（如 `科室`、`性别`）只允许精确匹配，避免把 `入院科室` 错认成 `出院科别`。
3. **关键词语义归类**（仅用于报告展示，不猜具体字段）
   含「费/金额/成本」→ 费用类；含「日期/时间」→ 日期类；含「编码/代码/ICD」→ 编码类；
   含「科室/科别」→ 分类类。这些列会进「未识别列」清单并附语义猜测，供人工判断。
4. **人工确认**
   `字段映射表.csv` 列出每一列的「原始列名 → 标准字段 → 置信度」。
   置信度 `medium` 的列建议扫一眼；关键字段（病案号、主诊断、费用）若只到 `medium`，
   必须人工确认后再引用报告结论。

## 二、同名列冲突处理

两列同时命中同一标准字段时，**保留先出现的**，后来的进 `duplicates` 并出现在字段映射表里
（不参与计算）。典型场景：表里既有「入院科室」又有「入院科别」。

## 五、未识别列怎么办

- 若未识别列**不是关键字段**（如主诊医师、编码员、质控标志）：忽略即可，报告里会列出来提示核对。
- 若未识别列**是分析必需的字段**（如主诊断被写成 `出院诊断名称(主)`）：
  两种处理方式，优先级从高到低：
  1. 在原表里把表头改成标准名或任意一个已知别名（推荐，一次性投入）；
  2. 让维护者在 `scripts/fields.py` 的 `FIELD_SPECS` 里补一条别名（长期方案）。
  **不要**试图用 `--transform-code` 之类的方式绕过——本技能没有该参数，
  也不接受在报告生成后手工改数。
