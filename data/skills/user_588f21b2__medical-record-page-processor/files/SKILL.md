# 病案首页数据处理器

> 一句话：**丢一个病案首页导出表进来，出一份能直接给科主任看的质控+运行报告。**
> 产物是单个离线 HTML（ECharts 已内联），双击即开、可打印成 PDF，另附可进 Excel 的质控清单。

## 技能定位与边界

**做**：字段识别对齐、数据清洗定型、质控校验、指标口径计算、汇总聚合、可视化报告、事实卡。

**不做**（命中请改推其他技能，不要硬接）：

| 用户真实需求 | 该用哪个 |
|--------------|----------|
| 选题研判、研究方案、样本量论证、标书/论文框架 | 病案首页科研助手 |
| 只要出图、不要质控与指标口径 | smart-charts |
| 纯文字描述、没有数据文件 | 先要数据文件 |
| 患者个体化诊疗建议、临床用药决策 | 不提供 |
| 数据买卖、外传、跨机构共享原始数据 | 拒绝 |

与「病案首页科研助手」的分工：**本技能是数据加工层**（把表变成可信的指标与图表），科研助手是研究设计层（把指标变成课题）。二者可串联：先用本技能产出清洗后数据与质控结论，再交给科研助手设计方案，科研方案里的「数据质量」章节可直接引用本技能的质量诊断。

## Activation Triggers

**TRIGGER**

- 用户提供 / 指向病案首页、出院病人明细、HIS 导出表，要求"处理一下""清洗""质控""校验""统计一下""出个报告/报表"
- 用户提到：病案首页、首页数据、住院明细、出院人次、平均住院日、药占比、耗占比、CMI、DRG 权重、手术率、31 天再入院、首页质控
- 用户给了 Excel/CSV 并问"这数据有什么问题""能不能出个分析"

**DO-NOT-TRIGGER**

- 要研究设计、标书、论文 → 病案首页科研助手
- 没有数据文件，只有口头想法
- 要 SQL 建库 / BI 后端 dashboard / 图片视频
- 嵌套 JSON 超过 1 层（本工具按二维表处理）

## 契约（5 条 MUST）

1. **MUST 走 CLI 工作流**，不要自写脚本替代。入口固定为
   `python {skill_base}/scripts/cli.py <mode> <输入> [flags]`。
   禁止绕开 CLI 直接调 pandas 手搓——字段字典、指标口径、质控规则都在脚本里，
   手搓等于丢掉本技能的全部领域价值。

2. **MUST 显式传 `--outdir`**，指向用户可见的目录（如 `./病案首页分析输出`、桌面目录、
   当前工作目录下的显式子目录）。默认值会落在当前工作目录，用户不容易找到产物。

3. **MUST 附由 LLM 写的解读**：报告「解读」区块不能是模板文字。
   流程是**两步**：① 正式生成一次（stdout 已含 `kpi` 与 `charts[].facts`）；
   ② 读这些数字写 2~4 句解读，用 `--annotation` 再生成一次。
   交付前确认 stdout 的 `annotation_source` 为 `"user"`；若为 `"default"` 说明还是模板文字，
   且输出会挂 `advisory` 提示。

4. **解读的每个数字 MUST 能在 `kpi` / `charts[].facts` / 质量诊断里找到出处**。
   不得凭印象编造，不得把"推测"写成"事实"。

5. **隐私字段 MUST NOT 出现在任何输出**。姓名、身份证号、联系电话、现住址、工作单位、
   联系人等信息默认被剔除且不写入任何文件；不要为了"方便"传 `--keep-identifiers`，
   除非用户明确要求且已知晓合规风险。

6. **病案号在报告与质控清单中默认打码**（保留尾 4 位，如 `****1234`），
   这是对外可分享的默认形态。只有当用户明确说明要回查整改记录时，
   才可传 `--show-ids` 生成完整 ID 的科内版本，并向用户说明两版的差别。

## 数据安全与信任设计（回答用户"数据会不会泄露"时直接引用）

用户（尤其病案科/信息科背景）最常见的顾虑是"数据敏感，不敢用"。标准回应：

1. **全程本机运行**：引擎是本机 Python 脚本，无任何网络请求；报告是自包含 HTML
   （ECharts 内联），断网可开。数据不经过任何服务器。
2. **默认隐私防线**：直接标识符列（姓名/身份证/电话/住址等）加载即整列剔除，不进入任何输出；
   病案号在 HTML 报告与质控问题清单中默认打码（`--show-ids` 可还原，供科内回查）。
3. **推荐流水线（最稳妥）**：若院内已有哈希化去标识工具（如 HMAC-SHA256 病案号→研究ID），
   先跑去标识、再喂本技能。病案号替换为稳定研究 ID 后，重复检测、31 天再入院、
   患者去重等逻辑照常工作；本技能已兼容 `研究ID` 字段作为替代主键。
4. **对外分享口径**：默认产物即可直接给科主任/上级检查；若要发给院外，
   建议先删除质控问题清单 CSV（其中样例明细含字段值），只保留 HTML 报告。

## 黄金示例（直接复制改路径）

**1 标准场景：一个目录的多年度导出 → 完整报告**

```bash
python {skill_base}/scripts/cli.py report "D:/病案首页数据/2023-2025" \
  --outdir "./病案首页分析输出" --export-clean
```

脚本自动完成：多文件纵向合并 → 脏表头定位 → 37 列字段识别 → 隐私剔除 →
派生指标 → 19 条质控规则 → KPI → 13 张图表 → 写 HTML + 附表。

**2 脏表头 + 老编码 CSV**

```bash
python {skill_base}/scripts/cli.py report "导出表.csv" \
  --encoding gb18030 --header-row 3 --outdir "./out"
```

`--header-row N` 表示第 N 行（0 基）是表头，其上全部丢弃。**N 必须先跑一次无参数版本看布局再定**，
不要拍脑袋。

**3 指定 Excel 工作表 + 试跑**

```bash
python {skill_base}/scripts/cli.py report "全院首页.xlsx" --sheet "2024年" \
  --max-rows 5000 --outdir "./out"
```

**4 只做质控，不要报告**

```bash
python {skill_base}/scripts/cli.py check "首页数据.csv" --outdir "./out"
```

**5 先摸底看字段能不能对上**

```bash
python {skill_base}/scripts/cli.py profile "首页数据.csv" --outdir "./out"
# 看 out/字段识别与数据概览.json 里的映射与未识别列，再决定是否调 --header-row
```

**6 写解读（第二步，MUST）**

```bash
python {skill_base}/scripts/cli.py report "首页数据" --outdir "./out" \
  --annotation "本报告覆盖 2023–2025 年 2100 条出院记录，平均住院日中位 6 天，
  但均值被 5.7% 的住院天数填报错误拉高到 12 天，建议先整改 Q005 再引用均值。
  费用结构中西药费占 22.7% 为首位，年度次均费用从 9958 元升至 10392 元（+4.4%）。"
```

**7 环境自检 / 生成演示数据**

```bash
python {skill_base}/scripts/cli.py --doctor          # 依赖与资产体检
python {skill_base}/scripts/cli.py sample "./demo"   # 生成模拟首页数据（含脏数据，供试跑）
```

## 模式与 flags

| 模式 | 作用 | 主要产物 |
|------|------|----------|
| `report`（默认） | 全套：清洗+质控+指标+HTML 报告 | HTML + 全部附表 |
| `profile` | 只做字段识别与数据摸底 | `字段识别与数据概览.json`、字段映射表 |
| `check` | 只做质控 | `质控问题清单.csv` |
| `sample` | 生成模拟病案首页数据 | 3 个演示文件 |
| `--doctor` | 环境与资产自检 | stdout JSON |

| Flag | 说明 |
|------|------|
| `--outdir DIR` | **必传**。输出目录 |
| `--sheet NAME\|N` | Excel 工作表 |
| `--header-row N` | 表头行号（0 基）；留空自动探测 |
| `--encoding` | CSV 编码（老系统常用 `gb18030`） |
| `--sep` | CSV 分隔符；留空自动嗅探 |
| `--los-offset 0\|1` | 住院天数口径：`0`=出院-入院（默认）；`1`=首尾日均计 |
| `--age-bins` | 年龄段切点，如 `0,18,45,60,75,200` |
| `--keep-identifiers` | 保留直接标识符（默认剔除，**慎用**） |
| `--show-ids` | 质控样例显示完整病案号（默认打码为 `****尾4位`） |
| `--theme light\|dark` | 报告主题，默认 light |
| `--title` / `--subtitle` | 报告主/副标题 |
| `--annotation` / `--annotation-file` | 解读文字 |
| `--export-clean` | 额外导出清洗后数据 CSV |
| `--max-rows N` | 只处理前 N 行（试跑） |
| `--no-facts-file` | 不写事实卡 JSON |

### stdout JSON（成功时单行）

`success` / `outdir` / `source_rows` / `plotted_rows` / `mapped_fields` / `unmapped_fields` /
`privacy_dropped` / `quality{score,summary}` / `kpi` / `charts[{id,type,title,facts}]` /
`warnings` / `outputs` / `html_path` / `annotation_source` / `facts_path`

**校对口径读这些字段**：`source_rows`=合并后原始行数；`plotted_rows`=进入分析的行数；
`kpi.出院人次.分子/分母`=每个指标的算式；`quality.score`=质量评分（0–100）。
失败时 stdout 为 `{"success": false, "error": {code_name, message, suggestion}}`。

## Hard Constraints

1. **MUST 先跑 `profile` 或带 `--max-rows` 试跑**再对全量数据出正式报告——
   字段没对上时全量结果只是错得更快。看 `unmapped_fields`：>0 时先核对
   `字段映射表.csv`，确认未识别列是否含关键字段（如"主诊断"被写成
   "出院诊断名称(主)"）。
2. **不完整年度 MUST 从同比结论中剔除**：工具会自动识别"末年人次 < 其他年度中位数 50%"
   的情况并加 ⚠ 事实，解读时不得把这种年份写成"业务量下降"。
3. **口径 MUST 显式声明**：报告里的平均住院日/药占比等均带口径说明。对外引用时
   必须连口径一起给（如"按出院日期归年、住院天数=出院日期-入院日期"）。
4. **`手术率` 口径**：手术编码/名称任一非空即计为有手术；若无这两个字段才退回手术费>0。
   与 HIS 的"手术台次"口径不同，不得混用。
5. **`31 天再入院率` 需要同一患者纵向数据**（病案号或研究ID 连续）。若输入是多年度分表且
   病案号未跨表统一，该指标不可信，须在解读里说明。
6. **MUST NOT** 硬编码任何绝对路径到生成物里。
7. **失败处理**：`success:false` 时读 `error.suggestion` 修正后重试，**同一环节最多重试 2 次**；
   仍失败则把 `code_name` / `suggestion` / 已尝试的修复如实报给用户等决策，
   **不得**静默改用自写脚本兜底。

## Exit Criteria（机械可判定）

* ✅ **成功**：stdout `{"success": true, ...}`，`html_path` 指向的文件存在且非空，
  且 `annotation_source == "user"` → 附解读交付，用 `present_files` 打开 HTML 预览。
* ℹ️ `profile` / `check` 模式不算交付完整报告，只是中间步。
* ❌ **失败**：`success:false` 或 exit code 1 → 按 `suggestion` 修，最多 2 次。
* 🛑 **仍失败（唯一必须的用户介入点）**：如实报告错误与已尝试的修复，等用户决策。

## 常见陷阱（实测踩过的）

| 现象 | 原因 | 处理 |
|------|------|------|
| 日期大量识别为缺失 | 同一列混排 `2023/03/02` `20230326` `2023-05-12 00:00:00`；pandas 默认只推断一种格式 | 工具已用 `format="mixed"` 逐元素解析；若仍失败说明是真正的空值 |
| 未识别列很多 | 列名是系统内码或缩写（如 `zyrq`） | 核对 `字段映射表.csv`；必要时先手工改表头再跑 |
| 手术率接近 100% | 数据里手术费分项被全量赋值（未做手术也有金额） | 检查该院手术费口径；工具优先用手术编码判定 |
| 费用分项偏差率极高 | 分项字段不完整或口径与总费用不同（含院外购药） | 只是提示，不阻断；解读时说明分项不完整 |
| 多文件合并后大量空值 | 各文件列名不一致 | 统一表头后重跑，或按文件分别出报告 |
| `xlrd 缺失` | 需读 `.xls` 老格式 | `pip install xlrd>=2.0.1` |
