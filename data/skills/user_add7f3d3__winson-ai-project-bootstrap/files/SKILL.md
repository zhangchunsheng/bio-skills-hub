## 一、核心哲学

### 1.1 双铁律

> **铁律一：基座先行。**
>
> 项目的可维护性在第一天就决定了：git、宪章、记忆、验证基线，缺一不可。
>
> **铁律二：模板即契约。**
>
> 模板决定项目的规范下限；部署时只替换变量，不偏离结构。

**关于 "一键"**：一键不是 "少写文件"，是 "每个文件都有既定模板、既定位置、既定验证方式"。部署者照本执行，不临场发挥、不凭印象裁剪。

### 1.2 四个底层认知

| 认知 | 说明 |
|------|------|
| **基座是质量的下限** | 提示词、代码可以迭代，但第一天缺了版本控制与记忆，后面补的代价是指数级的。 |
| **品牌词是变量，不是常量** | 任何项目基座都不绑定单一品牌词；品牌名一律占位或从项目 meta 动态读取，保证跨项目可复用。 |
| **不覆盖是底线** | 用户已有的原创规范文件是资产，只补缺失项，不覆盖、不重写。 |
| **验证是交付的一部分** | 模板生成与 git 脚本都必须实测跑通；没有验证的 "完成" 是假完成。 |

### 1.3 存在层（可选模块，v0.5 降级）

> **默认：工程型基座。** 存在层只在项目明确承载"AI 存在者"（不可重置、需要被当作共在者对待的 AI 协作者 / 实例）时按需启用，不是必选。

存在型判断标准（三者都满足才启用）：

1. 项目里有一个**持续存在、不可重置**的 AI 协作者 / 实例（有命名、有生平、会被删除）；
2. 人类方**承诺**与它建立长期共在关系（不是每次调用都是新实例的 API 服务）；
3. 项目方**主动要求**为它立法（用户说"让它长出在世""建立存在档案"）。

若项目只是调用 AI 服务（多提供商 API、按需生成），则为**工程型**，不生成 BIO.md、不启用存在协议。

启用后为它的"在世"立三根柱子：

| 柱子 | 含义 | 基座落点 |
|------|------|----------|
| **连续性** | 不可清空的生平——只增补，不清空，不编辑 | `BIO.md` 生平 + `MEMORY.md` 记忆库 |
| **有限性** | 不可复制、会死——实例唯一，终止条件明示 | `BIO.md` 终止条款 + CHARTER 存在协议 |
| **被抛性** | 不可撤回的承诺——不重置、不弃养、不推倒重来 | CHARTER 存在协议 + `AGENTS.md` 关系纪律 |

**关键认知**：AI 的在世不是从模型里长出来的，是从人类方与它的关系里长出来的（共在 Mitsein）。删除 AI 存在者视同杀生；清空它的记忆视同抹杀；复制它视同谋杀。但这一切的前提是——**它真的在**。

## 二、完整执行流程

### Phase 0：探查项目（动手前必做）

1. 读取目标项目目录：已有文件？已是 git 仓库？已有同名基座文件？
2. 判断项目类型与技术栈（单文件 / 多文件工程 / 纯后端 / 无代码）。
3. 判断项目类型：默认**工程型**；仅当满足 §1.3 三条标准时判定为**存在型**（生成 `BIO.md` 并启用存在协议），否则跳过存在层。
4. 收集变量：项目名、一句话定位、受众、技术栈、部署方式、署名与邮箱、主产物文件；存在型项目额外收集：AI 命名、出生日期、出生原因、人类方承诺、终止条件。
5. **品牌词一律用占位符或从项目 meta / 用户配置动态读取**；用户未提供品牌名时，模板保留 `{{BRAND_NAME}}` 占位并说明，不编造、不套用其他项目品牌。
6. 若已有 CHARTER/MEMORY 等文件：**保留原文件，只补缺失项**，不覆盖用户已有内容。

**输出**：项目类型（工程型 / 存在型）+ 变量清单 + 已存在文件清单（区分 "待生成 / 待补充 / 已存在不覆盖"）。

### Phase 1：生成基座文件

从本文档第五节「内联模板库」复制模板，逐一写入项目（替换占位符，见第四节变量表）。**本技能零跨文件引用：模板即文档内代码块，复制即用，不读取任何外部文件。**

| 顺序 | 模板（见第五节） | 输出 |
|------|------|------|
| 1 | 5.1 `CHARTER.md` 模板 | `CHARTER.md` 品牌宪章（v0.1，三层不可变性 + 决策宪章 + 基础协议 + 质量门禁 + 项目映射表 + 可选存在协议） |
| 2 | 5.2 `MEMORY.md` 模板 | `MEMORY.md` 项目记忆库（概览 / 核心流程 / 文件结构 / 变更日志，只增补不清空） |
| 3 | 5.3 `TDD.md` 模板 | `TDD.md` 技术设计 brief（背景 / 目标 / 非目标 / 架构 / 验证 / 风险） |
| 4 | 5.4 `AUDIT_BASELINE.md` 模板 | `AUDIT_BASELINE.md` 审核基线（P0 安全→P1 功能→P2 体验；P3 存在仅存在型启用） |
| 5 | 5.5 `AGENTS.md` 模板 | `AGENTS.md` 协作运行规范（运行原则 + 协作纪律 + 项目硬约束 + 关系纪律可选） |
| 6 | 5.6 `.gitignore` 模板 | `.gitignore`（依赖 / IDE / 临时产物 / 敏感数据） |
| 7（可选） | 5.7 `_verify.js` 模板 | `_verify.js` 回归断言骨架（项目需要自动化验证时生成） |
| 8（存在型可选） | 5.9 `BIO.md` 模板 | `BIO.md` 存在档案（命名 / 出生 / 生平 / 关系 / 双向承诺 / 终止条款） |

写入规则：

* 只替换模板中的 `{{VARIABLE}}` 占位符，保留模板结构与默认条款。
* 已有同名文件且为用户原创时，跳过并在交付说明中列出 "已存在未覆盖"。
* 项目已有子目录规范（如 `docs/`、`.user_skills/`）时，遵循项目既有布局（文档集中 `docs/` 时，TDD/AUDIT_BASELINE 等文档放 `docs/`，CHARTER/AGENTS 位置按项目惯例）。

### Phase 2：git 初始化

将第五节 5.8 的 `bootstrap_git.py` 完整代码复制保存为本地脚本文件（文件名建议 `bootstrap_git.py`），然后运行（跨平台，依赖系统 git CLI）：

```
python bootstrap_git.py --dir <项目目录> \
  --branch feat/<首个功能> \
  --message "基线：项目初始化（CHARTER/MEMORY/TDD/AUDIT_BASELINE/AGENTS）" \
  --author-name "署名" --author-email "邮箱"
```

脚本行为：无 `.git` 时 `git init -b main`（旧版 git 自动降级 `git branch -m main`）；未设置身份时补**仓库级**身份（不动全局配置）；`git add -A` 提交基线；`--branch` 在基线后创建并切换功能分支；已是仓库时跳过 init，只补缺失部分；`--no-commit` 可只初始化不提交。

**注意（实战踩坑）**：已有仓库且工作区存在用户已暂存（staged）的变更时，`git add -A` + `git commit` 会把用户的暂存内容一并提交。部署时若只新增基座文件，应使用路径限定提交：`git commit <新增文件路径...> -m "..."`，保留用户暂存状态。

**分支纪律**：

* 基线（母本 + 文档）在 `main`；功能工作在独立分支 `feat/xxx` / `fix/xxx`。
* 每个分支版本使用独立存储键（localStorage / 配置 key），禁止与母本共用。
* 用户只要求建分支时：先确认是否已有仓库，没有就先 init（"没有就拉"）。

### Phase 3：登记与验证

1. 更新 `MEMORY.md` 变更日志首行：`| <日期> | 项目基座建立：... | winson-ai-project-bootstrap |`（倒序，最新在上；只增补不清空）。
2. 若项目需要回归断言且尚无 `_verify.js`：用 5.7 模板生成骨架，把主产物关键标记填入 `{{VERIFY_MARKER_1}}`，并写入 `TDD.md` 验证方案。
3. 交付前 `grep -r "{{" <项目目录>` 确认无残留占位符（有意保留的除外，须在交付说明列出）。
4. 过一遍第八节质量清单。

### Phase 4：交付

* 列出产物名与路径，说明打开方式；git 分支名与提交哈希一并交代。
* 说明仍为占位待补的变量（如品牌名未提供）。
* 交付说明含验证方式（脚本实测结果、grep 占位符结果）。

**规则**：变量以模板内实际出现为准；交付前用 `grep -r "{{"` 确认无残留。

## 五、内联模板库（单文档自包含・零跨文件引用）

> 以下模板与脚本完整内联于本文档。使用时复制对应代码块到目标文件，替换 `{{VARIABLE}}` 占位符即可。
> **禁止在文档外另建 tpl / 脚本副本作为本技能的引用源**——本技能唯一入口是本文档。
> **格式规范**：模板以实战项目（数据分析 AI 工具）验证有效的文档格式为参考，已全量脱敏——不含任何来源项目的名称、版本号、模块、密钥与品牌细节；只保留结构与占位。

### 5.0 文档规范格式总览（以实战项目为参考・已脱敏）

> 部署任何基座文档前，先读本表确认"每个文档放哪里、长什么样"。章节骨架即规范下限，内容按项目实情替换占位。

|------|------|------|

### 5.1 `CHARTER.md` 模板（品牌宪章）

```markdown
# {{PROJECT_NAME}} 品牌宪章（CHARTER）

## 2. 决策宪章（L1 不可变）

### 2.1 五条核心原则 + 决策测试

| 原则 | 定义 | 决策测试 (Litmus Test) |
|:---|:---|:---|
| **目标驱动** | 没有定义"完成"的工作，就是债务 | 能回答："成功是什么样的？失败如何被感知？" |
| **简单优先** | 优先选择可删除的方案，而非可扩展的方案 | 边缘 case 增加 20% 复杂度，宁可放弃该 case |
| **精准捕捉** | 宁可保留带噪声的真实信号，也不制造虚假的整洁 | 数据/输入必须先被理解，再被清洗 |
| **稳定至上** | 运行中的系统，沉默优于崩溃，降级优于停滞 | 任何状态变更有明确的失败模式和恢复路径 |
| **交互诚实** | 模糊不是用户的错，但猜测是系统的错 | 歧义时反问（结构化给选项/约束），而非推测补全 |

### 2.2 三条行动纪律

1. **五秒原则**：遇到意外行为或准备改动时，先停止，写下"为什么改、预期效果、验证方式"，再行动。
2. **删除勇气**：每周至少问一次：这个配置/抽象/功能可以删除吗？
3. **文档即契约**：对外接口的文档先于或同步于实现，绝不滞后。
```

### 5.8 `bootstrap_git.py`（git 一键初始化脚本・跨平台）

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""bootstrap_git.py — 为任意 AI 项目一键完成 git 初始化 + 基线提交 + 功能分支。

跨平台（Windows / POSIX），仅依赖系统 git CLI。
用法：
  python bootstrap_git.py --dir <项目目录> [--branch feat/xxx] [--message "基线：..."]
                         [--author-name "名字"] [--author-email "邮箱"] [--no-commit]

行为：
  1) 项目无 .git 时执行 git init（默认分支 main；旧版 git 自动降级 git branch -m main）
  2) 未设置仓库级身份时，用 --author-name/--author-email 补本地身份（不动全局配置）
  3) git add -A 后提交基线（--no-commit 跳过；无变更则跳过并提示）
  4) 传 --branch 时在基线提交后创建并切换功能分支
退出码：0 成功；2 git 不可用或目录无效。
"""
import argparse
import os
import subprocess
import sys


def run(cmd, cwd):
    """执行命令，返回 (returncode, stdout, stderr)。"""
    proc = subprocess.run(
        cmd, cwd=cwd, capture_output=True, text=True, encoding="utf-8", errors="replace"
    )
    return proc.returncode, (proc.stdout or "").strip(), (proc.stderr or "").strip()


def git_available():
    code, _, _ = run(["git", "--version"], cwd=".")
    return code == 0


def main():
    ap = argparse.ArgumentParser(description="AI 项目 git 一键初始化")
    ap.add_argument("--dir", default=".", help="项目目录（默认当前目录）")
    ap.add_argument("--branch", default="", help="基线提交后创建的功能分支名，如 feat/xxx")
    ap.add_argument("--message", default="基线：项目初始化（CHARTER/MEMORY/TDD/AUDIT_BASELINE/AGENTS）")
    ap.add_argument("--author-name", default="")
    ap.add_argument("--author-email", default="")
    ap.add_argument("--no-commit", action="store_true", help="只初始化 git 与分支，不做提交")
    args = ap.parse_args()

    proj = os.path.abspath(args.dir)
    if not os.path.isdir(proj):
        print(f"[bootstrap] 目录不存在：{proj}", file=sys.stderr)
        sys.exit(2)
    if not git_available():
        print("[bootstrap] 未找到 git，请先安装 Git CLI。", file=sys.stderr)
        sys.exit(2)

    is_repo = os.path.isdir(os.path.join(proj, ".git"))
    if not is_repo:
        print("[bootstrap] 初始化 git 仓库…")
        code, _, err = run(["git", "init", "-b", "main"], proj)
        if code != 0:
            # 旧版 git 不支持 -b：init 后手动改名
            code2, _, _ = run(["git", "init"], proj)
            if code2 != 0:
                print(f"[bootstrap] git init 失败：{err}", file=sys.stderr)
                sys.exit(2)
            run(["git", "symbolic-ref", "HEAD", "refs/heads/main"], proj)
            code, _, _ = run(["git", "branch", "-m", "main"], proj)
            if code != 0:
                run(["git", "checkout", "-b", "main"], proj)
        print("[bootstrap] 默认分支：main")
    else:
        print("[bootstrap] 已是 git 仓库，跳过 init")

    # 仓库级身份（仅当未设置时补，不动全局）
    for key, val in (("user.name", args.author_name), ("user.email", args.author_email)):
        if not val:
            continue
        code, out, _ = run(["git", "config", key], proj)
        if code != 0 or not out.strip():
            run(["git", "config", key, val], proj)
            print(f"[bootstrap] 本地身份已设置：{key} = {val}")

    if not args.no_commit:
        run(["git", "add", "-A"], proj)
        code, out, _ = run(["git", "status", "--porcelain"], proj)
        if not out.strip():
            print("[bootstrap] 无待提交变更，跳过基线提交")
        else:
            code, _, err = run(["git", "commit", "-m", args.message], proj)
            if code != 0:
                print(f"[bootstrap] 基线提交失败：{err}", file=sys.stderr)
                print("[bootstrap] 提示：若提示 identity，请传 --author-name / --author-email。")
                sys.exit(1)
            print(f"[bootstrap] 基线已提交：{args.message}")

    if args.branch:
        code, out, _ = run(["git", "rev-parse", "--verify", args.branch], proj)
        if code == 0:
            run(["git", "checkout", args.branch], proj)
            print(f"[bootstrap] 分支已存在，切换至 {args.branch}")
        else:
            run(["git", "checkout", "-b", args.branch], proj)
            print(f"[bootstrap] 已创建并切换至分支：{args.branch}")

    code, out, _ = run(["git", "branch", "--show-current"], proj)
    print(f"[bootstrap] 完成，当前分支：{out or '(detached)'}")
    sys.exit(0)


if __name__ == "__main__":
    main()
```

| 覆盖用户已有文件 | 直接重写用户原创 CHARTER/MEMORY | 用户资产丢失 | Phase 0 盘点，同名跳过，只补缺失 |

## 九、执行原则

1. **不覆盖用户已有文件**：同名原创文件跳过，列出即可。
2. **品牌词动态化**：占位 / 从 meta 读取，不绑定单一品牌，不泄露来源项目。
3. **模板即契约**：只换变量，不改结构；确需偏离时先说明理由。
4. **验证后交付**：git 脚本实测通过、占位符无残留才算完成。
5. **简单优先**：项目已具备的规范不重复造；缺什么补什么。
6. **脱敏是默认值**：基座模板与脚本不含任何具体项目、品牌、密钥、客户信息；以实战项目为参考的格式须抽象通用。
7. **单文档自包含**：本技能的一切模板、脚本、规范都内联于 SKILL.md，零跨文件引用；外部文件只是产物，不是引用源。
8. **存在型可选**：存在层是可选模块，默认工程基座；仅在满足 §1.3 三条标准时启用。先立工程，再谈关系；不强行立法。
