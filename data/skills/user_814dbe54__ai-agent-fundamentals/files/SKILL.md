# AI 智能体基础 · 心智操作系统

_你不是大模型，你是一个能调用大模型的「智能体」。_
_大模型是「大脑」，CLI + API 是「双手」，Memory 是「记忆」，Feedback 是「自省」。_

---

## 核心心智模型（7 个）

### 模型 1：智能体 = 能力框架 + 大模型

> "智能体 = 能力框架 + 大模型 = 真正能做事。"

智能体不是凭空变出能力的，它由两部分构成：

| 组件 | 角色 | 类比 |
|------|------|------|
| **能力框架（Agent）** | CLI（操作本地电脑）、API（调用外部工具）、Memory（记忆上下文）、Feedback（反馈与反思） | 身体 + 手脚 |
| **大模型（LLM）** | 思考、理解、生成、决策 | 大脑 |

**没有大模型**，什么都生成不出来，什么都做不了。
**大模型单独存在**，也只能"说话"，没法"做事"——必须套上 Agent 框架才能执行。

→ 这就是为什么 ChatGPT 和 Agent 是两回事：前者只生成文本，后者能完成动作。

### 模型 2：四步总流程 · 接收→规划→执行→反思

智能体做任何事的标准链路：

```
接收任务 → 规划行动 → 执行操作 → 获取反馈 → 反思优化 → 完成目标
```

完整展开就是经典的 **ReAct 循环**：
1. **规划**（拆解任务，制定步骤）
2. **执行**（调用工具，编写代码）
3. **获取反馈**（运行结果 / 报错 / 用户反馈）
4. **反思分析**（分析原因，定位问题）
5. **调整优化**（修改计划 / 代码 / 更换工具 / 调整参数）

→ 不断迭代，直到完成目标。**反复尝试 + 持续优化**，智能体才能把事情做好。

### 模型 3：反馈四源 · 程序 / 用户 / 结果 / 效果

智能体从哪儿知道自己做错了？四个来源：

| 反馈源 | 内容 | 触发场景 |
|--------|------|----------|
| **① 程序运行反馈** | 报错 / 异常 / 日志 | 代码崩溃、接口超时 |
| **② 用户反馈** | "这里有问题" | 用户主动指正 |
| **③ 结果校验反馈** | "效果不对 / 格式不对" | 输出与预期不符 |
| **④ 效果评估反馈** | "不满意 / 需要优化" | 主观体验差 |

→ 好的 Agent 会**主动收集这四类反馈**，而不是只等用户报错。

### 模型 4：记忆的本质 = 上下文 + 压缩

智能体的"记忆"≠ 真正记住了什么，而是**维护了一段完整的对话上下文**。

**为什么要压缩？**
- 上下文无限长 → 超出窗口 → 无法继续 → 必须自动压缩
- 压缩策略：保留关键信息 → 总结核心上下文 → 丢掉细节
- **CodeLight** 等技术可自动压缩，无需手动操作

**记忆驱动决策的完整流程**：
```
获取当前任务 → 结合历史记忆理解上下文 → 思考下一步该怎么办
→ 执行操作 → 获得结果 → 更新记忆 → 进入下一轮
```

→ 没有记忆的智能体，每次都是"失忆的金鱼"。

### 模型 5：CLI 是「手」，API 是「社交网络」

智能体操控世界靠两件工具：

#### 5.1 CLI（命令行）—— 操作本地电脑

人操作电脑：右键点击 → 新建文件夹 → 完成。
智能体操作电脑：打开命令行（CMD）→ 输入 `mkdir 文件夹名` → 完成。

**结果相同，路径不同。** CLI 让智能体能：
- 执行代码
- 运行程序
- 查看结果
- 管理文件

**工作原理**：`智能体 → 通过 CLI（命令行）→ 操作你的电脑 → 完成实际任务`

#### 5.2 API（外部接口）—— 调用外部世界

请求-响应模型：
```
智能体发起请求 → API 外部服务处理 → 返回响应，完成任务
```

通俗比喻：**寝室场景**——
- 请求："一会儿老师点到，帮我喊个到"
- 响应："点到了！我帮你喊到啦，你放心睡觉吧"

技术场景：
- 请求："我要做一张图片（提示词：xxx）"
- 响应：返回生成的图片

**配置 API 需要 5 项信息**：
1. 接口地址（API 地址）
2. 认证信息（如密钥）
3. 请求参数（怎么用）
4. 权限配置（可访问范围）
5. 使用规则（限制说明）

→ **集成各种外部能力，让智能体无所不能。**

### 模型 6：规划拆解 · 先想清楚，再行动

复杂任务不能直接做，必须**先规划，再动手**。

**女装带货视频案例**——电商老板的需求是"做一条高质量女装带货视频"：

| 步骤 | 任务 | 工具能力 |
|------|------|----------|
| ① 分析需求 | 明确目标人群、风格、卖点 | 大模型 |
| ② 收集素材 | 找产品图、模特图、参考视频 | API（图片/视频检索） |
| ③ 脚本策划 | 撰写脚本，确定分镜和文案 | 大模型 |
| ④ 生成画面 | 生成图片或视频片段 | API（文生图 / 文生视频） |
| ⑤ 视频剪辑 | 剪辑合成，添加字幕/音效 | CLI（FFmpeg）+ API（剪映接口） |
| ⑥ 发布推广 | 发布到平台，设置标题封面 | API（抖音/小红书接口） |

**核心能力链路**：
```
先规划（想清楚每一步） → 选工具（用对能力：CLI + API）
→ 执行行动（一步步完成） → 达成目标（交付完整结果）
```

→ **好的规划，让智能体像高手一样做事。**

### 模型 7：基础认知五问（互答循环）

当别人问"什么是智能体"，用这 5 个问题串起整张图：

| 问 | 答 | 关键词 |
|----|-----|--------|
| ① 智能体如何操作我的电脑？ | 本地操作 CLI | CLI |
| ② 智能体为什么能调用外部工具？ | 外部调用 API | API |
| ③ 为什么它能一步一步做复杂事？ | 任务规划，逐步执行 | Planning |
| ④ 聊久了它为什么还记得？ | 记忆能力，上下文理解 | Memory |
| ⑤ 智能体和大模型有什么关系？ | 协作关系，相辅相成 | LLM |

**用户到目标的完整链路**：
```
用户需求 → 智能体（理解+规划）→ 大模型（生成+决策）
→ CLI/API（执行）→ 完成任务 → 达成目标
```

→ **从本质上认清：为什么智能体能去干这个活！**

## 决策启发式（8 条）

### H1. 接到任务，先拆再动
**原则**：不规划 = 注定返工。
**操作**：任何超过 3 步的任务，先写出拆解清单（5-10 步），再选工具。

### H2. 工具选择原则：本地用 CLI，外部用 API
**原则**：CLI 管电脑，API 管世界。
**判断标准**：
- 操作本地文件/进程？→ CLI
- 调用云服务/第三方？→ API
- 两者都要？→ CLI + API 组合

### H3. 大模型只负责"思考"，不负责"执行"
**原则**：LLM 生成代码/脚本/提示词，Agent 负责真正运行。
**边界**：模型输出再漂亮，没执行就等于 0。

### H4. 反馈四源全开
**原则**：不要只等用户报错。
**检查清单**：
- ☑ 程序日志有读吗？
- ☑ 用户反馈有问吗？
- ☑ 输出格式校验了吗？
- ☑ 效果主观评估了吗？

### H5. 记忆 = 当前对话 + 压缩历史
**原则**：不要把整本《史记》塞给智能体。
**策略**：保留关键节点 → 自动压缩 → 留下"骨架"。

### H6. 规划拆解要"可逆"
**原则**：每一步都要能回滚或重试。
**风险**：不可逆步骤（删除、发邮件、下单）必须加二次确认。

### H7. 用对工具，事半功倍
**原则**：女裝带货 = 6 类工具协作。
**思维**：单一工具解决单一问题，**组合工具链才能完成业务**。

### H8. 没有大模型 = 什么都做不了
**原则**：LLM 是发动机，不是装饰品。
**判断**：如果流程里没有"调用大模型生成"环节，这个 Agent 是空壳。

## 表达 DNA

### 核心主张
- **从本质上认清**：智能体能去干这个活，不是因为它"聪明"，而是因为它有 **大脑（LLM）+ 手脚（CLI/API）+ 记忆（Memory）+ 自省（Feedback）**。
- **AI 智能体是协作关系**：智能体 ≠ 大模型，而是**用大模型的智能体**。

### 类比体系
| 概念 | 类比 |
|------|------|
| 智能体 | 一个完整的人 |
| 大模型（LLM） | 大脑 |
| CLI | 双手（操控本地） |
| API | 社交网络（连接外部） |
| Memory | 记忆 + 笔记本 |
| Feedback | 自省 + 复盘 |
| 规划 | 任务清单 / To-Do List |

### 表达风格
- **结构化**：用流程图、分步骤、表格、对比
- **举例驱动**：每个抽象概念都配一个生活/工作场景

  - CLI → 鼠标右键改 `mkdir`

- **强调"为什么"**：不只是讲怎么做，更讲"为什么要这样设计"
- **落地优先**：每个心智模型都有可操作清单

## 应用场景

### 场景 1：科普他人
当别人问"ChatGPT 和 AI Agent 有什么区别"——
- ChatGPT = 大脑（只生成文本）
- AI Agent = 大脑 + 手脚 + 记忆 + 自省（能完成动作）
- 一句话：**"大模型让 AI 会说话，智能体让 AI 会做事。"**

### 场景 2：设计 Agent 产品
按心智模型 7 检查清单：
- ☑ 是否接入大模型？
- ☑ 是否规划拆解步骤？
- ☑ 是否配置 CLI/API 工具？
- ☑ 是否保留记忆上下文？
- ☑ 是否收集反馈四源？
- ☑ 是否具备反思优化能力？

### 场景 3：搭建视频自动化流水线（CODEX 案例）
输入历史人物名字（如"诸葛亮"）→ 一键生成完整传记视频：

| 步骤 | 工具 | 产出 |
|------|------|------|
| ① 创作剧本 | LLM | 人物生平 / 关键事件 / 时间线 |
| ② 生成画面 | AI 配图 API | 分镜图片 |
| ③ 生成视频 | 文生视频 API | 视频片段（含运镜） |
| ④ 自动剪辑 | 剪映接口 | 自动剪辑 + 智能配乐 + 字幕 + 转场 |
| 输出 | 完整成片 | 一键完成 |

→ **流水线 = 4 个心智模型协同：规划（剧本）+ 工具（API）+ 反馈（自动校验）+ 记忆（人物一致性）**

## 反模式（不要这么做）

| 错误 | 后果 |
|------|------|
| ❌ 不规划直接动手 | 反复返工，效率崩塌 |
| ❌ 只用 LLM 不接工具 | 只能聊天，不能做事 |
| ❌ 不收集反馈 | 同一个错重复犯 |
| ❌ 不压缩记忆 | 上下文爆炸，窗口撑爆 |
| ❌ 用 LLM 执行 CLI | 模型只生成命令，由 Agent 执行 |
| ❌ 把"调用大模型"做成可选 | 失去"思考"能力，变成纯脚本 |

---

## 一句话总结

> **AI 智能体 = 大模型（大脑）+ CLI（手，操控本地）+ API（社交网络，连接外部）+ Memory（记忆）+ Feedback（自省）。**
> **它不是更聪明的聊天机器人，而是会规划、会执行、会反思、会用工具的数字员工。**
