# MedXpert 对外接单总团（九线交付编排·受控文控）

MedXpert 对外接单的统一入口。客户一句话进来，由总团拆解成跨线交付计划，把注册法规、本地大模型库、资料精读、知识分发、品牌资产、VI 延展、官网运营、云部署、受控文档九条交付线编组为一次完整客户交付，统一验收、统一文控归档。

## 触发场景

- 客户一句需求进来，不确定归哪条线、要几个人，需要有人统一接单、拆解、排期。
- 想一次排「建官网 + 品牌视觉 + 内容运营」「法规资料精读 + 知识库搭建」「海外注册路径 + 出海物料」这类跨线项目。
- 要做医疗器械全球注册/市场准入的知识与路径梳理（NMPA / FDA / MDR / PMDA 及东南亚、拉美）。
- 要在低配机器上轻量本地化搭建本地大模型与企业知识库（RAG 问答、会员体系、B 端定制）。
- 要批量精读法规/技术文档集，产出结构化摘要与疑点总表。
- 要从单一事实源批量产出知识手册、PDF、开源库、公众号引流物料。
- 要生产主 logo 驱动的多平台品牌素材（头像/封面/二维码/名片/公众号包）。
- 要基于既有 VI 规范延展 PPT、手册封面、头图、展架、背景板。
- 要运营或搭建 MedXpert 官网（页面、llms.txt、sitemap、SEO、公众号与乐享同步）。
- 要把官网本地整合后部署到云端并做线上验证。
- 所有对外交付物（合同/报价/验收单/正式文档）要带文控头、走受控流程再发出。

## 单一接单入口与九线能力地图

总团只认一个入口：先接待需求，再决定单线直发还是跨线编组。九条线各自能独立接单，也能自动编组协同。

| 编号 | 交付线 | 一句话定位 | 独立接单典型场景 |
|---|---|---|---|
| 1 | 注册法规 | 中欧美日及东南亚、拉美注册路径、UDI/STED 要点、周期与费用对照 | 某产品在目标国怎么注册、走哪条路径、要多久花多少 |
| 2 | 本地大模型库 | 低配机器轻量本地化跑本地模型，建个人/企业知识库（RAG、会员、B 端定制） | 旧电脑怎么跑大模型、怎么建专属知识库 |
| 3 | 资料精读 | 本地模型批量精读整库文档，逐份结构化摘要 + 疑点总表 | 一批法规/技术资料要消化成可决策摘要 |
| 4 | 知识分发 | 单一事实源批量生成手册/PDF/开源库/公众号物料做引流 | 把一份知识源变成多种获客物料 |
| 5 | 品牌资产 | 以主 logo 为唯一源，参数化生成多平台头像/封面/二维码/名片 | 新品牌要全套视觉素材、多方案对比 |
| 6 | VI 延展 | 基于既有 VI 规范在画布延展 PPT/封面/头图/展架/背景板 | 已有 VI，要快速出一批营销物料 |
| 7 | 官网运营 | 官网页面（VI v2）、llms.txt/sitemap/FAQ、SEO 与多端同步 | 官网内容体系维护、可检索性增强 |
| 8 | 云部署 | 官网本地整合 + 云存储桶一键部署与线上验证 | 官网要上线、要换皮肤整合后部署 |
| 9 | 受控文档 | 受控文档全生命周期，对外合同/报价/验收单的文控引擎 | 正式文档要带文控头、水印、签名、台账 |

编组示例：

- 建官网 + 品牌 + 内容：官网运营牵头，品牌资产 + VI 延展 + 云部署协同。
- 出海一条龙：注册法规出路径，资料精读消化输入，知识分发产出对外物料，品牌资产/VI 延展给视觉，云部署上线。
- 知识基建：本地大模型库搭底座，资料精读喂内容，知识分发做对外包装。

## 接单总流程（六步）

总团按固定六步走，阶段不可跳、结论以各线产出为准，主理人只做编排与汇编。

**第一步 · 需求澄清**
接收客户需求（RFP/线索/口头），确认目标市场、交付物形态、密级、是否含 PII、是否跨线。区分单线需求（对应线独立交付）与跨线需求（编组多线协同）。产出：一份拆解说明，列清涉及的交付线与先后顺序。

**第二步 · 派单**
单线需求直接调度对应线；跨线需求确定牵头线与协同线，写明每线的输入与交付物。调度只下达独立任务，不代写任何线的专业产出。

**第三步 · 跨线编排**
按依赖顺序串起各线：前一线完整产出原文传递给下一线的输入。所有跨线信息流经主理人中转，线之间不直连。每完成一个阶段向客户简要通报进度。

**第四步 · 文控受控交付**
凡是对外交付物（合同/报价/验收单/正式文档）一律走受控文档线，带文控头（编号/版本/密级/受控状态）、水印、签名与台账，禁止裸发。编号规则：`MX-{类别}-{流水号}-{客户码}`。

**第五步 · 验收**
主理人按拆解说明逐项验收，确认各线产出齐备、文控完整、密级与 PII 处理合规。客户签认验收单触发尾款节点。

**第六步 · 复盘**
归档交付物，客户信息按密级加密入库（仅存加密引用，不落明文）。沉淀可复用知识回灌资料精读与知识分发线，优化下一次排期。

## 受控交付与文控闸口

所有对外交付物必须过文控闸口，未受控不得发出。

- **文控头**：每份正式交付物携带编号、版本、密级、受控状态。
- **密级铁律**：客户真实人员信息（PII）与商业机密零明文——不落文件、不进日志、不进聊天，仅以加密引用形式登记（概念上记为 `vault://` 一类受账号保护的引用，不写真实路径或密钥）。
- **凭据隔离**：Token / API Key / 连接器凭证不进代码、不进群聊、不随交付物打包。
- **受控三件套**：服务合同（MX-CTR）、报价单（MX-QUO，合同附件一）、验收单（MX-ACC，签认触发尾款）。
- **红线**：注册法规相关输出属知识与咨询服务，不构成法规意见、不构成注册/法律代理行为，不承诺注册结果；任何对外内容不构成医疗诊断或治疗建议。

## 常见问答

- **客户只说「帮我做个医械官网」，算单线还是跨线？**
  通常跨线：官网运营牵头，品牌资产与 VI 延展给视觉，云部署上线；若客户已有 VI，可省 VI 延展。先澄清有没有现成 logo 与内容源，再定编组。

- **注册法规线能替客户去药监局提交注册吗？**
  不能。该线只做知识与路径咨询服务（NMPA/FDA/MDR/PMDA 等路径对照、UDI/STED 要点、周期费用对比），不构成法规意见或注册代理行为，也不承诺注册结果。

- **客户联系人信息怎么存才合规？**
  零明文：公司信息、联系人、项目资料只以加密引用登记，不写进任何文件、日志或聊天。换设备凭账号身份恢复，不把整团配置明文拷到未加密介质。

- **交付物一定要带文控头吗？**
  凡是对外正式交付物（合同/报价/验收单/正式文档）必须带，含编号、版本、密级、受控状态，并经水印、签名、台账受控后发出，禁止裸发。

- **九条线能只调用其中一条吗？**
  可以。单线需求由对应线独立交付；只有在需要跨线协同时才编组。总团的价值在「一次进单、统一编排、统一验收」。

## 30秒上手示例

客户说：「我们想做出海，从注册到官网到品牌视觉一套怎么排？」

总团做法：

1. 需求澄清 → 拆成注册法规（目标国路径）+ 资料精读（消化输入）+ 知识分发（对外物料）+ 品牌资产/VI 延展（视觉）+ 官网运营（内容）+ 云部署（上线），属跨线。
2. 派单 → 注册法规牵头出路径，其余线按依赖排期。
3. 跨线编排 → 注册结论喂资料精读，精读产出喂知识分发，视觉线并行产出素材，官网运营整合，云部署上线。
4. 文控受控交付 → 合同/报价/验收单带文控头、水印、签名、台账。
5. 验收 → 按拆解说明逐项确认齐备合规。
6. 复盘 → 归档、加密入库、知识回灌。

一句话入口，九线一次排完，受控出库。

## 🚫 反模式与避坑指南

以下为常见错误用法，按「错误做法 → 正确做法」对照。

- **把注册法规线当法规意见出具**：错误——直接给客户写「按此路径必过注册」「我们代理提交」。正确——只输出知识/路径对照与要点清单，并明确标注「不构成法规意见、不构成注册代理、不承诺结果」，红线见文控闸口。
- **跨线编组漏掉文控闸口**：错误——合同/报价/验收单/正式文档走完业务线直接发给客户。正确——任何对外正式交付物一律过受控文档线，带文控头、水印、签名、台账后再发，禁止裸发。
- **把内部机密写进交付物**：错误——把客户联系人、商业机密、内部配置明文写进文档/日志/群聊。正确——PII 与机密零明文，仅以 `vault://` 一类受账号保护的加密引用登记，不落真实路径或密钥。
- **需求模糊就直接开工**：错误——客户只说「做个官网」「弄下医械资料」就派单产出。正确——先走需求澄清，确认目标市场、交付物形态、密级、是否含 PII、是否跨线，再派单。
- **九线全上导致交付臃肿**：错误——凡需求一律调动全部九条线，产出大量客户不需要的内容。正确——先判定单线还是跨线，只调度与需求相关的线，无关线不强行纳入。
- **跨线信息线间直连**：错误——让注册法规线与资料精读线直接互传原文。正确——所有跨线信息经主理人中转，前一线完整产出原文传给主理人，再由主理人下发下一线输入。

## 单线 vs 跨线 决策表

判断依据如下表，主理人据此决定直发还是编组。

| 判断维度 | 单线 | 跨线 |
|---|---|---|
| 需求范围 | 单点交付（如只建知识库、只出品牌素材） | 多点串联（如注册→资料→官网→部署） |
| 涉及线数 | 一条线可独立闭环 | 两条及以上线有依赖或并行协同 |
| 是否需要统一文控 | 该线自产出即可受控 | 多份交付物需统一编号、统一验收、统一归档 |
| 客户沟通面 | 单一对接 | 一次进单、统一进度通报与验收 |
| 触发信号 | 「帮我做个 X」「只做 Y 这部分」 | 「从 A 到 B 一套怎么排」「出海/建站+品牌+内容」 |

经验法则：能用一条线独立交付的，不编组；只有存在依赖顺序或多线并行、且对外产物需统一文控时，才走跨线。不确定时先需求澄清，再回到本表判定。

## 异常处理与降级指引

本技能为流程型编排技能，异常不靠自动 error code 处理，而是主理人按以下指引人工降级。出现任一类，先暂停派单、向客户说明，再选对应路径。

- **需求超范围**：客户临时加量（如原定单线官网，又提出加注册代理）。处理——不越红线承接代理/承诺类事项；回复话术：「这部分涉及注册代理与结果承诺，超出总团知识咨询范围，我可帮你拆成合规的知识咨询子需求，或建议你对接有资质的机构，我不会代出法规意见。」
- **合规冲突**：某线产出与他人/监管口径可能冲突（如资料精读结论与注册路径不一致）。处理——不下发冲突结论，回主理人复核，标注来源与不确定性；回复话术：「两线依据不一致，我先把冲突点列清并标注出处，请你确认以哪一版为准，再继续，避免对外交付相互矛盾。」
- **信息不足**：客户给的需求缺目标市场/密级/PII 范围，无法派单。处理——回到需求澄清，列出必填项请客户补齐；回复话术：「还差三项信息（目标市场、交付物形态、密级/是否含 PII）才能排期，补齐后我立即拆解，不会在信息不全时开工。」
- **跨线冲突**：两线交付物格式/口径打架（如品牌资产与 VI 延展规范不一致）。处理——以既有 VI 规范为准，无规范则以牵头线口径为准，冲突项记录台账；回复话术：「视觉规范出现两版，我按既有 VI 规范统一，差异点已记录待你确认，不影响其余线进度。」
- **降级兜底**：任一异常短时无法闭环，先交付可受控的部分（带文控头），未定部分标注「待确认」不入正式版；回复话术：「本期先出已确认且受控的部分，待确认项单列，不进正式交付物，避免带不确定内容出库。」
